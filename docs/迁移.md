# 迁移

把旧项目 `机械动力应力转动-AI漫画`（tag `冻结-1021` = `7d077904`）的第 6、7 章搬进来。阶段和验收标准见新项目方案第四节（旧项目 `预览/1021-0925-新项目方案/方案.md`），这里只写干活时要守的规矩和差异表。方案里的仓库名 `stress-rotation`、命令 `sr`、环境变量 `SR_*` 已改成 `mc-anim`、`anim`、`ANIM_*`（`决策/0003-改名-mc-anim.md`）。

## 原则

- **不改画面**：不改任何画面、规矩数值、镜头、台词，不借搬迁「统一」任何东西。旧代码和规矩值对不上的地方，一律登记成规矩例外（`作品/应力转动/规矩.toml`），不改画面。
- 旧代码原样搬，只改它放在哪、怎么被引用（import 路径、`getInputProps` 改成 context、资产引用改成 id）。`toThree` 副本原样搬、不合并（迁移不改代码，10-21 定的一次性搬家做法），这些副本和 lerp、Cam 等别的共用函数的副本一起登记在 `docs/副本表.tsv`（toThree 的正本在 `engine/core/three换算.ts`，别的见 `架构.md`「共用函数的正本」），以后重做哪一场再换成 import 正本、把表改小。
- 不重新生成配音、旧场景网格、世界存档。旧网格不重导：`6-4-3/编排/碎块.ts` 手写的 UV 依赖旧图集排布。
- 版本锁死：Remotion 4.0.537、three 0.186.1、react 19.3.0、esbuild 0.28.1、Node 24。这是逐帧比对的前提。Remotion 原锁 4.0.530（旧项目同版），用户 10-22 定升到 4.0.537（自带 Chromium 157），升级后全片重渲、用 `anim verify --对基线` 核对。
- 段名、台词 id 照 `作品/应力转动/旧名.tsv` 换；不搬旧 Git 历史。

## 怎么算搬完一段

- 用户 10-21 定：不要求逐像素，成片不要差太多就行，只修看得出来的差（东西没了、位置错、颜色明显不对、声音错位或缺失），几级像素差不追根因。
- 帧数完全相同；画面用 `anim verify --对基线` 和 `数据根/基线/<旧段号>/` 比（旧段号查 `作品/应力转动/旧名.tsv`），每帧「差 > 16/255 的像素占比」≤ 1×10⁻³ 算过，超了看并排图。
- 声音比整段响度（±0.5 LU）和起音落点（台词、音效落点差 ≤ 1 帧），不要求逐样本相同。阈值在 `verify/阈值.toml`。
- 基线由 `pipeline/适配器/旧项目/基线.ts` 生成（步骤见文件头），底噪和怎么复现见 `数据根/基线/底噪.md`。
- 基线以 `7d077904` 的代码为准；M0 对照已交付成片时，有差异的段由用户逐段指定以哪版为准。
- 过了以后 `anim verify accept`，把这一版记进 `作品/应力转动/认可/`。

## 整片合成的已知现象

- 伤害数字叠层的最后一帧：整片里 7-秒杀、7-风矢反击、7-骏马、7-墙头、7-上塔 这 5 段，叠层最后一帧（段内第 123、39、113、29、27 帧）不显示数字，叠层本身那一帧有字。已交付成片 `第6-7章-1020-1306.mp4` 也是这样（这几帧新旧要么逐像素相同、要么只差编码噪点），所以和交付版一致，不用用户定。只叠两段的冒烟片（`交付/1021-1635-冒烟-叠层接缝/`，7-秒杀 从全片第 0 帧起）却保留了这一帧：同一个 `pipeline/合成/叠层.ts`，结果随叠层在整片里的起点变。原因没细查，疑在 trim + setpts 挪到非零起点后 overlay `eof_action=pass` 的帧同步把最后一帧提前判成结束；以后出整片按「最后一帧丢」预期，改叠层滤镜时要重新核对这 5 处。

## 两个项目怎么分工

- 还没搬的场：用户要改，就在旧项目里小修，修完重渲这一场的基线。
- 已经搬过来的场：只在新项目改。
- 两边都不做「顺手统一」。
- 给用户看的预览一律写新仓库主检出的 `预览/`（`anim preview new`），不往旧项目写。10-21 渲染、整片两步写进旧项目 `预览/` 的 `1021-1748-搬家比对`、`1021-1852-新管线整片` 已克隆到新仓库 `预览/`（`1021-1748-搬家比对` 10-24 清理预览时挪到数据根 `archive/预览/`），旧项目里那两份删不删等用户定。
- 从 M3 起，整片一律由新管线出；没搬的段经「旧项目执行器」在冻结提交上渲母版（指纹 = 旧提交 + 旧段号），剪映草稿全程不断。
- 退役条件、退役时做的事见方案第四节。

## 「接受变化」只有两种情况

1. **用户在对比预览里明确同意了**：出 `预览/<UTC>-<主题>/`，新旧并排，`00-说明.md` 写清差在哪，用户在「你的回复：」下点头。
2. **旧的东西本来就是错的，而且不在画面上**：例如旧同步表把 6-4-3 的击穿声排进了本来没声音的 6-挑飞，新同步表照 cue 列就没有这几行，渲出来的画面和声音都不变。

除此之外，和旧版对不上就是迁移出错，要修，不能接受。两种情况都要登记进下面的差异表，一行一条。
