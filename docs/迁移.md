# 迁移

把旧项目 `机械动力应力转动-AI漫画`（tag `冻结-1021` = `7d077904`）的第 6、7 章搬进来。阶段和验收标准见新项目方案第四节（旧项目 `预览/1021-0925-新项目方案/方案.md`），这里只写干活时要守的规矩和差异表。

## 原则

- **不改画面**：不改任何画面、规矩数值、镜头、台词，不借搬迁「统一」任何东西。旧代码和规矩值对不上的地方，一律登记成规矩例外（`rules/规矩.toml`），不改画面。
- 旧代码原样搬，只改它放在哪、怎么被引用（import 路径、`getInputProps` 改成 context、资产引用改成 id）。`toThree` 只合并字面上完全等价的那几份。
- 不重新生成配音、旧场景网格、世界存档。旧网格不重导：`6-4-3/编排/碎块.ts` 手写的 UV 依赖旧图集排布。
- 版本锁死：Remotion 4.0.530、three 0.186.1、react 19.3.0、esbuild 0.28.1、Node 24。这是逐帧比对的前提。
- 段名、台词 id 照 `docs/旧名.tsv` 换；不搬旧 Git 历史。

## 怎么算搬完一段

- 帧数完全相同；画面和 `数据根/基线/<段键>/` 比，差异不超过 M0 测出的渲染底噪（同机、同 GPU 渲）。
- 音频新减旧 ≤ −90 dBFS；台词落点逐行一致。
- 基线由 `pipeline/适配器/旧项目/基线.ts` 生成（步骤见文件头），底噪和怎么复现见 `数据根/基线/底噪.md`。
- 基线以 `7d077904` 的代码为准；M0 对照已交付成片时，有差异的段由用户逐段指定以哪版为准。
- 过了以后 `sr verify accept`，把这一版记进 `verify/accepted/`。

## 两个项目怎么分工

- 还没搬的场：用户要改，就在旧项目里小修，修完重渲这一场的基线。
- 已经搬过来的场：只在新项目改。
- 两边都不做「顺手统一」。
- 从 M3 起，整片一律由新管线出；没搬的段经「旧项目执行器」在冻结提交上渲母版（指纹 = 旧提交 + 旧段号），剪映草稿全程不断。
- 退役条件、退役时做的事见方案第四节。

## 「接受变化」只有两种情况

1. **用户在对比预览里明确同意了**：出 `预览/<UTC>-<主题>/`，新旧并排，`00-说明.md` 写清差在哪，用户在「你的回复：」下点头。
2. **旧的东西本来就是错的，而且不在画面上**：例如旧清单漏收了 6-规矩风矢 的风扇、风场、放箭声，新 cue 补全后，渲出来的画面和声音都不变。

除此之外，和旧版对不上就是迁移出错，要修，不能接受。两种情况都要登记进下面的差异表，一行一条。
