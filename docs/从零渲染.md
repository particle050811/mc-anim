# 从零渲染（Windows 优先）

本文的读者是人，也可以是 AI 编程助手。条件是：一台 Windows 电脑，本机没有任何素材，只能从 GitHub 拿东西。照着做完，能把仓库里的三部作品渲成成片，画面、声音和作者渲的一样。Mac / Linux 的不同之处写在最后一节。

**给 AI 助手的规矩**（人也照这个来）：

1. 一步一步做。每一步都有「应该看到」，对上了再往下走。
2. 不改仓库里的任何文件，不加 `--重渲`，不删数据根里的东西，不跑 `git pull`、`git checkout` 之外的 git 命令。
3. 只用 `.\anim.cmd`（Mac / Linux 用 `./anim`）。不要用 `npx remotion …`，也不要用 `npm install`，装依赖只用 `pnpm install --frozen-lockfile`。
4. 仓库根的 `CLAUDE.md` 是作者自己的 AI 助手的工作纪律（写预览、开分支、提交这些）。只渲染的话，**不用照它做**。
5. 碰到本文「常见问题」里没有的报错，停下来，把完整的命令和输出交给人。不要自己改代码绕过去。

## 0. 要准备什么

| 项 | 要求 |
|---|---|
| 系统 | Windows 10 / 11，64 位 |
| 显卡 | 独立显卡最好（作者的验收机是 RTX 4060 Laptop）。集显也能渲，只是慢 |
| 内存 | 16 GB 起，32 GB 更好。渲染前会等空闲内存到 30% 以上才开始 |
| 硬盘 | 留 40 GB：代码和依赖约 2 GB，素材约 1.1 GB（解开以后差不多），渲染用的浏览器约 0.6 GB，每段的切片和成片合计 10～20 GB |
| 网络 | 见下面「下载源」。工具、npm 包、渲染用的浏览器都走国内镜像，不用代理；代码和素材只在 GitHub 上，**最好开代理** |
| 时间 | 下载 0.5～1 小时（看网速）。出片：作者的 Mac 上 应力转动 约 2 小时，另外两部各 20～40 分钟，Windows 一般慢一半左右 |

## 1. 打开 PowerShell

开始菜单搜「PowerShell」打开（Windows PowerShell 5.1 或 PowerShell 7 都行），先跑这两行，让中文正常显示：

```powershell
chcp 65001
[Console]::OutputEncoding = [Text.Encoding]::UTF8
```

**每开一个新的 PowerShell 窗口都要先跑这两行。** 下面的命令都在 PowerShell 里跑，一行一行地跑。

如果后面跑 `npm`、`pnpm` 时报「无法加载文件 …ps1，因为在此系统上禁止运行脚本」，跑一次下面这行，再重跑刚才那条：

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned -Force
```

## 2. 装工具

先查已经装了什么：

```powershell
git --version
node -v
ffmpeg -version
```

- `git --version` 应该看到 `git version 2.xx`。
- `node -v` 应该看到 `v24.`开头的版本（必须是 24，别的大版本不行）。
- `ffmpeg -version` 的第一行应该是 `ffmpeg version …`。

缺哪个装哪个。下面都从国内镜像 npmmirror 下，不用代理。`curl.exe` 是 Windows 10 / 11 自带的，要写全 `curl.exe`（PowerShell 里单写 `curl` 是另一个命令）。

**装完要关掉这个 PowerShell 窗口、重开一个**（新装的程序要在新窗口里才找得到），重开以后再跑一遍第 1 步那两行。

### Git

```powershell
curl.exe -L -o "$env:TEMP\Git-2.56.1-64-bit.exe" https://registry.npmmirror.com/-/binary/git-for-windows/v2.56.1.windows.1/Git-2.56.1-64-bit.exe
Start-Process "$env:TEMP\Git-2.56.1-64-bit.exe" -ArgumentList "/VERYSILENT","/NORESTART" -Wait
```

- 第一行打印下载进度，约 60 MB。
- 第二行会弹出「是否允许此应用更改你的设备」，点「是」。装完不出任何东西。

### Node 24

```powershell
curl.exe -L -o "$env:TEMP\node-v24.15.0-x64.msi" https://registry.npmmirror.com/-/binary/node/v24.15.0/node-v24.15.0-x64.msi
Start-Process msiexec.exe -ArgumentList "/i","$env:TEMP\node-v24.15.0-x64.msi","/passive" -Wait
```

- 同样会弹「是否允许」，点「是」，然后有个小进度条，自己关掉。
- 必须是 24 这个大版本。如果 `node -v` 已经是别的大版本（比如 22、26），先在「设置 → 应用」里卸掉 Node.js，再跑上面两行。

### ffmpeg

放进自己用户目录下，再加进 PATH，不用管理员权限：

```powershell
New-Item -ItemType Directory -Force "$env:LOCALAPPDATA\ffmpeg\bin" | Out-Null
curl.exe -L -o "$env:LOCALAPPDATA\ffmpeg\bin\ffmpeg.exe" https://registry.npmmirror.com/-/binary/ffmpeg-static/b6.1.1/ffmpeg-win32-x64
curl.exe -L -o "$env:LOCALAPPDATA\ffmpeg\bin\ffprobe.exe" https://registry.npmmirror.com/-/binary/ffmpeg-static/b6.1.1/ffprobe-win32-x64
[Environment]::SetEnvironmentVariable("Path", [Environment]::GetEnvironmentVariable("Path", "User") + ";$env:LOCALAPPDATA\ffmpeg\bin", "User")
```

这是 ffmpeg 6.1.1（gyan.dev 的 essentials 构建），出片够用。它不带 libsvtav1，所以第 4 步 `doctor` 里 libsvtav1 是 ✗，只影响 `film --分享版`（压小体积的分享版），不影响出片。要分享版的话，到 https://www.gyan.dev/ffmpeg/builds/ 下 `ffmpeg-release-full.7z`（国外，最好走代理），解开后用里面 `bin\` 的两个 exe 换掉上面那两个。

### pnpm

先让 npm、pnpm 都从国内镜像装包，再装 pnpm。pnpm 要 `11.25.0` 这一版，和仓库 `package.json` 里 `packageManager` 写的一样：

```powershell
npm config set registry https://registry.npmmirror.com
npm install -g pnpm@11.25.0
pnpm --version
```

- 第一行不输出东西。它写进你的用户配置，以后 pnpm 也照这个镜像下。
- 最后应该看到 `11.25.0`。

### Git 设置

```powershell
git config --global core.quotepath false
git config --global core.longpaths true
```

两条都不输出任何东西。仓库里的文件名大多是中文，路径也长，这两项必须设。

## 3. 拿代码

放在短路径下，比如 `D:\mc-anim`。没有 D 盘就用 `C:\mc-anim`，下面的路径跟着换。

这一步要连 GitHub（国外）：代码在 GitHub 上，`pnpm install` 里也有一个依赖（`gelatin-game-engine`）从 GitHub 下，别的依赖走第 2 步设的国内镜像。**最好先照「6. 代理」开好代理再跑。**

```powershell
cd D:\
git clone https://github.com/particle050811/mc-anim.git
cd D:\mc-anim
pnpm install --frozen-lockfile
```

- `git clone` 结束时应该看到 `Resolving deltas: 100%`，可能还有一行 `Updating files: 100%`。
- `pnpm install` 最后一行应该是 `Done in …`。报 `ERR_PNPM_…` 的话，看「常见问题」。
- `git clone` 卡住、报 `Failed to connect to github.com`，或者 `pnpm install` 卡在 `codeload.github.com`：照「6. 代理」开代理，删掉没下完的 `D:\mc-anim` 再从头跑这一步。

**以后的命令都在 `D:\mc-anim` 里跑。**换了窗口要先 `cd D:\mc-anim`。

素材、切片、成片都放在仓库旁边的 `D:\mc-anim-data`，叫「数据根」。第一次用到时会自动建，不用手动建。

## 4. 体检

```powershell
.\anim.cmd doctor
```

每项前面是 `✓`（过了）、`✗`（必需的没过）或 `!`（只是提示）。最后一行是「必需项全过」或「N 项必需的没过」。这时候应该：

- **必须是 ✓ 的**：Node、依赖、pnpm、ffmpeg、ffprobe、git core.quotepath、git core.longpaths。有 ✗ 就回第 2 步补，后面写了该怎么做。
- **这时是 `!` 很正常的**：`素材·<作品>`（还没下，第 5 步下）、`资产字节`、`数据根/…还不在`、`渲染浏览器`、`libsvtav1`、`uv`、`游戏环境`、`锁目录`，还有 `作品`（说有 3 部作品、要用 --作品 指定：后面的命令都带了 `--作品`，不用管）。

## 5. 下素材

素材挂在 GitHub Release 上（国外，约 1.1 GB），**最好开着代理**（「6. 代理」）。三部作品各下一次，每条命令会下自己那部作品还缺的东西：

```powershell
.\anim.cmd --作品 把回忆拼好给你 assets pull
.\anim.cmd --作品 亚波伦不放水 assets pull
.\anim.cmd --作品 应力转动 assets pull
```

- 开头一行是 `要下 N 个附件，共 X GB（particle050811/mc-anim 的 Release assets-v1）`，接着是 curl 的下载进度条。
- 每个附件下完、解开以后，会打印 `… 件字节，新放进数据根 … 件`，地形包是 `地形包 <名>/<版本>：N 个文件`。
- 三条都跑完，再跑一遍，每条都应该打印 `… 个附件的东西数据根里都有`。
- 再跑 `.\anim.cmd doctor`，三行 `素材·<作品>` 都应该是 ✓。`资产字节` 还会是 `!`、说有上千件不在，那是没有段用到的参考图和旧版，Release 不发，**不用管**。
- 下到一半断了（报 `curl: (56)`、`(28)`、`(35)` 这类），**原样再跑同一条**，会接着下。连续失败就看「6. 代理」。
- 每个附件下完都核 sha256，对不上不会解进去，所以从哪下都不怕下到被改过的。
- 大约：把回忆拼好给你 25 MB，亚波伦不放水 45 MB，应力转动 1.05 GB。

## 6. 代理

只有 GitHub 上的三样东西要它：代码（第 3 步）、`gelatin-game-engine` 这个依赖（第 3 步）、素材（第 5 步）。别的都走国内镜像。

先开好代理软件，在 PowerShell 里设这三行，再在**同一个窗口**里跑（或重跑）要连 GitHub 的那条命令：

```powershell
$env:HTTPS_PROXY = "http://127.0.0.1:7890"
$env:HTTP_PROXY = "http://127.0.0.1:7890"
$env:NODE_USE_ENV_PROXY = "1"
```

- `127.0.0.1:7890` 换成你自己代理软件的 HTTP 代理端口。Clash 默认是 7890，v2rayN 常见的是 10808 或 10809。
- 前两行 git、curl、pnpm 都认（`assets pull` 靠 curl 下载）；第三行让 Node 自己发的请求也走代理。
- 这三行只对当前窗口有效，重开窗口要重设。
- 代理开着也不影响国内镜像，不用来回关。

**没有代理**也可以试：直连 GitHub 有时能下，只是慢、会断，原样重跑会接着下。素材还可以换个下载地址：网上能找到一些「GitHub 加速」站，地址是在 `https://github.com/…` 前面加一段前缀，把带前缀的那一段设进 `ANIM_GITHUB_MIRROR`：

```powershell
$env:ANIM_GITHUB_MIRROR = "https://<加速站>/https://github.com"
.\anim.cmd --作品 应力转动 assets pull
```

这类站是第三方的，时好时坏，不保证能用；附件都核 sha256，下到假的会直接报错，不会用。

## 7. 先渲一张静帧试试

三部作品各出一张。第一次跑会先从国内镜像下载渲染用的浏览器（打印「从国内镜像下（约 125 MB）」和进度条，接着「渲染用的浏览器已放进数据根」），然后打包代码（一两分钟），所以第一张要多等几分钟。

```powershell
.\anim.cmd --作品 把回忆拼好给你 still 2-祭坛召唤 60 --到预览 试渲
.\anim.cmd --作品 亚波伦不放水 still 4-齐放 200 --到预览 试渲
.\anim.cmd --作品 应力转动 still 6-飞越主世界俯冲边城 60 --到预览 试渲
```

- 每条最后会打印 PNG 的路径，在 `D:\mc-anim\预览\<日期时间>-试渲\` 下面。打开看一眼：应该是正常的 Minecraft 画面，不是全黑、全白或者一片洋红。
- 不应该出现「字节…不在数据根」「这段打进包的是占位」「换成…秒静音」。出现了，说明第 5 步有作品没下全，回去重跑那条 `assets pull`。
- 过程中可能有好几行「等资源闸」「排队」「空闲内存…」，那是在等内存、等别的渲染让出机器，**不是卡住了**，耐心等。

## 8. 出片

一部一部来，一条命令出一部的成片。每条都会把缺的段先渲成切片，再接起来：

```powershell
.\anim.cmd --作品 把回忆拼好给你 film 2
.\anim.cmd --作品 亚波伦不放水 film 1-6
.\anim.cmd --作品 应力转动 film 6-7
```

| 作品 | 命令 | 成片长度 | 作者 Mac 上的耗时 |
|---|---|---|---|
| 把回忆拼好给你（MC 短片，配歌） | `film 2` | 约 56 秒 | 几十分钟 |
| 亚波伦不放水（Goety 短片） | `film 1-6` | 约 33 秒 | 约 20 分钟 |
| 应力转动（漫剧第 6、7 章） | `film 6-7` | 约 5 分 55 秒 | 约 2 小时 |

- 渲的时候会一段一段打印进度。**中途断了（关了窗口、断电、报错）就原样再跑同一条**：渲好的段会接着用，只补没渲完的。
- 跑完最后会打印成片目录，在 `D:\mc-anim-data\交付\<作品>\<UTC 日期时间>-<名>\` 下。里面有：
  - `<名>.mp4`：成片（默认 3840×2160、60 帧）。`<名>` 默认就是你给的选择器，比如 `2`、`1-6`、`6-7`。
  - `manifest.json`：这次用了哪些段、代码是哪个提交、时长多少。
  - 有台词的作品还有 `.srt` 字幕。
- 核对一下时长：

  ```powershell
  ffprobe -v error -show_entries format=duration -of csv=p=0 "<成片 mp4 的完整路径>"
  ```

  打印的秒数应该和上表差不多。

全部做完，三部成片就都在 `D:\mc-anim-data\交付\` 下了。

## 和作者渲的会差多少

- 素材、代码完全一样：每件素材都按 sha256 核过，代码是同一个提交。
- 画面：Windows 默认用 Vulkan 后端，同一台机器渲两遍逐帧相同。和作者的 Mac 比，11-14 在 RTX 4060 笔记本上照本文走一遍，两张静帧的 PSNR：应力转动 `6-飞越主世界俯冲边城` 第 60 帧 50，把回忆拼好给你 `2-祭坛召唤` 第 60 帧 34，并排看不出差别。差在草丛、小花、草方块顶面这些带随机偏移和朝向的东西：两种显卡算出来不一样，近处草多的画面差得多一些。
- 声音：完全按同一份配乐、配音、音效混，响度拉到同一个值。

## 常见问题

| 现象 | 怎么办 |
|---|---|
| 中文显示成乱码 | 跑第 1 步的两行 |
| `无法加载文件 …\npm.ps1` / `pnpm.ps1`，「禁止运行脚本」 | 跑第 1 步的 `Set-ExecutionPolicy` 那行 |
| `pnpm`、`node`、`ffmpeg`、`git` 不是内部或外部命令 / 无法识别 | 刚装完要关窗口重开；还不行就是没装上，回第 2 步 |
| `doctor` 里 Node ✗，说 .nvmrc 要 24 | 装 Node 24，见第 2 步 |
| `doctor` 里 pnpm ✗ | `npm install -g pnpm@11.25.0`，重开窗口 |
| `doctor` 里 依赖 ✗ | 在 `D:\mc-anim` 里重跑 `pnpm install --frozen-lockfile` |
| `npm`、`pnpm` 报 `ECONNREFUSED`、`ETIMEDOUT`、`ECONNRESET` | 网络偶发（代理软件切换、镜像一时没响应），原样重跑同一条 |
| `pnpm install` 报 `ERR_PNPM_OUTDATED_LOCKFILE` | 不要去掉 `--frozen-lockfile`。检查 `pnpm --version` 是不是 11.25.0 |
| `Filename too long` / 路径太长 | `git config --global core.longpaths true`，删掉 `D:\mc-anim` 重新 clone |
| `assets pull` 报 `HTTP 404`、`Release assets-v1 上没有 …` | 仓库作者还没把这一版的附件传上去。告诉人，等作者处理 |
| `assets pull` 报 sha256 对不上 | 重跑同一条。还不行就删掉 `D:\mc-anim-data\cache\发布\` 里那个 tar 再跑 |
| `assets pull` 很慢、反复断 | 见第 6 步设代理；断了就原样重跑，会接着下 |
| 打印「国内镜像没下成…改让 Remotion 从 … 下」 | 国内镜像这次不通，改从 Google 下（国外）。一直不动就按 Ctrl+C 停掉，照第 6 步设代理（三行都要），重跑同一条命令 |
| 报「浏览器下载失败」 | 同上，设代理后重跑 |
| `git clone` / `pnpm install` 报 `Failed to connect to github.com`、`codeload.github.com` 超时 | GitHub 在国外，照第 6 步开代理，删掉 `D:\mc-anim` 重跑第 3 步 |
| 一直打印「等资源闸」「空闲内存不够」 | 关掉别的大程序（浏览器、游戏），等它自己开始。不要强杀 |
| 报 `数据根里缺…`、`字节…不在` | 那部作品没下全，重跑它的 `assets pull` |
| 画面全黑 / 洋红 / 报 WebGL 错误 | 更新显卡驱动。笔记本要在显卡控制面板里让它用独显 |
| 渲到一半报错退出 | 原样再跑同一条 `film`，已渲完的段会沿用。同一处反复报错，就把完整输出交给人 |
| 磁盘满了 | `.\anim.cmd cache gc` 先看能删多少，确认后 `.\anim.cmd cache gc --执行` |

## Mac / Linux

- 用 Terminal，命令把 `.\anim.cmd` 换成 `./anim`，路径换成 `~/mc-anim` 这类。不用跑第 1 步。
- 装工具：Mac 用 Homebrew（`brew install git node@24 ffmpeg`），Linux 用发行版的包管理器，或者 nvm 装 Node 24（Node 安装包的国内镜像：https://registry.npmmirror.com/-/binary/node/v24.15.0/ ；Homebrew 的国内镜像可以用清华或中科大的）。然后和 Windows 一样 `npm config set registry https://registry.npmmirror.com`、`npm install -g pnpm@11.25.0`。
- 渲染用的浏览器：Apple 芯片的 Mac 和较新的 Linux（glibc 2.35 起）用 Remotion 自己打过补丁的构建，只在 remotion.media 上有（国外，约 180 MB，最好走代理）；Intel Mac、旧 Linux 和 Windows 一样走国内镜像。
- 代理：设 `export HTTPS_PROXY=http://127.0.0.1:7890 HTTP_PROXY=http://127.0.0.1:7890 NODE_USE_ENV_PROXY=1`。
- Mac 上和作者渲的是同一个后端，画面可以做到逐字节相同。
