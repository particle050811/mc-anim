# 成片时间轴（v1）

起因：用户 11-19 说改一处总是「顾头不顾尾」，后面接着的地方不连续（音乐突变、动作镜头突变），要像跑单元测试那样查；又要 image-flow 网页播放器做「类似剪映那样的时间轴，可以随意拖动……下面看到音频轴，这个音频轴暂时只存我们的音频对象，并不存放实际的音频」。

成片时间轴 json：mc-anim 出片时写、image-flow 播放器读。只存段、镜头、事件、声音对象这些元数据，不存音频。

代码：`pipeline/出片/时间轴.ts`（纯函数，算时间轴）、`作品源.ts`（按一份代码根打包加载作品数据）、`时间轴文件.ts`（写盘、补旧片）。

## 时间轴 json

### 放哪、叫什么

- 和成片 mp4 同一目录，文件名 = mp4 去掉扩展名 + `.时间轴.json`。例：`雷声接缝修正.mp4` → `雷声接缝修正.时间轴.json`。
- 播放器打开 `X.mp4` 时找同目录的 `X.时间轴.json`；找不到就不显示时间轴（老片照常放）。
- `anim film` 正式出片写完成片顺手写一份（manifest.json 的 `file.timeline` 记文件名）；算不出来只警告，成片照常。试看片（`run/草稿/`）不写。
- 老片补：`anim film timeline <交付夹|成片 mp4>`，按**当前代码**算，写在 mp4 旁边。发布夹（`发布/<作品>/<夹>/成片-…mp4`）里没有 manifest.json，按字节（先比大小，再比头尾各 1 MB 的 sha256）在 `交付/<作品>/` 里找出处，用那一夹的 manifest 取段、帧率、代码版本，文件名照样跟着发布夹里的 mp4 名。

### 结构（UTF-8，秒都是成片时间，从 0 起，保留到 6 位小数）

```jsonc
{
  "format": "mc-anim-timeline",
  "version": 1,
  "work": "亚波伦不放水",
  "film": "雷声接缝修正",            // 交付名
  "video": "雷声接缝修正.mp4",       // 同目录的视频文件名
  "fps": 60,
  "frameCount": 2410,
  "durationSec": 40.166667,
  "code": { "commit": "0e7ec571…", "dirty": false },   // 生成这份数据的代码；和 manifest.json 的不一致时 "stale": true
  "stale": false,

  // 段：按成片顺序首尾相接
  "segments": [ { "key": "1-召唤", "serial": "1-01", "startSec": 0, "durSec": 8.35, "startFrame": 0, "frameCount": 501 } ],

  // 镜头：每个镜头从哪一帧起（取不到就给 []）。段缝不一定是切镜，切镜不一定在段缝
  "shots": [ { "name": "2-03", "startSec": 9.1, "startFrame": 546, "segment": "2-开盘" } ],

  // 事件：场时间线上的事件换成成片秒（现身、齐放出手……），取不到给 []
  "markers": [ { "name": "yaBoLunAppears", "sec": 6.4, "segment": "1-召唤" } ],

  // 声音对象：一条 = 片里实际放的一截（段里的 cue；场声音每段一截）
  "audio": [
    {
      "id": "1-召唤/7",              // 段键/段内序号，唯一
      "segment": "1-召唤",
      "kind": "配乐",                // 配乐 | 音效 | 台词（资产 id 以 配乐/ 开头的是配乐；台词 cue 是台词；其余音效）
      "name": "战斗曲",
      "asset": "配乐/亚波伦/決戦の刻", // 台词给台词 id
      "startSec": 6.4,
      "durSec": 1.95,
      "inSec": 20.933,               // 从文件第几秒放起
      "rate": 1,
      "loop": false,
      "gainDb": -11.0,               // 起点增益（相对文件原样，dB；静音给 null）
      "endGainDb": -11.0,            // 末尾增益
      "fadeOutSec": null,
      "group": "场声音:战斗曲",       // 跨段的同一个声音：同 group 的几截在播放器里连起来画，接缝处画一道
      "fileDurSec": 215.69,          // 文件总长（量不到给 null）
      "cutAtSegEnd": false,          // 放到段尾、文件没放完、下一段也没接（=声音接缝检查会报的那种）
      "cutReason": null
    }
  ]
}
```

### 各字段怎么来的

- **段**：作品 `清单.ts` 顺序的正片段，段长按帧取整、首尾相接，和 `pipeline/出片/拼成片.ts` 接的一样（`engine/段/出帧.ts` 的 `filmStartFrameTable`）。片只出一串里的几段时从这串第一段起算 0。
- **镜头**：作品有 `动作体检.ts` 的，用 `auditMotion` 给的切镜（整部作品正片的帧）换成本片的帧；片从一镜中间起的，第 0 帧补上当时那一镜。动作体检的总帧数和整部作品对不上（没跟着改）就给 []。没有 `动作体检.ts` 的作品给 []。
- **事件**：段是窗口段（有 `sceneWindow`）的，取它那场 `场/<场键>/时间线.ts` 的 `events`，落在窗口 [起, 止] 里的换成成片秒；段缝上的同一个事件只记一次。
- **声音**：各段 `段.ts` 的 `sound`。场声音已经被 `windowSeg` 切进各段，认法是拿场时间线的 `sound` 名单和本段的声音表重切一遍（`engine/段/场声音.ts` 的 `sceneSoundSlice`），对上起秒、长秒的那几条就是，group 写 `场声音:<名>`。不往 cue 上加字段：engine 进段指纹，加字段全片过期。
  - 段里自己写、下一段从段头接着放的（声音接缝检查认得出的接续，比如「尖啸」接到下一段叫「尖啸（接 6-4-4）」），group 写 `接续:<头一截的 id>`；台词标了 接上段 的后半截也这样和前半截连成一组。不跨段的 group 是 null。
  - 台词按 `engine/段/放法.ts` 的 `segPlayPlan` 算起放、入点、长度（和母版一样），gainDb 是 0（台词总线原样放）。
  - 增益是 cue 上的增益（含音效总线、距离衰减），不含整片最后拉响度的那一下。逐格增益的 gainDb、endGainDb 取首尾两格。
  - `cutAtSegEnd` 直接用 `pipeline/段框架/声音接缝.ts` 的 `seamStatus`，和 `anim check` 的声音接缝检查同一个判断、同一套音频时长（锁里的数或量过的缓存）；段缝按整部作品的成片顺序看，片尾那段的下一段是清单里真正的下一段。写了 `cutReason` 的照样是 true，原因写在 `cutReason`（检查不报它，播放器照样画截断标记）。
- **stale**：出片时写的是 false。`film timeline` 补的：manifest.json 的 `code.commit` 和当前 HEAD 不同、或两边有一边是脏的，就是 true，命令行也会提示；段长对不上（片子是别的代码出的）另外列出来。

### 播放器怎么画（给 image-flow）

- 视频下面一块时间轴：刻度尺（秒 + 帧）、段轨、镜头轨（切镜竖线）、事件轨（小旗），再往下按 kind 分区的音频轨：配乐、音效、台词；同区里重叠的自动往下排成多行。
- 播放头可以拖、点刻度跳过去，和视频逐帧同步（复用播放器现有的帧号↔时间换算，跳到帧正中间）；横向可缩放（Ctrl/⌘ + 滚轮或捏合）、可横向滚动，缩放后播放头跟随。
- 音频块：宽 = durSec；块上写 name；悬停显示 asset、段、起止秒/帧、入点秒、增益、速率、循环、淡出；同 group 的几截连成一条，接缝画竖线、悬停显示两边文件位置；cutAtSegEnd 的块尾部画醒目的截断标记。点块 → 视频跳到块起点。
- 只画对象，不加载、不播放音频文件。
