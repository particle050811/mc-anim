  - 命中率依据（运行记录 10-22～11-01，成功 947 次、5534 帧次）：同段同帧同级别 74.2%（Astra 的 75.5% 也是这个口径），但这不是命中率，运行记录没存指纹。用母版 `.指纹.json` 的模块闭包和 git diff 夹：下界 5.2%（288 帧次：前后两次工作区都干净、之间的提交没动闭包）；上限 40.2%（2223 帧次：工作区有改动的按它的提交算，69% 的 still 工作区有改动，边改边看的都算成命中，所以偏高）；只看工作区干净的 1533 帧次，命中 18.8%。闭包用每段最新一份，90% 的帧次有，其余段按 engine、库、作品共用文件一改就算失效。
  - 能省多少：按记录的秒算 1.81 小时（下界）～3.44 小时（上限），占静帧总时间 7.62 小时的 24%～45%。这个秒含排队：有阶段记录的 120 次 still 共 10899 秒，等闸 6523 秒，出帧只有 3296 秒（每帧 9.4 秒），所以省下的大半是等锁，别的任务不抢锁时会少很多。
  - 方案：键 = 段指纹（已含级别、渲染设置、依赖版本、地形、平台）+ 帧 + 出帧方式（逐帧、同页连出画面不完全相同，不能混，见 `docs/渲染性能.md`）。存 `<数据根>/cache/静帧/<作品>/<段键>/`，PNG 平均 2.7 MB，`anim cache gc` 加一类按天数回收。`渲静帧` 开会话前先算指纹（`anim stale` 查一段约 6 秒，高负载下、含启动），全中就跳过打包、读组合（有阶段记录的平均 8.9 秒、中位 4.9 秒）和排队，`cp -c` 进新预览目录；部分命中只渲缺的。按内容算指纹，所以工作区有改动的也能命中。加 `--重渲` 绕过，查不确定性、比重渲这类诊断必须绕过。
  - 风险：命中时不再现已知的微小不确定性（`docs/渲染性能.md`），定稿要不要也走缓存要用户定；跨 worktree 共用要等「路径无关」的结论；指纹只记平台（darwin-arm64），不记显卡驱动，换驱动或换机器的差异不会让缓存失效。
