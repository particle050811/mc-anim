# 游戏导表：群系色表、方块表直接从游戏取

手写的两张表（资产 `数据/场景/关键帧/群系色`、`数据/场景/关键帧/方块表`，旧项目 `关键帧方块.py` 从 jar 里的 JSON 推算出来）漏掉的东西：
代码里改的颜色（暮色的树叶 coremod、原版沼泽草）、模组用代码烘焙的模型、资源包、只在运行时才有的方块状态。
取材 mod 的两个动作 `biomes`、`blocks` 在游戏里直接问渲染器，导出同结构的表；`anim gamedata` 导出并和手写表逐项核对。

**迁移期只出报告、不替换手写表**（会改画面）。新章节要用导出表，登记成新资产（见最后一节），由新段自己 import。

## 怎么用

```
anim mcai game start world=片场        开游戏（过资源闸，等渲染让出）
anim gamedata 导出                     导 群系色.json、方块表.json/.png 到 run/草稿/<UTC>-工作-游戏导表/，接着核对
anim gamedata 导出 --只 方块 --方块 'twilightforest:*,create:*'   只导一部分方块
anim gamedata 核对 <目录>              目录里的导出表和资产锁里的手写表比，写 核对.md、核对.json
anim mcai game stop
```

也可以直接调动作：`anim mcai biomes out=<路径>`、`anim mcai blocks out=<路径> [only=<通配,…>]`（路径不带扩展名）。

## 输出

**群系色.json**：`群系.<id>` 有 `草 叶 水`（和手写表同名同义，`#rrggbb`），另有 `天空 雾 水雾 温度 降水量 降水`、`温度修正`、`草修饰名`、`草覆盖`、`叶覆盖`。
颜色是游戏的 `BiomeColors` 取色器在 `采样点`（固定 4 点加 60 个伪随机点，种子写死）上给的值；草或叶随位置变的，`草`/`叶` 写不改时的底色，
另记 `草修饰`（原版的修饰名）或 `叶修饰`（群系 id）——和手写表的约定一样，`engine/voxel/群系色.ts` 能直接读——并在 `采样` 里记每个采样点的游戏值。
`取材` 记游戏版本、模组版本、启用的资源包、导出参数。

**方块表.json + .png**：结构和手写方块表一样（`贴图`、`面组`、`方块: {状态: [标志, 染色路, 面组…]}`，面 `[朝向, 剔除, 贴图, 叠加, 染色, 标志, 四角 xyz, 四角 uv]`，
场景坐标 X=16x、Y=16(1−z)、Z=16y），PNG 是 16×16 竖排，和手写表的贴图一样缩成 16×16。差别：

- 状态是**完整**的（`id[属性=值,…]`，属性按名排序），每个方块第一个是默认状态；手写表只写影响外观的属性。
- 面来自烘焙好的 `BakedQuad`（模组用代码造的模型、资源包换的模型都在），`uvShrinkRatio` 的收缩已还原；随机变体取第一个（`附加.变体数` 记有几个）。
- 染色路由假世界探出来（`TintProbe`）：取色器只读草、叶、水的取色器就记 `grass`/`foliage`/`water`，给定值的记 `#rrggbb`，按位置算的记 `动态:<取色器类>`。
- 渲染形状不是 MODEL 的：流体画成一个顶面（照手写表的液体面），其余（箱子、告示牌、机械动力的转动件等 BER 画的）不出面，记进 `附加.不画`。
- `附加` 另有 `发光`、`偏移`（XZ/XYZ 随机偏移）、`多染`（一个状态里不止一种染色）；`统计` 记数量和模型类。

**核对.md / 核对.json**（`pipeline/取材/游戏导表/核对.ts`）：群系的定值和修饰逐项比，随位置变的拿现行规则在采样点上和游戏比；
方块按手写键对到完整状态（手写键写了的属性都对上，其余取默认状态的值），比标志各位、染色路、面（几何、贴图、uv），并列出导出多出的状态和方块。

## 代码在哪、怎么换版本

```
sourcing/mod/src/main/java/mcai/
  gamedata/GameData.java      版本无关的窄接口：gameVersion、mods、resourcePacks、biomes()、blocks()
  gamedata/BiomeSource.java   取群系色：ids、info（气候、特效颜色、覆盖、修饰名）、color(id, 草|叶|水, x, z)
  gamedata/BlockSource.java   取方块模型：states、model(state) → 层、标志、面（Quad：位置 0..1、uv 0..16、贴图名、染色索引、明暗、剔除）、贴图像素
  gamedata/BiomeTable.java    出群系色表（只用接口和 Gson）
  gamedata/BlockTable.java    出方块表：换坐标、顶点顺序、叠加层合并、转向判断、贴图缩 16×16
  gamedata/TintProbe.java     染色路的判定（哨兵色）
  gamedata/Png.java           确定性的 PNG 编码
  gamedata/forge1201/         Forge 1.20.1 的实现，**只有这里 import 游戏类**
  action/BiomesAction.java、BlocksAction.java   两个动作，各有一行 new ForgeGameData()
sourcing/mod/test/game-data-test.sh             出表部分的离线测试（假 GameData，不开游戏）
pipeline/取材/游戏导表/                          anim gamedata：导出、核对
```

换到 NeoForge 1.21.1（或别的版本、加载器）：写一个 `gamedata/neoforge1211/` 实现 `GameData`，两个动作里那一行换掉（或按加载器选），表的结构和核对不用动。
`forge1201/` 和版本耦合的地方，移植时逐条看：

| 耦合点 | 1.20.1 Forge 的写法 | 换版本要查 |
|---|---|---|
| 群系注册表 | `level.registryAccess().registryOrThrow(Registries.BIOME)` | 新版本里这个方法改过名（1.21.2 前后），用 `Holder` 取 |
| 群系气候、特效 | `Biome.getModifiedClimateSettings()`、`getModifiedSpecialEffects()`（Forge 的 BiomeModifier 改过之后的） | NeoForge 同名方法；`BiomeSpecialEffects.GrassColorModifier` 的序列化名 |
| 草叶水取色 | `BiomeColors.GRASS/FOLIAGE/WATER_COLOR_RESOLVER`，暮色的 coremod 补丁打在 FOLIAGE 的 lambda 上 | 模组的补丁换成 mixin 后是否还经过这三个取色器 |
| 底色图 | `GrassColor.get(t, d)`、`FoliageColor.get(t, d)`（温度、湿度先夹到 0..1） | 色图资源路径、夹值方式 |
| 方块模型 | `BlockRenderDispatcher.getBlockModel`、`getQuads(state, side, rand, ModelData.EMPTY, renderType)`、`getRenderTypes` | NeoForge 的 `ModelData`、`ChunkRenderTypeSet` 包名 |
| 顶点格式 | `DefaultVertexFormat.BLOCK` 每顶点 8 个 int（xyz uv 色 光照 法线） | 格式变了要改 `quad()` 的步长和偏移 |
| uv 收缩 | `TextureAtlasSprite.uvShrinkRatio()` 收进 1/64 格 | 新版本有没有收缩、收多少，还原的判定要重核 |
| 变体、多部件 | 反射 `WeightedBakedModel`、`MultiPartBakedModel` 的私有字段（**按类型找，不按名字**：运行时是 SRG 名） | 字段类型变了就找不到，重核两个类的字段 |
| 取色器名 | 反射 `BlockColors` 的私有 Map | 同上，按类型找 |
| 流体 | `IClientFluidTypeExtensions.of(fluid).getStillTexture()`、`getTintColor` | NeoForge 同名在 `net.neoforged.neoforge.client.extensions.common` |
| 贴图像素 | `SpriteContents.getOriginalImage()`（取第一帧），拿不到再从资源管理器读 PNG | 动画帧的布局 |
| 模组、资源包清单 | `ModList`、`ForgeVersion`、`PackRepository.getSelectedIds()` | `FMLLoader`/NeoForge 版本类 |

## 已知不够的

- 机械动力的转动件、箱子、告示牌、旗帜、头颅等由方块实体渲染器画，方块模型里没有（`附加.不画` 或只出底座）；地形里要画它们得另做。
- `ModelData.EMPTY`：连接纹理（CTM 类模组）、机械动力的外壳连接取的是不连接的样子；要按位置取数据的模型（暮色的力场、巨型方块）一个面都不出，记进 `附加.不画`。
- 染色函数被别的模组包过一层的（夸克的「Greener Grass」把草、树叶的色乘一个矩阵，取材客户端开着），哨兵色认不出来，染色路记成 `动态:<方块>`；定值的树叶（白桦、云杉）记的是乘过的色。
- 随机变体只出第一个，随机旋转的方块（石头、草方块顶面）在导出表里是固定朝向，和手写表一样。
- 维度的天空、雾（暮色、下界）在维度特效里，不在群系表。
- 全量方块表的面组、贴图数会超过体素管线现在的上限（手写表的 16 位体素值、贴图图集按 4096 张以内设计），导出时超了会在 `提醒` 里报；新章节用前先按要用的方块 `--方块` 筛，或加大上限。

## 新章节怎么用导出表

1. `anim gamedata 导出` 出表，看 `核对.md` 里和手写表不同的地方是游戏对、还是手写规则对（各项差异的来历写进预览给用户）。
2. 定下用哪份后，按 `docs/决策/0002-资产标准.md` 登记新资产（例如 `数据/游戏导表/<游戏版本>/群系色`，来源写 `提取:` 或 `派生:`），`anim assets add` 入库。
3. 新段（或新的染色表模块）import 新资产；已有段继续用手写表，不过期。
