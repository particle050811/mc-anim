# 云和天（三渲二光影层的云组件、Photon 天）

代码在 `engine/light/云/`、`engine/light/天/Photon天.ts`，接在 `engine/三渲二/光影/光影渲染.tsx` 第 4 步。现在只有把回忆拼好给你在用，默认值在 `作品/把回忆拼好给你/默认.ts`。应力转动还用老的 `engine/light/大气.ts`、`大气/云.ts`，一行没改（用户 11-04 定，应力转动的指纹不能变）。

依据是 11-05 对各家光影和公开资料的调研，下面只记用到的结论。源码出处在第 5 节。

## 1. 算法（`配置.ts` 的 `云算法表`）

编号沿用调研时的 A～G。

| 编号 | 名 | 做法 | 出处 | 状态 |
|---|---|---|---|---|
| A | Photon积云 | 体积步进。2D 覆盖乘高度剖面，减去两张 3D Worley 做侵蚀；多次散射按八度近似；朝太阳和朝天各走几步算光学深度 | Photon `cumulus.glsl`；Schneider 2015（Horizon Zero Dawn）的覆盖 × 剖面 − 侵蚀；Wrenninge 2013（Oz）的八度多散射 | 有 |
| B | Photon高积云 | 同 A，层薄、步少，覆盖在积云和层云之间混 | Photon `altocumulus.glsl` | 有 |
| C | Photon卷云 | 球面上一张平面，卷曲噪声扭曲；朝太阳在平面上走几步 | Photon `cirrus.glsl` | 有 |
| C′ | 贴图层 | 平面：高积云的覆盖噪声贴在球面上取一次，自阴影取两点。比 B 便宜很多，用户 11-04 定远层用它（B5） | Agent 自己写 | 有 |
| D | 叠片 | N 片平面，每片阈值不同，叠出厚度 | BSL、Lux 的 6 片叠片（许可不让抄代码，要自己写） | 没做，配了报错 |
| E | 拉伸2D | 2D 贴图按高度阈值曲线挤出，可做圆角或方块感 | Complementary Reimagined（许可不让抄代码） | 没做 |
| F | 原版方块 | 原版 `clouds.png` 每个不透明像素拉成一格 12×12×4 的盒子，是场景网格，不在光影层画 | 原版 1.20.1 `LevelRenderer.buildClouds`；Distant Horizons 的盒子合并思路（LGPL，只参考） | 有（`原版方块.ts`、`原版方块云.tsx`） |
| G | 烘焙体素 | 把 A 的密度（可连同朝太阳的透射率）烘成 3D 贴图，按参数指纹缓存 | Nubis³（Guerrilla，SIGGRAPH 2023 讲稿）的体素化思路 | 没做 |

没有一家光影原生支持任意多层，都是每层一份写死的函数。我们按层数和算法生成 GLSL，一层一套函数、名字带层号，不在运行时用 `for` 套 `switch`。

## 2. 层的字段（`配置.ts` 的 `云层`）

字段名照各家通行的叫法，单位一律用世界格，组件内部乘 `云空间倍`（3）换成云空间米。

| 字段 | 通行叫法 | 参考默认 |
|---|---|---|
| 底高 | UE `Layer Bottom Altitude`、Photon `ALTITUDE`、Bliss `height` | 积云 300、高积云 1067、卷云 2000（离海平面，格） |
| 厚度 | Photon `THICKNESS`。不学 UE 把层顶叫 Height | 积云 400、高积云 160、卷云 500、贴图层 60 |
| 覆盖 [少, 多] | Photon、Bliss `coverage`。Photon 是一个区间，大尺度噪声在区间里插值 | 不给就按天气算 |
| 密度 | Photon `DENSITY`、Bliss `density`，乘在消光上 | 1 |
| 尺寸 | Photon `SIZE`、Complementary `SIZE_MULT` | 1 |
| 细节 | Photon `DETAIL_STRENGTH` | 1 |
| 形态 | Photon `cumulus_stratus_blend`（0 积云，1 层云） | 按天气 |
| 风、偏移 | Photon `WIND_SPEED/ANGLE`。位移只按段内秒数算，逐帧确定 | 不动 |
| 主步数、光步数 | Photon `PRIMARY_STEPS_H/Z`、`LIGHTING_STEPS` | 按质量档 |
| 透射率阈值 | UE `Stop Tracing Transmittance Threshold` | 0.075（Photon） |

调研里还有这些字段，现在没做：反照率、剖面、边缘锐化、卷曲、相函数、多散射参数、powder、视距、投影、每层单独的分辨率。

## 3. 质量档的各项依据（`配置.ts` 的 `云质量`）

各家体积云都靠降分辨率加时域累积来压噪点：Photon 是 1/4 分辨率累积约 20 帧，Bliss 1/2，Horizon Zero Dawn 每帧只更新 1/16 的像素。我们每帧独立渲染、乱序出帧结果也一样，不能用时域累积，所以只取不靠跨帧的手段：

- **半分辨率 + 按深度加权放大**（`分辨率`）。即联合双边上采样：帐篷权乘深度权，地形边缘不漏云。
- **蓝噪声抖动**（`抖动: '蓝噪声'`）。64×64 阈值表，照 Ulichney 1993 的 void-and-cluster 自己写（`蓝噪声.ts`）。只按像素坐标取，不按帧变。**试过，`快` 不开**：半分辨率放大用 4×4 帐篷权，正好把 Bayer 4×4 的 16 档平均成平的；蓝噪声 64×64 平均不掉，2-收集快乐 第 100 帧地平线那团背光的云起颗粒。
- **远处放大步长**（`远步增`）。每一步比上一步长几倍，近处细、远处粗；远处本来就被空气透视压淡。思路同 Photon `blocky_clouds.glsl` 的 `step_growth`，UE 也按距离调样本数。**试过，`快` 不开**：1.02 时远处的云同样起颗粒（地平线的云离镜头最远，步最长）。
- **主步数**（`步数倍`）。精确是 4 倍；`快` 取 3，2 倍时背光的云有轻微颗粒。
- **能量守恒积分**。每一步的散射按 `(1 − 透过率) / 消光` 解析积分（Hillaire 2016，Frostbite 天和云课程讲义），步长拉长也不漏光。Photon 原样就是这个式子，移植时已核对过，不用另做。
- **复用上一帧**（`复用`）。输入完全相同（所有 uniform、天色图、尺寸），这个像素的深度也和上一帧一样，就留着上一帧的结果。逐字节不变；乱序出帧时就现算。
- **天色图挪到 GPU**（`光影选项.天算法: 'GPU'`）。float32 片元着色器展开 2048×1024 天色图，和 CPU 精确版只在半精度的末位上有差。

还没试的（估的收益见优化总地图「云和天」页）：
- 朝太阳透射率预烘成 3D 体：段内云不动、太阳不动时才有收益。
- 空间跳跃：预计算覆盖图（Photon `CLOUDS_CUMULUS_PRECOMPUTE_LOCAL_COVERAGE`），空区大步走、进云退一步（Schneider 2015）。
- 两遍：低分辨率先求每块进云、出云的区间。
- 远景云预烘全景：只适合机位基本不动的段。

## 4. 天

Photon 天用预积分散射表（Bruneton 2017 的参数化，随包发 `scattering.dat`），展开成等距柱状天色图。`精确` 在 CPU 上算，和 `大气.ts` 的 `buildSky` 逐位相同；`GPU` 见上一节。没做的有 Hillaire 2020 的 192×108 天空视图 LUT，每帧现算、太阳可以每帧动。
