# 调度：看见、决定、留下原因

程序只守底线，主 Agent 决定怎么派活。不是自动派发服务，也不会按“实验只能一路”或短作业优先替人做决定。资源闸不改变画面、标签页并发、编码参数和段顺序。

## 主 Agent 什么时候看

派重活前、任务完成时、收到看守通知时、给用户汇报时看一次 `anim 调度`。默认折叠队列，只显示前三张；完整信息用 `--json`。`--一行` 适合贴在工作记录里。调度走独立快路径，不加载 Remotion；不写运行记录和耗时表，查看本身在调度日志记一条 `汇报`。

机器行包含负载/核、闸口径内存%、压力、free、压缩、swap、累计换出、GPU、热和可用盘。平台读不到显示 `?`，不当成零。持锁信息来自信息文件，不翻渲染日志。持锁和排队行紧跟 pid 标 `死`（一行状态写 `持锁#N死`、`死票n`）：进程没了或早于这次开机的锁和票，等下一个等待者回收，不算占用，不算预计等待，也不按排队告警；别的机器上的持有者查不了 pid，不标死。旧持锁者显示“旧闸，无信息”，不能假装知道它的帧数或预计。准备打包和 CPU 后处理也登记在跑。

`anim 调度 预计 <选择器>` 给出队列等待下界和各段 render/still 的纯跑估计。still 优先取明细首帧和后续帧，缺明细取阶段表出帧；绝不把含排队的 `anim still` 总耗时当纯跑。没有样本显示 null，无预计的前方任务按 23 秒下界，不是交付承诺。

## 手段

所有改调度命令的 `--为什么` 必填。票可写完整票名或加引号的 `'#pid'`（shell 的 `#` 是注释）。目标不唯一必须用完整票名。指令通常一个 1 秒轮询内生效；不会中断当前段来插入另一段。

| 看到 | 可用手段 |
|---|---|
| 小任务被长任务挡住 | `anim 调度 先 <票> --为什么 …`，或让正在跑的多段任务让路 |
| 实验挡产出 | `后 <票> [--分钟 30] --为什么 …`；到期回队尾 |
| 暂缓不再必要 | `恢复 <票> [--原序] --为什么 …`；只有明确 `--原序` 才恢复原位 |
| 内存低于 30%，但确认这一票峰值小 | `放行 <票> --为什么 …`，只越过这一张票的内存判断和队序 |
| 压力 4 严重 | 默认仍挡；确认风险才 `放行 <票> --强 --为什么 …` |
| 多段 render 或正规批需要让出 | `让路 <票> [--分钟 30] --为什么 …`；当前段不动，下一张票暂缓领 |
| 单项、旧式整批 | 不能让路，只能等或取消；命令会直说 |
| 决定不再继续 | `取消 <票> [--杀持锁] [--强] --为什么 …`；持锁者必须额外确认（写全名取消它的残留票也算），强才 SIGKILL |
| 孤儿 Remotion Chrome | `清孤儿 --为什么 …`；只清 ppid=1、Remotion 下载目录的 headless shell |
| 合批、错开派活等外部决定 | `记 --看到 … --决定 … --为什么 …` |

放行不是全局改下限，也不继承给下一段。30% 保持不变。授权跟任务 id 走，放行后再改序不失效；默认 30 分钟到期（锁可能被长渲染占着，到轮到时当初看的读数已经过时），到期作废，写 `放行过期` 事件、在票主人的 stderr 说明、叫醒 `盯`，这张票回到正常判断，还要放行就重发。暂缓和让路默认 30 分钟，避免指令被忘记后永久占着队列。`让路` 不是释放全部浏览器内存；多段 render 保留原会话，常规内存闸继续保护下一项。长时间让路需要回收这一路内存时，由主 Agent 决定取消，不暗改同页路径。

取消发信号前先核对目标还是原来的进程：票和锁判死的（pid 没了、早于这次开机）不发信号，留给下一个等待者回收，退出 0；pid 还在但进程启动得比拿锁或领票还晚，说明 pid 被复用了，同样不发信号，退出 1，这个进程退出前票或锁不会被回收。读不到启动时刻（没有 ps）时只凭 pid 和开机时间，stderr 警告一行。信号时目标刚退出按没发算；别的信号错误报错退出 1。决定事件的 `结果` 记真实发生的事（`已发 SIGTERM`、`未发信号：…`、`信号失败：…`），`取消` 事件只在信号真发出去时写。其余改调度命令对死目标直接报错。

取消会在目标 stderr 写“被调度取消：原因，不要原样重发”。子代理收到退出 143 或 75 不应盲目重跑；先看决定/路令。旧进程不认识取消原因，只能在新日志中归因。Node 无法知道普通 `kill` 的发起者，只有经调度命令发出的取消才有明确“谁决定的”。子会话标记只记环境事实并警告，不冒充权限验证；主子 Agent 可能共用 session id，必须命名路。

## 盯与等

主 Agent 用自己的后台工具挂 `anim 调度 盯 --最长 1740`，处理通知后再挂。它每 5 秒检查，遇到新告警、崩溃、回收死锁、同会话路完/路败或指定任务结束，输出一行后退出，每件带 UTC 时间；无事件零输出。父进程退出也退出。到点退出码 **124**，不是业务失败。

游标按会话一份，记月份和字节偏移，没挂时写入的、跨月的都会补报；同会话两只 `盯` 共用游标，一件事只醒一只。一次最多报 3 件，多的说「另 N 件未报（最重 X）」，重挂接着报。新会话第一次挂只补报 30 分钟内的，更早的用 `anim 调度 日志 --事 告警` 查。

`--任务` 接受 `#pid`、任务 id、这个任务用过的任意票名（改过序的、早先段的都行），解析成任务 id 后等它的任务止或崩溃；已经结束的立刻报；日志里找不到就报用法错误，退出 2。旧闸的任务不写日志，用 `等 --pid`。

没挂看守也不是无声：任务起检查同会话活看守，10 分钟内只提醒一次 `盯未挂`。等待者每 3 秒、持锁者每 30 秒也记告警；这些记录不等于已有人处理，主 Agent 仍要挂 `盯`。

初始告警阈值：
- 等内存 3 分钟；预计不超过 60 秒的票、预计缺失的 still 等 5 分钟。
- 任意票等 `max(10 分钟, 3×预计)`；重放行任务等 10 分钟。
- 队深至少 4 且创新高；持锁超 `max(3×预计, 预计+10 分钟)`，无预计按 30 分钟。
- 声明总帧且仍未完成、有心跳却 5 分钟没有新帧；持锁者死亡立即报。
- 负载大于核×2 持续 3 分钟；3 分钟 swap 增长至少 1 GiB；压力至少 2。
- 孤儿 Chrome 连续两轮；连贯批持锁 30 分钟且有人等 5 分钟。
- 同类同对象首次、×2、×4，最多三次。条件持续消失 5 分钟（或这么久没人采样）事件结束，再成立是新事件；队深按高水位，队列清空后复位。
- 排队票的对象是任务 id，改序不换；暂缓的票不告警、不算队深，恢复后等待重新起算。持锁类的对象是任务 id 加段，没声明段的加票。持锁者死了只报死，不再报超时和无帧。
- 负载和孤儿超过 90 秒没采样就重新算持续。读不到的负载、swap、孤儿显示 `?`，不入历史，既不算过载也不算恢复。

等内存只在轮到这张票且锁空时计时；锁在活进程手里时，等待原因就是锁在谁手里。死锁不看内存和队位，每个等待者每轮先回收并清孤儿。心跳、监测、信息文件、告警这些记录写失败只在 stderr 提示，不影响排队和渲染。

`anim 调度 等 --pid n | --文件 p | --闸空 | --内存 n [--最长 秒]` 给子代理分段前台等。默认最长 540 秒，到点 124；闸空必须队列和锁连续 30 秒都空，不能把段间交接当全部结束；死锁、死票不算占用（只读判断，回收仍归下一个等待者），到点在 stderr 说卡在谁。这是观察条件，不是拿到锁，重活开跑仍必须过闸。不要另写 until/sleep 盯锁脚本，不要给真渲染排队设短超时。

`ANIM_TIME_LIMIT` 是**每票从拿锁时算**的可选执行限时（秒），不包括排队；到点记限时杀，收尾后退出 124。多段每段重算。Node 的 SIGHUP 处理不依赖 nohup；要抗终端断开，用执行工具的后台任务或适用平台的会话分离机制。

## 路、令和批

```sh
anim 调度 路 开 纹理核对 --说明 '改好后跑三张静帧'
ANIM_ROUTE=纹理核对 ANIM_PURPOSE=核对 anim still 6-规矩风矢 0 --到预览 工作-调度核对
anim 调度 令 纹理核对 '让路，先交产出，不要原样重发'
anim 调度 路 完 纹理核对 --结果 '证据目录与提交号'
anim 调度 路 看
```

路只写日志、从日志回放，不维护任务板，不解析会话 journal，不改用户钩子。路令保存在 `run/调度/令/`；让路令在排队循环生效，专用退出码 **75**（不是失败），默认 30 分钟失效。路名不能代替会话/工作区；发起者同时记录这些信息。

`anim 批 <任务文件> <输出目录> [--保留浏览器] [--连贯 <为什么>]` 复用已准备的包。ASCII 环境变量 `PKGS` 是包键到本地包目录的 JSON，如 `{"基":"/绝对路径/包"}`。任务每行 `<包键> <段键> <帧串> <输出名> [留=全|帧,帧]`，空行和 `#` 注释忽略；帧串可 `0-29` 或 `0,10,20`。默认每项新浏览器，保持旧实验的加载历史；显式选项才保留浏览器。输出名不能包含路径分隔符。

`开闸批(声明, 环境?)` 返回 `一项(声明, fn)`、`结束()`，必须 finally 结束。累计持锁至少 120 秒且有人等，或收到让路指令，才在项间放锁、下项领新票；不是每个短项都交接。连贯批必须有原因，仍响应明确让路。旧脚本整批包一次 `过渲染闸` 自动记日志，但不能中途交接。

## 协议与复盘

- 日志：`run/logs/调度/YYYY-MM.jsonl`（UTC 月），每行一次 O_APPEND write，小于 4 KiB。白名单取发起环境，命令截取前 200 字并遮敏，不 dump env。
- 锁：`run/locks/渲染.lock` 和 `放行.lock` 内容仍是纯 pid；信息放 `.信息.json`。票名仍是 15 位序号、主机、pid，内容 JSON；新代码兼容纯 pid 旧票。拒绝改名旧票，旧轮询不会找新名。
- `上次放行` 仍写纯秒数，pid/任务写 `上次放行.信息.json`。只在上次进程仍活着时保留 60 秒间隔；没有匹配旁文件的旧格式保守等间隔。等待资源时不持放行锁，提示列明间隔、负载、内存。
- verify accept 只在需要解码时懒过放行闸；extract 的检查/列出/只打印和空任务不进闸。真正解码和预读仍走重闸，不降成“小任务”。
- game start 先排渲染队，再判断负载和内存，启动就绪后返回；build 走放行闸。两个 MC 客户端互斥保持不变。film、预览 mp4 只登记 CPU 活，不增加等待，原 nice 不改。
- SIGINT/SIGTERM/SIGHUP 退出码 130/143/129，写被杀和任务止、放锁删票、清本次临时文件和叶子进程。SIGKILL 由后续读者从 `在跑/` 认领一条崩溃记录；没有后续读者时不会凭空有日志。

`anim 调度 日志 --从 <ISO> --到 <ISO> --事 <事> --票 <票> --段 <段> --路 <路>` 过滤事件。`anim 调度 复盘 --日 11-01` 汇总持锁、谁等谁、内存等待、占锁用途比例、被杀/取消、决定、死票和告警到决定延迟。旧历史缺字段不能从日志补造；缺发起/用途的单列“未声明”。完整票改序前后由同一任务关联。

回测脚本和实测证据随实现交付，不把一次测量变成永久资源规矩。原阶段表缺被杀、压力、CPU、swap、逐帧心跳和孤儿轨迹，所以只能给可观测项的叫醒次数下界，不宣称精确恢复整晚。
