# 调度：看见、决定、留下原因

程序只守底线，主 Agent 决定怎么派活。不是自动派发服务，也不会按“实验只能一路”或短作业优先替人做决定。资源闸不改变画面、标签页并发、编码参数和段顺序。

## 主 Agent 什么时候看

派重活前、任务完成时、收到看守通知时、给用户汇报时看一次 `anim 调度`。默认折叠队列，只显示前三张；完整信息用 `--json`。`--一行` 适合贴在工作记录里。调度走独立快路径，不加载 Remotion；带 `--作品`、`--调试`、`-h`/`--help` 或 `ANIM_DEBUG=1` 时走完整路由（慢一点），行为和别的命令一样。不写运行记录和耗时表，查看本身在调度日志记一条 `汇报`。

机器行包含负载/核、闸口径内存%、压力、free、压缩、swap、累计换出、GPU、热和可用盘。平台读不到显示 `?`，不当成零。持锁信息来自信息文件，不翻渲染日志。持锁和排队行紧跟 pid 标 `死`（一行状态写 `持锁#N死`、`死票n`）：进程没了、早于这次开机，或 pid 被别的进程复用了（现在这个进程比锁、票最后写入还晚 5 分钟以上才启动）的锁和票，等下一个等待者回收，不算占用，不算预计等待，也不按排队告警；别的机器上的持有者查不了 pid，不标死。旧持锁者显示“旧闸，无信息”，不能假装知道它的帧数或预计。排队行把 `死`、`重复#pid`、`等内存`、`暂缓` 放最前，超预算只截段和路名；重复按种、作品、段、级别、帧号、帧数都相同判，只提示不去重。准备打包和 CPU 后处理也登记在跑。`anim render` 放开闸后派生段签、转存还在后台子进程里跑（`决策/0008` 末节），CPU/准备 行列 `后台#pid 段 排n`；调度日志记 `后台排`、`后台起`、`后台等内存起`、`后台等内存止`、`后台止`、`后台满`、`后台等齐`，不算占锁也不算等闸，复盘单列 `后台`。

`anim 调度 预计 <选择器> [--级别 视频|预览]`（默认视频）给出队列等待下界和各段 render/still 的纯跑估计，只认同级样本。优先取明细首帧和后续帧，缺明细取阶段表出帧，render 再缺才回退耗时表；绝不把含排队的 `anim still` 总耗时当纯跑。没有样本显示 null，无预计的前方任务按 23 秒下界，不是交付承诺。领票时有人挡就在 stderr 打印「前面 N 张，约 X 分」（有无预计的标 `≥`），口径同上。这个数和队列行的「约几分后」只算这张票自己那把锁和同队前面的票，放行票不等渲染锁；放行票实际还要等间隔、负载、内存，这些不在数里。

## 手段

所有改调度命令的 `--为什么` 必填。票可写完整票名或加引号的 `'#pid'`（shell 的 `#` 是注释）。目标不唯一必须用完整票名。指令通常一个 1 秒轮询内生效；不会中断当前段来插入另一段。

| 看到 | 可用手段 |
|---|---|
| 小任务被长任务挡住 | `anim 调度 先 <票> --为什么 …`，或让正在跑的多段任务让路 |
| 实验挡产出 | `后 <票> [--分钟 30] --为什么 …`；到期回队尾 |
| 暂缓不再必要 | `恢复 <票> --为什么 …` 回队尾；票没在暂缓就报错 |
| 要回改序前的位置 | `恢复 <票> --原序 --为什么 …`；`先`、`后` 记过原序才行，没有就报错，不会悄悄去队尾 |
| 内存低于 30%，但确认这一票峰值小 | `放行 <票> [--分钟 30] --为什么 …`，只越过这一张票的内存判断和队序 |
| 压力 4 严重 | 默认仍挡；确认风险才 `放行 <票> --强 --为什么 …` |
| 多段 render 或正规批需要让出 | `让路 <票> [--分钟 30] --为什么 …`；当前段不动，下一张票暂缓领 |
| 单项、旧式整批 | 不能让路，只能等或取消；命令会直说 |
| 决定不再继续 | `取消 <票> [--杀持锁] [--强] --为什么 …`；持锁者必须额外确认（写全名取消它的残留票也算），强才 SIGKILL |
| 孤儿 Remotion Chrome | `清孤儿 --为什么 …`；只清 ppid=1、Remotion 下载目录的 headless shell |
| 合批、错开派活等外部决定 | `记 --看到 … --决定 … --为什么 …` |

放行不是全局改下限，也不继承给下一段：写完授权再核对票还在，票主人刚好拿锁走了就撤掉授权、报错（决定事件记 `未放行`）。30% 保持不变。授权跟任务 id 走，放行后再改序不失效；默认 30 分钟到期（锁可能被长渲染占着，到轮到时当初看的读数已经过时），到期作废，写 `放行过期` 事件、在票主人的 stderr 说明、叫醒 `盯`，这张票回到正常判断，还要放行就重发。暂缓和让路默认 30 分钟，避免指令被忘记后永久占着队列；原因写进票，票主人的等待提示会说。`让路` 不是释放全部浏览器内存；多段 render 保留原会话，常规内存闸继续保护下一项。长时间让路需要回收这一路内存时，由主 Agent 决定取消，不暗改同页路径。

`取消` 只认票和持锁者：`anim render` 已放闸、只剩等后台时对不上目标，要停就直接给 CPU/准备 行的 pid 发 SIGTERM（后台子进程跟着收尾）。取消发信号前先核对目标还是原来的进程：票和锁判死的不发信号，留给下一个等待者回收，退出 0；进程启动得比拿锁或领票还晚（这里不留余量，信号撤不回来），说明 pid 被复用了，同样不发信号、退出 0。复用它的进程不受影响，不用等它退出。没人排队时死锁留着，下一个来的回收。读不到启动时刻（没有 ps）时只凭 pid 和开机时间，也就认不出复用，stderr 警告一行。信号时目标刚退出按没发算；别的信号错误报错退出 1。决定事件的 `结果` 记真实发生的事（`已发 SIGTERM`、`未发信号：…`、`信号失败：…`），`取消` 事件只在信号真发出去时写。其余改调度命令对死目标直接报错。

取消会在目标 stderr 写“被调度取消：原因，不要原样重发”。Windows 上 `process.kill` 是无条件终止（读 Node 文档得出，未在 Windows 实测）：退出钩子不跑，没有这句话，不放锁、不删票、不写被杀，只有后来的崩溃，票和锁等下一个等待者回收；那里没有 ps，它留下的 Chrome 查不到，命令输出会直说。子代理收到退出 143 或 75 不应盲目重跑；先看决定/路令。旧进程不认识取消原因，只能在新日志中归因。Node 无法知道普通 `kill` 的发起者，只有经调度命令发出的取消才有明确“谁决定的”。子会话标记只记环境事实并警告，不冒充权限验证；主子 Agent 可能共用 session id，必须命名路。

## 盯与等

主 Agent 用自己的后台工具挂 `anim 调度 盯 --最长 1740`，处理通知后再挂。它每 5 秒检查，遇到新告警、崩溃、回收死锁、同会话路完/路败，输出一行后退出，每件带 UTC 时间；无事件零输出。父进程退出也退出。到点退出码 **124**，不是业务失败。

游标按会话一份，记月份和字节偏移，没挂时写入的、跨月的都会补报；同会话两只 `盯` 共用游标，一件事只醒一只。一次最多报 3 件，多的说「另 N 件未报（最重 X）」，重挂接着报。新会话第一次挂只补报 30 分钟内的，更早的用 `anim 调度 日志 --事 告警` 查。

`--任务` 接受 `#pid`、任务 id、这个任务用过的任意票名（改过序的、早先段的都行），解析成任务 id 后只等它的任务止或崩溃，所以 `盯 --任务 X && 下一步` 退 0 就是 X 结束了；已经结束的立刻报；日志里找不到就报用法错误，退出 2。它不报别的告警、不动共用游标，也不算挂了看守（任务起照样提醒 `盯未挂`）：主子 Agent 可能共用会话，子代理不能把主 Agent 的告警读走。旧闸的任务不写日志，用 `等 --pid`。

没挂看守也不是无声：任务起检查同会话活看守，10 分钟内只提醒一次 `盯未挂`。等待者每 3 秒、持锁者每 30 秒也记告警；这些记录不等于已有人处理，主 Agent 仍要挂 `盯`。

初始告警阈值：
- 等内存 3 分钟；预计不超过 60 秒的票、预计缺失的 still 等 5 分钟。
- 任意票等 `max(10 分钟, 3×预计)`；重放行任务等 10 分钟。
- 队深至少 4 且创新高；持锁超 `max(3×预计, 预计+10 分钟)`，无预计按 30 分钟。
- 声明总帧且仍未完成、有心跳却 5 分钟没有新帧；持锁者死亡立即报。
- 负载大于核×2 持续 3 分钟；3 分钟 swap 增长至少 1 GiB；压力至少 2。
- 孤儿 Chrome 连续两轮；连贯批持锁 30 分钟且有人等 5 分钟。
- 同类同对象首次、×2、×4，最多三次。条件持续消失 5 分钟（或这么久没人采样）事件结束，再成立是新事件；队深按高水位，队列清空后复位。
- 排队票的对象是任务 id，改序不换；暂缓的票不告警、不算队深，恢复后等待重新起算。持锁类的对象是任务 id 加段，没声明段的加票。持锁者死了只报死，不再报超时和无帧。
- 负载和孤儿超过 90 秒没采样就重新算持续。读不到的负载、swap、孤儿显示 `?`，不入历史，既不算过载也不算恢复。

等内存只在轮到这张票且锁空时计时；锁在活进程手里时，等待原因就是锁在谁手里。票上的 `等内存起`、`卡在` 票主人每轮对一次，被别人用旧内容盖掉（改调度和票主人写票撞上）下一轮补回。死锁不看内存和队位，每个等待者每轮先回收并清孤儿。心跳、监测、信息文件、告警这些记录写失败只在 stderr 提示，不影响排队和渲染。

`anim 调度 等 --pid n | --文件 p | --闸空 | --内存 n [--最长 秒]` 给子代理分段前台等。默认最长 540 秒，到点 124；闸空必须队列和锁连续 30 秒都空，不能把段间交接当全部结束；后台转存不占闸，闸空时它可能还在占 CPU，要计时先看 CPU/准备 行；死锁、死票不算占用（只读判断，回收仍归下一个等待者），到点在 stderr 说卡在谁。这是观察条件，不是拿到锁，重活开跑仍必须过闸。不要另写 until/sleep 盯锁脚本，不要给真渲染排队设短超时。

`ANIM_TIME_LIMIT` 是**每票从拿锁时算**的可选执行限时（秒），不包括排队；到点记限时杀，收尾后退出 124。多段每段重算。Node 的 SIGHUP 处理不依赖 nohup；要抗终端断开，用执行工具的后台任务或适用平台的会话分离机制。

## 路、令和批

```sh
anim 调度 路 开 纹理核对 --说明 '改好后跑三张静帧'
ANIM_ROUTE=纹理核对 ANIM_PURPOSE=核对 anim still 6-规矩风矢 0 --到预览 工作-调度核对
anim 调度 令 纹理核对 --让路 '先交产出，不要原样重发'
anim 调度 令 纹理核对 --撤
anim 调度 路 完 纹理核对 --结果 '证据目录与提交号'
anim 调度 路 看
```

路只写日志、从日志回放，不维护任务板，不解析会话 journal，不改用户钩子。路令保存在 `run/调度/令/`，动作是明确字段，不看文字内容；让路令在排队循环生效，专用退出码 **75**（不是失败），30 分钟失效，`--撤` 提前撤。走路由的命令和直接 import 闸、没接异常的脚本都退 75（film 派生段签、cache 转存、voice gen 的复核把过闸包在 try 里，也透传）；脚本自己 `catch` 了 `调度让路` 的，退出码由它自己定（异常带 `退出码` 字段）。路名不能代替会话/工作区；发起者同时记录这些信息。

`anim 批 <任务文件> <输出目录> [--保留浏览器] [--连贯 <为什么>]` 复用已准备的包。ASCII 环境变量 `PKGS` 是包键到本地包目录的 JSON，如 `{"基":"/绝对路径/包"}`。任务每行 `<包键> <段键> <帧串> <输出名> [留=全|帧,帧]`，空行和 `#` 注释忽略；帧串可 `0-29` 或 `0,10,20`。默认每项新浏览器，保持旧实验的加载历史；显式选项才保留浏览器。输出名不能包含路径分隔符。

`开闸批(声明, 环境?)` 返回 `一项(声明, fn)`、`结束()`，必须 finally 结束。累计持锁至少 120 秒且有人等，或收到让路指令，才在项间放锁、下项领新票；不是每个短项都交接。声明 `项数: 1` 的批没有让路点，`让路` 直说不能让路；没声明项数的按多项算。连贯批必须有原因，仍响应明确让路。旧脚本整批包一次 `过渲染闸` 自动记日志，但不能中途交接。

## 协议与复盘

- 日志：`run/logs/调度/YYYY-MM.jsonl`（UTC 月），每行一次 O_APPEND write，小于 4 KiB；超长先丢 队、机、快照，再收缩发起者和长文字，决定、为什么、谁 不丢，stderr 提示一行。白名单取发起环境，不 dump env。命令逐项遮再截前 200 字：Authorization、Cookie 整段，URL 内嵌凭据，名字带 token、secret、password、passwd、pass、pwd、auth、cookie、credential、key 的值，长得像 `sk-`、`ghp_` 的值。运行记录和耗时表的命令行用同一函数。
- 字段：领票、拿锁、放锁带 队（深度、前面、持锁）和 机（闸的读数，没有 level、显存）；拿锁带 等锁秒、等内存秒、被越次数（先、恢复 --原序、放行越队时给被越过的票加一）；被杀带 当时（持锁、排队、其他）、已跑秒、取消后秒、负载；限时杀带 已跑秒；崩溃带 当时 和最后 心跳；任务止带 错误（走路由的命令）；决定带解析后的 任务、票 和原样的 目标。
- 锁：`run/locks/渲染.lock` 和 `放行.lock` 内容仍是纯 pid；信息放 `.信息.json`。回收者过 `<名>.lock.回收` 这道门（O_EXCL，一次一个，门里重读判死再改名）；门留下了 10 秒作废，这种情况下回收晚 10 秒。旧项目的工具不认门，靠改走后核对、改回兜着。票名仍是 15 位序号、主机、pid，内容 JSON；新代码兼容纯 pid 旧票。拒绝改名旧票，旧轮询不会找新名。读路径（看、盯、排队监测）见到活的旧票、占够 10 秒的活旧锁写 `见到旧协议`，一小时最多一条。
- `上次放行` 仍写纯秒数，pid/任务写 `上次放行.信息.json`。只在上次进程仍活着时保留 60 秒间隔；没有匹配旁文件的旧格式保守等间隔。等待资源时不持放行锁，提示列明间隔、负载、内存。
- verify accept 只在需要解码时懒过放行闸；extract 的检查/列出/只打印和空任务不进闸。真正解码和预读仍走重闸，不降成“小任务”。
- game start 先排渲染队，再判断负载和内存，启动就绪后返回；build 走放行闸。两个 MC 客户端互斥保持不变。film、预览 mp4 只登记 CPU 活，不增加等待，原 nice 不改。
- SIGINT/SIGTERM/SIGHUP 退出码 130/143/129，写被杀和任务止、放锁删票、清本次临时文件和叶子进程。SIGKILL 由后续读者从 `在跑/` 认领一条崩溃记录；没有后续读者时不会凭空有日志。

`anim 调度 日志 [--从 --到 --日 --事 --票 --段 --路]` 过滤事件。时间都是 UTC，写 `2026-11-01`、`11-01` 或 `2026-11-01T08:00:00Z`（也认 `+08:00`），只给日期的 `--到` 算到当天结束，写错报用法错误。`--路` 同时查事件自己的路名和发起者的 `ANIM_ROUTE`。

`anim 调度 复盘 --日 11-01` 过滤条件同上，只定汇报哪些，配对总用全部日志：领票在窗口外、挡路者不满足过滤也归得上。等待算在拿锁那一刻，占锁算在放锁那一刻。

- `等闸`：总秒 = 持锁者秒 + 内存秒 + 未归因秒；`其中已崩溃者秒` 是等一个已经死了的持锁者。
- `等谁`、`发起等秒`：只和同一把锁的持锁段求交；领票和拿锁按任务 id 关联，改序不丢。持锁者崩溃时，它的区间关到崩溃或回收死锁被发现为止，所以等它的时间归它。
- `未归因`：`分解` 按原因（`旧闸 #pid`、`放行卡在…`、`锁空或无持锁记录`），`无等待数据次` 是拿锁既没等锁秒也没领票，`明细` 列到任务。缺数据只进这里，不静默丢。
- `没等到`：领了票没拿到锁就结束（被杀、崩溃、任务止）或还在等（未结束）。`等内存未结束` 同理，秒数也计入 `等内存`。
- `占锁秒`：崩溃者算到最后心跳，否则隔几小时才被发现会虚增。
- `告警到决定秒`：决定落库时记解析后的任务和票，按任务 id 或告警对象配对；升级连发时从最早一条算，配过的不再配，没指向谁的决定（`记` 不带目标、`清孤儿`）不进统计。`记 机器 …` 可以指向机器级告警。
- `当前持锁`：读现状，不靠回放，旧闸持锁者也看得到；窗口不含此刻时为空，已死的不算。

旧历史缺字段不能从日志补造；缺发起或用途的单列「未声明」。
