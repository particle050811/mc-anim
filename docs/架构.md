# 架构

摘自新项目方案（旧项目 `预览/1021-0925-新项目方案/方案.md` 第二、三节），用户 10-21 拍板「按推荐来」。为什么另起新项目见 `决策/0001-另起新项目.md`，资产怎么登记见 `决策/0002-资产标准.md`。

## 分层

```
engine ← world ← content/场 ← content/段 ← content/注册.tsx
```

| 层 | 放什么 | 不放什么 |
|---|---|---|
| `engine/` | 怎么画、怎么动、怎么出声：core（时钟、数学、镜头，`Cam`、`toThree` 各只有一份）、voxel、model、light、post、anim、flight、audio、ui | 剧情、具体角色 |
| `world/` | 片里的东西长什么样、默认怎么动，跨场共用：角色/、生物/、物品/、地点/、界面/、特效/；全片默认值集中在 `world/默认.ts` | 只属于某一场的编排 |
| `content/场/<场键>/` | 一条场时间线（`时间线.ts`）、本场共用的布局和编排、`末态.ts`（下一场接世界状态用） | 别的场的东西 |
| `content/段/<段键>/` | `段.ts`（纯数据）、`画面.tsx`、本段专用的编排 | 两段都要用的东西 |
| `content/核对/` | 预览、对照、核对用的 Composition | 正式段会用到的东西 |
| `pipeline/` | Node 管线：cli、环境、闸、指纹、渲、合成、剪辑包、适配器/{剪映,远端,旧项目}、检查、运行记录 | 画面代码 |
| `py/sr_py/` | 配音、ASR、对齐、口型、配乐分析、jar 提取、图集配方。JSON 进，文件和 JSON 出；不自己推算路径，路径由 `sr` 传进来 | |
| `sourcing/` | 取材 mod（Forge 1.20.1）、`mcai/mcai.py`、数据包（`datapacks/`）、`extract/` 取材脚本、`worlds/<世界>.toml`、`jars.toml`、`extract.toml`、`captures.toml` | |

**依赖规则**（`sr check` 用 esbuild metafile 拿真实依赖图来查，不用文本 grep，**没有白名单**）：
- 只能往左边 import；段不许引用别的段；场只许引用上一场的 `末态.ts`。
- 两段要共用的东西，往下放到场或 `world/` 里。
- `content/核对/` 可以 import 任何东西，任何东西都不许 import 它。
- pipeline 只 import 纯模块：`清单.ts`、`段/*/段.ts`、`场/*/时间线.ts`、`末态.ts`。它们的闭包里不许有 react、three、remotion。
- 只有 `content/设置.ts` 读 `getInputProps`，转成 React context 往下传；整份渲染设置进指纹。
- 渲染代码里不许出现 `Math.random`、`Date.now`、相对路径 import 的资产、写死的路径或主机名。
- 一个 npm 包，不拆 workspace（拆了会给 Remotion 打包添麻烦）。

## 段的形状

- `段.ts` 是纯数据：所属场、时钟、机位、声音 cue 表（台词、音效、配乐挂点）、叠层（伤害数字、称号、字幕）、用到的地形包。
- `画面.tsx` 负责画，`<声音轨 cues>` 照 cue 表播放。播放和混音规则照搬旧的 `游戏音效.tsx`、`混音.ts`，母版里的声音仍由 Remotion 混出。
- 时钟有两种：
  - `场窗口`：段 = 场时间线上 [起事件, 止事件] 这一截，照第 7 章 `7-1/时间线.ts` 的写法。**新章节一律用它。**
  - `自带`：迁移时照搬第 6 章原来的段界写法，不为了套新模式改画面。要不要改成场窗口，由用户逐段决定。
- 同一场里标了「连续」的相邻段，首尾正好差 1 帧。其余段之间硬切，只要求世界状态（位置、朝向、道具）连续。
- 剪辑包、字幕、同步表、清单都直接读 cue 表，不渲第 0 帧收日志。
- 叠层迁移期间仍单独渲成透明层、合成时叠上，保证像素和旧版一致。改成直接画进段算画面改动，等用户点名。

## 规矩

- 全片默认值写在 `world/默认.ts` 或对应的共用模块，登记在 `rules/规矩.toml`（默认值、级别、原话、针对、出处、落点、例外）。
- 级别：带用户原话、并且原话说的就是这一类情况的，才是「原话」级，算硬约束；其余是「参考」级。
- 段里要例外，写 `例外('规矩id', 值, {段, 原因})`。`sr check` 双向核对：代码里的例外都在表里登记过，表里的例外代码里都找得到；默认值的落点符号必须存在。例外只写在 `content/段/<段键>/` 或 `content/场/<场键>/` 里；搬家暂放在 `world/地点/<地点>/<旧目录>/` 的剧情编排拆回之前也可以写在那里（`迁移.md` 差异表 R2）。
- 落点写成 `<路径> [符号、符号…]`，路径从顶层目录写起；还在旧项目里的写 `旧:` 或 `待迁移:` 开头，`sr check` 记作待迁移、不算违规，搬完改成新路径。
- Agent 不得把规矩推广到全片，只能在预览的 `00-说明.md` 里提议，用户点头后再登记。

## 指纹、过期和验收

- 每段的指纹由这些算出：`画面.tsx` 的 esbuild 依赖闭包源码、闭包里所有 `asset:` 的 sha、声明的地形包版本、渲染设置、lockfile 里 remotion 和 three 的版本、`remotion.config.ts`、执行平台。
- 改了共用代码，全片都会过期。`sr stale` 列出过期的段、哪项输入变了、预计耗时，什么时候重渲由用户定。`sr film` 默认拒绝用过期母版，加 `--允许过期` 才用，并逐段写进 manifest。
- 母版：整个工程只打包一次，逐段 `renderMedia`。格式是 CRF 1 + PCM 的 mkv，先写临时名再原子改名。渲染并发为 1。
- `sr verify`：指纹变了的段抽帧，和 `verify/accepted/<平台>/<段键>.toml` 记的那一版比；超过阈值就必须 `sr verify accept <段> --理由 …`，这一步会改 Git 里的文件。画面每一次变化都会出现在 diff 里，后面的提交把它悄悄改回去也会被拦住。
  - 认可记录存认可那版的指纹、理由、提交，和抽样帧（首帧、每 24 帧、末帧）的原始像素 sha256、16×9 块均值，以及音频 PCM 的 sha256、积分响度、起音落点。
  - 哈希不一样时，认可那版的母版还在缓存里就逐像素数「差 > 16/255 的像素占比」，不在就只比块均值；声音比响度和起音落点，不要求逐样本相同（用户 10-21：成片不要差太多就行）。超了出 旧|新|差 并排图给人看。阈值在 `verify/阈值.toml`。
  - 迁移期间 `sr verify --对基线` 直接和数据根 `基线/<旧段号>/` 的旧项目基线比。
- 单段门：帧数和清单一致；段音频减去按 cue 重混的结果，残差低于阈值；近白像素占比不超标。整片门：总帧数等于各段之和；接缝不悄悄丢帧；量响度和真峰值；抽帧拼总览放进预览。

## 数据和资产

- 资产只登记 id，字节放 Git 外的数据根：

```
stress-rotation-data/          环境变量 SR_DATA，各 worktree 共用
├─ store/<sha前2位>/<sha256>   内容寻址，只增不改：网格、碎块、配音原件和成品、截图、提取产物
├─ 私有/<sha前2位>/<sha256>    不公开的：用户录音、九胡配音和音色、配乐、取材账号皮肤、小说原文
├─ terrain/<包名>/<版本>/      区段包，版本目录只写不改
├─ cache/{母版,叠层,求解,对齐,画面截}/<键>/<指纹>.*
├─ 基线/<段键>/                迁移验收用的旧版基准帧和音频
├─ 交付/<UTC 月日-时分>-第6-7章/  成片、srt、拼接表、同步表、剪辑包、manifest.json
├─ archive/                    备选版本的对照 mp4
└─ run/{logs/耗时.tsv, 运行记录/, locks/, queue/}
```

- 资产表 `assets/registry/*.toml` 由人写，`assets/资产锁.json` 由工具生成。字段和可见性见 `决策/0002-资产标准.md`。
- 代码里写 `import x from 'asset:贴图/实体/九胡'`，解析插件按资产锁换成 `store/` 里的文件。打包规则和旧项目一样：png 内联、同步解码，ogg 解成 wav。资产锁里查不到的 id 打包直接失败，报错里写该跑哪条命令。
- 区段包、网格 .bin 在运行时用 `dataUrl(id)` 取。段要声明用到哪些地形包；渲染时请求了没声明的包就报错，保证指纹不漏依赖。
- 私有内容缺失时：配乐换成静音，并在运行记录里报出来；配音缺一句就直接失败，不静默替换。

## 环境和跨平台

- 环境模块只有一份，在 `pipeline/环境/`，用 TS 写。取值顺序：环境变量 > `sr.local.toml`（不进 Git）> 默认值。
- 不开 shell：npm scripts 只留 `"sr"` 一条，子进程一律用数组参数，Windows 的 `.cmd` 交给 cross-spawn。
- 锁：O_EXCL 建锁文件，内容写 pid 和主机名；持有者死了就回收；Windows 上删锁遇到 EPERM/EBUSY 退避重试；按票排队，不插队。协议和旧项目 `参考模型库/工具/公共/锁.py` 兼容，迁移期间 `SR_LOCK_DIR` 指向旧项目的 `.资源闸/`。
- 只在 Mac 上有的做成可选适配器：videotoolbox 编码、剪映读回解密、image-flow 录音。缺了只影响这一项。
- 统一 UTF-8；Git 设 `core.quotepath false`、`core.longpaths true`；时间一律 UTC。
- 工具链：Node 24、npm、TS strict、vitest；Python 3.11+、uv、pytest；Java 17、Gradle wrapper。Remotion 4.0.530、three 0.186.1、react 19.3.0、esbuild 0.28.1 锁死，旧项目退役前不升级。
