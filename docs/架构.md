# 架构

新项目方案用户 10-21 拍板「按推荐来」。为什么另起新项目、为什么叫 mc-anim、资产怎么登记见 `决策/0001`、`0003`、`0002`。

## 分层

```
engine ← 库 ← 作品公共 ← 场 ← 段 ← 作品/应力转动/注册.tsx
```

| 层 | 放什么 | 不放什么 |
|---|---|---|
| `engine/` | 怎么画、怎么动、怎么出声：core（时钟、数学、坐标、镜头）、voxel、model、light、post、anim、flight、audio、ui、三渲二（把回忆拼好给你的画风底座，用法见 `engine/三渲二/画布.tsx` 文件头） | 剧情、具体角色 |
| `库/` | 多部作品共用的东西长什么样、默认怎么动：角色/、生物/、物品/、界面/、特效/；本作品全片默认值在 `作品/应力转动/默认.ts` | 只属于某一场的编排 |
| `作品/应力转动/场/<场键>/` | 场时间线（`时间线.ts`）、本场共用的布局和编排、`末态.ts`（下一场接世界状态用） | 别的场的东西 |
| `作品/应力转动/段/<段键>/` | `段.ts`（纯数据）、`画面.tsx`、本段专用的编排 | 两段都要用的东西 |
| `作品/应力转动/核对/` | 预览、对照、核对用的 Composition | 正式段会用到的东西 |
| `pipeline/` | Node 管线：cli、环境、闸、指纹、渲、合成、配音、适配器、检查、运行记录、世界（`docs/世界.md`） | 画面代码 |
| `py/anim_py/` | 配音、ASR、对齐、口型、配乐分析、jar 提取、图集配方、字节码翻译动作（`决策/0007`）。JSON 进，文件和 JSON 出；路径由 `anim` 传进来，不自己推算 | |
| `sourcing/` | 取材 mod（Forge 1.20.1，导表部分见 `游戏导表.md`）、`mcai/mcai.py`、`datapacks/`、`extract/`、`worlds/<世界>.toml`、`jars.toml`（jar、官方映射、结构化许可）、`extract.toml`（取材配方，含场景网格的 mcai mesh 配方） | |

**依赖规则**（`anim check` 用 esbuild metafile 拿真实依赖图查，**没有白名单**）：
- 只能往左边 import；段不许引用别的段；场只许引用上一场的 `末态.ts`。两段共用的东西往下放到场或作品公共目录（多部作品用的放 `库/`）。
- 一部作品不许 import 别的作品（包括核对），共用的放 `库/` 或 `engine/`。
- `作品/应力转动/核对/` 可以 import 任何东西，任何东西都不许 import 它。
- pipeline 只 import 纯模块：`清单.ts`、`段/*/段.ts`、`场/*/时间线.ts`、`末态.ts`，和它们引的 `engine/段/` 框架（表在 `pipeline/检查/上下文.ts`），以及两端共用的字节格式 `engine/voxel/区段模型.ts`。闭包里不许有 react、three、remotion。例外：`pipeline/世界/体素库.ts` 按路径动态 import `engine/voxel/` 的格式、解码、合并规则、方块表（不在 metafile 图里，`pipeline/世界/存档.test.ts` 守纯度）。
- 只有 `engine/段/设置.ts` 读 `getInputProps`，转成 React context 往下传；整份渲染设置进指纹。
- 渲染代码里不许出现 `Math.random`、`Date.now`、相对路径 import 的资产、写死的路径或主机名。
- 一个包，不拆 workspace（拆了给 Remotion 打包添麻烦）。

## 共用函数的正本

- lerp、smoothstep、hermite、mulberry32 这类小函数，坐标换算和机位，各只有一份正本，新代码一律 import：
  - `engine/core/数学.ts`：插值、夹、smoothstep 一族、缓动、hermite、角度、取余、mulberry32 和随机工具
  - `engine/core/坐标.ts`：游戏、场景（Z 朝上）、three（Y 朝上）三套坐标互换、方块格、游戏朝向
  - `engine/core/机位.ts`：`Cam`（pos、tgt、lens、roll）、焦距和视角互换、`插机位`、`机位轨`
  - `engine/core/three换算.ts`：要 three 对象的部分：`场景到three`（旧名 `toThree`）、`摆相机`、`投到画面`
  - `库/角色/骨骼表.ts`（`插骨`、合并、叠加）、`库/角色/史蒂夫挥手.ts`、`库/原版物理.ts`（原版逐刻下落；生物和物品的重力顺序不同）
- 除 `three换算.ts` 外都是纯模块，`段.ts`、`时间线.ts`、`末态.ts` 也能用（`engine/core/正本纯.test.ts` 守）。
- 正本表在 `pipeline/检查/正本表.ts`（按名字、按探针求值、按记号认）。迁移来的旧副本原样不动（改了会让段过期），登记在 `docs/副本表.tsv`（正本 × 文件 × 处数）。
- `anim check` 的「副本」：某文件的副本比表里多就违规；表只许减少（和 main 的分叉点比）。重做哪一场时顺手换成正本、把表改小。
- 加正本：正本表加一项（配探针或记号），跑 `anim check 副本` 照报的数第一次登记；分叉点的正本表里没有的 id 才许从 0 加。各正本文件头写了旧副本差在哪，旁边 `.test.ts` 拿代表性副本对。

## 段的形状

- 新章节、新作品用段框架（写法见 `docs/新段.md`）：`段.ts` 写 `窗口段(场时间线, {…})`，`画面.tsx` 写 `定义画面(段, 声音地址, 组件)`，声音自动放。老段照旧写法，不迁。
- `段.ts` 是纯数据：所属场、段长（秒）、场窗口、声音 cue 表、叠层（伤害数字、称号、字幕）、用到的地形包。
- `画面.tsx` 负责画；`定义画面` 挂的 `<段声音>` 照 cue 表播放（`engine/段/放法.ts`，混音分档 `engine/audio/混音.ts`），和画面同一遍混出。
- 段界两种写法：
  - 有 `场窗口`：段 = 场时间线上 [起秒, 止秒) 这一截。新章节一律用场窗口（`窗口段` 就是这种）。
  - 只写段长：迁移时照搬第 6 章原来的段界；要不要改成场窗口由用户逐段定。
- 同一场里标了「连续」的相邻段，后一段的 `场窗口.起秒` 正好接前一段的 `止秒`；其余硬切，只要求世界状态（位置、朝向、道具）连续。
- 字幕、清单直接读 cue 表。
- cue 的形状（`engine/段/段定义.ts`）：
  - 台词 `{ 秒, 台词, 接上段?, 长秒? }`：秒是开口落在段内第几秒，文件头 = 秒 − 开口秒，开口秒和字幕位置写在 `台词.toml`。放到文件完多 1/24 秒（`台词尾余秒`）、段尾或同一句的下一截为止，`长秒` 只给例外（6-3-2 压路机）。
  - 一句跨段或断成两截，后半截写 `接上段: true`，秒是这一截起放的时刻；不算开口、不出字幕，`anim check` 要求前面真有开口。
  - 音效、配乐 `{ 秒, 资产, 名, 长秒, 档?, 入点秒?, 速率?, 循环?, 增益?, 淡出秒? }`：秒是起放时刻，入点秒是从文件第几秒放，`增益` 是常数或逐格增益 `{ 每秒, 值 }`（第 6、7 章每秒 24，格间线性插值），常数可带 `淡出秒`。资产 id 以 `配乐/` 开头的是配乐。
- 叠层、字幕画进段里（用户 11-05 定「母版 = 成片切片」）：切片就是成片的一截，成片只接不叠（`决策/0014`）。

## 时间：按秒写（用户 11-06 定原生 60 帧，`决策/0015-原生60帧.md`）

- 画面是时间的函数：取时间只用 `engine/段/时间.tsx` 的 `use当前秒()`、`<秒Sequence 起秒 长秒 剪秒>`、`use段().秒`；核对段一帧一个视图用 `use视图下标()`。不直接调 `useCurrentFrame()`，`anim check` 的「时间」规则拦着（零容忍，只有 `时间.tsx` 豁免）。
- 段长对齐到 1/60 秒（`段定义.ts` 的 `段格`，`段帧数(段, fps)` 换成输出帧），cue 不对齐。一格一个值的老数据按秒读：连续量用 `engine/段/按时取值.ts` 的 `插表`，硬切用 `取档`。
- Composition 按成片档 60 帧跑，第 0 帧就是段起点，段间没有零头（`出帧.ts` 的 `全片起帧表`）。声音由 `<段声音>` 放、和画面同一遍出（`渲段.ts` 用 `separateAudioTo` 写 wav）；`段画面.tsx` 把没入点、不循环的 cue 前移到前一个输出帧、用负的 `trimBefore` 补静音，起点按样本准。
- 字幕、台词落点按输出帧排（`pipeline/合成/段字幕.ts`、`台词落点.ts`）。

## 光照环境（新段用）

- 环境描述 `engine/light/环境.ts`（纯数据，`定义环境` 加载时就查）：
  - 维度：`engine/light/维度.ts` 有原版三个和暮色森林；别的模组维度写在 `库/维度/<模组>.ts`。
  - 时刻：游戏时间（0 日出、6000 正午，照 1.20.1 `DimensionType.timeOfDay`）算日月和天光，或写美术光向 `太阳`，二选一。时间固定的维度（暮色森林）只能写 `太阳`。
  - 天气：雨、雷 0～1，现在只调灯（直射 × (1 − 雨)，天光照 `getSkyDarken`）。
  - 灯光档位：`灯光档位.ts`（数照 `光照配比.ts`，现有 `暮色`、`主世界`）。表里没有的写 `灯光: { 配比: {…} }`，不往表里加档（会让用 `<环境>` 的段全部过期）。
  - 雾、高度雾、云（Photon、原版方块云）、主光投影。
- `<环境 描述 画法 镜头 离地? 穹顶中心? 帧?>`（`engine/light/环境组件.tsx`）直接放在 ThreeCanvas 下：
  - 画法按需引：一种一个模块 `engine/light/画法/<名>.tsx`（`export default 定义画法('<名>', 组件)`），段 import 后传给 `画法`，名字要和描述的一样；换画法就传数组。模组专有的放 `库/画法/<名>.tsx`。
  - 没有总表：加画法只加模块，已有段指纹不变。共用部件在 `环境部件.tsx`，改它会让所有用 `<环境>` 的段过期。
  - 主世界画法按时刻算太阳时画原版月亮和星星（`星月.tsx`，算法在纯模块 `天球.ts`，照 1.20.1 `LevelRenderer`）；写美术光向时不画。
- 预设：`暮色环境`（`engine/light/环境预设.ts`）= `TwilightLighting`；`主世界环境`（`作品/应力转动/地点/主世界环境.ts`）= `FlightSky` + `FlightFog`；都在 `核对-环境` 里和现有组件逐像素比过。
- 随帧变：`定义环境轨({ 基础, 关键帧: [{ 帧, 时刻?, 雨?, 雷?, 缓动? }] })`；延时摄影用 `按游戏流速` 算时刻。
- 段在 `段/<段键>/环境.ts`（几段共用写 `场/<场键>/环境.ts`）`export default` 描述或环境轨；场窗口段按场内帧取就传 `帧`。`anim check` 的「加载」把它们当纯模块执行再查（`pipeline/检查/环境声明.ts`）：重核描述、档位名、画法模块名、关键帧帧号（一秒 24 帧）在段长内。
- 已有段的 `TwilightLighting`、`FlightSky` 不换：画面一样也会让段过期，换不换由用户定。

## 配音（`anim voice`）

- 唯一人写的源是作品的 `台词.toml`：每句 id、角色、文本，可选 念（交给 TTS、对口型的字，和字幕不同时写）、语言、语气、`["台词"."合成"]`（后端、参考、种子、强度、参数等）、`["台词"."口型手修"]`（手标字的起止，绑成品 sha）；`["配音"]` 定默认后端、候选种子、成品响度（−18 LUFS、峰值 −1.5 dBFS）、新配音许可，`["音色"."<角色>"]` 定克隆参考和逐字稿。配音、开口、文本哈希、成品sha、口型由工具写回（只改那一行，认不出的写法报错不写）。
- 文本哈希是念的字的哈希：只改字幕时写 念 = 原来的字，配音不过期；念改了 `anim check` 报配音过期。
- 流程：`gen` 出候选到 `<数据根>/run/草稿/配音/<作品>/<id>/<后端>-种子<n>.wav`（旁边 `.json` 记参数）→ 自动复核 → 人试听挑 → `use` 定稿：裁静音（−45 dB，头留 0.03 秒、尾留 0.15 秒）、拉响度、48 kHz 单声道，原件 `配音/原件/<id>` 和成品 `配音/<id>` 登记，写回 `台词.toml`，出句模块。
- 句模块 `作品/<名>/台词/<id>.ts`：一句一个，工具生成、进 Git，别手改（`anim check` 认得出）。里面是念、开口、时长、字的起止、嘴型关键帧。新段 import 自己用的几句，用 `engine/audio/台词句轨.tsx` 放声音、`库/角色/句口型.ts` 取嘴和点头；改一句只让用到它的段过期。
- 第 6、7 章的旧段还用 `作品/应力转动/配音/台词轨.tsx`、`口型.ts`，读旧项目的两份整表（读法 `pipeline/配音/旧表.ts`）；改走句模块会改指纹，等用户定。这些句子 `use` 换成品要加 `--不管旧表`。
- 口型：字的起止取 口型手修 > 同版成品的现有句模块 > 对齐器（Qwen3-ForcedAligner，配置 `aligner`，过放行闸），再按 Rhubarb 规则由拼音拆音素出 A～F、X 嘴型（`py/anim_py/配音/口型.py`）。pypinyin 钉 0.55.0，换版本可能改嘴；`anim voice check` 按字重算嘴逐项比。
- 合成交给 image-flow（`决策/0009`，用户 10-31 定）：`py/anim_py/配音/后端/image_flow.py` 一个候选调一次 `imgflow speak`，默认 RunningHub 的 IndexTTS2（用户 10-31 定：统一用 IndexTTS2，本机模型占内存太多），按次收费要 `--允许付费`。后端可插拔（`anim voice backends`），要别的模型在 image-flow 配渠道、写 `[配音.后端参数.image-flow]` 的 `模型`。`--dry-run` 只打命令。
- 复核（`py/anim_py/配音/复核.py`，`gen` 后自动跑，`review` 单独重跑，`--不复核` 不跑）：本机免费的 `音色`（Resemblyzer 相似度）、`起伏`（基频跨度、响度跨度，棒读的跨度小）默认跑；付费的 `听写`、`语气` 只有接口和 `--dry-run`，启用要用户定。结果并进候选 `.json`，一句的候选连同现成品汇成 `<候选目录>/复核.md`。音色低于 0.85 只提示不挡（短句普遍偏低）。复核过放行闸。
- `sourcing/mcai/mcai.py` 只用标准库，连 127.0.0.1 一律直连，不管 `HTTP_PROXY`。
- 对齐器用自己的 venv，子进程调；`anim_py.配音` 跑在项目 venv（`uv run --frozen --project <代码根>`）；复核要 torch，在 `pyproject.toml` 的 `voice-review` 组，复核时才带 `--group voice-review`。

## 规矩

- 全片默认值写在 `作品/应力转动/默认.ts` 或对应的共用模块，登记在 `作品/应力转动/规矩.toml`（默认值、级别、原话、针对、出处、落点、例外）。
- 级别：带用户原话、并且原话说的就是这一类情况的，才是「原话」级，算硬约束；其余是「参考」级。
- 段里要例外，写 `例外('规矩id', 值, {段, 原因})`。`anim check` 双向核对：代码里的例外都登记过，表里的例外代码里都找得到；默认值的落点符号必须存在。例外只写在 `段/<段键>/` 或 `场/<场键>/` 里；搬家暂放在 `作品/应力转动/地点/<地点>/<旧目录>/` 的剧情编排拆回之前也可以（`迁移.md` 差异表 R2）。
- 落点写成 `<路径> [符号、符号…]`，路径从顶层目录写起；还在旧项目的写 `旧:` 或 `待迁移:` 开头，记作待迁移。
- 出处里的 `M/<名>.md` 指 agent-context 的记忆，根是配置 `记忆`（`ANIM_MEMORY`）。`anim check` 查文件在不在、`:行号` 有没有超出；记忆仓库不在本机就跳过。记忆删了、改名或合并了，出处跟着改。
- Agent 不得把规矩推广到全片，只能在预览的 `00-说明.md` 里提议，用户点头后再登记。

## 指纹、过期和验收

- 每段的指纹由这些算出：`画面.tsx`、`段.ts`、`设置.ts`、作品外壳的默克尔根（`pipeline/指纹/默克尔.ts`：模块去掉注释、类型、格式后，把 import 说明符换成目标的哈希再哈希；npm 包记 lockfile 版本，`asset:` 记 sha），`段.地形` 声明的地形包版本、渲染设置、remotion 和 three 等的版本、webpack 改写和 ogg 解码的规范化文本、影响输出的 tsconfig 选项、执行平台。文件路径不进指纹：只改注释、挪文件、换 import 写法不让段过期。
- 过期按段算：只有依赖闭包含改动文件的段过期。外壳和 `设置.ts` 的闭包（`作品/<名>/index.ts`、`注册.tsx`、`engine/段/注册工厂.tsx`、`设置.ts`、`设置值.ts`、`engine/core/渲染设置.ts`）每段都有，改它们才全片过期。
- 共用代码只增不改：模块哈希按整个文件算，在用的文件哪怕只加一个导出，闭包里有它的段全部过期。要新写法就新加文件。测试和金样（`*.test.ts`、`金样/`）不在任何段的闭包里。
- 时间线时刻的 `依据` 不算内容（`pipeline/指纹/去依据.ts`，用户 10-31 定）：`{ 在: {…}, 依据: '…' }` 和段窗 `{ 键, 起, 止, 依据: '…' }` 两种形状里字面量的 `依据` 在哈希前去掉，这种模块连注释一起去；别的结构里同名字段照算。渲染代码不许读它，`anim check` 的「结构」拦着。
- 一批段一起算指纹（stale、film、verify、认指纹、gc）：一次 esbuild 打包建全图（`建默克尔图`），再按段取闭包，结果和逐段单独算逐字相同（`pipeline/指纹/指纹.test.ts`）。
- `anim stale` 每段三态：✓ 切片（画面 mp4、声音 wav）都在（缺段签的标出，用到时自动补）、◐ 渲过但切片不在（要用时重渲，报预计耗时）、✗ 过期（说明哪项输入变了，和同一档最近渲过的记录比）。`--严格`：有 ✗ 时退出码 1。什么时候重渲由用户定。
- 地形按段依赖：`pipeline/渲/地形注入.ts` 的 `段渲染环境(键, 地形)` 是唯一注入点，`renderMedia`、`renderStill`、`renderFrames` 都传 `envVariables`。出切片用指纹里的地形项，不重读表（版本目录只增不改，批次中途表变了照样读得到，下次 stale 再报过期）；still、bench 当场读 `段现在的地形(段)`。页面的 `engine/voxel/区段包位置.ts` 从 `process.env` 取（变量名在 `engine/段/地形环境.ts`，`REMOTION_` 开头是因为 Studio 只把这种写进页面）。读没声明的包报错；`anim studio` 传全表；闭包里写到没声明的包名，`anim check` 只提示。
- 地形用量：页面记本页读过的包和区段（`engine/voxel/地形用量.ts`），关页面前收走（`pipeline/渲/地形用量.ts`），写到 `<数据根>/run/地形用量/<作品>/<段键>.json`（包、版本、区段、已量帧），用来收窄 `段.地形`。多次渲染按并集累积；包换版本就重记；整段重渲先清旧记录，渲完才是这个指纹全部帧的准数。只记不读：写不上只报警告。别的工具要接：开浏览器后 `收地形用量(browser)`，渲染传 `段渲染环境`，渲完 `记已量帧`，关浏览器前 `等地形用量写完()`。
- 切片（`pipeline/渲/渲段.ts`、`段产物.ts`；用户 11-06 定只留 `anim film` 一条出片路，`决策/0014`）：整个工程只打包一次，逐段 `renderMedia`，并发 1。画面按成片档直接压成 `cache/母版/<作品>/<段键>/<画面指纹前 16 位>.mp4`（4K60 h264，参数在 `pipeline/渲/设置.ts` 的 `渲染参数`；帧数 = 这段在全片里的输出窗，渲完核对），同一遍用 `separateAudioTo` 写同名 `.wav`（声音指纹 = 画面指纹）；先写临时名再原子改名。每段在渲染闸里依次出画面声音、派生段签、删旧。主检出渲完删同段同级别的旧切片（`pipeline/缓存/钉.ts` 的 `删旧`），worktree 里只新增。
- `anim film`（`pipeline/合成/拼成片.ts`）：缺的段当场渲（`--重渲` 全部重渲），没有「用过期切片」的选项；只拷流接画面、接各段声音拉到 −16 LUFS，`--分享版` 另压 1080p60 AV1。交付自足 = 有 `全片-未拉响度.flac`。manifest 是版本 3（各段记画面、声音指纹）；更早的交付夹原样留着，`适配器/bili/时间轴.ts` 照读它们。
- 段签（`pipeline/段签/`）：每段渲完在闸里从切片派生 `段签/<作品>/<段键>/<画面指纹前 16 位>/`：`签.json`（版本 3：切片 mp4 和 wav 的字节 sha、大小、改于；首尾帧 160×90 灰度）、`声音.flac`（解回来 PCM sha 等于签名才收）。版本 1、2 不认（用户 11-06「旧的不用兼容」）。同一指纹重渲字节变了：上一份记进 `历史.jsonl` 并自查（抽样帧比块均值，超容差报重渲漂移），上一套挪进 `历史/<上一份字节 sha 前 16 位>/`。verify、认指纹要段签时缺了、切片在就当场派生（`pipeline/段签/取.ts`）。
- 认指纹（用户 11-06 定，`决策/0013-认指纹.md`，`pipeline/指纹/认指纹.ts`）：只认 ✗ 的段，和同一档最近一份段签齐、切片在的旧指纹比；渲染设置、私有配乐、`ogg解码.cjs` 变了或记了缺字节的直接拒。抽 n 帧（默认 12）照切片参数同页连出，转成和切片同一个 bt709 yuv420p 比，不一样再按块平均差过 `verify/阈值.toml`。全在噪声内就在新指纹名下克隆旧切片、复制段签并记 `沿用`，stale 标「沿用」，film、verify、gc 都当它是这个指纹的切片；有一帧不同不登记、报帧号。不比声音和没抽到的帧；要补整段比对用 `anim --低优先 film <段> --重渲`。
- `anim verify`：指纹变了的段抽帧，和 `作品/<名>/认可/<平台>/<段键>.toml` 记的认可版比（比切片的输出帧；切片没了报要重渲，`--渲` 当场渲）；超过阈值就必须 `anim verify accept <段…> --理由 …`（要逐段点名：一个场键、章号对上多段就拒；每段都签好才一起写），这一步改 Git 里的文件，画面每一次变化都出现在 diff 里，后面悄悄改回去也会被拦住。认可记录的尺寸、帧数和切片对不上（CRF1 时代的旧档）报「这段没有现行认可，要重新认可」。
  - 只有真要解码才过放行闸，一条命令只过一次；指纹和认可版一样的段不解码（用户 10-30 授权）。例外是同一指纹重渲过（段签签名或切片大小、改于和记的不一样）：照样比，认可那版的像素只取认可参考或段签证明是认可那版的切片。
  - 认可记录存指纹、理由、提交，抽样帧（首帧、每 24 帧、末帧）的原始像素 sha256 和 16×9 块均值，音频 PCM sha256、积分响度、起音落点，以及 `换算`（YUV 换 RGB 的公式名）。
  - 认可那版的像素按 认可参考（`认可参考/<作品>/<平台>/<段键>/<指纹前 16 位>-<抽样键>.mkv`，FFV1 存 yuv420p 原样，旁边 `.json` 记抽样键和各帧 yuv sha，逐帧核）→ 段签证明的切片 → 只比块均值 取。比法（用户 11-02 定，`pipeline/验收/比较.ts`）：两边按固定公式由 YUV 换 RGB（不用 swscale，各版本取整不同），d = 新 − 旧，4 像素网格上 8×8、16×16、64×64 窗口各通道平均取绝对值最大，16×16 > 10、64×64 > 4、8×8 > 24 任一条判变了，16×16 在 6～10 出并排图「看一眼」。声音比响度和起音落点，不要求逐样本相同（用户 10-21：成片不要差太多就行）。阈值在 `verify/阈值.toml`。
  - accept 签名取自段签，写完再从这版的切片抽认可参考（备不上只警告）；`anim verify 补参考` 给已有认可补参考。
- 逐帧校验（`pipeline/验收/逐帧校验.ts`，用法见 `anim help verify`）：`--存` 把每帧 PNG 的 sha 写到 `run/逐帧校验/<作品>/<名>/<段键>.tsv`，`--比` 再渲一次列出不同的帧（有不同退出码 1）。和 verify 的分工：那边比认可版的抽样帧、有阈值、能 accept；这边每帧按字节比、没有阈值，只用来查同一份代码走不同路径出的图是否一致。只有同一批帧能比（`docs/渲染性能.md`「静帧连出」），所以 `--比` 总是照基准存的帧连着渲。不写母版，不碰段签和认可；`cache gc` 不删 `run/逐帧校验/`。
- 望远（用户 11-15 定做，`docs/望远.md`）：`anim still … --望远` 照原镜头把原帧里的一块用整张图原生渲出来。只在 still 的包里加入口（`pipeline/渲/望远.ts`），不进指纹。
- 测速 `anim bench`、渲染记时 `anim 耗时`：分阶段、每帧的记录在 `run/logs/耗时.tsv`、`阶段耗时.tsv`、`渲染明细/`（只留最近 300 份），数据取自 Remotion 的 verbose 日志和 onProgress，不往 engine 里加计时（engine 进指纹）。怎么读、各项提速的数见 `docs/渲染性能.md`。
- 每次打包在系统临时目录出一份约 345 MB 的包，会话结束（含 SIGINT/SIGTERM/SIGHUP）删（`pipeline/渲/打包残留.ts`）；SIGKILL 留下的由 `cache gc` 的「残留」在超过 24 小时、确认没进程用时删。webpack 持久缓存的目录名由 `pipeline/资产/缓存名.ts` 去掉资产锁、求解指纹（`assets add` 后不再冷打包；`缓存名.test.ts` 验过不会读到过期缓存）。
- 原方案里还有的门没做：段音频减按 cue 重混的残差、近白像素占比、整片抽帧总览。现在有的：帧数核对、成片响度和真峰值。

- 取材产物（`pipeline/取材/`）：`anim extract` 按配方导出，和锁比 sha（PNG 再比像素 sha，Pillow、zlib 换版本字节会变）；`--登记` 把新产物写进资产表和锁，来源 `提取:<配方>@<jar sha12>`，许可按 `jars.toml` 的结构化许可继承。配方可以用 `{产物清单}` 按锁反推要导什么（新件用 `--新 <id>`），用 `{产物来源}` 按件记取自哪个 jar。

## 基岩实体和动画

新做的 GeckoLib / YSM / Blockbench 生物直接播 mod 里的原文件，不手抄关键帧（`新生物.md`）。已有角色（`库/角色/魔法酒狐.tsx` 等）照旧。

- `库/生物/定义生物.ts`：声明几何、多层贴图（`engine/model/贴图合成.ts`）、外观变体、默认动画层。
- 和手抄版对照：`作品/把回忆拼好给你/核对/基岩动画/`（`对照.test.ts` 逐骨骼比，`核对-基岩动画` 同机位左右比）。

## 环境和跨平台

- 环境模块只有一份，在 `pipeline/环境/`。取值顺序：环境变量 > `anim.local.toml`（不进 Git）> 默认值。
- 不开 shell：`package.json` 的 scripts 只留 `"anim"`，子进程一律数组参数，Windows 的 `.cmd` 交给 cross-spawn。打印给人照抄的命令用 `pipeline/环境/命令文本.ts` 按本机的壳加引号。
- 子命令都认 `--help`、`-h`、`anim help <命令>`；参数原样转给别的程序的（`mcai`、`studio`）标 `透传`。
- 锁：O_EXCL 建纯 pid 锁，死锁、死票由读者回收；收到 SIGINT/SIGTERM/SIGHUP 放锁删票，退出码 130/143/129。
- 资源闸（`pipeline/闸/`）：用户 10-04、10-05 定控制并发、不吃满内存、按 CPU/内存综合调度；用户 11-01 定总纲：程序守底线，主 Agent 看和决定，日志不翻会话就能复盘。具体机制和数值是 Agent 定的实现，见 `调度.md`、`决策/0012-调度.md`。
