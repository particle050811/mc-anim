# 架构

摘自新项目方案（旧项目 `预览/1021-0925-新项目方案/方案.md` 第二、三节），用户 10-21 拍板「按推荐来」。为什么另起新项目见 `决策/0001-另起新项目.md`，为什么叫 mc-anim 见 `决策/0003-改名-mc-anim.md`，资产怎么登记见 `决策/0002-资产标准.md`。

## 分层

```
engine ← 库 ← 作品公共 ← 场 ← 段 ← 作品/应力转动/注册.tsx
```

| 层 | 放什么 | 不放什么 |
|---|---|---|
| `engine/` | 怎么画、怎么动、怎么出声：core（时钟、数学、坐标、镜头；共用函数的正本见下文「共用函数的正本」）、voxel、model、light、post、anim、flight、audio、ui、三渲二（把回忆拼好给你的画风底座：平涂、正交像素机位、贴图像素对齐、描边、整片后期，用法见 `engine/三渲二/画布.tsx` 文件头） | 剧情、具体角色 |
| `库/` | 多部作品共用的东西长什么样、默认怎么动：角色/、生物/、物品/、界面/、特效/（本作品专有的角色、地点在 `作品/<名>/`）；本作品全片默认值集中在 `作品/应力转动/默认.ts` | 只属于某一场的编排 |
| `作品/应力转动/场/<场键>/` | 一条场时间线（`时间线.ts`）、本场共用的布局和编排、`末态.ts`（下一场接世界状态用） | 别的场的东西 |
| `作品/应力转动/段/<段键>/` | `段.ts`（纯数据）、`画面.tsx`、本段专用的编排 | 两段都要用的东西 |
| `作品/应力转动/核对/` | 预览、对照、核对用的 Composition | 正式段会用到的东西 |
| `pipeline/` | Node 管线：cli、环境、闸、指纹、渲、合成、配音、适配器/{远端,旧项目}、检查、运行记录、世界（读存档、编辑层、烘焙区段包、查询出图，见 `docs/世界.md`） | 画面代码 |
| `py/anim_py/` | 配音、ASR、对齐、口型、配乐分析、jar 提取、图集配方、字节码翻译动作（`动作翻译/`：生物模型类的 setupAnim 翻成姿态程序，`engine/anim/姿态程序.ts` 求值，见 `决策/0007-字节码翻译动作.md`）。JSON 进，文件和 JSON 出；不自己推算路径，路径由 `anim` 传进来 | |
| `sourcing/` | 取材 mod（Forge 1.20.1；从游戏导群系色表、方块表的部分按版本隔开，见 `游戏导表.md`）、`mcai/mcai.py`、数据包（`datapacks/`）、`extract/` 取材脚本、`worlds/<世界>.toml`、`jars.toml`（jar、官方映射和结构化许可）、`extract.toml`（取材配方，场景网格的取材范围也记在这里：mcai mesh 配方，旧网格按网格头反填、标「不重导」） | |

**依赖规则**（`anim check` 用 esbuild metafile 拿真实依赖图来查，不用文本 grep，**没有白名单**）：
- 只能往左边 import；段不许引用别的段；场只许引用上一场的 `末态.ts`。
- 两段要共用的东西，往下放到场或作品公共目录（多部作品用的放 `库/`）。
- 一部作品不许 import 别的作品（`作品/甲/` 里任何文件，包括核对，都不许引 `作品/乙/`），共用的放 `库/` 或 `engine/`。
- `作品/应力转动/核对/` 可以 import 任何东西，任何东西都不许 import 它。
- pipeline 只 import 纯模块：`清单.ts`、`段/*/段.ts`、`场/*/时间线.ts`、`末态.ts`，和 `engine/段/` 里它们引的框架（`段定义`、`设置值`、`时间线`、`歌网格`、`声音助手`、`窗口段`、`清单工具`、`地形环境`，表在 `pipeline/检查/上下文.ts`）。`engine/voxel/区段模型.ts` 是两端共用的纯字节格式定义，也按纯模块检查。它们的闭包里不许有 react、three、remotion。
  例外是 `pipeline/世界/体素库.ts`：烘焙、查询要执行 `engine/voxel/` 的区段包格式、区段解码、合并规则、方块表，它注册 `asset:` 的 Node 钩子后按路径动态 import 这几个模块（不在 metafile 依赖图里），闭包里同样不许有 react、three、remotion（`pipeline/世界/存档.test.ts` 守）。
- 只有 `engine/段/设置.ts` 读 `getInputProps`，转成 React context 往下传；整份渲染设置进指纹。
- 渲染代码里不许出现 `Math.random`、`Date.now`、相对路径 import 的资产、写死的路径或主机名。
- 一个 npm 包，不拆 workspace（拆了会给 Remotion 打包添麻烦）。

## 共用函数的正本

- lerp、smoothstep、hermite、mulberry32 这类小函数，坐标换算和机位，各只有一份正本，新代码一律 import：
  - `engine/core/数学.ts`：插值、夹、smoothstep 一族、缓动、hermite、角度、取余、mulberry32 和随机工具
  - `engine/core/坐标.ts`：游戏、场景（Z 朝上）、three（Y 朝上）三套坐标互换、方块格、游戏朝向
  - `engine/core/机位.ts`：`Cam`（pos、tgt、lens、roll）、焦距和视角互换、`插机位`、`机位轨`
  - `engine/core/three换算.ts`：上面两个文件里要 three 对象的部分：旧名 `toThree` 的正本 `场景到three`、摆 three 相机（`摆相机`）、`投到画面`
  - `库/角色/骨骼表.ts`（`插骨`、合并、叠加）、`库/角色/史蒂夫挥手.ts`（原版挥手）、`库/原版物理.ts`（原版逐刻下落、落地刻；生物和物品的重力顺序不同）
- 除 `three换算.ts` 外这些正本都是纯模块（只有类型 import），`段.ts`、`时间线.ts`、`末态.ts` 和它们引的编排也能用；`engine/core/正本纯.test.ts` 守着这一条。
- 正本表在 `pipeline/检查/正本表.ts`（每个正本的认法：按名字、按行为在探针上求值比、按记号）。迁移来的旧代码里原样搬的副本不动（改了会让段过期），登记在 `docs/副本表.tsv`（正本 × 文件 × 处数）。
- `anim check` 的「副本」规则：某个文件的副本比表里登记的多就是违规（新代码改成 import 正本）；表只许减少（和 main 的分叉点比）。重做哪一场时顺手把那里的副本换成正本，再把表改小。
- 加正本：在正本表加一项（配探针或记号），它的旧副本跑一遍 `anim check 副本` 照报的数第一次登记进表；分叉点的正本表里没有的 id 才许这样从 0 加上去。
- 各正本文件头写了旧副本和正本差在哪（参数顺序、夹不夹、单位），旁边的 `.test.ts` 拿代表性的副本在同一批输入上对。

## 段的形状

- 新章节、新作品的段用段框架（`docs/新段.md`）：`段.ts` 写 `窗口段(场时间线, { 起, 止, 声音表, 声音 })`，声音用 `放(资产, 帧, 目标峰值)`、`说(台词, 帧)` 每个只写一次；`画面.tsx` 写 `定义画面(段, 声音地址, 组件)`，声音自动放，`use段()` 取段内帧和事件帧。本段的声音表、地址表由 `anim cues` 生成（`声音表.生成.ts`、`声音地址.生成.ts`，按段分开免得加一声全片过期）；render、still、studio 开跑前自动跑。跨段的声音写在场时间线的 `声音` 里，各段自动放落进自己窗口的那截；老场里加新段用 `接老段` 把老段摆上场时间线。段键只在目录名和清单里。下面几条说的 cue 形状、落点规则段框架照用。老段照旧写法，不迁。
- `段.ts` 是纯数据：所属场、时钟、机位、声音 cue 表（台词、音效、配乐挂点）、叠层（伤害数字、称号、字幕）、用到的地形包。
- `画面.tsx` 负责画，`<声音轨 cues>` 照 cue 表播放。播放和混音规则照搬旧的 `游戏音效.tsx`、`混音.ts`，母版里的声音仍由 Remotion 混出。
- 时钟有两种：
  - `场窗口`：段 = 场时间线上 [起事件, 止事件] 这一截，照第 7 章 `7-1/时间线.ts` 的写法。**新章节一律用它**（段框架的 `窗口段` 就是这一种）。
  - `自带`：迁移时照搬第 6 章原来的段界写法，不为了套新模式改画面。要不要改成场窗口，由用户逐段决定。
- 同一场里标了「连续」的相邻段，首尾正好差 1 帧。其余段之间硬切，只要求世界状态（位置、朝向、道具）连续。
- 字幕、清单都直接读 cue 表，不渲第 0 帧收日志。
- cue 的形状（`engine/段/段定义.ts`）：
  - 台词 `{ 帧, 台词, 接上段?, 帧数? }`：帧是开口落在段内第几帧（可带小数），文件头 = 帧 − 开口秒 × fps，开口秒和字幕位置写在 `作品/应力转动/台词.toml` 那一条。从文件头放到文件完多 1 帧、段尾或同一句的下一截为止（照旧 `台词轨.tsx`），`帧数` 只给不按这个算的（6-3-2 压路机）。
  - 一句台词跨段或在段里断成两截时，后半截写 `接上段: true`，帧是这一截起放的整帧；文件头照本段前半截或清单上一段的开口推。它不算开口、不出字幕，`anim check` 要求前面真有开口。
  - 音效、配乐 `{ 帧, 资产, 名, 帧数, 档?, 入点秒?, 速率?, 循环?, 增益?, 淡出? }`，字段同旧 `音效清单.ts` 的 SfxClipLog：帧是起放的整帧，入点秒是从文件第几秒放，`增益` 是常数或逐帧数组（按秒读，格间线性插值，见下面「时间」），常数可带 `淡出`（最后 淡出 帧乘 (帧数 − 第几帧) ÷ 淡出，线性往下收）。配乐 = 资产 id 以 `配乐/` 开头。
  - 迁移时照基线 `_表/声音清单/` 逐条转写，当时用 `pipeline/适配器/旧项目/声音对照.ts` 现算台词落点、字幕表、SRT、音效清单、同步表，和基线逐条比（11-06 删了，看 git 历史）。
- 叠层、字幕画进段里（用户 11-05 定「母版 = 成片切片」）：段的 Composition 按成片档出帧，渲出来的切片就是成片的一截，成片只接不叠（`docs/决策/0014-单一出片路.md`）。

## 时间：按秒写（用户 11-06 定原生 60 帧，`决策/0015-原生60帧.md`）

- 画面是时间的函数：段里取时间只用 `engine/段/时间.tsx`，`use当前秒()`（段内第几秒，带小数，嵌套 Sequence 里从那一层起算）、`<秒Sequence 起秒 长秒 剪秒>`；`use段()` 也给 `秒`。核对段「一帧一个视图」用 `use视图下标()`。不直接调 `useCurrentFrame()`、`use编排fps()`，`anim check` 的「时间」规则拦着；没迁的文件冻在 `docs/帧号例外表.tsv`，只许减少。
- 段长、cue 还是数据：`段.ts` 的 `帧数`、`fps` 照旧（段长 = 帧数 ÷ fps 秒），cue 的 `帧`、`帧数`、逐帧 `增益` 以 1/fps 秒为一格（第 6、7 章 1/24 秒）。读的代码按秒算位置，不对齐到格：连续量用 `engine/段/按时取值.ts` 的 `插表`（格间线性插值），硬切的（闪光一档一格）用 `取档`。第 i 项就是第 i 格那一刻的值，格点上两种读法和以前 24 帧输出时取到的一样。
- 原生段（`段.ts` 写 `时钟: '秒'`）：Composition 按成片档的帧率（60）跑，外面包 `<原生时钟>`，段界零头（`出帧.ts` 的相位）用负的 `from` 补上；声音照 `段.ts` 的 cue 由 `定义画面` 挂的 `<段声音>` 放，和画面同一遍出（`pipeline/渲/渲段.ts` 用 `separateAudioTo` 写出段的 wav）。cue 起点按秒落，Remotion 的 `Sequence` 收小数 `from`、`@remotion/media` 按 (帧 − from) ÷ fps 秒取文件，起点样本准；露出来要等 `from` 之后第一个整输出帧，不到一帧的头会切掉。
- 没迁的段（兼容层，待删，`待办.md`）：外面包 `编排时钟.tsx`，里面的帧是 24 帧编排帧、`<Sequence playbackRate>` 缩放到 60 出，声音另按 24 帧单独出一遍。`时间.tsx` 的工具在兼容层里也按秒对，共用组件先迁到秒，新旧段都能用。成片接声音时各段的 wav 从本段声音起点接到下一段声音起点（`拼成片.ts`），新旧段交界处可能差不到 1/60 秒，补静音。

## 光照环境（新段用）

- 环境描述 `engine/light/环境.ts`（纯数据，`定义环境` 加载时就查）：
  - 维度：`engine/light/维度.ts` 的原版三个和暮色森林；别的模组维度在 `库/维度/<模组>.ts` 另写，不往这个文件里堆。
  - 时刻：游戏时间（0 日出、6000 正午，照 1.20.1 `DimensionType.timeOfDay`）算太阳、月亮和天光；或者写美术光向 `太阳`，二选一。时间固定的维度（暮色森林 13000）只能写 `太阳`。
  - 天气：雨、雷 0～1。现在只调灯（直射 × (1 − 雨)，天光照 `getSkyDarken`）；雨丝、天色变灰、云变厚没做。
  - 灯光档位：`灯光档位.ts`，数照 `光照配比.ts`；`暮色`、`主世界` 就是现用的两套。表里没有的灯（新作品、新光影）写 `灯光: { 配比: { 直射, 天光, 环境光, 自发光 } }`，不往表里加档（加档会让用到 `<环境>` 的段全部过期）。
  - 雾、高度雾、云（Photon、原版方块云）、主光投影。
- `<环境 描述 画法 镜头 离地? 穹顶中心? 帧?>`（`engine/light/环境组件.tsx`）：直接放在 ThreeCanvas 下面，照描述摆天、灯、云、雾。
  - 画法按需引：每种一个模块 `engine/light/画法/<名>.tsx`（现有 `主世界`、`暮色`），`export default 定义画法('<名>', 组件)`；段 `import 主世界 from '@engine/light/画法/主世界.tsx'` 传给 `画法`，名字要和描述的 `画法` 一样（描述在段里换画法就传数组）。
  - 没有总表：加画法（下界、末地、模组维度）只加一个模块，已有段的依赖闭包不变、指纹不变。各画法共用的部件（投影主光、雾、原版云、接口）在 `环境部件.tsx`，改它会让所有用 `<环境>` 的段过期。模组专有的画法放 `库/画法/<名>.tsx`。
  - 主世界画法按时刻算太阳时，加原版的月亮和星星（`星月.tsx`，算法在纯模块 `天球.ts`：照 1.20.1 `LevelRenderer` 重写的撒星、月相取 `moon_phases.png` 的格、日月星随天角转，月亮不透明度和星星亮度都乘 1 − 雨）。写美术光向 `太阳` 时不画星月。
- 预设：
  - `暮色环境`（`engine/light/环境预设.ts`）= `TwilightLighting`；
  - `主世界环境`（`作品/应力转动/地点/主世界环境.ts`）= `FlightSky` + `FlightFog`；
  - 两个都在 `核对-环境` 里和现有组件逐像素比过。
- 随帧变：`定义环境轨({ 基础, 关键帧: [{ 帧, 时刻?, 雨?, 雷?, 缓动? }] })`，各项各自插值，头尾之外保持；延时摄影用 `按游戏流速` 算时刻。
- 段在 段.ts 之外声明环境：写在 `段/<段键>/环境.ts`（几段共用写在 `场/<场键>/环境.ts`），`export default` 一份描述或环境轨，画面里 `<环境 描述={…} 画法={…} 镜头={…} />`。场窗口段要按场内帧取，就传 `帧`。
  - `anim check` 的「加载」把这些 环境.ts 当纯模块执行，再查（`pipeline/检查/环境声明.ts`）：用 `定义环境`、`定义环境轨` 重核（时刻、天气、雾、关键帧顺序；没套 `定义…` 的字面量也查到）、灯光档位名在表里、画法有模块且 `定义画法` 的名和文件名一样、关键帧帧号小于 段.ts 的帧数（场目录的不查帧号）。
- 已有段的 `TwilightLighting`、`FlightSky` 不换：画面一样也会让段过期，换不换由用户定。

## 配音（`anim voice`）

- 唯一人写的源是作品的 `台词.toml`：每句的 id、角色、文本，可选 念（交给 TTS、对口型的字，和字幕不同时写）、语言、语气、`["台词"."合成"]`（这句的后端、只交给 TTS 的 念、参考、逐字稿、种子、语气参考、强度、不裁、后端的 参数）、`["台词"."口型手修"]`（对齐不准时手标的字的起止，绑成品 sha）；`["配音"]` 定默认后端、候选种子、成品响度（−18 LUFS、峰值 −1.5 dBFS）、新配音的许可，`["音色"."<角色>"]` 定克隆参考（音色资产 id）和逐字稿。配音、开口、文本哈希、成品sha、口型 这几项由工具写回（只改那一行；改完重新解析核对，认不出的写法报错不写）。
- 文本哈希 是念的字（念，没写就是文本）的哈希：只改字幕时写 念 = 原来的字，配音不算过期；念的字改了 `anim check` 报配音过期。
- 流程：`gen`（按句的后端分批，一批只起一次模型）出候选到 `<数据根>/run/草稿/配音/<作品>/<id>/<后端>-种子<n>.wav`，旁边的 `.json` 记后端、种子、参考、参数 → 自动复核（见下）→ 人试听挑一个 → `use` 定稿：裁静音（−45 dB，头留 0.03 秒、尾留 0.15 秒）、拉响度、48 kHz 单声道，原件 `配音/原件/<id>` 和成品 `配音/<id>` 登记（资产表里没有就补进 `<作品根>/资产表/配音.toml`，可见性 私有），写回 `台词.toml`，出句模块。

## 规矩

- 全片默认值写在 `作品/应力转动/默认.ts` 或对应的共用模块，登记在 `作品/应力转动/规矩.toml`（默认值、级别、原话、针对、出处、落点、例外）。
- 级别：带用户原话、并且原话说的就是这一类情况的，才是「原话」级，算硬约束；其余是「参考」级。
- 段里要例外，写 `例外('规矩id', 值, {段, 原因})`。`anim check` 双向核对：代码里的例外都在表里登记过，表里的例外代码里都找得到；默认值的落点符号必须存在。例外只写在 `作品/应力转动/段/<段键>/` 或 `作品/应力转动/场/<场键>/` 里；搬家暂放在 `作品/应力转动/地点/<地点>/<旧目录>/` 的剧情编排拆回之前也可以写在那里（`迁移.md` 差异表 R2）。
- 落点写成 `<路径> [符号、符号…]`，路径从顶层目录写起；还在旧项目里的写 `旧:` 或 `待迁移:` 开头，`anim check` 记作待迁移、不算违规，搬完改成新路径。
- 出处里的 `M/<名>.md` 指 agent-context 的记忆，根是配置 `记忆`（`ANIM_MEMORY`）。`anim check` 查文件在不在、`:行号` 有没有超出；记忆仓库不在本机就跳过。记忆删了、改名或合并了，出处跟着改。
- Agent 不得把规矩推广到全片，只能在预览的 `00-说明.md` 里提议，用户点头后再登记。

## 指纹、过期和验收

- 每段的指纹由这些算出：`画面.tsx`、`段.ts`、`设置.ts`、作品外壳的默克尔根（`pipeline/指纹/默克尔.ts`：每个模块去掉注释、类型、格式后，把 import 说明符换成目标的哈希再哈希；npm 包记 lockfile 版本，`asset:` 记 sha），声明的地形包版本（只有 `段.地形` 里的，改别的包不让段过期）、渲染设置、lockfile 里 remotion 和 three 等的版本、webpack 改写和 ogg 解码的规范化文本、影响输出的 tsconfig 选项、执行平台。文件路径不进指纹：只改注释、挪文件、换 import 写法不让段过期。
- 过期按段算：改了一个文件，只有依赖闭包里含它的段过期（画面、段.ts、设置.ts、外壳四个根的闭包）。外壳和 `设置.ts` 的闭包每段都有（`作品/<名>/index.ts`、`注册.tsx`、`engine/段/注册工厂.tsx`、`设置.ts`、`设置值.ts`、`engine/core/渲染设置.ts`），改它们才是全片过期；改 `engine/core/数学.ts` 只让 import 了它的段过期。
- 新增文件不让旧段过期，共用代码只增不改：要新写法就新加文件，不改已有段在用的共用文件。模块哈希按整个文件算，在用的文件哪怕只加一个导出，闭包里有它的段也全部过期、要重渲重验。测试和金样（`*.test.ts`、`金样/`）不在任何段的闭包里，随便加。
- `anim stale` 列出过期的段、哪项输入变了、预计耗时，什么时候重渲由用户定。`anim film` 缺的段当场渲（`--重渲` 全部重渲），没有「用过期切片」的选项。
- `anim film`（`pipeline/合成/拼成片.ts`，用户 11-05 定「母版 = 成片切片」）：各段渲出来就是成片的一截（叠层、字幕画在段里，按成片档的 4K60 参数压好，`pipeline/渲/渲段.ts`），film 只拷流接画面、接各段声音拉到 −16 LUFS，`--分享版` 另压 1080p60 AV1。交付自足 = 有 `全片-未拉响度.flac`（剪映剪辑包用户 11-06 定不要了，以前还要 `剪辑包/画面.mp4`）。`anim film 补声音 <交付…> | --全部 [--只看]` 给 10-30 以前的旧交付补 FLAC：源要是出片时那一份（v2 比 manifest 记的母版字节 sha；v1 没记，母版、段签派生时的母版改于都不能晚于 manifest.json），拼出的响度还要和 manifest 的 原LUFS 一样才收；补了什么记进交付里的 `补做.json`，只新增文件。
- `anim stale` 每段三态：✓ 切片（画面 mp4、声音 wav）都在（段签缺的标「缺段签」，verify、认指纹用到时自动补）、◐ 渲过但切片不在（有 `.指纹.json` 或段签，要用时重渲，报预计耗时）、✗ 过期。差异和同一档（级别、输出帧率、缩放一样）最近渲过的画面记录比，没有同档的退到同一级别最近的、并注明。`--严格`：有 ✗ 时退出码 1（默认总是 0），◐ 不算。
- 认指纹（用户 11-06 定，`决策/0013-认指纹.md`，`pipeline/指纹/认指纹.ts`）：`anim 认指纹 <选择器…> --理由 … [--抽 <n>] [--级别 …] [--只看]` 只认 ✗ 的段：和同一档最近一份段签齐、切片和配的 wav 都在的旧指纹比（只比切片，CRF1 时代的 `.mkv` 母版不比，`决策/0014`），渲染设置、私有配乐、`ogg解码.cjs` 变了或记了缺字节的直接拒（静帧证明不了）；抽 n 个输出帧（默认 12，首尾加均匀）照切片的参数（带字幕）同页连出，PNG 经 Remotion 自带的 ffmpeg 用和切片编码同一个 bt709 滤镜转 yuv420p，和旧切片解出的 yuv 比，不一样就按固定公式换 RGB 算块平均差，过 `verify/阈值.toml` 的变了门槛算不同。全在噪声内就在新指纹名下克隆（`cp -c`，退回硬链接、复制）一份旧切片（mp4，wav 按配对的声音指纹克隆）、复制段签并记 `沿用`（自、原渲、理由、帧、比法、于、提交）、写两份 `.指纹.json`；stale 标「沿用」，film、verify、gc 都当它是这个指纹的切片。有一帧不同不登记、报帧号。不比声音和没抽到的帧；补整段比对用 `anim --低优先 film <段> --重渲`（段签同指纹重渲自查），光 verify 比的是沿用的旧签名。
- 时间线时刻的 `依据` 不算内容（`pipeline/指纹/去依据.ts`，用户 10-31 定）：`{ 在: {…}, 依据: '…' }` 和段窗 `{ 键, 起, 止, 依据: '…' }` 两种形状里字面量的 `依据` 在默克尔哈希前去掉，有这种条目的模块连注释一起去（esbuild 不去对象里的注释，只改注释的提交也算改）；只认这两种形状，别的结构里同名字段、帧号、拼出来的 `依据` 都照算。渲染代码不许读它，`anim check` 的「结构」拦着（`依据: x.依据` 透传不算读；`engine/voxel/主世界地形.ts` 读的是 交界.json 自己的字段）。算法名 `merkle-v1` 没换，但含这种条目的模块哈希会变一次，闭包里有这些模块的段都跟着过期一次，规模不小：10-31 实测 `把回忆拼好给你` 48 段里 45 段指纹变了（43 段因 `分镜.ts`，2 段因 `核对/段框架示范/时间线.ts`；这些段都没有地形，画面不变），要重渲才能出片，见 `待办.md`。
- 地形按段依赖：`pipeline/渲/地形注入.ts` 的 `段渲染环境(键, 地形)` 是唯一注入点，`renderMedia`、`renderStill`、`renderFrames` 都传 `envVariables`（film、still、bench、`verify --渲` 走这里）。出切片传指纹的地形项 `r.画面指纹.项.地形`，不重读表：批次中途表变了，页面还是指纹那版，旧版本目录只增不改、读得到，下次 `anim stale` 再报过期；still、bench 不算指纹，`段现在的地形(段)` 当场读。页面的 `engine/voxel/区段包位置.ts` 从 `process.env` 取（环境变量名在 `engine/段/地形环境.ts`，`REMOTION_` 开头是因为 Studio 只把这种写进页面），Node 里的体素库（`pipeline/世界/体素库.ts`）不取包，不用传；Node 工具要取包就设同一个变量。没拿到表、读没声明的包都报错。`anim studio` 传全表。闭包里写到没声明的包名，`anim check` 只提示（`主世界地形.ts` 带默认包名，写到不等于读到）。
- 地形用量：页面记本页读过的包和区段（`engine/voxel/地形用量.ts`，不碰画面），关页面前收走（`pipeline/渲/地形用量.ts`），写到 `<数据根>/run/地形用量/<作品>/<段键>.json`：`{ 作品, 段, 指纹?, 已量帧: "0-99,620", 包: { <包>: { 版本, 区段: ["级|i|j", …] } }, 更新于 }`，用来收窄 `段.地形`。多次渲染按并集累积；包的版本换了，那个包重记、已量帧清零；整段重渲（`开始整段量`）先清旧记录并记指纹，渲完才是这个指纹全部帧的准数，之后的 bench、still 只往上加。已量帧只记渲完的；崩在中途的那次，页面读过的可能已写进文件而帧没记。只记不读：文件写不上、是坏 JSON 都只报警告，不影响渲染（母版先改名再记）。别的工具要接：开浏览器后 `收地形用量(browser)`，渲染传 `envVariables: 段渲染环境(键, 地形)`，渲完 `await 记已量帧(键, 帧们)`，关浏览器前 `await 等地形用量写完()`。`核对-世界编辑` 自己拼路径，不经 `packDir`，不记。
- 一批段一起算指纹（stale、film、verify、认指纹、gc）：一次 esbuild 打包建好全图（`建默克尔图`），再按段取闭包；缺字节、私有配乐按本段闭包判，结果和逐段单独算逐字相同（`pipeline/指纹/指纹.test.ts` 有等值测试）。
- 切片（`pipeline/渲/渲段.ts`、`段产物.ts`，用户 11-06 定只留 `anim film` 一条出片路，`决策/0014`）：整个工程只打包一次，逐段 `renderMedia`，渲染并发为 1。画面按成片档直接压成 `cache/母版/<作品>/<段键>/<画面指纹前 16 位>.mp4`（4K60 h264，参数在 `pipeline/渲/设置.ts` 的 `渲染参数`；帧数 = 这段在全片里的输出窗，渲完核对），声音按编排帧率另出 `<声音指纹前 16 位>.wav`；都先写临时名再原子改名。每段在渲染闸里依次出画面、出声音、派生段签、删旧：没有 CRF1、没有后台转存（`决策/0008` 的 CRF1→压缩母版这条作废）。主检出渲完删同段同级别的旧切片（`pipeline/缓存/钉.ts` 的 `删旧`，命中「已是最新」也清，CRF1 时代的 `.mkv`、`.x264.mkv` 同样算旧的；worktree 里只新增不删）。
- 段签（`pipeline/段签/`）：每段渲完在闸里当场从切片派生 `段签/<作品>/<段键>/<画面指纹前 16 位>/`：`签.json`（版本 3：切片 mp4 和 wav 的字节 sha、大小、改于；verify 的签名，和 `扫母版` 同一份代码算，画面取自 mp4、声音取自 wav；首尾帧 160×90 灰度）、`声音.flac`（解回来 PCM sha 等于签名才收）。版本 1、2 是 CRF1 时代的，照读（补交付、认可参考找旧版用），版本 1 的 `抽样.mkv` 不用了，`anim cache gc` 回收。同一指纹重渲字节变了：上一份记进 `历史.jsonl` 并自查（抽样帧 sha 一样是同画面，不一样比块均值，超容差算重渲漂移、报警要跑 verify），上一套原样挪进 `历史/<上一份字节 sha 前 16 位>/`。verify、认指纹要段签时缺了或对不上，切片在就当场派生（`pipeline/段签/取.ts`）；切片不在只能用已有的段签。
- 每次打包在系统临时目录出一份约 345 MB 的包，会话结束删，SIGINT/SIGTERM/SIGHUP 也同步收尾删（`pipeline/渲/打包残留.ts`，先摘 public 链接）；SIGKILL 等留下的由 `cache gc` 的「残留」列入计划：只扫系统临时目录的 `remotion-webpack-bundle-*`，超过 24 小时且进程表能确认没有使用者才可删。发现进程引用目录就留着，仍有归属不明的渲染进程或读不到 ps 也留着；`--执行` 才删除，删前再核时间和进程，仍用同一个 `删打包`。打包用 Remotion 的 webpack 持久缓存。Remotion 拿整份配置的 md5 当缓存目录名，`pipeline/资产/缓存名.ts` 让资产锁、求解指纹不进这个名字（`assets add` 后不再冷打包）；`asset:` 每次编译按当时的锁改写、DefinePlugin 的值 webpack 自己跟踪，所以不会读到过期缓存（`缓存名.test.ts` 用真 webpack 验过）。
- 渲染全程记时（`pipeline/运行记录/阶段.ts`、`渲染明细.ts`，`anim 耗时` 看，怎么读见 `docs/渲染性能.md`）。分阶段：film、still 的算指纹、打包（备素材、webpack）、开浏览器、读组合、等闸、出帧、编码、查帧数、声音、段签、清旧（11-06 以前后台转存的 派生段签、转存、等后台 只在旧记录里），film 的接段、拼声音、拉响度、压成片、分享版等，记进运行记录的 `阶段` 字段和 `run/logs/阶段耗时.tsv`；`耗时.tsv` 的列不变。每帧：每次 renderMedia、renderStill 留一份 `run/logs/渲染明细/*.json`（每帧毫秒、这帧在等哪个 delayRender、机器负载和内存），只留最近 300 份。pipeline 不进指纹，加记时不让段过期；数据取自 Remotion 的 verbose 日志和 onProgress，不往 engine 里加计时（engine 进指纹）。
- `anim verify`：指纹变了的段抽帧（新这一版的签名读段签；哈希和认可版不一样、要看像素的帧解段签记的那份切片，比的是成片的输出帧；这个指纹的切片没了报要重渲才能验收，`--渲` 当场渲，`决策/0014`），和 `作品/应力转动/认可/<平台>/<段键>.toml` 记的那一版比；超过阈值就必须 `anim verify accept <段…> --理由 …`（一次可认可多段、共用一个理由，但要逐段点名：一个场键、章号对上多段就拒；每段都签好才一起写），这一步会改 Git 里的文件。画面每一次变化都会出现在 diff 里，后面的提交把它悄悄改回去也会被拦住。CRF1 时代的认可（1440p、按编排帧率的帧数）和切片的尺寸、帧数对不上，报「参考是旧档的、要重新认可」，算不过、不比。
  - 只有真要解码（和认可版比，或 accept 签名）才过放行闸，一条命令只过一次；指纹和认可版一样的段不解码、不等闸（用户 10-30 授权）。例外是同一指纹重渲过：段签的签名和认可记录不一样，或切片大小、改于和段签记的不一样（只读 签.json、stat 切片判断），照样比一次；这时现在的切片不是认可那版，认可那版的像素只取认可参考，或段签（现在的、`历史/` 里的）证明是认可那版的切片，不拿现在的冒充。
  - 认可记录存认可那版的指纹、理由、提交，和抽样帧（首帧、每 24 帧、末帧）的原始像素 sha256（ffmpeg 解成 rgb24，从切片算；CRF1 时代的从 CRF1 算）、16×9 块均值，以及音频 PCM 的 sha256、积分响度、起音落点；11-02 起还记 `换算`（比像素时 YUV 换 RGB 的公式名，和代码里的不一样 verify 会提示）。
  - 哈希不一样时，认可那版的像素按 认可参考（`认可参考/<作品>/<平台>/<段键>/<指纹前 16 位>-<抽样键>.mkv`，认可那版的抽样帧，FFV1 存解出来的 yuv420p 原样；抽样键是认可记录各抽样帧哈希的摘要，同一指纹重渲后再 accept 就是另一个文件，旧参考不会冒充新认可；旁边 `.json` 旁记记着抽样键和各帧 yuv sha，比的时候逐帧核，对不上只算这一段不过；11-02 以前克隆的老参考没有旁记，核认可记录的 rgb 哈希）→ 段签证明是认可那版的切片（CRF1 时代的认可：压缩母版、CRF1）→ 都没有只比块均值 取。有像素就比块平均差（用户 11-02 定，预览 `1102-1143-verify比法`，`pipeline/验收/比较.ts`）：两边都由 YUV 按固定公式换 RGB（不用 ffmpeg 的 swscale，各版本取整不同），d = 新 − 旧，4 像素网格上的 8×8、16×16、64×64 窗口里各通道平均取绝对值的最大值，16×16 > 10、64×64 > 4、8×8 > 24 任一条判变了，16×16 在 6～10 之间不判失败、出并排图「看一眼」。accept 签名取自段签，要这版的切片在（认可参考要从它抽），认可文件都写完再从这版的切片抽认可参考（备不上只警告，不会认可一半）；`anim verify 补参考 [<选择器>]` 给已有的认可补参考（从段签证明是认可那版的切片抽）、给老参考补旁记，只新增文件。声音比响度和起音落点，不要求逐样本相同（用户 10-21：成片不要差太多就行）。变了、看一眼的出 旧|新|差 并排图（下排放大红框那块）和 `00-说明.md` 给人看。阈值在 `verify/阈值.toml`。
  - 和旧项目基线比的 `verify --对基线` 随 CRF1 一起删了（`决策/0014`）：基线是 1440p、24 帧的，和 4K60 切片的帧对不上。
- 逐帧校验（`pipeline/验收/逐帧校验.ts`）：`anim verify 逐帧 <选择器…> [--帧 a-b|帧,帧] --存 <名>` 把每帧 PNG 的 sha 写到 `run/逐帧校验/<作品>/<名>/<段键>.tsv`（`#` 开头几行记段帧数、段指纹、提交，下面是 帧、sha256、字节；不覆盖已有的），`--比 <名>` 再渲一次列出不同的帧，还说明段指纹变没变，有不同退出码 1；本机缺地形包的段，存过基准的算没过，没存过的只跳过，一段都没渲也算没过。`--留图 <目录>`：`--存` 留全部 PNG，`--比` 只留不同的帧；目录里已有这次可能写的 PNG 就开跑前拒。和 `anim verify` 的分工：那边比认可版的抽样帧、有阈值、能 accept；这边每帧都比、按字节、没有阈值。一条命令只打包一次（用完删）、每段过一次渲染闸、并发 1，同页连续渲、声音开着（和 renderMedia 一样）；不写母版，不碰段签和认可，不记耗时表（渲染明细照写，标签 `逐帧校验:`）。比的是段的 Composition，不含透明叠层。帧号是输出帧（和切片同一套参数，带字幕）；只有同一批帧能比（`docs/渲染性能.md`「静帧连出」）：`--存 --帧` 定这一批是哪些帧；`--比` 总是照基准存的帧连着渲，给了 `--帧` 就渲到其中最后一帧为止，前面的帧不省。`anim cache gc` 不删 `run/逐帧校验/`。
- 测速：`anim bench <段> --帧 <起>-<止>` 照切片参数（输出帧号、带字幕）渲一段帧，分阶段计时，不写缓存。Remotion 版本回归、各项提速的数见 `docs/渲染性能.md`。
- 单段门：帧数和清单一致；段音频减去按 cue 重混的结果，残差低于阈值；近白像素占比不超标。整片门：总帧数等于各段之和；接缝不悄悄丢帧；量响度和真峰值；抽帧拼总览放进预览。

- 音频入库（`assets add`、`extract --登记`）顺手量时长、采样峰值、积分响度，写进锁条目的可选字段 `时长`、`峰值`、`响度`（`pipeline/资产/音频量.ts`）；指纹只认 sha256，这几个字段不让段过期。早先入库、锁里没量过（没有 `时长`）的，`anim assets measure` 补（共用锁和各作品的锁，只加缺的字段；量过仍缺峰值的静音、缺响度的太短条目不再重量；字节不在本机的跳过并报件数；`--检查` 只报，有能补的退出码 1；有量不出的也退出码 1）。入库、`assets measure`、`anim cues` 现量用的是同一个函数 `量音频数`，锁里的数和 `放()` 现量的逐位一样。
- 代码里写 `import x from 'asset:贴图/实体/九胡'`，解析插件按资产锁换成 `store/` 里的文件。打包规则和旧项目一样：png 内联、同步解码，ogg 解成 wav。资产锁里查不到的 id 打包直接失败，报错里写该跑哪条命令。
- 群系色表、方块表现在用手写的（`数据/场景/关键帧/`，从 jar 推算）；`anim gamedata` 能从开着的游戏直接导同结构的表并和手写表核对，迁移期只出报告，新章节要用就登记成新资产（`游戏导表.md`）。
- 区段包、网格 .bin 在运行时用 `dataUrl(id)` 取。段要声明用到哪些地形包；页面只拿到声明的包和版本，读了没声明的包就报错，保证指纹不漏依赖（见「指纹、过期和验收」）。区段的解码器是编好的 WASM，字节和源码都进 Git（`engine/voxel/区段解码器.生成.ts`、`wasm/区段解码.ts`），`anim world 解码器` 从源码重编。
- 私有内容缺失时：配乐换成静音，并在运行记录里报出来；配音缺一句就直接失败，不静默替换。按 cue 放的私有配乐不打进包，渲染代码用 `engine/audio/私有配乐.ts` 按 id 现取，段指纹记它有字节（sha）还是缺了换静音。
- 随仓库发字节：写了 `<作品根>/随仓库.toml` 的作品，这些段渲片要用的非私有资产放 `<作品根>/字节/`（`anim assets vendor` 现算重写，`anim check` 核对），渲染前补进数据根 `store/`，公开仓库 clone 下来就能渲（`决策/0005-随仓库发字节.md`）。
- 搬来的代码里还直接 import 私有资产的（九胡配音、配乐、结构罗盘截图、巨人的取材账号皮肤），import 块顶上标 `// 待迁移（私有资产）：原因`，`anim check` 记成待迁移；改走 cue 或定了降级办法后删掉标记。数据根里没有的字节（私有的，或公开仓库没随仓库发的），打包时换占位（`pipeline/资产/缺字节.ts`，接在 webpack改写 外面）：闭包碰到它们的段入口（画面、叠层）整个换成一渲就抛错的组件，别处的 `asset:<id>` 换成一取值就抛错的模块；段指纹记一项 `缺字节`。

## 基岩实体和动画

新做的 GeckoLib / YSM / Blockbench 生物直接播 mod 里的原文件，不手抄关键帧（步骤见 `新生物.md`）。已有的角色（`库/角色/魔法酒狐.tsx` 等）照旧，迁移期不改。
- `engine/anim/插值.ts`、`Molang.ts`：插值（linear、step、catmullrom、bezier、GeckoLib 4 缓动名，公式照 GeckoLib 4.8.4 源码）和 Molang 子集（解析一次，常量烘成数；除以 0 得 0，同 mocha；精度 float / double 可选）。
- `engine/anim/基岩动画.ts`：`.animation.json` 播放器，纯模块。两种口径（默认 `'通用'`）：`'TLM'` 照 TLM 1.5.3 的 GeckoLib 3 分支反汇编（关键帧 pre/post、catmull 取点、hold 当 once、parallel_ 控制器转角叠加、不读 blend_weight），`'通用'` 照 Bedrock / GeckoLib 4 文档（hold 停在最后一帧、权重、start_delay/loop_delay）。Molang TLM 按 float、通用按 double。多层混合 `混合层`：覆盖或叠加，带权重。
- `engine/anim/动画控制器.ts`：基岩版 `animation_controllers` 状态机（固定步长从 0 推、记历史）和 GeckoLib 控制器（时刻表 + transitionLength 过渡），出一张骨骼表，在 `基岩实体` 里当一层。
- `engine/model/实体材质.ts`：受伤变红、原版实体光照、发光、半透明，按选项共用材质；缓存按最近使用丢（上限 512），组件卸载时放手，贴图没人用了就释放材质。`基岩实体.tsx`：几何 + 实体材质 + 多层动画；发光骨骼拆成两份画。
- `库/生物/定义生物.ts`：声明几何、多层贴图（`engine/model/贴图合成.ts` 叠成一张）、外观变体、默认动画层，得到组件。
- 和手抄版对照：`作品/把回忆拼好给你/核对/基岩动画/`（`对照.test.ts` 逐骨骼 1e-6（尾巴 1e-3 度，float），`核对-基岩动画` 左右两张画布同机位）。

## 环境和跨平台

- 环境模块只有一份，在 `pipeline/环境/`，用 TS 写。取值顺序：环境变量 > `anim.local.toml`（不进 Git）> 默认值。
- 不开 shell：npm scripts 只留 `"anim"` 一条，子进程一律用数组参数，Windows 的 `.cmd` 交给 cross-spawn。打印给人照抄的命令（`extract --只打印`）用 `pipeline/环境/命令文本.ts` 按本机的壳加引号：POSIX 单引号，Windows 双引号。
- 子命令都认 `--help`、`-h` 和 `anim help <命令>`（路由统一拦，打 `用法`、`说明`，命令可以给 `帮助` 换成详细的）；参数原样转给别的程序的（`mcai`、`studio`）标 `透传`，`--help` 交给那边。
- 锁：O_EXCL 建纯 pid 锁，主机另写旁文件；死锁/死票由读者回收并记原持有者，Windows 删除重试保留。票名兼容旧代码，内容升级 JSON；旧票不能改名。SIGINT/SIGTERM/SIGHUP 放锁删票、写任务止及耗时，退出码 130/143/129；SIGKILL 走在跑登记由读者认领崩溃。
- 资源闸（`pipeline/闸/`）：用户 10-04、10-05 定的是控制并发、不吃满内存、按 CPU/内存综合调度；30%、核×0.8、60 秒是 Agent 选的实现值。用户 11-01 定的是总纲：程序守底线，主 Agent 看和决定，日志不翻会话就能复盘。下面的具体机制是主 Agent 11-01 的裁决，不是用户定值：渲染先排队判内存再拿 GPU 位，不看负载；内存不足不持锁，人工只放行一票，压力 4 须加 --强。放行闸在锁外等资源，只短暂持锁记时间；60 秒只在上次放行者仍在跑时挡，旧格式保守兼容。正规批按累计持锁时间/明确指令让路，不改同页路径。调度日志、快照、告警、路令见 `调度.md`，归属与取舍见 `决策/0012-调度.md`。
- 报错：预期内的（用法错、选不出作品、仓库代码里 throw 的 Error、esbuild 构建失败）只打信息，`--调试` 或 `ANIM_DEBUG=1` 才打调用栈；调用栈总记进运行记录（`pipeline/cli/路由.ts`）。
- 只在 Mac 上有的做成可选适配器：image-flow 录音。缺了只影响这一项。
- 统一 UTF-8；Git 设 `core.quotepath false`、`core.longpaths true`；时间一律 UTC。
- 工具链：Node 24、npm、TS strict、vitest；Python 3.11+、uv、pytest；Java 17、Gradle wrapper。Remotion 4.0.537、three 0.186.1、react 19.3.0、esbuild 0.28.1 锁死，升级要用户点名（Remotion 用户 10-22 定从 4.0.530 升上来；它自带的 Chromium 157 比 4.0.530 的 149 慢，见 `docs/渲染性能.md`）。
