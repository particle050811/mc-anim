# 架构

摘自新项目方案（旧项目 `预览/1021-0925-新项目方案/方案.md` 第二、三节），用户 10-21 拍板「按推荐来」。为什么另起新项目见 `决策/0001-另起新项目.md`，为什么叫 mc-anim 见 `决策/0003-改名-mc-anim.md`，资产怎么登记见 `决策/0002-资产标准.md`。

## 分层

```
engine ← 库 ← 作品公共 ← 场 ← 段 ← 作品/应力转动/注册.tsx
```

| 层 | 放什么 | 不放什么 |
|---|---|---|
| `engine/` | 怎么画、怎么动、怎么出声：core（时钟、数学、坐标、镜头；共用函数的正本见下文「共用函数的正本」）、voxel、model、light、post、anim、flight、audio、ui、三渲二（把回忆拼好给你的画风底座：平涂、正交像素机位、贴图像素对齐、描边、整片后期，用法见 `engine/三渲二/画布.tsx` 文件头） | 剧情、具体角色 |
| `库/` | 多部作品共用的东西长什么样、默认怎么动：角色/、生物/、物品/、界面/、特效/（本作品专有的角色、地点在 `作品/<名>/`）；本作品全片默认值集中在 `作品/应力转动/默认.ts` | 只属于某一场的编排 |
| `作品/应力转动/场/<场键>/` | 一条场时间线（`时间线.ts`）、本场共用的布局和编排、`末态.ts`（下一场接世界状态用） | 别的场的东西 |
| `作品/应力转动/段/<段键>/` | `段.ts`（纯数据）、`画面.tsx`、本段专用的编排 | 两段都要用的东西 |
| `作品/应力转动/核对/` | 预览、对照、核对用的 Composition | 正式段会用到的东西 |
| `pipeline/` | Node 管线：cli、环境、闸、指纹、渲、合成、剪辑包、配音、适配器/{剪映,远端,旧项目}、检查、运行记录、世界（读存档、编辑层、烘焙区段包、查询出图，见 `docs/世界.md`） | 画面代码 |
| `py/anim_py/` | 配音、ASR、对齐、口型、配乐分析、jar 提取、图集配方、字节码翻译动作（`动作翻译/`：生物模型类的 setupAnim 翻成姿态程序，`engine/anim/姿态程序.ts` 求值，见 `决策/0007-字节码翻译动作.md`）。JSON 进，文件和 JSON 出；不自己推算路径，路径由 `anim` 传进来 | |
| `sourcing/` | 取材 mod（Forge 1.20.1；从游戏导群系色表、方块表的部分按版本隔开，见 `游戏导表.md`）、`mcai/mcai.py`、数据包（`datapacks/`）、`extract/` 取材脚本、`worlds/<世界>.toml`、`jars.toml`（jar、官方映射和结构化许可）、`extract.toml`（取材配方，场景网格的取材范围也记在这里：mcai mesh 配方，旧网格按网格头反填、标「不重导」） | |

**依赖规则**（`anim check` 用 esbuild metafile 拿真实依赖图来查，不用文本 grep，**没有白名单**）：
- 只能往左边 import；段不许引用别的段；场只许引用上一场的 `末态.ts`。
- 两段要共用的东西，往下放到场或作品公共目录（多部作品用的放 `库/`）。
- 一部作品不许 import 别的作品（`作品/甲/` 里任何文件，包括核对，都不许引 `作品/乙/`），共用的放 `库/` 或 `engine/`。
- `作品/应力转动/核对/` 可以 import 任何东西，任何东西都不许 import 它。
- pipeline 只 import 纯模块：`清单.ts`、`段/*/段.ts`、`场/*/时间线.ts`、`末态.ts`，和 `engine/段/` 里它们引的框架（`段定义`、`设置值`、`时间线`、`歌网格`、`声音助手`、`窗口段`、`清单工具`，表在 `pipeline/检查/上下文.ts`）。它们的闭包里不许有 react、three、remotion。
  例外是 `pipeline/世界/体素库.ts`：烘焙、查询要执行 `engine/voxel/` 的区段包格式、合并规则、方块表，它注册 `asset:` 的 Node 钩子后按路径动态 import 这几个模块（不在 metafile 依赖图里），闭包里同样不许有 react、three、remotion（`pipeline/世界/存档.test.ts` 守）。
- 只有 `engine/段/设置.ts` 读 `getInputProps`，转成 React context 往下传；整份渲染设置进指纹。
- 渲染代码里不许出现 `Math.random`、`Date.now`、相对路径 import 的资产、写死的路径或主机名。
- 一个 npm 包，不拆 workspace（拆了会给 Remotion 打包添麻烦）。

## 共用函数的正本

- lerp、smoothstep、hermite、mulberry32 这类小函数，坐标换算和机位，各只有一份正本，新代码一律 import：
  - `engine/core/数学.ts`：插值、夹、smoothstep 一族、缓动、hermite、角度、取余、mulberry32 和随机工具
  - `engine/core/坐标.ts`：游戏、场景（Z 朝上）、three（Y 朝上）三套坐标互换、方块格、游戏朝向
  - `engine/core/机位.ts`：`Cam`（pos、tgt、lens、roll）、焦距和视角互换、`插机位`、`机位轨`
  - `engine/core/three换算.ts`：上面两个文件里要 three 对象的部分：旧名 `toThree` 的正本 `场景到three`、摆 three 相机（`摆相机`）、`投到画面`
  - `库/角色/骨骼表.ts`（`插骨`、合并、叠加）、`库/角色/史蒂夫挥手.ts`（原版挥手）、`库/原版物理.ts`（原版逐刻下落、落地刻；生物和物品的重力顺序不同）
- 除 `three换算.ts` 外这些正本都是纯模块（只有类型 import），`段.ts`、`时间线.ts`、`末态.ts` 和它们引的编排也能用；`engine/core/正本纯.test.ts` 守着这一条。
- 正本表在 `pipeline/检查/正本表.ts`（每个正本的认法：按名字、按行为在探针上求值比、按记号）。迁移来的旧代码里原样搬的副本不动（改了会让段过期），登记在 `docs/副本表.tsv`（正本 × 文件 × 处数）。
- `anim check` 的「副本」规则：某个文件的副本比表里登记的多就是违规（新代码改成 import 正本）；表只许减少（和 main 的分叉点比）。重做哪一场时顺手把那里的副本换成正本，再把表改小。
- 加正本：在正本表加一项（配探针或记号），它的旧副本跑一遍 `anim check 副本` 照报的数第一次登记进表；分叉点的正本表里没有的 id 才许这样从 0 加上去。
- 各正本文件头写了旧副本和正本差在哪（参数顺序、夹不夹、单位），旁边的 `.test.ts` 拿代表性的副本在同一批输入上对。

## 段的形状

- 新章节、新作品的段用段框架（`docs/新段.md`）：`段.ts` 写 `窗口段(场时间线, { 起, 止, 声音表, 声音 })`，声音用 `放(资产, 帧, 目标峰值)`、`说(台词, 帧)` 每个只写一次；`画面.tsx` 写 `定义画面(段, 声音地址, 组件)`，声音自动放，`use段()` 取段内帧和事件帧。本段的声音表、地址表由 `anim cues` 生成（`声音表.生成.ts`、`声音地址.生成.ts`，按段分开免得加一声全片过期）；render、still、studio 开跑前自动跑。跨段的声音写在场时间线的 `声音` 里，各段自动放落进自己窗口的那截；老场里加新段用 `接老段` 把老段摆上场时间线。段键只在目录名和清单里。下面几条说的 cue 形状、落点规则段框架照用。老段照旧写法，不迁。
- `段.ts` 是纯数据：所属场、时钟、机位、声音 cue 表（台词、音效、配乐挂点）、叠层（伤害数字、称号、字幕）、用到的地形包。
- `画面.tsx` 负责画，`<声音轨 cues>` 照 cue 表播放。播放和混音规则照搬旧的 `游戏音效.tsx`、`混音.ts`，母版里的声音仍由 Remotion 混出。
- 时钟有两种：
  - `场窗口`：段 = 场时间线上 [起事件, 止事件] 这一截，照第 7 章 `7-1/时间线.ts` 的写法。**新章节一律用它**（段框架的 `窗口段` 就是这一种）。
  - `自带`：迁移时照搬第 6 章原来的段界写法，不为了套新模式改画面。要不要改成场窗口，由用户逐段决定。
- 同一场里标了「连续」的相邻段，首尾正好差 1 帧。其余段之间硬切，只要求世界状态（位置、朝向、道具）连续。
- 剪辑包、字幕、同步表、清单都直接读 cue 表，不渲第 0 帧收日志。
- cue 的形状（`engine/段/段定义.ts`）：
  - 台词 `{ 帧, 台词, 接上段?, 帧数? }`：帧是开口落在段内第几帧（可带小数），文件头 = 帧 − 开口秒 × fps，开口秒和字幕位置写在 `作品/应力转动/台词.toml` 那一条。从文件头放到文件完多 1 帧、段尾或同一句的下一截为止（照旧 `台词轨.tsx`），`帧数` 只给不按这个算的（6-3-2 压路机）。
  - 一句台词跨段或在段里断成两截时，后半截写 `接上段: true`，帧是这一截起放的整帧；文件头照本段前半截或清单上一段的开口推。它不算开口、不出字幕，`anim check` 要求前面真有开口。
  - 音效、配乐 `{ 帧, 资产, 名, 帧数, 档?, 入点秒?, 速率?, 循环?, 增益?, 淡出? }`，字段同旧 `音效清单.ts` 的 SfxClipLog：帧是起放的整帧，入点秒是从文件第几秒放，`增益` 是常数或逐帧数组，常数可带 `淡出`（最后 淡出 帧乘 (帧数 − 第几帧) ÷ 淡出，线性往下收）。配乐 = 资产 id 以 `配乐/` 开头。
  - 迁移时照基线 `_表/声音清单/` 逐条转写，`node pipeline/适配器/旧项目/声音对照.ts` 现算台词落点、字幕表、SRT、音效清单、同步表，和基线逐条比。
- 叠层迁移期间仍单独渲成透明层、合成时叠上，保证像素和旧版一致。改成直接画进段算画面改动，等用户点名。

## 光照环境（新段用）

- 环境描述 `engine/light/环境.ts`（纯数据，`定义环境` 加载时就查）：
  - 维度：`engine/light/维度.ts` 的原版三个和暮色森林；别的模组维度在 `库/维度/<模组>.ts` 另写，不往这个文件里堆。
  - 时刻：游戏时间（0 日出、6000 正午，照 1.20.1 `DimensionType.timeOfDay`）算太阳、月亮和天光；或者写美术光向 `太阳`，二选一。时间固定的维度（暮色森林 13000）只能写 `太阳`。
  - 天气：雨、雷 0～1。现在只调灯（直射 × (1 − 雨)，天光照 `getSkyDarken`）；雨丝、天色变灰、云变厚没做。
  - 灯光档位：`灯光档位.ts`，数照 `光照配比.ts`；`暮色`、`主世界` 就是现用的两套。表里没有的灯（新作品、新光影）写 `灯光: { 配比: { 直射, 天光, 环境光, 自发光 } }`，不往表里加档（加档会让用到 `<环境>` 的段全部过期）。
  - 雾、高度雾、云（Photon、原版方块云）、主光投影。
- `<环境 描述 画法 镜头 离地? 穹顶中心? 帧?>`（`engine/light/环境组件.tsx`）：直接放在 ThreeCanvas 下面，照描述摆天、灯、云、雾。
  - 画法按需引：每种一个模块 `engine/light/画法/<名>.tsx`（现有 `主世界`、`暮色`），`export default 定义画法('<名>', 组件)`；段 `import 主世界 from '@engine/light/画法/主世界.tsx'` 传给 `画法`，名字要和描述的 `画法` 一样（描述在段里换画法就传数组）。
  - 没有总表：加画法（下界、末地、模组维度）只加一个模块，已有段的依赖闭包不变、指纹不变。各画法共用的部件（投影主光、雾、原版云、接口）在 `环境部件.tsx`，改它会让所有用 `<环境>` 的段过期。模组专有的画法放 `库/画法/<名>.tsx`。
  - 主世界画法按时刻算太阳时，加原版的月亮和星星（`星月.tsx`，算法在纯模块 `天球.ts`：照 1.20.1 `LevelRenderer` 重写的撒星、月相取 `moon_phases.png` 的格、日月星随天角转，月亮不透明度和星星亮度都乘 1 − 雨）。写美术光向 `太阳` 时不画星月。
- 预设：
  - `暮色环境`（`engine/light/环境预设.ts`）= `TwilightLighting`；
  - `主世界环境`（`作品/应力转动/地点/主世界环境.ts`）= `FlightSky` + `FlightFog`；
  - 两个都在 `核对-环境` 里和现有组件逐像素比过。
- 随帧变：`定义环境轨({ 基础, 关键帧: [{ 帧, 时刻?, 雨?, 雷?, 缓动? }] })`，各项各自插值，头尾之外保持；延时摄影用 `按游戏流速` 算时刻。
- 段在 段.ts 之外声明环境：写在 `段/<段键>/环境.ts`（几段共用写在 `场/<场键>/环境.ts`），`export default` 一份描述或环境轨，画面里 `<环境 描述={…} 画法={…} 镜头={…} />`。场窗口段要按场内帧取，就传 `帧`。
  - `anim check` 的「加载」把这些 环境.ts 当纯模块执行，再查（`pipeline/检查/环境声明.ts`）：用 `定义环境`、`定义环境轨` 重核（时刻、天气、雾、关键帧顺序；没套 `定义…` 的字面量也查到）、灯光档位名在表里、画法有模块且 `定义画法` 的名和文件名一样、关键帧帧号小于 段.ts 的帧数（场目录的不查帧号）。
- 已有段的 `TwilightLighting`、`FlightSky` 不换：画面一样也会让段过期，换不换由用户定。

## 配音（`anim voice`）

- 唯一人写的源是作品的 `台词.toml`：每句的 id、角色、文本，可选 念（交给 TTS、对口型的字，和字幕不同时写）、语言、语气、`["台词"."合成"]`（这句的后端、只交给 TTS 的 念、参考、逐字稿、种子、语气参考、强度、不裁、后端的 参数）、`["台词"."口型手修"]`（对齐不准时手标的字的起止，绑成品 sha）；`["配音"]` 定默认后端、候选种子、成品响度（−18 LUFS、峰值 −1.5 dBFS）、新配音的许可，`["音色"."<角色>"]` 定克隆参考（音色资产 id）和逐字稿。配音、开口、文本哈希、成品sha、口型 这几项由工具写回（只改那一行；改完重新解析核对，认不出的写法报错不写）。
- 文本哈希 是念的字（念，没写就是文本）的哈希：只改字幕时写 念 = 原来的字，配音不算过期；念的字改了 `anim check` 报配音过期。
- 流程：`gen`（按句的后端分批，一批只起一次模型）出候选到 `<数据根>/run/草稿/配音/<作品>/<id>/<后端>-种子<n>.wav`，旁边的 `.json` 记后端、种子、参考、参数 → 自动复核（见下）→ 人试听挑一个 → `use` 定稿：裁静音（−45 dB，头留 0.03 秒、尾留 0.15 秒）、拉响度、48 kHz 单声道，原件 `配音/原件/<id>` 和成品 `配音/<id>` 登记（资产表里没有就补进 `<作品根>/资产表/配音.toml`，可见性 私有），写回 `台词.toml`，出句模块。
- 句模块 `作品/<名>/台词/<id>.ts`：一句一个，工具生成、进 Git，别手改（头上的校验码对数据，`anim check` 认得出手改）。里面是念、开口、有声长、时长、文件秒数、字的起止、嘴型关键帧，纯数据。新段 import 自己用的几句和 `asset:<配音>`，用 `engine/audio/台词句轨.tsx` 放声音、`库/角色/句口型.ts` 取嘴和点头；加一句、改一句只让用到它的段过期。放法和嘴原样复用 `做台词轨`、`mouthAt`、`withTalkNod`，同一句新旧两条路一样（`pipeline/配音/句口型.test.ts` 逐帧比嘴和点头，`台词句轨.test.ts` 比交给 `做台词轨` 的表和 cue）；`核对-台词句轨` 拿两句真渲过，声音落点和 cue 对上）。
- 第 6、7 章的旧段还用 `作品/应力转动/配音/台词轨.tsx`、`口型.ts`，从旧项目的两份整表（资产 `数据/配音/台词表`、`口型`）取数据；改走句模块会改它们的指纹，等用户定。这些句子 `use` 换成品要加 `--不管旧表`（旧段不跟着变）。32 个句模块是 `anim voice lip --从旧表` 从旧表生成的，`anim voice check --对旧表` 逐项核对。
- 口型：字的起止取 口型手修（绑的成品就是现在这版）> 同版成品的现有句模块 > 对齐器（Qwen3-ForcedAligner，配置 `aligner`，过放行闸），再按 Rhubarb 的规则由拼音拆音素、出 A～F、X 嘴型（`py/anim_py/配音/口型.py`）。pypinyin 钉 0.55.0，换版本可能改嘴；`anim voice check` 按字重算嘴逐项比。
- TTS 后端可插拔（`py/anim_py/配音/后端/`，`anim voice backends` 列出）：本机的 `firered-本机`（默认，FireRedTTS3，cfg 1.2、30 步，fp32 约 16 GB）、`indextts2-本机`、`gpt-sovits`（api_v2 服务）、`openai-speech`（OpenAI 兼容服务）过渲染闸；云端的 `firered-魔搭` 要 `--允许云端`，`indextts2-runninghub` 按次收费要 `--允许付费`。`--dry-run` 只打请求。加后端：写一个 `后端` 子类，登记进 `后端表`。
- 复核（`py/anim_py/配音/复核.py`，`anim voice review <id…>` 单独重跑，`gen` 出完候选自动跑，`--不复核` 不跑）：复核项可插拔，同后端的做法。本机免费、默认跑的：`音色`（Resemblyzer 和角色参考音频的相似度）、`起伏`（Praat 基频的音高跨度和标准差、RMS 响度跨度，棒读的跨度小）；付费的 `听写`（Qwen3-ASR + Gemini 听写比字）、`语气`（Gemini 比着打分）只有接口和 `--dry-run`，没接，启用要用户定。结果并进候选旁 `.json` 的 `复核` 字段，一句的全部候选连同现成品（当对照）汇成 `<候选目录>/复核.md`。量法和比字规则照旧项目 `语气.py`、`听写.py`。音色低于旧项目挑候选的下限 0.85 只记提示不挡：一两秒的短句普遍偏低（7-黄叛-受死 的现成品 0.836）。复核过放行闸。
- 外部模型仓库各用自己的 venv，`anim_py` 只用子进程调（`_firered本机.py` 这类跑脚本不 import anim_py）；`anim_py.配音` 本身跑在项目 venv（`uv run --frozen --project <代码根>`，版本按 `uv.lock`，pypinyin 是项目依赖）；复核要 torch，放在 `pyproject.toml` 的 `voice-review` 组，只有复核时带 `--group voice-review`。

## 规矩

- 全片默认值写在 `作品/应力转动/默认.ts` 或对应的共用模块，登记在 `作品/应力转动/规矩.toml`（默认值、级别、原话、针对、出处、落点、例外）。
- 级别：带用户原话、并且原话说的就是这一类情况的，才是「原话」级，算硬约束；其余是「参考」级。
- 段里要例外，写 `例外('规矩id', 值, {段, 原因})`。`anim check` 双向核对：代码里的例外都在表里登记过，表里的例外代码里都找得到；默认值的落点符号必须存在。例外只写在 `作品/应力转动/段/<段键>/` 或 `作品/应力转动/场/<场键>/` 里；搬家暂放在 `作品/应力转动/地点/<地点>/<旧目录>/` 的剧情编排拆回之前也可以写在那里（`迁移.md` 差异表 R2）。
- 落点写成 `<路径> [符号、符号…]`，路径从顶层目录写起；还在旧项目里的写 `旧:` 或 `待迁移:` 开头，`anim check` 记作待迁移、不算违规，搬完改成新路径。
- 出处里的 `M/<名>.md` 指 agent-context 的记忆，根是配置 `记忆`（`ANIM_MEMORY`）。`anim check` 查文件在不在、`:行号` 有没有超出；记忆仓库不在本机就跳过。记忆删了、改名或合并了，出处跟着改。
- Agent 不得把规矩推广到全片，只能在预览的 `00-说明.md` 里提议，用户点头后再登记。

## 指纹、过期和验收

- 每段的指纹由这些算出：`画面.tsx`、`段.ts`、`设置.ts`、作品外壳的默克尔根（`pipeline/指纹/默克尔.ts`：每个模块去掉注释、类型、格式后，把 import 说明符换成目标的哈希再哈希；npm 包记 lockfile 版本，`asset:` 记 sha），声明的地形包版本、渲染设置、lockfile 里 remotion 和 three 等的版本、webpack 改写和 ogg 解码的规范化文本、影响输出的 tsconfig 选项、执行平台。文件路径不进指纹：只改注释、挪文件、换 import 写法不让段过期。
- 过期按段算：改了一个文件，只有依赖闭包里含它的段过期（画面、段.ts、设置.ts、外壳四个根的闭包）。外壳和 `设置.ts` 的闭包每段都有（`作品/<名>/index.ts`、`注册.tsx`、`engine/段/注册工厂.tsx`、`设置.ts`、`设置值.ts`、`engine/core/渲染设置.ts`），改它们才是全片过期；改 `engine/core/数学.ts` 只让 import 了它的段过期。
- 新增文件不让旧段过期，共用代码只增不改：要新写法就新加文件，不改已有段在用的共用文件。模块哈希按整个文件算，在用的文件哪怕只加一个导出，闭包里有它的段也全部过期、要重渲重验。测试和金样（`*.test.ts`、`金样/`）不在任何段的闭包里，随便加。
- `anim stale` 列出过期的段、哪项输入变了、预计耗时，什么时候重渲由用户定。`anim film` 默认拒绝用过期母版，加 `--允许过期` 才用，并逐段写进 manifest。
- `anim stale --严格`：有过期段时退出码 1（默认总是 0）。
- 一批段一起算指纹（stale、render、verify、film）：一次 esbuild 打包建好全图（`建默克尔图`），再按段取闭包；缺字节、私有配乐按本段闭包判，结果和逐段单独算逐字相同（`pipeline/指纹/指纹.test.ts` 有等值测试）。
- 母版：整个工程只打包一次，逐段 `renderMedia`。格式是 CRF 1 + PCM 的 mkv，先写临时名再原子改名。渲染并发为 1。
- 打包用 Remotion 的 webpack 持久缓存。Remotion 拿整份配置的 md5 当缓存目录名，`pipeline/资产/缓存名.ts` 让资产锁、求解指纹不进这个名字（`assets add` 后不再冷打包）；`asset:` 每次编译按当时的锁改写、DefinePlugin 的值 webpack 自己跟踪，所以不会读到过期缓存（`缓存名.test.ts` 用真 webpack 验过）。
- still、render 分阶段计时：打包、开浏览器、读组合（getCompositions）、等闸、出帧、编码，记进运行记录的 `阶段` 字段和 `run/logs/阶段耗时.tsv`（`pipeline/运行记录/阶段.ts`）；`耗时.tsv` 的列不变。
- `anim verify`：指纹变了的段抽帧，和 `作品/应力转动/认可/<平台>/<段键>.toml` 记的那一版比；超过阈值就必须 `anim verify accept <段…> --理由 …`（一次可认可多段、共用一个理由，但要逐段点名：一个场键、章号对上多段就拒；每段都签好才一起写），这一步会改 Git 里的文件。画面每一次变化都会出现在 diff 里，后面的提交把它悄悄改回去也会被拦住。
  - 只有真要解码（和认可版、基线比，或 accept 签名）才过放行闸，一条命令只过一次；指纹和认可版一样的段不解码、不等闸（用户 10-30 授权）。
  - 认可记录存认可那版的指纹、理由、提交，和抽样帧（首帧、每 24 帧、末帧）的原始像素 sha256、16×9 块均值，以及音频 PCM 的 sha256、积分响度、起音落点。
  - 哈希不一样时，认可那版的母版还在缓存里就逐像素数「差 > 16/255 的像素占比」，不在就只比块均值；声音比响度和起音落点，不要求逐样本相同（用户 10-21：成片不要差太多就行）。超了出 旧|新|差 并排图给人看。阈值在 `verify/阈值.toml`。
  - 迁移期间 `anim verify --对基线` 直接和数据根 `基线/<旧段号>/` 的旧项目基线比。
- 测速：`anim bench <段> --帧 <起>-<止>` 照母版参数渲一段帧，分阶段计时，不写缓存。Remotion 版本回归、各项提速的数见 `docs/渲染性能.md`。
- 单段门：帧数和清单一致；段音频减去按 cue 重混的结果，残差低于阈值；近白像素占比不超标。整片门：总帧数等于各段之和；接缝不悄悄丢帧；量响度和真峰值；抽帧拼总览放进预览。

## 数据和资产

- 资产只登记 id，字节放 Git 外的数据根：

```
mc-anim-data/          环境变量 ANIM_DATA，各 worktree 共用
├─ store/<sha前2位>/<sha256>   内容寻址，只增不改：网格、碎块、配音原件和成品、截图、提取产物
├─ 私有/<sha前2位>/<sha256>    不公开的：用户录音、九胡配音和音色、配乐、取材账号皮肤、小说原文
├─ terrain/<包名>/<版本>/      区段包，版本目录只写不改
├─ cache/{母版,叠层,对齐,画面截}/<键>/<指纹>.*
├─ cache/去重账.json           anim cache gc 克隆去重的账本（文件 → sha、克隆自谁）
├─ cache/求解/<键>.json        模块初始化时的重计算（航线求解），键含求解代码的闭包指纹（engine/core/求解缓存.ts），删了就现算
├─ 基线/<段键>/                迁移验收用的旧版基准帧和音频
├─ 交付/<UTC 月日-时分>-第6-7章/  成片、srt、拼接表、同步表、剪辑包、manifest.json
├─ archive/                    备选版本的对照 mp4
├─ cache/私有配乐/<id>          按 cue 现取的私有配乐：私有/ 里那份的拷贝，缺了是静音 wav（pipeline/资产/私有配乐.ts）
└─ run/{logs/{耗时.tsv,阶段耗时.tsv}, 运行记录/, locks/, queue/, public/}
   └─ public/                  Remotion 的 public 目录，只放三个链接：terrain → <数据根>/terrain、求解 → <数据根>/cache/求解、私有配乐 → <数据根>/cache/私有配乐
```

- 缓存回收 `anim cache gc`（`pipeline/缓存/`）：默认只打印每类删多少、留多少、为什么留，`--执行` 才删，Windows 也能跑。
  - 母版、叠层只删旧指纹的媒体文件，`.指纹.json` 留着（stale 拿它说明哪项变了）。保留：各渲染级别的当前指纹、认可记录那版（verify 逐像素比要它，没了只能比块均值）、`交付/` 下 manifest 引用的（edit-package 要读）、每段每级别最近一份（按 `.指纹.json` 的时间排，和 `film --允许过期` 取的同一份；迁移时硬链接过来的母版文件本身是旧时间）、近 2 天渲的（别的 worktree 的当前指纹这边算不出）。当前指纹算不出、指纹里记了缺字节、代码里没有的作品，整个目录留着。删大小按 inode 算：迁移时有过硬链接，名字全删了才腾出空间。
  - 留下的内容相同的（同大小再比 sha256）在 Mac 上用 `cp -c` 克隆成 APFS 共享块，`cache/去重账.json` 记 sha 和克隆自谁。
  - `run/草稿/` 超过 14 天没动的删；各检出的 `node_modules/.cache/webpack/` 里旧 Remotion 版本的整个删，同版本每个环境留最近用的「作品数」份，其余 3 天没用的删；渲染崩掉留下的 `.渲染中-`、`.写入中-` 临时文件超过 1 天删。`run/`、`cache/` 下不认识的条目只报告。`--只 母版,叠层` 只做其中几类（逗号分开）。
- `run/public/` 由 `pipeline/渲/public目录.ts` 建（anim render 和 studio 共用；Windows 用 junction）。不把数据根直接当 public：Remotion 打包时把 public 整个拷进包，链接只转发不拷。渲染代码经 `engine/core/数据源.ts` 按相对 public 的路径取（`terrain/<包>/<版本>/…`、`求解/<键>.json`、`私有配乐/<id>`）。

- 资产表 `assets/registry/*.toml` 由人写，`assets/资产锁.json` 由工具生成。字段和可见性见 `决策/0002-资产标准.md`。只有一部作品用的可以登记在 `<作品根>/资产表/`、锁在 `<作品根>/资产锁.json`，用时和共用的并起来（`决策/0004-多作品.md`「作品资产表」）。
- 取材产物（`pipeline/取材/`）：`anim extract` 按配方导出，和锁比 sha（PNG 再比像素 sha，Pillow、zlib 换版本字节会变、像素不变）；`--登记` 把锁里没有的产物追加进资产表、入库、写锁，来源 `提取:<配方>@<jar sha12>`，许可按 `jars.toml` 每个 jar 的结构化许可（代码、资源、声音、结构、模型）继承，没定的（`LicenseRef-待核-*`）留待定；`--许可 [--写]` 只补资产表里待定的。配方步骤可以用 `{产物清单}` 按锁反推要导什么（原版和模组音效一条配方 722 件；锁里还没有的新件用 `--新 <id>` 加进清单），用 `{产物来源}` 写每件产物取自哪个 jar，`--登记` 按件记来源、算许可。
- 音频入库（`assets add`、`extract --登记`）顺手量时长、采样峰值、积分响度，写进锁条目的可选字段 `时长`、`峰值`、`响度`（`pipeline/资产/音频量.ts`）；指纹只认 sha256，这几个字段不让段过期。早先入库、锁里没量过（没有 `时长`）的，`anim assets measure` 补（共用锁和各作品的锁，只加缺的字段；量过仍缺峰值的静音、缺响度的太短条目不再重量；字节不在本机的跳过并报件数；`--检查` 只报，有能补的退出码 1；有量不出的也退出码 1）。入库、`assets measure`、`anim cues` 现量用的是同一个函数 `量音频数`，锁里的数和 `放()` 现量的逐位一样。
- 代码里写 `import x from 'asset:贴图/实体/九胡'`，解析插件按资产锁换成 `store/` 里的文件。打包规则和旧项目一样：png 内联、同步解码，ogg 解成 wav。资产锁里查不到的 id 打包直接失败，报错里写该跑哪条命令。
- 群系色表、方块表现在用手写的（`数据/场景/关键帧/`，从 jar 推算）；`anim gamedata` 能从开着的游戏直接导同结构的表并和手写表核对，迁移期只出报告，新章节要用就登记成新资产（`游戏导表.md`）。
- 区段包、网格 .bin 在运行时用 `dataUrl(id)` 取。段要声明用到哪些地形包；渲染时请求了没声明的包就报错，保证指纹不漏依赖。
- 私有内容缺失时：配乐换成静音，并在运行记录里报出来；配音缺一句就直接失败，不静默替换。按 cue 放的私有配乐不打进包，渲染代码用 `engine/audio/私有配乐.ts` 按 id 现取，段指纹记它有字节（sha）还是缺了换静音。
- 随仓库发字节：写了 `<作品根>/随仓库.toml` 的作品，这些段渲片要用的非私有资产放 `<作品根>/字节/`（`anim assets vendor` 现算重写，`anim check` 核对），渲染前补进数据根 `store/`，公开仓库 clone 下来就能渲（`决策/0005-随仓库发字节.md`）。
- 搬来的代码里还直接 import 私有资产的（九胡配音、配乐、结构罗盘截图、巨人的取材账号皮肤），import 块顶上标 `// 待迁移（私有资产）：原因`，`anim check` 记成待迁移；改走 cue 或定了降级办法后删掉标记。数据根里没有的字节（私有的，或公开仓库没随仓库发的），打包时换占位（`pipeline/资产/缺字节.ts`，接在 webpack改写 外面）：闭包碰到它们的段入口（画面、叠层）整个换成一渲就抛错的组件，别处的 `asset:<id>` 换成一取值就抛错的模块；段指纹记一项 `缺字节`。

## 基岩实体和动画

新做的 GeckoLib / YSM / Blockbench 生物直接播 mod 里的原文件，不手抄关键帧（步骤见 `新生物.md`）。已有的角色（`库/角色/魔法酒狐.tsx` 等）照旧，迁移期不改。
- `engine/anim/插值.ts`、`Molang.ts`：插值（linear、step、catmullrom、bezier、GeckoLib 4 缓动名，公式照 GeckoLib 4.8.4 源码）和 Molang 子集（解析一次，常量烘成数；除以 0 得 0，同 mocha；精度 float / double 可选）。
- `engine/anim/基岩动画.ts`：`.animation.json` 播放器，纯模块。两种口径（默认 `'通用'`）：`'TLM'` 照 TLM 1.5.3 的 GeckoLib 3 分支反汇编（关键帧 pre/post、catmull 取点、hold 当 once、parallel_ 控制器转角叠加、不读 blend_weight），`'通用'` 照 Bedrock / GeckoLib 4 文档（hold 停在最后一帧、权重、start_delay/loop_delay）。Molang TLM 按 float、通用按 double。多层混合 `混合层`：覆盖或叠加，带权重。
- `engine/anim/动画控制器.ts`：基岩版 `animation_controllers` 状态机（固定步长从 0 推、记历史）和 GeckoLib 控制器（时刻表 + transitionLength 过渡），出一张骨骼表，在 `基岩实体` 里当一层。
- `engine/model/实体材质.ts`：受伤变红、原版实体光照、发光、半透明，按选项共用材质；缓存按最近使用丢（上限 512），组件卸载时放手，贴图没人用了就释放材质。`基岩实体.tsx`：几何 + 实体材质 + 多层动画；发光骨骼拆成两份画。
- `库/生物/定义生物.ts`：声明几何、多层贴图（`engine/model/贴图合成.ts` 叠成一张）、外观变体、默认动画层，得到组件。
- 和手抄版对照：`作品/把回忆拼好给你/核对/基岩动画/`（`对照.test.ts` 逐骨骼 1e-6（尾巴 1e-3 度，float），`核对-基岩动画` 左右两张画布同机位）。

## 环境和跨平台

- 环境模块只有一份，在 `pipeline/环境/`，用 TS 写。取值顺序：环境变量 > `anim.local.toml`（不进 Git）> 默认值。
- 不开 shell：npm scripts 只留 `"anim"` 一条，子进程一律用数组参数，Windows 的 `.cmd` 交给 cross-spawn。
- 锁：O_EXCL 建锁文件，内容写 pid 和主机名；持有者死了就回收；Windows 上删锁遇到 EPERM/EBUSY 退避重试；按票排队，不插队。协议和旧项目 `参考模型库/工具/公共/锁.py` 兼容，迁移期间 `ANIM_LOCK_DIR` 指向旧项目的 `.资源闸/`。
- 资源闸（`pipeline/闸/闸.ts`，用户 10-04、10-05 定）：渲染闸拿「渲染」锁、只等内存够；放行闸等离上次放行满 60 秒、1 分钟负载低于核数 × 0.8、内存够，记下放行时间就放锁。两条规则的测试用假时钟、假读数（`闸.test.ts`）。
- 报错：预期内的（用法错、选不出作品、仓库代码里 throw 的 Error、esbuild 构建失败）只打信息，`--调试` 或 `ANIM_DEBUG=1` 才打调用栈；调用栈总记进运行记录（`pipeline/cli/路由.ts`）。
- 只在 Mac 上有的做成可选适配器：videotoolbox 编码、剪映读回解密、image-flow 录音。缺了只影响这一项。
- 统一 UTF-8；Git 设 `core.quotepath false`、`core.longpaths true`；时间一律 UTC。
- 工具链：Node 24、npm、TS strict、vitest；Python 3.11+、uv、pytest；Java 17、Gradle wrapper。Remotion 4.0.537、three 0.186.1、react 19.3.0、esbuild 0.28.1 锁死，旧项目退役前不再升级（Remotion 用户 10-22 定从 4.0.530 升上来；它自带的 Chromium 157 比 4.0.530 的 149 慢，见 `docs/渲染性能.md`）。
