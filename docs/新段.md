# 新段怎么写（段框架）

新章节、新作品的段用 `engine/段/` 的段框架：段的窗口从场时间线上取，声音每个只写一次，段键只出现在目录名和 `清单.ts` 里。老段（应力转动第 6、7 章，把回忆拼好给你的 42 段）照旧，不迁（迁了画面不变也会让它们全部过期重渲，要不要迁由用户定）。

示范：`作品/把回忆拼好给你/核对/段框架示范/`（3 秒，一发烟花，三声音效加一截私有配乐）和接在它后面的 `核对/段框架示范续/`（1.5 秒）。切点前远处那一发是跨段的场声音，两段共用 `段框架示范/时间线.ts`。

## 一段由哪几个文件组成

```
作品/<作品>/场/<场键>/时间线.ts     本场的事件表：export default 定义场时间线({ 场, 事件 })。同一场各段共用
作品/<作品>/段/<段键>/段.ts          窗口段(线, { 起, 止, 声音表, 声音 })：窗口、声音 cue。纯模块
作品/<作品>/段/<段键>/画面.tsx       定义画面(段, 声音, 组件)：只画；声音自动放
作品/<作品>/段/<段键>/声音表.生成.ts   anim cues 生成：本段 cue 用到的声音的时长、峰值、响度，台词的配音和开口。进 Git，不手改
作品/<作品>/段/<段键>/声音地址.生成.ts anim cues 生成：资产 id → 打包后的地址（asset: import），带上声音表。进 Git，不手改
```

核对段没有场，事件表直接写在段目录里（示范就是这样）。几个核对段共用一条时间线的，放在头一段的目录里，别的核对段引它。`anim check` 只放行核对段之间引 `时间线.ts`。`anim new seg <段键> --场 <场键>` 一次建好这些文件、排进清单末尾；`anim new work <作品名>` 起一部新作品（`清单.ts`、`注册.tsx`、`index.ts` 和一个能渲的 `核对-起步`）。

## 写法

`段.ts`：

```ts
import { 窗口段 } from '@engine/段/窗口段.ts';
import 线 from '../../场/2-门口/时间线.ts';
import 声音表 from './声音表.生成.ts';

export default 窗口段(线, {
  起: '开场',
  止: '收尾',             // 或 { 帧数: 72 }
  声音表,
  声音: ({ 放, 说, 接着说, 事件 }) => [
    放('音效/把回忆拼好给你/entity.firework_rocket.launch', 事件.发射, -14),
    放('音效/把回忆拼好给你/entity.firework_rocket.twinkle', 事件.噼啪, { 峰值: -18, 名: '火星' }),
    放('配乐/把回忆拼好给你-抖音原声', 0, { 入点秒: 31.26, 增益: 0.5, 名: '原声', 淡出: 12 }),
    说('甲-1', 事件.开口),
  ],
});
```

- 帧数 = 止 − 起，fps、画幅默认 24 和 1280×720（`定义场时间线` 的 `fps`、`画幅` 可改），`场窗口` 是 [起, 止) 在场时间线上的帧。`事件` 是各事件落在本段第几帧（段内帧，可以是负的或超过段尾）。
- 事件的时刻：`{ 秒 }`、`{ 帧 }`，或 `{ 接: '别的事件', 加秒?, 加帧? }`；帧 = Math.round(秒 × fps)，只在这里取整一次。要歌网格（拍、小节、句）的，给 `定义场时间线` 传 `解析: 歌网格解析(网格, 句们)`（`engine/段/歌网格.ts`）。
- `窗口段` 的其余字段（`地形`、`连续`、`叠层`、`名`）同 `定义段`。

`放(资产, 帧, 目标)`：

- 目标是数字 = 本声音的采样峰值放到多少 dBFS（增益 = 10^((目标 − 文件峰值) ÷ 20)）；也可以 `{ 响度: LUFS }`（按积分响度）或 `{ 增益 }`（直接给倍数，逐帧数组也行），三选一，都不给 = 原样。
- 帧数不给 = 放到文件完或段尾（`ceil((时长 − 入点秒) × fps ÷ 速率)`）；`循环: true` 不给帧数就放到段尾。
- 其余选项 `名`（默认取 id 最后一截）、`入点秒`、`速率`、`淡出`、`档` 和老 cue 字段一样，见 `docs/架构.md`「段的形状」。
- 资产 id 以 `配乐/` 开头的记进配乐清单；锁里在私有库的配乐不打进包，按 id 现取（缺了是静音，同 `engine/audio/私有配乐.ts`）。

`说(台词, 帧)`：帧是开口落在段内第几帧，配音、开口秒照作品的 `台词.toml`；落点和老的 `台词轨.tsx` 一样（从文件头放到文件完多 1 帧、段尾或同一句的下一截）。一句话的后半截写 `接着说(台词, 帧)`（= 老写法的 `接上段: true`），跨段的由 anim cues 照清单上一段推出上段开口帧，写进本段声音表。

## 跨段的声音（场声音）

一个声音从上段起、下段接着放，写在场时间线上，只写一次：

```ts
export default 定义场时间线({
  场: '8-城门',
  事件: { 开场: { 在: { 秒: 0 } }, 远处炸: { 在: { 秒: 2.6 } }, 收: { 在: { 秒: 9 } } },
  声音: [
    { 资产: '音效/…/entity.firework_rocket.blast', 名: '远处一发', 在: '远处炸', 峰值: -16 },
    { 资产: '音效/…/weather.rain.1', 名: '雨', 在: '开场', 止: '收', 循环: true, 响度: -30, 淡出: 24 },
  ],
});
```

- 这条时间线上的每个 `窗口段` 都会自动带上落在自己窗口里的那一截，排在段自己的 cue 后面。规则见 `engine/段/场声音.ts`。
  - 后一段那截的 `入点秒` = 原入点 + 已经放过的帧数 × 速率 ÷ fps。逐帧算出的文件位置，和一口气放完一模一样（单测逐帧核对了切点前后）。
  - `淡出` 按整个声音的结尾算，落在哪段，就由那段的那截逐帧带上。
- 选项和 `放()` 一样：`峰值`、`响度`、`增益` 三选一，另有 `名`、`入点秒`、`速率`、`档`、`淡出`。`在`、`止` 可以写事件名，也可以写时刻（`{ 秒 }`、`{ 帧 }`、`{ 接 }`），`止` 还能写 `{ 帧数 }`。不给 `止` 就放到文件完；`循环` 必须给 `止`。
- 循环的声音：Remotion 的 `loop` 只在 [入点, 文件尾] 之间绕。所以一段要从文件中间接上时，会拆成两条：先放到文件尾，再从文件头循环。拆开的地方取整到帧，后一条比一口气放完早不到 1 帧，以后每一圈都差这么多。
- 不想要某个场声音的段（比如插进来的别处镜头），写 `窗口段(线, { …, 不放场声音: ['雨'] })`；写 `true` 就一个都不放。
- 名字在一条时间线里不能重名，默认取资产 id 的最后一截。
- 声音表：起点在窗口之后的场声音（或给了 `止`、在窗口之前就结束的）不查表，免得每段的表都记上全场的声音。其余的要先查表才知道放多长；这些就算没落进本段，也会留在本段的声音表里，地址表里不会有它。
- 老写法的 `声音/跨段音效.ts` 是手工版的同一回事，老段照旧用它。

`画面.tsx`：

```tsx
import { 定义画面, use段 } from '@engine/段/段画面.tsx';
import 段 from './段.ts';
import 声音 from './声音地址.生成.ts';

export default 定义画面(段, 声音, () => {
  const { 帧, 秒, 场帧, 事件, 段: 本段 } = use段(段);
  …
});
```

`定义画面` 包一层 `<段声音>`：照 `段.ts` 的 cue 放每一声（`@remotion/media` 的 Audio，台词按全片台词增益，音效、配乐按 cue 增益和淡出），同时记进音效清单、配乐清单、台词清单，和老的 `音效轨`、`台词轨` 一样。不想自动放的给 `{ 声音: false }`，自己放 `<段声音 />`。

## 和老写法对照（以 `作品/把回忆拼好给你/段/2-烟花/` 为例）

| | 老写法 | 段框架 |
|---|---|---|
| 一个声音写几次 | 4 处：`场/2-门口/门口之夜声音.ts` 的 id 表和手量的 `文件秒`、`门口之夜音效轨.tsx` 的 `asset:` import 和 `地址` 表 | 1 处：`段.ts` 的 `放(id, 帧, 目标)`；时长、峰值、地址由 anim cues 生成 |
| 增益 | 手写倍数（`声音增益` 表） | 写目标峰值 dBFS 或 LUFS，倍数现算 |
| 段键出现在 | 目录名、清单、`段.ts` 的 `段时钟('2-烟花')`、`画面.tsx` 的 `段时钟('2-烟花')` | 目录名、清单 |
| 帧数、窗口 | `分镜.ts` 的 `段时钟(段键)` 按段键查表 | `窗口段(线, { 起, 止 })` 从场时间线现算 |
| fps、画幅 | 每段 `段.ts` 写一遍 `fps`、`宽`、`高` | 场时间线给默认 |
| 放声音 | 画面里挂 `<门口之夜音效轨 段={段} />`、`<台词轨 …/>`，各场一份 | `定义画面` 自动放，不用写 |
| 画面取事件帧 | `段时钟(段键).场窗口.起帧` 自己减 | `use段(段).事件.炸开` 直接是段内帧 |
| 新作品 | 照抄 `清单.ts` 尾部、`注册.tsx`、`index.ts` | `anim new work`；`清单.ts` 尾部换成 `清单工具(清单)` |

老写法里 `分镜.ts` 的 `解时刻`、`解事件`、`排段` 抽成了 `engine/段/时间线.ts`（再加 `歌网格.ts`），`pipeline/段框架/等值.test.ts` 逐拍、逐小节、逐句核对两边算的一样。`分镜.ts` 本身没动。

## anim cues 和生成的两份文件

```
anim cues [<段键、段名、编号或章…>]     段.ts 的声音改了就跑：重算本段声音表、地址表，变了才写
anim cues --检查                       只核对不写；对不上退出码 1（anim check 的「加载」也查这一项）
```

- 数从哪来：资产锁条目里有 `时长`、`峰值`、`响度` 就用锁的（取材登记合进来以后 `assets add` 入库时量）；没有就沿用盘上声音表里的（每件记了量的是哪份字节，锁里 sha256 的前 12 位，对得上才沿用：换台机器重跑不重量，不会因为 ffmpeg 版本不同改了生成的文件）；再没有才用 ffmpeg 现量（`ebur128=peak=sample`、ffprobe 时长），按 sha 缓存在 `<数据根>/cache/音频数/`。量要字节在数据根里。`anim check` 不量：锁、盘上表、缓存都没有（新加的声音，或同一个 id 换了字节，比如重配的配音）就报「跑 anim cues」。
- 第一次生成时 `段.ts` 要 import 的声音表还不存在：先写一张空表，在「收集」模式下执行一遍 `段.ts`（`放()` 遇到表里没有的 id 记下来、给一帧占位），量完写表，再正常执行一遍拿最终 cue。`anim new seg` 建段时就写好空表，新段立刻能渲。
- 为什么按段分开生成两份，不做一张全作品的大表：段指纹按闭包里每个模块的内容算，一张大表加一个声音，所有段都过期；按段分开，一段只依赖自己用的那几个声音。为什么分成两份：`段.ts` 要进 pipeline 的纯模块闭包（不许有 `asset:`），只引纯数的声音表；`asset:` import 放在只给 `画面.tsx` 用的地址表里。
- 哪些段归 anim cues 管：默认导出是 `窗口段` 做的（`段.ts` 直接引 `@engine/段/窗口段.ts` 或目录里已有声音表的直接认，经场里自己写的工厂间接用的，在收集模式下执行一遍认）。
- `anim render`、`still`、`studio` 开跑前自动跑 cues（`pipeline/段框架/自动.ts`）。生成的两份文件和 cue 对不上，就重新生成；变了才写，写了哪份会打出来。
  - 只看一眼就认得出的段：`段.ts` 直接引 `窗口段`，或者目录里已经有声音表（`anim new seg` 建段时就写了空表）。不执行老段，所以开跑前不会变慢。
  - 所选的段生成失败（缺字节、台词没配音这类），就停下不渲。没选的段失败，只打一行提醒。Studio 照样起来，那段在 Studio 里报错。
  - 为什么自动生成，而不是报错让人去跑：这两份文件完全由 `段.ts`、场时间线、资产锁、`台词.toml` 和字节算出来。人去跑也是同一条命令、同一个结果。只报错的话，Studio 起不来，每改一声都要多敲一条命令。生成的文件进 Git，`git diff` 看得见。`anim check` 照样核对（CI 和合并前不靠自动生成）。
  - 开着 Studio 时改了 `段.ts` 的声音，不会自动重新生成，要手跑 `anim cues`。`anim film`、`verify` 不自动跑。

## 老场里加新段（接老段）

应力转动第 6、7 章的场，没有 `定义场时间线` 做的场时间线：老段是 `定义段` 直接写的帧数，有的场另有自己的老时间线文件（如 `地点/古城4x/7-1/时间线.ts`）。这些老时间线的闭包里有 `asset:`，新段的纯模块引不了。

接法是不改老段，在 `场/<场键>/时间线.ts` 里用 `接老段`（`engine/段/老段接续.ts`），把老段按清单顺序首尾相接摆上一条场时间线：

```ts
import { 接老段 } from '@engine/段/老段接续.ts';

export default 接老段({
  场: '7-墙头追逐',
  老段: [
    { 键: '7-墙头', 帧数: 30 },
    { 键: '7-上塔', 帧数: 28 },
    { 键: '7-音波', 帧数: 89 },
  ],
  事件: {
    开始: { 在: { 接: '7-音波.止' }, 依据: '暂定：接在本场最后一个老段后面' },
    结束: { 在: { 接: '开始', 加秒: 3 }, 依据: '暂定' },
  },
});
```

- 每个老段有两个事件：`<段键>.起`、`<段键>.止`。新段（`窗口段`）从这条线上取窗口；`声音` 写的场声音只放进新段，老段照旧。
- 老段的帧数是抄成数写进来的，不 import 老段的 `段.ts`，因为场不许引段（分层规则）。`anim check` 的「加载」会把抄的帧数、场、fps、画幅逐个和老段的 `段.ts` 对一遍（`pipeline/段框架/核对.ts` 的 `查老段接续`）。
- 有 `场窗口` 的老段，会带上 `起帧`。老时间线里段与段之间跳过一截的（如 7-1-6 的 `skipTo`），要接得准就手给那一段写 `起帧`。
- `anim new seg <段键> --场 <老场>`：这场还没有 `时间线.ts`、清单里又有这场的老段时，自动生成上面这样的文件。新段的 `--起`、`--止` 事件接在最后一个老段后面，先给 3 秒。在应力转动的 `7-墙头追逐` 试建过一次，`anim cues`、`anim check` 都过了，试完已删。
- 新场（比如第 8 章）照常用 `定义场时间线`。要接上一场的时间轴，就自己写事件。

## 检查

- `段.ts` 的闭包是纯的（`engine/段/` 的 `时间线`、`歌网格`、`声音助手`、`窗口段`、`场声音`、`老段接续`、`清单工具` 登记成纯模块，`pipeline/检查/上下文.ts`）。
- `anim check` 的「加载」对每个段框架的段跑一遍 `anim cues --检查` 的核对。
- 台词、清单、资产规则照旧适用（台词 cue 照样要在 `台词.toml` 登记、每句恰好开口一次）。

## 还没有的

- 循环又带入点秒的 cue（同老写法，不支持）。
- `use段()` 的 `帧` 是 `useCurrentFrame()`：在画面里再套 `Sequence` 时，里面拿到的是 Sequence 内的帧。
