# 新段怎么写（段框架）

新章节、新作品的段用 `engine/段/` 的段框架：段的窗口从场时间线上取，声音每个只写一次，段键只出现在目录名和 `清单.ts` 里。老段（应力转动第 6、7 章，把回忆拼好给你的 42 段）照旧，不迁（迁了画面不变也会让它们全部过期重渲，要不要迁由用户定）。

示范：`作品/把回忆拼好给你/核对/段框架示范/`（3 秒，一发烟花，三声音效加一截私有配乐）和接在它后面的 `核对/段框架示范续/`（1.5 秒）。切点前远处那一发是跨段的场声音，两段共用 `段框架示范/时间线.ts`。

## 一段由哪几个文件组成

```
作品/<作品>/场/<场键>/时间线.ts     本场的事件表：export default defineSceneTimeline({ 场, 事件 })。同一场各段共用
作品/<作品>/段/<段键>/段.ts          windowSeg(timeline, { 起, 止, soundTable, 声音 })：窗口、声音 cue。纯模块
作品/<作品>/段/<段键>/画面.tsx       definePicture(seg, soundUrl, 组件)：只画；声音自动放
作品/<作品>/段/<段键>/声音表.生成.ts   anim cues 生成：本段 cue 用到的声音的时长、峰值、响度，台词的配音和开口。进 Git，不手改
作品/<作品>/段/<段键>/声音地址.生成.ts anim cues 生成：资产 id → 打包后的地址（asset: import），带上声音表。进 Git，不手改
```

核对段没有场，事件表直接写在段目录里（示范就是这样）。几个核对段共用一条时间线的，放在头一段的目录里，别的核对段引它。`anim check` 只放行核对段之间引 `时间线.ts`。`anim new seg <段键> --scene <场键>` 一次建好这些文件、排进清单末尾；`anim new work <作品名>` 起一部新作品（`清单.ts`、`注册.tsx`、`index.ts`、一个能渲的 `核对-起步`，和 `段/说明.md`）。`段/说明.md` 别删：`注册.tsx` 的 `webpackContext('./段')` 要 `段/` 在，git 不记空目录，还没有正片段时就靠它；`anim check` 和打包前都查这件事。

## 写法

`段.ts`：

```ts
import { windowSeg } from '@engine/段/窗口段.ts';
import timeline from '../../场/2-门口/时间线.ts';
import soundTable from './声音表.生成.ts';

export default windowSeg(timeline, {
  起: 'opening',
  止: 'wrapUp',           // 或 { 长秒: 3 }
  soundTable,
  声音: ({ 放: play, 说: say, 事件: events }) => [
    play('音效/把回忆拼好给你/entity.firework_rocket.launch', events.launch, -14),
    play('音效/把回忆拼好给你/entity.firework_rocket.twinkle', events.crackle, { 峰值: -18, 名: '火星' }),
    play('配乐/把回忆拼好给你-抖音原声', 0, { 入点秒: 31.26, 增益: 0.5, 名: '原声', fadeOutSec: 0.5 }),
    say('甲-1', events.speak),
  ],
});
```

- 时间一律是秒（`docs/决策/0015-原生60帧.md`）。段长 = 止 − 起，起止对齐到 1/60 秒；画幅默认 1280×720（`defineSceneTimeline` 的 `aspect` 可改），`sceneWindow` 是 [startSec, endSec) 在场时间线上的秒。`事件` 是各事件落在本段第几秒（段内秒，可以是负的或超过段尾）。
- 事件的时刻：`{ 秒 }`、`{ 帧 }`（按 60 帧一秒），或 `{ after: '别的事件', addSec?, addFrames? }`；事件的秒不对齐到格，只有段窗口的起止对齐。要歌网格（拍、小节、句）的，给 `defineSceneTimeline` 传 `resolveTime: parseSongGrid(网格, 句表)`（`engine/段/歌网格.ts`）。
- `windowSeg` 的其余字段（`地形`、`continuous`、`叠层`、`名`）同 `defineSeg`。
- 声音回调拿到的 `放`、`说` 是中文键，解构时改成英文局部名（`{ 放: play, 说: say, continueLine, 事件: events }`）（示范就是这样），代码里不新增中文标识符（`docs/命名.md`）。

`放(资产, 秒, 目标)`：

- 目标是数字 = 本声音的采样峰值放到多少 dBFS（增益 = 10^((目标 − 文件峰值) ÷ 20)）；也可以 `{ 响度: LUFS }`（按积分响度）或 `{ 增益 }`（直接给倍数，也可以是逐格增益 `{ 每秒, 值 }`），三选一，都不给 = 原样。
- `长秒` 不给 = 放到文件完或段尾（`(时长 − 入点秒) ÷ 速率`，不取整）；`循环: true` 不给长秒就放到段尾。
- 截到段尾的声音下一段不会接着放。`anim check` 的「声音接缝」按成片顺序查：放到段尾、文件还剩 0.1 秒以上、末尾还有声，下一段又没从段头接着放，就报错（用户 11-19 听出亚波伦现身的雷声在段缝被一刀切掉）。要响过段尾的写成场声音（下一节）；故意截的（硬切到别处）写 `cutReason: '原因'`。同一检查也核场声音在段缝上文件位置不跳、整条增益不跳（`pipeline/段框架/声音接缝.ts`）。加检查前已有的、用户听过的记在作品根的 `声音接缝基线.tsv`，只许减少。
- 其余选项 `名`（默认取 id 最后一截）、`入点秒`、`速率`、`fadeOutSec`、`档` 和 cue 字段一样，见 `docs/架构.md`「段的形状」。
- `gainEnvelope`：随时间变的音量乘子，点的秒是段内秒，写法同下面「音量走势」的点（`{ sec, db, curve? }`）。例：`作品/亚波伦不放水/段/5-击败/段.ts` 段尾结算曲 0.06 秒等功率淡入、`6-结算舞/段.ts` 片尾 1.5 秒等功率淡出。
- 资产 id 以 `配乐/` 开头的记进配乐清单；锁里在私有库的配乐不打进包，按 id 现取（缺了是静音，同 `engine/audio/私有配乐.ts`）。

`说(台词, 秒)`：秒是开口落在段内第几秒，配音、开口秒照作品的 `台词.toml`；从文件头放到文件完多 1/24 秒、段尾或同一句的下一截。一句话的后半截写 `continueLine(台词, 秒)`（cue 上是 `接上段: true`），跨段的由 anim cues 照清单上一段推出上段开口秒，写进本段声音表。

`画面.tsx`：画面写成时间的函数（用户 11-06 定原生 60 帧，`docs/决策/0015-原生60帧.md`）。

```tsx
import { definePicture, useSeg } from '@engine/段/段画面.tsx';
import { SecondSequence, useCurrentSec } from '@engine/段/时间.tsx';
import seg from './段.ts';
import soundUrl from './声音地址.生成.ts';

const Spark: React.FC = () => {
  const sec = useCurrentSec(); // 从 SecondSequence 的起点算
  return <div style={{ opacity: Math.max(0, 1 - sec / 0.6) }} />;
};

export default definePicture(seg, soundUrl, () => {
  const { 秒: sec, 事件: events } = useSeg(seg); // 秒：段内第几秒（带小数）；事件：各事件的段内秒
  return (
    <>
      <Scene t={sec} />
      <SecondSequence startSec={events.crackle} 长秒={0.6}>
        <Spark />
      </SecondSequence>
    </>
  );
});
```

- 取时间只用 `useCurrentSec()`、`useSeg().秒`、`<SecondSequence>`（`engine/段/时间.tsx`），不直接调 `useCurrentFrame()`（`anim check` 的「时间」规则）。Composition 按成片帧率（60）跑，每个输出帧按自己的时刻现算。
- 老数据一格一个值的表（逐帧查表、编排里 24 帧一格的动作表）按秒读：连续量 `interpTable(表, 秒 × 每秒)`，硬切 `pickTier`（`engine/段/按时取值.ts`）。
- 核对段一秒一个视图：`useCheckView(views)`（`engine/段/核对画面.tsx`），见下面「核对段」。

## 核对段

只给自己和用户看的核对画面（看模型、机位、灯、特效），不进成片。骨架在 `engine/段/`：

- `核对段.ts`（纯模块，段.ts、视图.ts 用）：`checkSeg({ sec, aspect?, terrain? })` 写 段.ts（场 `核对`、默认 1280×720、没有声音）；`CheckShot`（眼 `eye`、看 `target`、`fov`、可选 `up`，场景坐标）；视图长短不一的用 `sequenceViews(views)` 排时间（例：`核对-史蒂夫关节`）。
- `核对画面.tsx`：`CheckCanvas`（three 画布，dpr 一律 `canvasDpr(1)`，`background` 是清屏色）、`CheckCamera`（透视机位，中性色调映射）、`ZUp`（场景 Z 朝上 → three Y 朝上）、`NeutralLights`、`CheckGround`、`CheckLabel`（左上角视图名和说明）、`checkGrey`（中性灰底和地面的颜色）、`useCheckView(views)`（一秒一个视图）。

`anim new seg 核对-<名>` 建 `视图.ts`（视图表：名、机位、说明）、`段.ts`（段长 = 视图数）、`画面.tsx`（灰底、灯、地面、一个方块、视图名），排进清单末尾，不建声音文件。要声音的核对段照段框架示范写窗口段。

画布一律用 `CheckCanvas`，别直接写 `ThreeCanvas`：不给 dpr 时 R3F 最多按 2 倍画，4K 档（截图 3 倍）就成了 2560 宽画完再放大，糊（11-16 查出 25 个核对画面这样，迁过来一起补上）。正交、`flat`、`shadows`、`key` 这些 ThreeCanvas 的参数照样能传。机位要放在别处算的（`placeCamera`、第一人称机位）照旧写自己的，只换画布。

## 跨段的声音（场声音）

一个声音从上段起、下段接着放，写在场时间线上，只写一次：

```ts
export default defineSceneTimeline({
  场: '8-城门',
  事件: { opening: { 在: { 秒: 0 } }, distantBurst: { 在: { 秒: 2.6 } }, wrapUp: { 在: { 秒: 9 } } },
  声音: [
    { 资产: '音效/…/entity.firework_rocket.blast', 名: '远处一发', 在: 'distantBurst', 峰值: -16 },
    { 资产: '音效/…/weather.rain.1', 名: '雨', 在: 'opening', 止: 'wrapUp', 循环: true, 响度: -30, fadeOutSec: 1 },
  ],
});
```

- 这条时间线上的每个 `windowSeg` 都会自动带上落在自己窗口里的那一截，排在段自己的 cue 后面。规则见 `engine/段/场声音.ts`。
  - 后一段那截的 `入点秒` = 原入点 + 已经放过的秒数 × 速率。算出的文件位置，和一口气放完一模一样（单测核对了切点前后）。
  - `fadeOutSec` 按整个声音的结尾算：尾在本截里就带 `fadeOutSec`，跨到后面段的那几截写成逐格增益（每秒 60 个值）。
- 选项和 `放()` 一样：`峰值`、`响度`、`增益` 三选一，另有 `名`、`入点秒`、`速率`、`档`、`fadeOutSec`。`在`、`止` 可以写事件名，也可以写时刻（`{ 秒 }`、`{ 帧 }`、`{ after }`），`止` 还能写 `{ 长秒 }`。不给 `止` 就放到文件完；`循环` 必须给 `止`。
- 循环的声音：Remotion 的 `loop` 只在 [入点, 文件尾] 之间绕。所以一段要从文件中间接上时，会拆成两条：先放到文件尾，再从文件头循环。拆开的地方按秒算，不取整。
- 不想要某个场声音的段（比如插进来的别处镜头），写 `windowSeg(timeline, { …, excludeSceneSound: ['雨'] })`；写 `true` 就一个都不放。
- 名字在一条时间线里不能重名，默认取资产 id 的最后一截。
- 声音表：起点在窗口之后的场声音（或给了 `止`、在窗口之前就结束的）不查表，免得每段的表都记上全场的声音。其余的要先查表才知道放多长；这些就算没落进本段，也会留在本段的声音表里，地址表里不会有它。
- 老写法的 `声音/跨段音效.ts` 是手工版的同一回事，老段照旧用它。

### 音量走势（gainAutomation）

跨段的音量变化（配乐淡入淡出、出手前把音效收一下、某一截整体压低）写在场时间线上，每个 `windowSeg` 乘到自己的资产 cue 上：场声音切进来的那截、段里 `放()` 的都乘，台词不管。规则在 `engine/段/音量包络.ts`。

```ts
gainAutomation: [
  {
    target: { names: ['战斗曲', '战斗曲-齐放'] },   // 按名（场声音名或 放() 的名），或 { kind: '配乐' | '非配乐' }（按资产 id 是不是 配乐/ 开头）
    points: [
      { 在: { after: 'yaBoLunAppears', addSec: -1.5 }, db: -Infinity },
      { 在: 'yaBoLunAppears', db: 0, curve: 'equalPowerIn' },        // curve 是从上一点到这一点怎么过渡
      { 在: { after: 'volleyDone', addSec: -0.122 }, db: 0 },
      { 在: { after: 'volleyDone', addSec: 1.028 }, db: -Infinity, curve: 'equalPowerOut' },
    ],
  },
],
```

- 点的 `在` 同场声音（事件名或时刻），`db` 可以是 `-Infinity`（无声）。第一点之前取第一点，最后一点之后取最后一点；几条都管到同一个声音的，倍数相乘。
- 过渡按倍数在两点之间插：`cosine`（默认）半余弦缓动 0.5 − 0.5·cos(πx)；`equalPowerIn` sin(π/2·x)；`equalPowerOut` 按 cos(π/2·x) 落下去。前后 dB 一样就是保持。
- 整条 cue 落在常数区：`增益` 乘一个数（逐格增益每格都乘）。碰到坡道：cue 另带一张包络表 `envelope`，每秒 60 个、格落在段的输出帧上（Remotion 一帧取一次增益），cue 起点不在帧上也取到准数；表只铺坡道那一截，前后取头尾。
- 读 cue 的增益（放、声音接缝、时间轴）一律用 `cueGainAt`。`增益` 的逐格表和 `段定义.ts` 的 `cueGain` 没动：它们在每一段（老段、核对段）的指纹里。
- 例：`作品/亚波伦不放水/场/1-台地/时间线.ts`（用户 11-19 选的试听版 F），逐帧核对在同目录 `音量走势.test.ts`。

`useSeg(seg)` 还给 `sceneSec`（场时间线上的秒）和 `段`（本段定义）。`definePicture` 包一层 `<SegSound>`：照 `段.ts` 的 cue 放每一声（`@remotion/media` 的 Audio，台词按全片台词增益，音效、配乐按 cue 增益和淡出秒），同时记进音效清单、配乐清单、台词清单。不想自动放的给 `{ 声音: false }`，自己放 `<SegSound />`。

## anim cues 和生成的两份文件

```
anim cues [<段键、段名、编号或章…>]     段.ts 的声音改了就跑：重算本段声音表、地址表，变了才写
anim cues --check                       只核对不写；对不上退出码 1（anim check 的「加载」也查这一项）
```

- 数从哪来：资产锁的 `时长`、`峰值`、`响度` > 盘上声音表里记的（按 sha 前 12 位对得上才沿用，换机器、换 ffmpeg 不重量）> ffmpeg 现量（按 sha 缓存在 `<数据根>/cache/音频数/`，要字节在数据根）。`anim check` 不量：都没有（新声音、同 id 换了字节）就报「跑 anim cues」。
- 第一次生成时 `段.ts` 要 import 的声音表还不存在：先写一张空表，在「收集」模式下执行一遍 `段.ts`（`放()` 遇到表里没有的 id 记下来、给 1 毫秒占位），量完写表，再正常执行一遍拿最终 cue。`anim new seg` 建段时就写好空表，新段立刻能渲。
- 按段分开、不做全作品大表：大表加一个声音，所有段都过期。分成两份：`段.ts` 要进 pipeline 的纯模块闭包（不许有 `asset:`），只引纯数的声音表；`asset:` import 放在只给 `画面.tsx` 用的地址表里。
- 哪些段归 anim cues 管：默认导出是 `windowSeg` 做的（`段.ts` 直接引 `@engine/段/窗口段.ts` 或目录里已有声音表的直接认，经场里自己写的工厂间接用的，在收集模式下执行一遍认）。
- `anim film`、`still`、`studio` 开跑前自动跑 cues（`pipeline/段框架/自动.ts`）。生成的两份文件和 cue 对不上，就重新生成；变了才写，写了哪份会打出来。
  - 只看一眼就认得出的段：`段.ts` 直接引 `窗口段.ts`，或者目录里已经有声音表（`anim new seg` 建段时就写了空表）。不执行老段，所以开跑前不会变慢。
  - 所选的段生成失败（缺字节、台词没配音这类），就停下不渲。没选的段失败，只打一行提醒。Studio 照样起来，那段在 Studio 里报错。
  - 自动生成（用户 10-31 定保留）：两份文件完全由输入算出，人跑也是同一个结果；进 Git，`git diff` 看得见，`anim check` 照样核对。
  - 开着 Studio 时改了 `段.ts` 的声音，不会自动重新生成，要手跑 `anim cues`。`anim film`、`verify` 不自动跑。

## 老场里加新段（接老段）

应力转动第 6、7 章的场，没有 `defineSceneTimeline` 做的场时间线：老段是 `defineSeg` 直接写的段长，有的场另有自己的老时间线文件（如 `地点/古城4x/7-1/时间线.ts`）。这些老时间线的闭包里有 `asset:`，新段的纯模块引不了。

接法是不改老段，在 `场/<场键>/时间线.ts` 里用 `continueOldSeg`（`engine/段/老段接续.ts`），把老段按清单顺序首尾相接摆上一条场时间线：

```ts
import { continueOldSeg } from '@engine/段/老段接续.ts';

export default continueOldSeg({
  场: '7-墙头追逐',
  legacySegs: [
    { 键: '7-墙头', 秒: 1.25 },
    { 键: '7-上塔', 秒: 1.167 },
    { 键: '7-音波', 秒: 3.717 },
  ],
  事件: {
    start: { 在: { after: '7-音波.止' }, 依据: '暂定：接在本场最后一个老段后面' },
    end: { 在: { after: 'start', addSec: 3 }, 依据: '暂定' },
  },
});
```

- 每个老段有两个事件：`<段键>.起`、`<段键>.止`。新段（`windowSeg`）从这条线上取窗口；`声音` 写的场声音只放进新段，老段照旧。
- 老段的段长是抄成数写进来的，不 import 老段的 `段.ts`，因为场不许引段（分层规则）。`anim check` 的「加载」会把抄的段长、起秒、场、画幅逐个和老段的 `段.ts` 对一遍（`pipeline/段框架/核对.ts` 调 `checkOldSeg`）。
- 有 `场窗口` 的老段，会带上 `起秒`。老时间线里段与段之间跳过一截的（如 7-1-6 的 `skipTo`），要接得准就手给那一段写 `起秒`。
- `anim new seg <段键> --scene <老场>`：这场还没有 `时间线.ts`、清单里又有这场的老段时，自动生成上面这样的文件。新段的 `--start`、`--end` 事件接在最后一个老段后面，先给 3 秒。
- 新场（比如第 8 章）照常用 `defineScene`（规矩「新场写法」）。要接上一场的时间轴，就自己写事件。
- 核对段之间可以互相引用 `时间线.ts`（用户 10-31 同意，只影响核对段）。

## 检查

- `段.ts` 的闭包是纯的（`engine/段/` 的 `时间线`、`歌网格`、`声音助手`、`窗口段`、`场声音`、`老段接续`、`清单工具` 登记成纯模块，`pipeline/源码/上下文.ts`）。
- `anim check` 的「加载」对每个段框架的段跑一遍 `anim cues --check` 的核对。
- 台词、清单、资产规则照旧适用（台词 cue 照样要在 `台词.toml` 登记、每句恰好开口一次）。

## 还没有的

- 循环又带入点秒的 cue（同老写法，不支持）。

## Remotion skill

Remotion 官方 skill `remotion-best-practices` 放在 `.claude/skills/`，不进 Git；`anim wt new` 会复制进新 worktree，缺了用 `npx skills experimental_install` 装回。它只当 API 参考，和我们的差别：

- 它说的 `npx remotion studio|render|still` 一律换成 `anim studio|film|still`（要按作品取根、算指纹、过资源闸）。
- 不照它的 `remotion-upgrade` 自行升级：升 Remotion 要用户点名，升完全片 `anim verify --render`。
- 它说做视频先开 Studio；我们先出静帧进预览。
