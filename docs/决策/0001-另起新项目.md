# 0001 另起新项目

- 状态：已定（用户 10-21）
- 来源提交：旧项目 `机械动力应力转动-AI漫画` 的 `7d077904`，已打 tag `冻结-1021`。旧 Git 历史不搬，查来历回旧仓库看。

## 背景

用户 10-21：「不要试图在旧的项目上改动屎山」「设计一个全新的方案 然后在新的项目弄」。旧项目的单个功能大多做得不错，问题出在组织层，在旧代码上修补修不掉：

1. **同一件事登记好几处，靠手抄对齐**：加一段要改清单、清单帧数、注册三处；一句台词散在 4 份 json 里；「这一段有哪些声音」要渲第 0 帧从日志里收，晚起的声音会漏收。
2. **没有「场」和「世界」这两层**：共用代码寄住在某一段的目录里（`6-4-1/古城画面.tsx` 被别处 49 个文件引用），结构白名单里有 132 条段互引，toThree 有 32 份。
3. **产物只看文件在不在**：代码改了母版也不重渲，「改过的东西后面又没了」一部分就出在这里。
4. **渲染开关是隐式全局变量，平台和路径写死**：15 个文件直接读 `getInputProps()`，环境推算抄了三份。
5. **源码、产物、数据混在一起**：贴图和 ogg 进了 `src/`，网格二进制进了 Git（仓库打包 315 MiB）。
6. **规矩被推广成全片铁律，又没有出处等级**：10-21 因此撤回过几处（`62f145c6`、`0b4b9aac`、`c9c7344c`）。

## 决定

- 新仓库 `stress-rotation`，数据根 `stress-rotation-data`（Git 外），命令 `sr`。骨架照「渐进搬迁」，验收和平台做法取自「跨平台与开源优先」，规矩表格式取自「数据驱动」。
- 旧代码原样搬进来，只改位置和引用；逐段和旧版比画面、声音，过了才算搬完（`docs/迁移.md`）。
- 戏暂不改写成 YAML：先用带类型的 `段.ts` 加场时间线，第 8 章写过一轮再看。
- 第 8 章等 `7-黑暗监守` 搬完（M5）后直接在新项目里做。

## 后果

- 旧项目冻结结构，只为出片做小修；已搬的场只在新项目改。
- 迁移期间两个项目共用旧项目的锁目录 `.资源闸/` 排队用 GPU。
- 退役条件全部满足后，旧仓库打 tag `退役`，保留 30 天再由用户决定删除还是冷备。
