### 设计和取舍

保留格式 2 的遍历、整列、区间跳过、色板和块索引，只把逐格概率条件于状态类，并给字面值树训练初值。不是有损平滑，也不是跨区段字典。

每包目录带一份 `模型.bin`，不把模型编进代码。理由：地形按包内容寻址、按段声明进指纹，换一个世界的模型不应让全部地形段的代码指纹变；多个包的模型可以同时存在，Worker 按含版本的模型 URL 缓存。主线程一次下载、向各 Worker 广播一次，区段 Range 不重复带表。`assets pack/pull` 沿用整目录打包、清单验证，不需要新的远端接口。

表格式（小端）：`u32[MCQM, 1, 类数, 状态跨度]`，接 `u8[跨度]` 的状态类、`u16[类数×1371]` 的初值、`u16[类数×跨度]` 的字面值权重。类数固定 32；未见状态归 31、权重 1。中性表为类数 1、跨度 0 的 16 字节头，表示初值 1024、权重 1，仍走同一个解码算法。训练表不额外压缩：每包只下载一次、成本相对大包很小，少一条异步解表路径；小包按全包真实字节择优，不把固定表成本藏在「区段比例」里。

训练顺序、抽样、平局规则、小包双编码择优见 `docs/世界.md`「训练、复现和小包」。预测/跳过概率条件于状态类，整列概率仍共享；空间概率按 1/32 更新，字面值按 1/16 更新；沿用复核过的 32 类方案，不再调参迎合全包结果。没有新依赖。

格式 2 的 WASM 和初值冻结在 `pipeline/世界/烘焙/格式2*`，只给转码读历史包，不留在 engine。引擎、查询只读格式 3，错版本或缺表都报错。模型参数改变只产生新包版本；解码语法变化仍要升格式版本。

合并门槛（定的时候写下的）：完整下载节省不明显低于约 10%，真实渲染没有稳定回退，指定帧 PNG sha 全同；不能拿抽样压缩率掩盖代价。

## 模型

一列从上往下，每格先猜和上一格一样，猜错再猜左列、前列同高的格，都错才记色板号；上下文是左、前两列在这一高度变没变、三者相不相同、上一次猜错没有、上一格是不是空气。跳过和整列是省时间的：左、前两列接下来都不变时只记一位，整列和左（前）列一样也只记一位。块文件索引不变，Range 取的逻辑不变。编码 `pipeline/世界/烘焙/区段编码.ts`，解码 `wasm/区段解码.ts`（AssemblyScript）→ `engine/voxel/区段解码器.生成.ts` → `engine/voxel/区段解码.ts`，Chromium 和 Node 共用，Windows 不用另装东西。

## 字节从哪来

- 算法（自适应二进制区间编码，LZMA 用的那种）公开，这里是自己写的，没有拷第三方代码。
- 编译器 `assemblyscript` 0.28.20（Apache-2.0，依赖 binaryen、long 也是 Apache-2.0），开发依赖、版本钉死。产物用 `--runtime stub`，模块里只有我们自己的解码函数；渲染、烘焙、转码都不装它也能跑，只有重编 WASM 才要。
- 复现：`pnpm install --frozen-lockfile && anim world decoder --check`。编译选项写在 `pipeline/世界/区段解码器.ts`，它们进 WASM 字节；同样的源码换目录、换文件名编出来字节相同。
- WASM 生成文件是代码（小、改了要进指纹），所以进 Git，不走 `0002` 的数据根字节，也不走 `0005`、`0006`。地形包照旧挂 Release（`0006`）。
- `anim check` 比源码 sha（不要求装 asc）；`decoder --check` 才真的重编。

## 只留一种读路径

`engine/` 和 `anim world` 的查询只读现行格式，旧格式只有转码工具读。

- 理由：包按版本内容寻址，登记的都转完了，没有调用方要读旧包。要回退就回退代码，旧代码读旧目录，旧目录还在。留两种的话，旧分支会一直留在所有地形段的依赖闭包里，多一条要测、永远不走的路径。
- 代价：没转的包读不了，报错提示 `anim assets pull` 或 `anim world transcode`。

- 旧附件留在 Release 上（`0006` 只增不改），旧提交还能拉。

- **留裙边**：区段是 34×34 列（核心 32×32 加一圈相邻区段的格）。变换 1、3 只碰第 2～31 列，同一格在两个区段里的两份抄本始终一样。
- 换进去的是 `minecraft:stone`、不染色；判断只看「是不是整格不透明」（`blockProps.full`，`occlusionMask` 第 0 位）。树叶、玻璃、水、花草、半砖都不算整格。区段最上一层上面当空气，最下一层下面当石头，照 `网格.ts`。粗级各自按自己那一级判断。下界没有石头，换什么要另选。
- 封腔：六邻连通、穿过所有非整格，**不设最小口径**，1 格的口也算通。种子是区段最上一层和第 0、1、32、33 列的全部非整格（碰到核心的边就当连通、不填）。跨区段精确连通只多省 1.6、1.3 个点，还会多出裙边面，不做。
- 不截面的定底：每列下限 = 自己和周围 8 列里最低的「有面露出来的格」。它换的格是变换 1 的子集，所以**按列的规则只要不截面，在 1 之后就没有增量**；照原样定底多省的那一截（主世界约 19 个点）动的全是有面露出来的格，即远离地表的洞穴网，见「深洞」。
- 邻圈：本段从不出邻圈格的面，网格只拿它的挡面掩码剔核心边格的面，所以邻圈里整格的可以换石头，掩码是 0 的非空气（花草、火把）可以归成空气。「整格全换」和「只换被埋的」差不到 1 个点，编码器可以逐段取小的。同一格的两份抄本从此不一样；`查询/源.ts` 只读核心列，不受影响。
- 核心边：六面被埋的整格，网格只给它出朝邻圈的裙边面，换石头后裙边贴图变成石头、并得更大。邻段换粗一级画时，被换格朝着的父格必是整格或树叶（粗级合并先比不透明度，`生成.ts` 的 `mergeKey`），反例 0。唯一例外是主世界 507 格（0.04%）：粗段最底一格不实、`k底` 以下又不出面，从那个洞里看得到这块裙边，贴图会变；转码时可以判（多查一次粗一级）。粗级的核心边、包边那一侧不放开。已知对数深度写 `gl_FragDepth` 加 MSAA 时侧对镜头的裙边墙会抢采样点（1 像素线），那里颜色会变成石头，要在级别交界的帧上出静帧或 `anim reuse` 验。

### 核对

核对器（原型的 `核对.ts`，现在是 `pipeline/世界/烘焙/可见核对.ts`）：原格子和改后的格子各走一遍渲染那条路（`importedSectionVoxels` → `buildSectionMesh`），比五种材质的顶点、UV、贴图层、颜色（含环境光遮蔽）和分段，两种树叶画法各比一遍。留出集（601／575 段）、随机大样本（4883／6876 段）、**峡谷、敞口大洞集**（263／269 段，用户 11-14 点名，`找峡谷.ts` 挑，位置在 `结果/峡谷集-<包>.tsv`）全过：变换 1、邻圈逐字节相同；封腔「只少不改」（新网格每个面都在旧网格里、顺序不变，少的面都贴着被填的格，被填格另由 `封闭` 独立复核），坏 0。`可见.test.ts`：侧面 1 格口的洞、崖下 1 格高口的凹洞、只连到核心边的洞都不填。

### 渲染收益

- 封腔：真画过的区段填腔后面数 96%～99.7%，少的几乎全是实心面。按 `docs/渲染性能.md` 第四轮「一帧拆解」的口径，每帧最多省 2～3 ms（≤ 0.8%），光栅深度采用后更小。**封腔的渲染收益在计时波动以内，做它只为体积那 1 个点。**

### 64×64

把 2×2 区段拼成一个 66 列的大区段：体积对四个小的主世界 0.865、暮色 0.885（安全项之后，抽样估计），解码快 3%～11%（解码器只改一个常量）。CPU 提交绘制每帧最多省 28～76 ms（10%～16%，上限），但第四轮清单第 3 项「区段并进大缓冲、一类材质一次多段绘制」打的是同一块 CPU，不改格式、不改画面。代价：视锥剔除变粗；远近分级交界从 32 米挪到 64 米，**改画面**，全片认可过期；加载、建网格粒度大 4 倍；要改格式、重传 Release。

| 4. 逐格预测（格式 3，不训练模型，即中性表） | 2.14 | 7.99 | −59%（全高 −59%） |
| 5. 每包训练模型（格式 3） | 1.79 | 6.99 | −16%（全高 −12%） |
| 6. 可见变换（埋格换石、封腔、邻圈、核心边） | **1.05** | **2.65** | −41%（全高 −62%） |

- 对照：Linker 1.0.20 同一块地不剔洞穴 606.6 MB、剔洞穴 369.4 MB（.blend）。
- 省得最多的是第 3 步和第 4 步。第 2 步变大，原因推测有三个，都没拆开量：
  - 区段多带一圈邻居的列（34×34 对 32×32，多 13%）；
  - 群系和方块合成一个条目、按格存（MC 是 4×4×4 一格）；
  - 每列分段加 gzip，本身就不如 MC 的位压缩加 deflate。
- 顺序会影响每一步分到的功劳：比如先做可见变换，它就会显得省得更多。表里按的是这几项开发的先后。
- 做法：临时脚本，不进仓库。在笔记本 `D:\mc-anim-linker-cmp` 那份对照代码里跑：
  - 第 1 步读 .mca 的 NBT，只取 `block_states`、`biomes` 的色板和 long 数组，按区块 zlib；
  - 第 2 步把中性表的包逐段解开，用 `编格式1区段` 重编；
  - 第 4～6 步：烘焙时临时留下 `.训练输入`（中性表的暂存包），再从它转出带可见变换的包。
