# 0011 地形压缩：区段换逐格预测压缩

## 格式 3（用户 11-02 定合并）

用户原话：「好的 早点合并吧」。旧目录一个字节不改。新附件未上传，**不能据此宣称其他机器已能 pull**；上传和推送还要用户点头，顺序是先上传再推送。

### 设计和取舍

保留格式 2 的遍历、整列、区间跳过、色板和块索引，只把逐格概率条件于状态类，并给字面值树训练初值。不是有损平滑，也不是跨区段字典。原型经第三批区段复核：主世界 87.10%、暮色 83.15%，解码约 ×1.04；这些是抽样，不替代下面的全包实测。

每包目录带一份 `模型.bin`，不是把模型编进代码。理由：地形按包内容寻址、按段声明进指纹，换一个世界的模型不应让全部地形段的代码指纹变；多个包的模型可以同时存在，Worker 按含版本的模型 URL 缓存。主线程一次下载、向各 Worker 广播一次，区段 Range 不重复带表。`assets pack/pull` 沿用整目录打包、清单验证，不需要新的远端接口。

表格式（小端）：`u32[MCQM, 1, 类数, 状态跨度]`，接 `u8[跨度]` 的状态类、`u16[类数×1371]` 的初值、`u16[类数×跨度]` 的字面值权重。类数固定 32；未见状态归 31、权重 1。中性表为类数 1、跨度 0 的 16 字节头，表示初值 1024、权重 1，仍走同一个解码算法。训练表不额外压缩：每包只下载一次、成本相对大包很小，少一条异步解表/解压路径；小包按全包真实字节择优，不把固定表成本藏在“区段比例”里。

训练顺序、每 L 抽 1/40、平局规则及小包 ≤1024 区段双编码择优，见 `docs/世界.md`。训练每包一次；烘焙用中性表暂存已固定的格子，再与转码共用定稿流程。因此状态号、遍历和写包顺序不受 Worker 完成先后影响。预测/跳过概率条件于 U/W/N/U 的状态类，整列概率仍共享；空间概率按 1/32 更新，字面值按 1/16 更新。训练用 8 次原上下文伪计数、16 次全局字面值先验平滑，沿用复核过的 32 类方案，不再调参迎合全包结果。没有新依赖，Remotion 4.0.537、three 0.186.1、AssemblyScript 0.28.20 不变。

格式 2 的 WASM 和初值冻结在 `pipeline/世界/烘焙/格式2*`，只给转码读历史包；不保留在 engine 中。引擎、查询只读格式 3，错版本或缺表都报错。模型参数改变只产生新包版本；解码语法变化仍要升格式版本。

### 验收边界

- 全包转码后从磁盘逐格比状态、群系和区段头，再登记；旧目录逐文件 sha 回读。
- 重新转码、烘焙/重烘、不同线程都应出同一目录指纹；小存档测试和正式包复验分开记。
- 真实浏览器 Worker 核同一批区段；画面严格比完整 PNG sha256，不用肉眼或容差。渲染只经全局渲染闸，转码 nice 10、2 线程。
- 尚未在 Windows 实机跑，不把“无原生依赖”写成 Windows 已验收；不访问 Release、不上传、不推送。
- 若完整下载节省明显低于约 10%，或真实渲染有稳定回退、任意指定帧 sha 不同，不值得直接合；不能拿抽样压缩率掩盖这些代价。

## 字节从哪来

- 算法（自适应二进制区间编码，LZMA 用的那种）公开，这里是自己写的，没有拷第三方代码。
- 编译器 `assemblyscript` 0.28.20（Apache-2.0，依赖 binaryen、long 也是 Apache-2.0），开发依赖、版本钉死。产物用 `--runtime stub`，模块里只有我们自己的解码函数，没有内存管理这类运行时；渲染、烘焙、转码都不装它也能跑，只有重编 WASM 才要。
- 复现：`pnpm install --frozen-lockfile && anim world 解码器 --检查`。编译选项写在 `pipeline/世界/区段解码器.ts`，它们进 WASM 字节。同样的源码换目录、换文件名编出来字节相同（2291 字节，sha256 `b47d73ed8014…`）。
- 模型初值：`anim world 解码器 --训练 主世界-116 暮色放大-1752-扩展 --抽 20`。按块文件名和文件内先后每 20 个区段取一个，数每个上下文 0、1 的频率。统计的是格子，和包是什么格式无关：从格式 1 的包学的表，和从转完的包再学一遍逐字节相同（10-31 核过）。
- 这两份是代码（小、改了要进指纹），所以进 Git，不走 `0002` 的数据根字节，也不走 `0005`、`0006`。地形包照旧挂 Release（`0006`）。
- `anim check` 比源码 sha（不要求装 asc）；`解码器 --检查` 才真的重编。

- 本机数据根已经有新包时 `pull` 只说都有了，不去问 Release，所以这台机器上看不出没传。`anim check` 也只比发布锁和代码，不联网。
- `cache/发布/` 里的新 tar 要留到传完：tar 带时间戳，重打出来字节不同，和发布锁的 sha 对不上。
- 旧附件留在 Release 上（`0006` 只增不改），旧提交还能拉。

### 四种变换

百分比是区段字节对现行格式 3 的比（不含块索引、`包.json`、模型表），按 L 分层加权到全包；括号里是上一轮那份留出集（606、603 段）的数，括号外是各级另抽的随机大样本（主世界每级 1000、暮色每级 1500 段）。第 0 级占全包七成多字节，留出集里只有 96 段，所以两份样本差两三个点。

| 变换 | 主世界-116 | 暮色放大-1752-扩展 | 网格 | 结论 |
|---|---:|---:|---|---|
| 1 埋住的整格换石头 | 71.0%（72.8%） | 92.2%（92.4%） | 逐字节相同 | 做 |
| 3 封死的腔填实 | 99.7%（99.7%） | 99.9%（99.9%） | 只少不改 | 单做没用，和 1 一起再省约 1 个点 |
| 1+3 | **69.8%**（71.7%） | **91.1%**（91.4%） | 同上 | 可做 |
| 2 按列定底（照任务原样） | 54.2%（53.2%） | 84.8%（86.9%） | 三到六成的区段网格变了 | **不做** |
| 1+2+3 | 51.1%（50.1%） | 82.4%（84.4%） | 同上 | 不做 |
| 4 2×2 拼成 64×64（在 1+3 之后，再乘 0.87） | 约 61% | 约 80% | 没量 | 要改格式，另议 |
| 4 拼完裙边列能动，再做一遍 1+3 | 约 56% | 约 78% | 没量 | 同上 |

- **做法里最要紧的一条是留裙边**：区段是 34×34 列（核心 32×32 加一圈相邻区段的格）。核心最外一列（第 1、32 列）的格即使整格被埋，网格也给它出裙边面；最外一圈（第 0、33 列）在邻段里也是核心的边。所以这四圈一格不动，变换只碰第 2～31 列，同一格在两个区段里的两份抄本也就始终一样（拼大时逐格比过，不同 0）。代价是 22% 的列完全没省，「上界」那一行就是放开它最多能到哪。
- 换进去的是 `minecraft:stone`、不染色；判断只看「是不是整格不透明」（`blockProps.full`，网格 `occlusionMask` 的第 0 位）。树叶、玻璃、水、花草、半砖都不算整格，不换也不当遮挡。区段最上一层上面当空气，最下一层下面当石头，都照 `网格.ts`。粗级各自按自己那一级的格子判断。
- 封腔的连通是六邻、穿过所有非整格（空气、水、树叶、花草……），**不设最小口径**，1 格的口也算通。种子是区段最上一层和第 0、1、32、33 列的全部非整格：碰到核心的边就当连通、不填。
- 按列定底照任务原样做（自己和周围 8 列最低地表 − 4 以下全换石头，地表照 `浮空下地表` 移植）会把峡谷壁、洞壁截掉：单做，留出集里主世界 289/601、暮色 199/575 段网格变了；叠在 1+3 上还有 216、139 段变，其中 94、64 段动到了从本段顶上就漫得到的露天格。改成「只动看不见的」以后它在 1+3 之后一格也不剩，所以这一项不存在安全版。
- 跨区段的连通做精确（8×8 个区段拼成一片再判断，两包各 40 片 1440 段）只比每段自己判断多省 1.6、1.3 个点，还会在封死的地下多出裙边面，不做。
- 拼 64×64 的收益里约 6 个点是少存了重复的那圈相邻列（66² 对 4×34²），其余是色板、头和自适应概率合并；各子区段 `k底` 以下按石头填，真烘时那一截是真方块，所以略偏乐观。没有解码器，解码耗时没量。

解码耗时比（WASM，留出集 A/B/B/A 各 8 遍，同上一轮口径；机器上另有渲染计时在跑，负载 3～5）：主世界 1 埋格 0.65～0.71、1+3 0.63～0.73；暮色 1 埋格 0.85～1.00、1+3 0.91～0.92。
