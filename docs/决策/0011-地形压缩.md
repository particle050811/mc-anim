## 落在哪

| 什么 | 在哪 |
|---|---|
| 格式 | 块文件头和 `包.json` 的格式版本 2；区段字节写在 `engine/voxel/区段包.ts` 文件头。块文件索引不变，所以 Range 取的逻辑不变 |
| 模型、编码 | `pipeline/世界/烘焙/区段编码.ts`（TS）。一列从上往下，每格先猜和上一格一样，猜错再猜左列、前列同高的格，都错才记色板号；上下文是左、前两列在这一高度变没变、三者相不相同、上一次猜错没有、上一格是不是空气。跳过和整列是省时间的：左、前两列接下来都不变时只记一位，整列和左（前）列一样也只记一位 |

## 字节从哪来

- 算法（自适应二进制区间编码，LZMA 用的那种）公开，这里是自己写的，没有拷第三方代码。
- 编译器 `assemblyscript` 0.28.20（Apache-2.0，依赖 binaryen、long 也是 Apache-2.0），开发依赖、版本钉死。产物用 `--runtime stub`，模块里只有我们自己的解码函数，没有内存管理这类运行时；渲染、烘焙、转码都不装它也能跑，只有重编 WASM 才要。
- 复现：`npm ci && anim world 解码器 --检查`。编译选项写在 `pipeline/世界/区段解码器.ts`，它们进 WASM 字节。同样的源码换目录、换文件名编出来字节相同（2291 字节，sha256 `b47d73ed8014…`）。
- 模型初值：`anim world 解码器 --训练 主世界-116 暮色放大-1752-扩展 --抽 20`。按块文件名和文件内先后每 20 个区段取一个，数每个上下文 0、1 的频率。统计的是格子，和包是什么格式无关：从格式 1 的包学的表，和从转完的包再学一遍逐字节相同（10-31 核过）。
- 这两份是代码（小、改了要进指纹），所以进 Git，不走 `0002` 的数据根字节，也不走 `0005`、`0006`。地形包照旧挂 Release（`0006`）。
- `anim check` 比源码 sha（不要求装 asc）；`解码器 --检查` 才真的重编。

## 只留一种读路径

`engine/` 和 `anim world` 的查询只读格式 2，格式 1 只有转码工具读。

- 理由：包按版本内容寻址，登记的都转完了，没有调用方要读旧包。要回退就回退代码，旧代码读旧目录，旧目录还在。留两种的话，gzip 分支会一直留在所有地形段的依赖闭包里，多一条要测的路径，而这条路径永远不走。
- 代价：没转的包读不了，报错提示 `anim assets pull` 或 `anim world 转码`（`decodeTileHeader`）。没登记的 `测试-修整-岛-编辑示例` 也转了，`核对/世界编辑/画面.tsx` 里写的版本跟着改。

## 上传之前

`作品/应力转动/发布锁.json` 已经写成新附件（`terrain-43b681414058.tar`、`terrain-d85050c74ee2.tar`，在打包这台机器的 `cache/发布/`），**Release `assets-v1` 上还是旧文件**。

- **传之前不能推送**：推上去之后别的机器按发布锁 `anim assets pull`，新附件拿不到，也渲不了地形（旧包这版代码不读）。顺序是 `anim assets pack --上传` → 推送。
- 这时 `pull` 不会静默出错：先发一个 HEAD，404 就报「Release 上没有 … 发布锁比 Release 新 … anim assets pack --上传」，不写数据根（`发布.test.ts` 守）。10-31 对真的 Release 探过：`terrain-43b681414058.tar` 是 404，`terrain-9cd3fdcf8361.tar` 是 200。连不上这类不算 404，照旧走下载的重试。
- 本机数据根已经有新包时 `pull` 只说都有了，不去问 Release，所以这台机器上看不出没传。`anim check` 也只比发布锁和代码，不联网。
- `cache/发布/` 里的新 tar 要留到传完：tar 带时间戳，重打出来字节不同，和发布锁的 sha 对不上。
- 旧附件留在 Release 上（`0006` 只增不改），旧提交还能拉。

## 否决的

| 方案 | 为什么不要 |
|---|---|
| 抹平地下方块（第 0 档，主世界 27%、暮色 36%）；瘦身、封洞、定底 | 真的改了地形数据。以后挖到没预留的地方要回存档重烘，用户定不做 |
| 不换格式（报告原来的建议） | 用户定换：下载量从 2.39 GB 降到 1.15 GB。渲染基本不变快，本来也不是为这个 |
| 参考列区间编辑 + 静态 rANS（Astra 的方案 A，59%、55%） | 比逐格预测大很多，解主世界还更慢（0.54 对 0.27 毫秒） |
| 不加跳过、整列（WASM，41.4%、40.3%） | 小不到 1 个百分点，解码慢约三成 |
| JS 版（约 42%、41%，解主世界 0.48 毫秒） | 比 WASM 慢近一倍，工人里没有理由不用 WASM |
| GPU、视频硬件解码 | 熵解码是串行的，小区段的调度、回读开销大；AV1、HEVC 的无损模式没有硬件保证（未实测） |
| 色板也进区间编码 | 色板原样存，占压缩后约 2～3%，省不了多少，还多一套模型 |
