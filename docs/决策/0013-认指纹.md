# 0013 认指纹：画面没变的过期段沿用旧切片

- 状态：已做（11-06），已合并。11-11 起也是优化、重构的验收办法，见「优化、重构怎么验收」。11-17 改比法：旧帧不再从切片解，用渲出旧切片的那个提交重出（用户 11-17 定「新的单帧对比旧的单帧，旧的单帧用旧代码单独渲一次」）。
- 只比切片（`docs/决策/0014-单一出片路.md`）。
- 依据：用户 11-06 同意加一档「认指纹」：段指纹是「输入变了就过期」的保守做法，注释、格式已靠 esbuild 规范化挡住，但依赖升小版本、重构（搬函数、改名）、和画面无关的打包规则改动都会让段过期、整段重渲，画面其实一样。抽几帧，新代码和旧代码各出一遍比，一样就登记成沿用旧切片，不重渲；有一帧不一样就不登记、照常过期。
- 实现：`pipeline/验收/认指纹.ts`（抽帧、找旧版、比一帧、登记）、`pipeline/验收/旧代码出帧.ts`（查旧提交、在旧检出里出帧）、`pipeline/环境/开worktree.ts` 的 `openTempCheckout`（临时检出）、`pipeline/指纹/命令.ts`（`anim reuse`、`anim stale` 的标记），测试 `认指纹.test.ts`、`旧代码出帧.test.ts`。

## 用法

```
anim reuse <选择器…> --reason "…" [--sample <n>] [--dry-run]
```

- 只认过期（`anim stale` 的 ✗）的段；切片在的、渲过只是切片不在的（◐）跳过。选择器必填，不默认全片。
- `--reason` 必填，写为什么认为画面没变（「three 0.186.1 → 0.186.2」「搬函数」），记进段签。
- `--dry-run`：只列每段和哪个旧指纹比、旧帧用哪个提交出（查自哪里）、比哪几帧、指纹差在哪，不出帧、不登记。
- 只认视频档：旧那边用的 `verify frames` 只出视频档。
- 退出码：选中的过期段有没认下来的（帧不同、没有能比的旧切片、查不到旧提交、旧代码出帧失败）是 1。

## 优化、重构怎么验收（用户 11-11 定）

用户 11-11：「逐字节不变 不是死要求 你如果能找到方便的对比方法的话，那就不需要这个东西」。下面的分法是 Agent 照这句话定的。

- **预期不改画面的改动（重构、搬代码、提速、换表）用 `anim reuse` 验收**，不用 `anim verify frames` 先存后比。reuse 只认逐像素一样的：差一个像素也认不下。
- 只在某几帧起作用的改动，加大 `--sample`，或另出那几帧的静帧。碰声音的改动认指纹验不了。
- **认不下的不算过**：差多少 reuse 会报（差像素占比、最大差、块平均差），出改前改后的并排静帧（`anim still … --vs main`）给用户定，Agent 不自己认。
- **`anim verify frames` 留给查路径差**：同一份代码单帧、跳帧、顺序、重渲出的图该逐字节一样，这里预期差是 0，默认不加容差（`docs/渲染性能.md`「重渲不一致」）。只改 `pipeline/` 的改动段不过期、认指纹不比，靠它或 `anim still --vs`。
- **verify frames 报差多少（用户 11-16 要）**：`--save` 默认留基准 PNG，`--compare` 对不同的帧报差像素占比（任一通道差 > 0、> 8、> 32）、最大差和块平均差（同一个 `computeBlockDiff`，附 `verify/阈值.toml` 下的判法），结尾列最差的 5 帧。过不过照旧逐字节；`--tolerance <级>` 可以把最大差不超过它的帧算过，查路径差时不给。
- **`anim diff` 比两份代码或两组参数（用户 11-17 同意做）**：预期有差，要知道差在哪、差多少。`anim diff <A（旧）> <B（新）>` 吃两个静帧目录（同名配对，名字不同按「第N帧」配）、两张 PNG 或两个视频（按帧号对齐抽帧，`--frames`、`--every`），`anim still <段> <帧…> --vs <检出|分支|main>` 一步做完两边出图和比。数和门槛同一套（`computeBlockDiff`、`verify/阈值.toml`），另报各档超门槛的块数；出 旧｜新｜差 并排图（差图带符号，红亮蓝暗绿色变），挑差得最多的几个窗口框出来、打印 `anim still … --tele` 原生复查命令。差多少一律给数，不靠眼判（有一次 Agent 判「看不出」的 7 个色阶正是用户指的那条线）。
- 数据的字节一致不在这条里，照旧：地形逐格无损、烘焙和转码可复现、资产 sha 对锁。

## 怎么比

1. **旧版**：同一档（级别、输出帧率、缩放一样）渲过的指纹里最近一份能用的（`.指纹.json` 按时间排，和 `anim stale` 拿来说差异的是同一串）：段签齐、切片 mp4 和配的 wav 都在、帧数和这段现在一样、下面 2、3 条不拦。拦下的往前找下一份（别的 worktree 拿不同编码参数试渲的切片常常是最近一份），`--dry-run` 列出跳过了哪几份、为什么。
2. **静帧证明不了的差异不用这份**：渲染设置变了（编码参数、尺寸、帧数、inputProps 都在里面）、私有配乐变了（只影响声音）、打包规则里 `ogg解码.cjs` 变了（只影响声音）、新指纹记了缺字节（打进的是占位）。代码、依赖版本、别的打包规则、地形版本、平台、指纹算法换过都不拦，让像素说话。
3. **旧切片是哪个提交渲的**（`findRenderSource`）：先看旧指纹 `.指纹.json` 的 `renderCommit`（11-17 起出切片时记当前提交和有没有未提交改动；认指纹登记时记像素源头那次的提交，不是认下时的提交）；没记的（11-17 以前的切片）翻运行记录：开始时刻不晚于段签 `派生于` 的 `film`（早先叫 `render`）里，产物有 `<作品>/<段键>/<指纹前 16 位>.mp4` 的最晚一条，取它的 `code.commit`。沿用来的切片按段签 `沿用.原渲` 那个指纹找（连着认几次也指到头）。交付 manifest 的 `code.commit` 不用：那是接成片那次的提交，切片可能是更早命中缓存的。带未提交改动渲的、查不到的、提交不在仓库里的（被 gc、别的仓库），这份不用。
4. **旧帧**：在那个提交上开临时检出（`mc-anim-wt/.认指纹-<提交>-<pid>/`，分离头指针，依赖照 `anim wt new` 从 pnpm store 导，约几秒；用完 `git worktree remove`，进程被杀也删），跑它自己的 `anim verify frames <段…> --frames <帧> --save <临时名> --keep-images <临时目录>`：和出切片同一种走法（同页按帧号升序连出、切片参数带字幕、声音开着），出无损 PNG，基准记录读完就删。只调旧提交早就有的命令（11-15 起参数是英文），不 import 旧代码。同一个提交的段共用一个检出；帧号一样的段一次 `verify frames`（一次打包），帧号不一样的分开跑（`verify frames` 只收一份帧号；多跑一次打包几秒，比把帧号并起来每段多出几十帧省）。旧那边过闸、低优先、运行记录都照旧代码自己的（票的种是「逐帧校验」，用途「认指纹」）。
   - **旧代码今天算出的指纹必须是切片那份**（沿用来的是原渲那份）：`verify frames` 的基准记录里有。对不上说明数据、资产或环境变过，旧代码重出的不是切片的画面，不认。
5. **新帧**：新代码打一次包，每段过一次渲染闸（`种: still`、`用途: 认指纹`），同样的帧号、同样的走法出 PNG。同一批帧才能比：一帧的像素取决于同页面在它之前渲过哪些帧（`docs/渲染性能.md`「静帧连出」），所以新旧两边出的是同一串帧号。
6. **比一帧**（`comparePng`）：PNG 逐字节一样是「一样」；字节不同就解码逐像素比，全同是「像素同」（PNG 编码器不同也会字节不同），有一个像素差就是「不同」。不用容差，也不用 `verify/阈值.toml`；不同的帧报差像素占比、最大差、块平均差（`帧差.ts`，和 verify frames 同一套），解码过放行闸。
   - 以前比的是旧切片解出来的帧，按块平均差过 `verify/阈值.toml`：切片是 x264 CRF18 + 40 Mbps 上限压的，画面完全没变时块平均差 16×16 也到 8～9（三渲二）、4.4（体素，11-06 实测），4K 高动态段的压缩损失远超门槛（6-挡箭 原画对它自己的切片 12 帧里 11 帧判「变了」），编码本身也不确定（码率上限加 x264 多线程，同一份像素编两次差到 16×16 23），所以拿新原画编一遍再比也不行。原画是确定的：同一份代码出两遍逐字节一样，旧提交上渲和新提交上渲（代码没碰画面时）也逐字节一样。
7. **全部一样（含像素同）才登记**；有一帧不同就不登记，照常过期，报不同的帧号和差多少。旧提交查不到、开不了检出、旧代码出帧失败、指纹对不上，也是不登记、照常过期并说原因，不退回对切片比：那条路对 4K 段几乎认不下，留着只是两套判法。

## 登记存在哪

不加别名表，在新指纹名下放一套和真渲出来一样的文件，用切片的地方都不用改：

| 什么 | 怎么放 |
|---|---|
| 切片 | 旧版的 mp4 和配的 wav 克隆到新指纹的名字。Mac 上 `cp -c`（APFS clonefile，不占空间，和 `cache gc` 的去重同一种克隆），不行退回硬链接，再不行整份复制。先克隆到 `.写入中-` 临时名，最后改名 |
| 段签 | `段签/<作品>/<段键>/<新指纹>/`：`声音.flac` 克隆过来，`签.json` 照抄旧的，改 `指纹`、`级别`；新加 `沿用`：`自`（直接沿用的指纹）、`原渲`（真渲出这份切片的指纹，连着认几次也指到头）、`理由`、`帧`（比过的帧）、`比法`、`于`、`提交`（认下时的提交）。`历史.jsonl` 记一行 `沿用: true` |
| `.指纹.json` | 新指纹照常写一份（`anim stale` 下次和它比差异），`renderCommit` 记像素源头那次渲的提交（就是这次重出旧帧用的提交），下次认指纹在它上面重出 |
| 记号 | `.用过`、`.检出-*` 照真渲一样记 |

写的顺序：段签、`.指纹.json`、最后切片改名。中途断了，`stale` 看到的是 ◐（渲过、切片不在），重跑 `anim reuse` 接着认（段签带 `沿用`、切片没在的不算「已有」）。旧指纹的文件一个不删。

## 和别的部分的关系

- **stale**：切片在就是 ✓，另标「沿用 <旧指纹>（认指纹，没真渲过）」。
- **film**：读新指纹的切片和段签，和真渲出来的没区别，命中「已是最新」不重渲。
- **verify**：签名是旧版的，和认可记录比哈希一样就过；会多打一行提示「现在的指纹是认指纹沿用 … 的切片」。verify 比不出沿用之后新代码有没有变：它比的签名、声音都是旧那版的。
- **认可**：不动认可记录。旧指纹的认可照样有效；`verify accept` 照常可以把新指纹记成认可版。
- **段签自查**：同一指纹真渲一次（`film --rerender`），派生段签时看到字节 sha 不一样，照「同一指纹重渲」比签名（抽样帧 sha、块均值、声音 sha），把沿用那套挪进 `历史/`，超容差报「重渲漂移」。这就是事后补整段比对的办法。
- **cache gc、删旧**：新指纹的切片是当前指纹，留着；旧指纹的那份照常按钉判，没人钉就删。克隆的块是共享的，删旧名字不影响新名字那份（`认指纹.test.ts` 验了）；gc 报「能省多少」按文件大小算，删克隆过的旧切片其实腾不出那么多。
- **worktree**：只新增。worktree 里认下的新指纹，合并后在主检出算出来是同一个指纹，直接用。

## 风险

- **没抽到的帧可能不同**：12 帧只是抽样。中间某段时间才出现的变化（某几帧的特效、字幕、一闪而过的东西）抽不到就认下了。重构类改动通常要么全段都不变、要么处处都变，所以抽样能抓住大多数；拿不准就加大 `--sample`，或者别认、照常重渲。
- **声音没比**：静帧不出声音。改动碰到台词、cue、混音、配乐的段不要认。「怎么比」第 2 条只挡了「只影响声音」的那几项输入，代码里改了声音逻辑挡不住。
- **旧那边是旧代码今天的出帧，不是切片本身**：指纹对上了，画面输入（代码、资产、地形、渲染设置）就是那一份；不进指纹的（`pipeline/` 的出帧走法、浏览器、显卡驱动）用的是旧提交和这台机器今天的。换机器、换驱动后同一指纹重渲本来就可能变（段签自查管这个），认下的切片和新代码今天的出帧之间也可能差这一层。
- **每段多花一遍出帧**：旧那边和新那边各出一遍，外加开检出（几秒）和旧那边的打包。
- **补整段比对**：`anim --low-priority film <段…> --rerender`（主 Agent 合并后排，给静帧让路），段签自查会拿新渲的整段比沿用的签名，漂移就报警；再 `anim --low-priority verify <段…>` 和认可版比。光跑 verify 不行：沿用之后 verify 比的签名、声音都是旧那版的。

## 不做的

- 不对切片比，也不在旧提交找不到时退回对切片比（「怎么比」第 6、7 条）。
- 不 import 旧提交的函数在本进程里出帧：只调它的命令行，旧代码的函数名、签名各提交不一样。
- 不默认全片（要逐段或按场、章点名）。
