## 管线

```
sourcing/extract.toml 配方（苦力怕动作、僵尸动作）
  → py/anim_py/动作翻译（读 client jar + 官方映射，符号执行）→ 姿态程序 JSON
  → anim extract 核 sha 入库：资产 动作/角色/<名>
  → engine/anim/姿态程序.ts 按 JVM 语义求值 → EntityModel 的 pose
```

- 命令：`anim extract 苦力怕动作 僵尸动作`。官方映射 `client-1.20.1-mappings.txt` 不许原样再分发，不进仓库、不进资产库，本机自取：`anim extract --下载` 按 `sourcing/jars.toml` 登记的地址下到数据根 `cache/映射/`、核 sha（游戏目录 `缓存/` 里早先放的也认）。1.21.11 的映射没登记，临时下在数据根 `cache/动作翻译映射/`，手动跑时 `--映射 proguard:<那个路径>` 显式给。手动跑：`python -m anim_py.动作翻译 <输出.json> <模型类> --jar <jar>[,<jar>…] [--映射 proguard:<client.txt> | srg:<tsrg>[,<client.txt>]] [--模型 <实体模型.json>:<名> | --层 <方法名>] [--固定 名=值]… [--不带prepare]`。
- 画面里用：`const 求 = 姿态求值器(程序, MODEL.root)`，每帧 `求({ limbSwing, limbSwingAmount, ageInTicks, netHeadYaw, headPitch, 'entity.isAggressive()': true, … })`。也可以用 `求部件姿态(程序, 根, 输入)` 直接拿 `pose` 参数。
- 一只原版生物翻一次约 0.3～1 秒（监守者的动画定义大，约 2 秒），纯 Python，不要 JDK。
- 关键帧动画的生物要给 `AnimationState` 输入：`<名>.lastTime`、`<名>.accumulatedTime`（long）。`姿态程序.ts` 的 `动画状态('entity.roarAnimationState', 开始刻)` 按「第几刻 start()、之后速度 1」给出这两个；不给就是没开始（默认 `Long.MAX_VALUE`）。

## 翻译器怎么做（`py/anim_py/动作翻译/`）

| 文件 | 做什么 |
|---|---|
| `类文件.py` | 读 class 文件：常量池、字段、方法、Code、BootstrapMethods。`类路径` 按顺序在几个 jar 里找类 |
| `映射.py` | 把 jar 里的名字换成官方名，有三种：`恒等`（NeoForge 1.20.2 起、MC 26.1 起不混淆）；`proguard:<client.txt>`（原版混淆客户端，成员名沿类层级往上找）；`srg:<tsrg>[,<client.txt>]`（Forge 1.17～1.20.1 的运行时 SRG 名）。SRG 表三种都认：mcp_config 的 `obf_to_srg.tsrg`、`config/joined.tsrg`（混淆名 → SRG，要带 client.txt 接到官方名），ForgeGradle 的 `build/createMcpToSrg/output.tsrg`（官方名 → SRG，不用 client.txt）。翻译开头查类路径里认不认得 `ModelPart.xRot`，映射和 jar 对不上就报错（以前会静默翻出空程序） |
| `执行.py` | 符号执行：构造函数 → `prepareMobModel` → `setupAnim` |
| `库类.py` | jar 里没有字节码的 Java 库类照语义具体执行：`ArrayList`、`HashMap`（遍历序照 JDK 的桶序）、`ImmutableList`、Guava 和 commons-compress 的 `Lists`/`Maps`、`Arrays.asList/setAll`、`Optional`、迭代器 |
| `部件树.py` | 没给 `--模型` 又要按名字找部件（关键帧动画）时，从模型类唯一的无参 `static LayerDefinition xxx()` 具体跑出部件树；`--层` 指定方法名 |
| `图.py` | 表达式图：哈希合并、常量折叠、导出成拓扑序，带 Python 参考求值 |
| `__main__.py` | 命令行 |

`执行.py` 的规则：
- **构造函数具体地跑**，记下每个字段对应哪个部件。字段名和部件名不一定对得上：原版 CreeperModel 的 `leftHindLeg` 就是 `right_hind_leg`。
- **哪些东西变成输入**：
  - 实体是不透明对象，在它上面的调用、读字段都变成输入，名字照调用链写：`entity.isAggressive()`、`entity.getMainHandItem().is(Items.BOW)`。
  - 从实体取的东西判 null（`getVehicle() != null` 这类）也是输入：`entity.getVehicle() == null`，不给按非 null 算。注册表对象（`Items.BOW`）、构造参数当非 null。
  - 模型字段没写过就读成输入，构造函数里写的常量当默认值：`model.attackTime`、`model.young`。
  - 拿实体算值的静态方法，结果也当输入：`CrossbowItem.getChargeDuration(entity.getUseItem())`。
- **分支**：
  - 条件是常量的，只走一边，常量界的循环靠这个展开。
  - 条件是符号的，两边各跑到直接后必经点再按条件合成 `sel`。已经知道真假的条件记在「事实」里，后面同样的条件直接取值。
  - `tableswitch`、`lookupswitch` 分 n 路走。
- **枚举**：
  - 枚举按序号（int）算。枚举上的方法、字段，对每个常量具体跑一遍，再查表。
  - javac 生成的 `$SwitchMap$` 类，具体跑它的静态初始化。
  - `HumanoidModel.getArm(arm)` 这类返回值按条件在几个部件里取一个（`条件引用`）。
- **调用**：
  - 内联这些方法：模型自己的、父类的、`ModelPart` 的（照它的字节码跑）、`AnimationUtils` 这类带字节码的静态方法。
  - `Mth`、`Math` 按「类.方法(描述符)」记成内建函数（`图.内建`，和 TS 的 `内建函数` 一一对应）。
  - 字符串拼接（indy）、lambda、`getAllParts().forEach(ModelPart::resetPose)` 也认得。
- **构造里建的对象**（存部件的 `ArrayList`、`Vector3f` 这些）连同堆里的内容带进 `prepareMobModel`、`setupAnim`。
- **静态初始化**：只为枚举、数值、数组字段、模型自己类层级的类具体跑 `<clinit>`。`Items.BOW` 这类注册表对象当不透明，不然要具体跑整个物品注册表。类型是 `AnimationDefinition`、插值方式、通道目标、`Vector3f` 的静态字段也具体跑（关键帧动画定义）。
- **关键帧动画**（1.20.1 的 `HierarchicalModel.animate`、`animateWalk`、`KeyframeAnimations.animate`）不做专门的内建，照字节码跑，靠下面几样：
  - `AnimationState` 是「照跑类」：从实体取到的这种对象，方法照字节码跑，字段读成输入（默认取无参构造跑完的值），写进去的本次求值里记着（`updateTime` 写了马上 `ifStarted` 读）。别的类要这样，加进 `照跑类`。
  - lambda、方法引用当闭包，传给库类、`Interpolation`、`Target.apply`（`ModelPart::offsetRotation`）时照调。
  - `Mth.binarySearch(lo, hi, IntPredicate)` 照 JVM 的二分步骤展开成判定树，不假设单调；谓词不许改状态。
  - `org.joml.Vector3f` 模拟：构造、`x/y/z`、`set`、`lerp`、`mul`、`add`。JOML 默认不用 `Math.fma`（`joml.useMathFma` 没开），`lerp` 是 `(b - a) * t + a` 两次舍入。
  - `getAnyDescendantWithName` 按部件树找（`root` 走 `root()`），没有的名字给空 `Optional`，游戏里同样跳过。
- **1.21.2 起的入口**：找不到老签名 `setupAnim(实体, 5 个 float)` 时，找 `setupAnim(X)`、`X` 是 `EntityRenderState` 子类的那个（桥方法跳过：子类收窄状态类型时，如 1.21.11 的 `SkeletonModel`，桥方法的参数也是渲染状态）。状态是不透明对象，读它的字段成了 `state.walkAnimationPos` 这样的输入。`Model.resetPose()`（1.21.2 起 `setupAnim` 一开头调）当整棵复位。

## 格式 `姿态程序/1`

```json
{ "格式": "姿态程序/1", "模型类": "net.minecraft.client.model.ZombieModel",
  "方法": ["…/HumanoidModel.prepareMobModel", "…/AbstractZombieModel.setupAnim"], "复位": false,
  "输入": { "limbSwing": {"类型": "f", "来源": "参数"},
            "entity.getMainArm()": {"类型": "i", "来源": "实体", "枚举": ["LEFT", "RIGHT"], "枚举类": "…/HumanoidArm"},
            "model.young": {"类型": "i", "来源": "模型字段", "默认": 1} },
  "固定": {}, "节点": [["in", "f", "limbSwing"], ["c", "f", 0.6662], ["*", "f", 0, 1], …],
  "输出": { "right_leg": { "xRot": 57, "z": 12 } }, "警告": [], "来源": {"jar": ["client-1.20.1.jar"], "映射": "ProGuard"} }
```

- 节点是 `[运算, 类型, 参数…]`，参数是前面节点的下标。类型有 `i`、`j`（long）、`f`、`d`、`z`（布尔）；boolean、byte、char、short、枚举序号都按 `i`。
- 运算：
  - 常量、输入、部件初始姿态：`c`、`in`、`rest`
  - 算术、位运算、取反、类型转换：`+ - * / %`、`shl shr ushr and or xor`、`neg`、`conv`
  - 比较：`< <= > >= == !=`
  - 逻辑运算（类型 `z`）：`not and or`
  - 其他：`sel`（按条件取一个）、`call`（内建函数）、`tab`（按下标查常量表）
- 特殊常量写成串：NaN、无穷写 `"NaN"`、`"Infinity"`；超出 2^53 的 long 也写成串（输入的 `默认` 也是，如 `lastTime` 的 `"9223372036854775807"`）。TS 那边 long 输入收 bigint 或十进制串。
- `输出` 是「部件 → 字段 → 节点」。字段有 `x y z xRot yRot zRot xScale yScale zScale visible skipDraw`。没写到的字段保持模型的初始姿态。`skipDraw`（只不画自己、子部件照画）`姿态程序.ts` 还没接：`EntityModel` 的 `hide` 是连子部件一起藏。1.20.1 原版翻得出的 17 只里没有写它的。
- `setupAnim` 本来就是空的（原版史莱姆）翻出空程序（`输出` 是 `{}`），不算错。
- `复位`：程序开头把整个模型复位成初始姿态（`root().getAllParts().forEach(ModelPart::resetPose)`）。
- 求值照 JVM 语义：
  - float 每步舍入到 float32，int 是 32 位补码，long 用 BigInt。
  - `(int)` 强转饱和、NaN 转成 0。
  - `fcmpl`、`fcmpg` 遇到 NaN 的结果换成对应的比较加 `not`。
  - `Mth.sin`、`Mth.cos` 查 65536 格的表。
- 输入的单位和原版一样（度、刻）。`库/生物` 手抄版的约定不同，对照时要换算：
  - 头偏、头仰和原版反号：`netHeadYaw = −headYaw`。
  - `ageInTicks = 秒 × 20`。

## 验证

1. **对着 JVM 逐位比**（`py/tests/test_动作翻译.py`）
   - 样例在 `py/tests/动作翻译样例/`：自己写的 `ModelPart`、`EntityModel`、`Mth` 桩（名字照官方名，走恒等映射），加一个样例模型。
   - 样例模型覆盖常量界循环、符号条件、枚举 switch（SwitchMap）、int switch、int / long / double 运算、继承、`prepareMobModel` 写字段给 `setupAnim` 读、静态辅助方法改传进来的部件。
   - 600 组随机输入（掺了 NaN、±0、无穷、超出 int 的大数），翻译结果和 JVM 真跑的结果逐位相同。没有 JDK 17 时跳过。
   - 这一步验出并修掉了三处错：i/j 的 `and`、`or` 被当成逻辑运算；`math.sin(inf)` 这类在 Python 里抛异常（JVM 给 NaN）；long 常量过 JSON 丢位。
2. **内建函数逐个对 JVM**（同一个 pytest，`sample/Builtins.java`）
   - 每个内建函数 400 组随机输入加边界值（NaN、±0、无穷、±2^31 附近）。`Mth` 走照 1.20.1 字节码写的桩（`javap` 核过真 jar 的 `Mth`），`java/lang/Math` 走 JDK 本身。
   - `Mth` 的全部逐位相同。这一步查出两处：`Mth.clamp(III)I` 是 `Math.min(Math.max(v, lo), hi)`，`lo > hi` 时取 `hi`；`Mth.floor(F)I` 比 −2^31 还小时 `i − 1` 溢出成 2^31 − 1（Python 版遇到无穷还会抛异常）。
   - `java/lang/Math` 的 `sin`、`cos`、`pow`、`atan2`、`exp`：JDK 规范只保证 1 ulp，这台机器上 HotSpot 的结果和 Python 的 libm 在约 2%～15% 的输入上差最后一位，Python、TS 两边都按 1 ulp 比。原版生物的转角主要走 `Mth.sin/cos` 查表，不受影响。
3. **TS 求值器**（`engine/anim/姿态程序.test.ts`）
   - 同一个样例程序拿 80 组 JVM 真值逐位比，夹具是 `engine/anim/姿态程序.样例.json`；内建函数每个 60 组，夹具是 `engine/anim/姿态程序.内建样例.json`。
   - 改了翻译器后，用 `ANIM_UPDATE_POSE_SAMPLE=1` 跑 pytest 重写夹具。pytest 会查夹具和当前翻译结果一致。
4. **和手抄版对照**（`库/生物/姿态程序对照.test.ts`，资产在数据根时才跑）
   - 苦力怕、僵尸各比 3000 组随机输入，手抄版写到的转角全对上。最大差约 2e-4 弧度，出在 limbSwing 上千时：手抄版用 double 和 `Math.cos`，原版用 float、查表。
   - 已知差别：僵尸手抄版省掉了 `setupAttackAnimation` 出手时的两处动作，翻译版都有：
     - 身子扭 `sin(√t·2π)·0.2`；
     - 两臂跟着绕身子挪位置。
     手臂转角之后被 `animateZombieArms` 整个盖掉，所以转角对得上。
5. **配方可复现**：`anim extract 苦力怕动作 僵尸动作` 重跑，和资产锁逐字节一样。
6. **映射**（`py/tests/test_动作翻译映射.py`）：照真文件格式手写的 client.txt 和三种 tsrg 小样，换回官方名。真 jar 上核过：`client-1.20.1-srg.jar`（Forge 安装器生成的 SRG 名客户端）配三种 SRG 表翻出的苦力怕、僵尸，和混淆客户端配 client.txt 翻出的一样（除了 `来源`）。

8. **真 jar 对 JVM**（`py/tests/test_动作翻译真jar.py`，缺 JDK、jar、映射、Prism 下载的库时跳过）

   - 设 `ANIM_REAL_POSE_DUMP=<目录>` 时，程序、部件树和真值写到那里，`engine/anim/姿态程序.真jar.test.ts` 拿 TS 求值器再比一遍（也全对上）。这些来自 Mojang 和模组作者的 jar，不进仓库。

## 不支持的写法

翻译时会报 `不支持`，消息里带类、方法、字节码位置和调用链；或者记一条警告：

| 写法 | 现在怎么办 | 以后 |
|---|---|---|
| 条件是符号的循环（`while (f < -π) f += 2π`） | 报不支持。`ModelUtils.rotlerpRad`（1.20.1）、`Mth.rotLerpRad`（1.21.x，参数次序改了）做成了内建；差大到加减 2π 不动（差的绝对值过 2^27，JVM 里死循环）时给 NaN，2^27 以内的照样算（JVM 转上千万圈也会出来） | 遇到别的再加内建 |
| 1.21.x 的关键帧动画（`AnimationDefinition.bake` 成 `KeyframeAnimation`，构造里 `ModelPart.createPartLookup` 用 stream） | 报不支持（1.21.11 的监守者、骆驼卡在 `Objects.requireNonNull` 之后的 stream） | 1.20.1 的已做；1.21 的按需补库类（stream）或把 `KeyframeAnimation` 做成照跑 |
| 部件名重了（青蛙、嗅探兽：根下面又有一个叫 `root` 的部件） | 报不支持 | 翻译器按名字认部件，TS 那边 `restPose` 也按名字；要做得给部件换成按路径认，两边一起改 |
| `AnimationState` 速度不是 1 | 照算，但 `动画状态` 帮手只管速度 1：逐帧 `(long)(差 × 速度)` 取整跟历史有关 | 要的话给求值器加「累计时间」直接当输入 |
| 构造函数里的 stream | 报不支持 | `ImmutableList.of`、`Arrays.setAll` 等已做（`库类.py`）；stream 按需加 |
| JDK 21 的 `Math.clamp`（1.21.11 的 `HumanoidModel` 经 `SpearAnimations` 调） | 报不支持（1.21.11 的僵尸翻不出） | 加内建，`sample/Builtins.java` 要在 JDK 21 上跑才有真值 |
| 只在部分分支里写的部件字段 | 记警告，没写的那支按初始姿态算（游戏里是沿用上一帧，跟历史有关） | 要逐帧带状态的话，给求值器加「上一帧姿态」输入 |
| 写之前先读部件字段（模型不复位时） | **不记警告**，读到的按初始姿态算。例：僵尸游泳时 `head.xRot = rotlerpRad(swimAmount, head.xRot, …)` 从上一帧的头仰往目标插值，翻译版从初始姿态插 | 同上；先在翻译器里对「读了又会写的字段」记警告（会改资产字节，等用户定） |
| 同名但参数是符号的实体调用（`entity.getSwimAmount(…)` 出现两次、参数不同） | 合成同一个输入（名字里符号参数写成 `…`） | 遇到再按参数节点区分 |
| 引用数组用符号下标、`jsr/ret`、`multianewarray`、带类体的枚举常量用符号序号调方法、符号上的 `i2b/i2c/i2s`、字符串运算 | 报不支持 | 原版生物没见到 |
| 异常 | 不管（不走 catch） | |
| 渲染器里设的姿态（`setupRotations`、缩放、`ModelPart` 以外的变换） | 不在 setupAnim 里，翻不到 | 渲染器那一层另算 |
| 实体那边的计算（`getSwimAmount`、`getAttackAnim` 等） | 都是输入，调用方给值 | |
| `Mth`、`Math` 的函数 | 白名单，按版本和描述符列在 `图.内建`；不在单子上的 `Mth` 方法照它的字节码内联 | 新版本语义变了就换名字，两边一起加，`sample/Builtins.java` 跟着加 |
| `org.joml.Vector3f` | 模拟构造、`x/y/z`、`set`、`lerp`、`mul`、`add`（关键帧动画用到的） | 别的方法按需加 |
| `Mth.binarySearch` 的谓词改状态 | 报不支持 | |

## 多版本、多模组

- **原版混淆客户端**（1.14～1.21.x）：`proguard:` 映射。
- **Forge 1.20.1 的模组 jar**（运行时是 SRG 名）：`srg:` 映射；`--jar` 写 `<模组.jar>,client-1.20.1-srg.jar`，模组的父类（`HumanoidModel` 这些）从 SRG 名的客户端里找，一个映射管所有 jar。原版 SRG 客户端上核过（见验证 6），真模组 jar（暮色森林）也逐位对过（验证 8）。冰与火的模型继承 Citadel 的 `AdvancedEntityModel`，不是原版 `ModelPart`，没试。
- **NeoForge 1.20.2 起、MC 26.1 起**：不混淆，走恒等映射，样例测试走的就是这条。
- **1.21.2 起 `setupAnim` 改成收 `EntityRenderState`**，不再收「实体 + 5 个 float」。入口做了（见上「1.21.2 起的入口」）：1.21.11 的苦力怕、猪、烈焰人翻得出，苦力怕、烈焰人逐位对过。`Mth.sin/cos` 改成收 double，内建按新描述符另加了一份（`Mth.sin(D)F`），老的照旧。调用方给的是渲染状态的字段，不是实体：怎么从游戏状态算出 `walkAnimationPos` 这些归渲染器那层（`extractRenderState`），不在翻译范围里。
- 1.21.11 是最后一个混淆的版本；它的官方映射临时放在数据根 `cache/动作翻译映射/`，没在 `jars.toml` 登记（登记的 1.20.1 映射在 `cache/映射/`）。
- 写死的类名都是官方名：`ModelPart`、`Entity`、`EntityModel`、`EntityRenderState`、`AnimationState`（照跑类）、关键帧动画那几个类型（`执行.py` 开头），`Model`、`HierarchicalModel`、`ModelUtils`（`执行.py` 的派发、`图.内建`），`LayerDefinition`（`部件树.py`）。换大版本先核这些名字。
- 一部作品要用哪个版本的哪只生物，就在 `extract.toml` 里加一条配方、在 `assets/registry/动作.toml` 里登记。模组 jar 照 `jars.toml` 的「模组」登记。

## 顺手发现的（没改）

- `engine/anim/关键帧动画.ts` 的 `mthCos` 少舍入一次：它把 `x × 10430.378 + 16384` 一起舍入到 float32，JVM 是先舍入乘积、加完再舍入一次。
  - 后果：随机 200 万个输入里有 1220 个（约 0.06%）查到相邻一格，差约 1e-4 弧度。`mthSin` 没有这个问题。
  - 用到它的手抄生物（监守者、恼鬼、幽灵马）都受影响。改它会让这些段过期，所以照现状留着。新代码用 `姿态程序.ts` 的 `内建函数`，那里的 `Mth` 和 JVM 逐位一样。
