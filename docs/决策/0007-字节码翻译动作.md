# 0007 字节码翻译动作

- 状态：原型做完（10-30）。原版苦力怕、僵尸翻出的姿态程序已登记成资产（`动作/角色/苦力怕`、`动作/角色/僵尸`），和 `库/生物/` 的手抄版对照过。**还没有段用它**；它只给新内容用，已有的段、手抄版都不动（迁移不改画面）。
- 依据：`预览/1030-1233-整体优化方案/01-方案.md` 第 2.4 条（探索性）。原来的设想是用 ASM 读字节码，做不成就退回 2.2「录制部件姿态」。现在做成了，而且不用 ASM。
- Linker（BaiGave，All Rights Reserved）的 `JvmPoseLowering` 只是想法的来源。它的代码、jar 都没看、没反编译；这里是照 JVMS 和原版字节码（`javap`）自己写的。

## 管线

```
sourcing/extract.toml 配方（苦力怕动作、僵尸动作）
  → py/anim_py/动作翻译（读 client jar + 官方映射，符号执行）→ 姿态程序 JSON
  → anim extract 核 sha 入库：资产 动作/角色/<名>
  → engine/anim/姿态程序.ts 按 JVM 语义求值 → EntityModel 的 pose
```

- 命令：`anim extract 苦力怕动作 僵尸动作`。要先把官方映射 `client-1.20.1-mappings.txt` 放到游戏目录的 `缓存/` 下（`sourcing/jars.toml` 登记了下载地址和 sha；映射文件不许原样再分发，所以不进仓库、不进资产库）。手动跑：`python -m anim_py.动作翻译 <输出.json> <模型类> --jar <jar>[,<jar>…] [--映射 proguard:<client.txt> | srg:<tsrg>,<client.txt>] [--模型 <实体模型.json>:<名>] [--固定 名=值]… [--不带prepare]`。
- 画面里用：`const 求 = 姿态求值器(程序, MODEL.root)`，每帧 `求({ limbSwing, limbSwingAmount, ageInTicks, netHeadYaw, headPitch, 'entity.isAggressive()': true, … })`。也可以用 `求部件姿态(程序, 根, 输入)` 直接拿 `pose` 参数。
- 一只原版生物翻一次约 0.3～1 秒，纯 Python，不要 JDK。

## 翻译器怎么做（`py/anim_py/动作翻译/`）

| 文件 | 做什么 |
|---|---|
| `类文件.py` | 读 class 文件：常量池、字段、方法、Code、BootstrapMethods。`类路径` 按顺序在几个 jar 里找类 |
| `映射.py` | 把 jar 里的名字换成官方名，有三种：`恒等`（NeoForge 1.20.2 起、MC 26.1 起不混淆）；`proguard:<client.txt>`（原版混淆客户端）；`srg:<tsrg>,<client.txt>`（Forge 1.20.1 模组，SRG 名经混淆名换成官方名）。成员名沿类层级往上找 |
| `执行.py` | 符号执行：构造函数 → `prepareMobModel` → `setupAnim` |
| `图.py` | 表达式图：哈希合并、常量折叠、导出成拓扑序，带 Python 参考求值 |
| `__main__.py` | 命令行 |

`执行.py` 的规则：
- **构造函数具体地跑**，记下每个字段对应哪个部件。字段名和部件名不一定对得上：原版 CreeperModel 的 `leftHindLeg` 就是 `right_hind_leg`。
- **哪些东西变成输入**：
  - 实体是不透明对象，在它上面的调用、读字段都变成输入，名字照调用链写：`entity.isAggressive()`、`entity.getMainHandItem().is(Items.BOW)`。
  - 模型字段没写过就读成输入，构造函数里写的常量当默认值：`model.attackTime`、`model.young`。
  - 拿实体算值的静态方法，结果也当输入：`CrossbowItem.getChargeDuration(entity.getUseItem())`。
- **分支**：
  - 条件是常量的，只走一边，常量界的循环靠这个展开。
  - 条件是符号的，两边各跑到直接后必经点再按条件合成 `sel`。已经知道真假的条件记在「事实」里，后面同样的条件直接取值。
  - `tableswitch`、`lookupswitch` 分 n 路走。
- **枚举**：
  - 枚举按序号（int）算。枚举上的方法、字段，对每个常量具体跑一遍，再查表。
  - javac 生成的 `$SwitchMap$` 类，具体跑它的静态初始化。
  - `HumanoidModel.getArm(arm)` 这类返回值按条件在几个部件里取一个（`条件引用`）。
- **调用**：
  - 内联这些方法：模型自己的、父类的、`ModelPart` 的（照它的字节码跑）、`AnimationUtils` 这类带字节码的静态方法。
  - `Mth`、`Math` 按「类.方法(描述符)」记成内建函数（`图.内建`，和 TS 的 `内建函数` 一一对应）。
  - 字符串拼接（indy）、lambda、`getAllParts().forEach(ModelPart::resetPose)` 也认得。
- **静态初始化**：只为枚举、数值、数组字段、模型自己类层级的类具体跑 `<clinit>`。`Items.BOW` 这类注册表对象当不透明，不然要具体跑整个物品注册表。

## 格式 `姿态程序/1`

```json
{ "格式": "姿态程序/1", "模型类": "net.minecraft.client.model.ZombieModel",
  "方法": ["…/HumanoidModel.prepareMobModel", "…/AbstractZombieModel.setupAnim"], "复位": false,
  "输入": { "limbSwing": {"类型": "f", "来源": "参数"},
            "entity.getMainArm()": {"类型": "i", "来源": "实体", "枚举": ["LEFT", "RIGHT"], "枚举类": "…/HumanoidArm"},
            "model.young": {"类型": "i", "来源": "模型字段", "默认": 1} },
  "固定": {}, "节点": [["in", "f", "limbSwing"], ["c", "f", 0.6662], ["*", "f", 0, 1], …],
  "输出": { "right_leg": { "xRot": 57, "z": 12 } }, "警告": [], "来源": {"jar": ["client-1.20.1.jar"], "映射": "ProGuard"} }
```

- 节点是 `[运算, 类型, 参数…]`，参数是前面节点的下标。类型有 `i`、`j`（long）、`f`、`d`、`z`（布尔）；boolean、byte、char、short、枚举序号都按 `i`。
- 运算：
  - 常量、输入、部件初始姿态：`c`、`in`、`rest`
  - 算术、位运算、取反、类型转换：`+ - * / %`、`shl shr ushr and or xor`、`neg`、`conv`
  - 比较：`< <= > >= == !=`
  - 逻辑运算（类型 `z`）：`not and or`
  - 其他：`sel`（按条件取一个）、`call`（内建函数）、`tab`（按下标查常量表）
- 特殊常量写成串：NaN、无穷写 `"NaN"`、`"Infinity"`；超出 2^53 的 long 也写成串。
- `输出` 是「部件 → 字段 → 节点」。字段有 `x y z xRot yRot zRot xScale yScale zScale visible skipDraw`。没写到的字段保持模型的初始姿态。
- `复位`：程序开头把整个模型复位成初始姿态（`root().getAllParts().forEach(ModelPart::resetPose)`）。
- 求值照 JVM 语义：
  - float 每步舍入到 float32，int 是 32 位补码，long 用 BigInt。
  - `(int)` 强转饱和、NaN 转成 0。
  - `fcmpl`、`fcmpg` 遇到 NaN 的结果换成对应的比较加 `not`。
  - `Mth.sin`、`Mth.cos` 查 65536 格的表。
- 输入的单位和原版一样（度、刻）。`库/生物` 手抄版的约定不同，对照时要换算：
  - 头偏、头仰和原版反号：`netHeadYaw = −headYaw`。
  - `ageInTicks = 秒 × 20`。

## 验证

1. **对着 JVM 逐位比**（`py/tests/test_动作翻译.py`）
   - 样例在 `py/tests/动作翻译样例/`：自己写的 `ModelPart`、`EntityModel`、`Mth` 桩（名字照官方名，走恒等映射），加一个样例模型。
   - 样例模型覆盖常量界循环、符号条件、枚举 switch（SwitchMap）、int switch、int / long / double 运算、继承、`prepareMobModel` 写字段给 `setupAnim` 读、静态辅助方法改传进来的部件。
   - 600 组随机输入（掺了 NaN、±0、无穷、超出 int 的大数），翻译结果和 JVM 真跑的结果逐位相同。没有 JDK 17 时跳过。
   - 这一步验出并修掉了三处错：i/j 的 `and`、`or` 被当成逻辑运算；`math.sin(inf)` 这类在 Python 里抛异常（JVM 给 NaN）；long 常量过 JSON 丢位。
2. **TS 求值器**（`engine/anim/姿态程序.test.ts`）
   - 同一个样例程序拿 80 组 JVM 真值逐位比，夹具是 `engine/anim/姿态程序.样例.json`。
   - 改了翻译器后，用 `ANIM_UPDATE_POSE_SAMPLE=1` 跑 pytest 重写夹具。pytest 会查夹具和当前翻译结果一致。
3. **和手抄版对照**（`库/生物/姿态程序对照.test.ts`，资产在数据根时才跑）
   - 苦力怕、僵尸各比 3000 组随机输入，手抄版写到的转角全对上。最大差约 2e-4 弧度，出在 limbSwing 上千时：手抄版用 double 和 `Math.cos`，原版用 float、查表。
   - 已知差别：僵尸手抄版省掉了 `setupAttackAnimation` 出手时的两处动作，翻译版都有：
     - 身子扭 `sin(√t·2π)·0.2`；
     - 两臂跟着绕身子挪位置。
     手臂转角之后被 `animateZombieArms` 整个盖掉，所以转角对得上。
4. **配方可复现**：`anim extract 苦力怕动作 僵尸动作` 重跑，和资产锁逐字节一样。
5. **1.20.1 原版覆盖面**（试翻，没逐只对照）：22 只里 17 只翻得出。
   - 翻得出：苦力怕、僵尸、恼鬼、马、铁傀儡、蜘蛛、狼、鸡、牛、猪、骷髅、末影人、恶魂、史莱姆、悦灵、美西螈、鹦鹉。
   - 翻不出：
     - 监守者：构造里有 `ImmutableList.of`，之后还有关键帧 `animate`。
     - 烈焰人：构造里有 `Arrays.setAll` + lambda。
     - 骆驼、青蛙：关键帧 `animate`。
     - 蜜蜂：`ModelUtils.rotlerpRad` 里有 `while` 归一角度，循环次数取决于输入。
   - 鹦鹉有 8 条警告、狼有 1 条，都是只在部分分支里写的字段（见下）。

## 不支持的写法

翻译时会报 `不支持`，消息里带类、方法、字节码位置和调用链；或者记一条警告：

| 写法 | 现在怎么办 | 以后 |
|---|---|---|
| 条件是符号的循环（`while (f < -π) f += 2π`） | 报不支持 | 常见的几种（角度归一、`rotlerpRad`）做成内建函数 |
| 关键帧动画 `HierarchicalModel.animate(AnimationState, AnimationDefinition, …)`（监守者、骆驼、青蛙等 1.19 起的生物） | 报不支持 | 做成内建：`AnimationDefinition` 从静态初始化里取成关键帧数据，交给 `engine/anim/关键帧动画.ts`；`AnimationState` 的起止和累计时间当输入 |
| 构造函数里的 `ImmutableList.of`、`Arrays.setAll`、stream | 报不支持 | 按需加：具体执行就行 |
| 只在部分分支里写的部件字段 | 记警告，没写的那支按初始姿态算（游戏里是沿用上一帧，跟历史有关） | 要逐帧带状态的话，给求值器加「上一帧姿态」输入 |
| 同名但参数是符号的实体调用（`entity.getSwimAmount(…)` 出现两次、参数不同） | 合成同一个输入（名字里符号参数写成 `…`） | 遇到再按参数节点区分 |
| 引用数组用符号下标、`jsr/ret`、`multianewarray`、带类体的枚举常量用符号序号调方法、符号上的 `i2b/i2c/i2s`、字符串运算 | 报不支持 | 原版生物没见到 |
| 异常 | 不管（不走 catch） | |
| 渲染器里设的姿态（`setupRotations`、缩放、`ModelPart` 以外的变换） | 不在 setupAnim 里，翻不到 | 渲染器那一层另算 |
| 实体那边的计算（`getSwimAmount`、`getAttackAnim` 等） | 都是输入，调用方给值 | |
| `Mth`、`Math` 的函数 | 白名单，按版本和描述符列在 `图.内建` | 新版本语义变了就换名字，两边一起加 |
| `org.joml.Vector3f` | 只认 `new Vector3f(x, y, z)` 和 `x()`、`y()`、`z()` | |

## 多版本、多模组

- **原版混淆客户端**（1.14～1.21.x）：`proguard:` 映射。
- **Forge 1.20.1 的模组 jar**（运行时是 SRG 名）：`srg:` 映射，SRG 名经混淆名换成官方名。**这条还没拿真模组试过。**
- **NeoForge 1.20.2 起、MC 26.1 起**：不混淆，走恒等映射，样例测试走的就是这条。
- **1.21.2 起 `setupAnim` 改成收 `EntityRenderState`**，不再收「实体 + 5 个 float」。翻译器现在只认老签名，要加一个入口：把渲染状态当不透明对象，读它的字段（`state.walkAnimationPos` 等）就成了输入。
- 写死的类名只有三个：`ModelPart`、`Entity`、`EntityModel`（`执行.py` 开头），都是官方名。换大版本先核这三个名字。
- 一部作品要用哪个版本的哪只生物，就在 `extract.toml` 里加一条配方、在 `assets/registry/动作.toml` 里登记。模组 jar 照 `jars.toml` 的「模组」登记。

## 顺手发现的（没改）

- `engine/anim/关键帧动画.ts` 的 `mthCos` 少舍入一次：它把 `x × 10430.378 + 16384` 一起舍入到 float32，JVM 是先舍入乘积、加完再舍入一次。
  - 后果：随机 200 万个输入里有 1220 个（约 0.06%）查到相邻一格，差约 1e-4 弧度。`mthSin` 没有这个问题。
  - 用到它的手抄生物（监守者、恼鬼、幽灵马）都受影响。改它会让这些段过期，所以照现状留着。新代码用 `姿态程序.ts` 的 `内建函数`，那里和 JVM 逐位一样。
