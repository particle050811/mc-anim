- 实现：`pipeline/渲/段产物.ts`（指纹、路径、输出帧数、参数的唯一来源）、`pipeline/渲/渲段.ts`（唯一的渲段路）、`pipeline/合成/命令.ts`（`anim film`）；verify、认指纹、stale、gc、still、bench、逐帧校验都改成从 `段产物们` 取。

## 用户定的（11-06）

- 「要改 改成直接出带字幕的成片」
- 「那个 render 不用了 可以直接删了吧」

主 Agent 转述的细则：`anim render` 整个删，不留别名；`anim film <选择器…>` 是唯一出片路（一段也行），`--重渲`、`--级别` 留下；`--到预览`、`--留CRF1`、`--只派生` 删；提示语一律指向 `anim film <段> --重渲`；闸的任务种 `render`、耗时表标签 `render:<作品>/<段>:<级别>` 照旧（调度日志、耗时表的历史行和预计耗时接得上）。

## 现在是什么样

| 什么 | 怎样 |
|---|---|
| 一段的产物 | `cache/母版/<作品>/<段键>/<画面指纹前 16 位>.mp4`（成片档 4K60 h264 CRF18、bt709，叠层、这段的字幕画在里面，帧数 = 这段在全片的输出窗）和 `<声音指纹前 16 位>.wav`（11-06 起和画面同一遍出，声音指纹 = 画面指纹，`决策/0015`）。指纹、路径和合并前 main 上 film 渲的切片逐位相同 |
| 渲 | `anim film` 缺哪段渲哪段（`--重渲` 全部）。每段一张渲染闸票，闸里依次：出画面（核帧数）和声音（11-06 起同一遍）→ 派生段签 → 主检出删同段同级别的旧产物。没有后台子进程、没有 CRF1、没有转码 |
| 段签 | 版本 3，渲完在闸里当场派生：签名从 mp4（画面）和 wav（声音）算，`签.json` 记两份的样子。版本 1、2（CRF1 时代）11-06 起不认（文末「删旧兼容」）。verify、认指纹 要段签时缺了，切片在就当场补（`pipeline/段签/取.ts`） |
| verify | 比切片的输出帧。切片没了报「要重渲才能验收（anim film <段> --重渲）」，`--渲` 当场渲。CRF1 时代的认可记录（2560×1440、编排帧数）和切片尺寸帧数对不上，报「这段没有现行认可，要重新认可」，算不过，不比；看过切片后 `anim verify accept` 重新认可 |
| 认指纹 | 只和同一档（级别、输出帧率、缩放一样）的旧切片比，旧切片配的 wav 也要在。新帧照切片参数出（带字幕），经 Remotion 自带的 ffmpeg 用和切片编码同一个 bt709 滤镜（zscale）转 yuv420p 再比；登记沿用时克隆 mp4 和 wav |
| stale | ✓ 要 mp4、wav 都在；差异和同档最近的画面记录比 |
| gc、删旧 | 认 mp4、wav；CRF1 时代的 `.mkv`、`.x264.mkv`、`cache/叠层/` 的 `.mov` 都不是谁的当前产物（11-06 起代码不认，只报告，文末「删旧兼容」） |
| still、bench、逐帧校验 | 帧号是输出帧，参数和切片一样（带字幕）；`找组合` 只认按成片档注册的那个 Composition，帧数对不上就报错，不再猜 |

## 删了什么

| 删的 | 为什么 |
|---|---|
| `anim render`（连 `--到预览`、`--留CRF1`、`--只派生 [--重做]`） | 用户定。`--到预览` 读压缩母版给人看，现在切片就是成片的一截，直接看交付或切片；`--留CRF1` 只为 `verify --对基线`；`--只派生` 从 CRF1 补段签，现在段签渲完当场派生，缺了 verify、认指纹自己补 |
| CRF1 母版、转码存压缩母版（`渲/转码.ts`、`转存.ts`） | 切片按成片参数直接压好，再转一遍是重复编码 |
| 后台转存、后台队列、后处理、每指纹占用标记（`渲/后台转存*.ts`、`后台队列.ts`、`后处理.ts`、`母版占用.ts`） | 都是为了让 CRF1 的转码不占渲染闸；没有转码了，派生段签留在闸里（一段几秒） |
| `anim cache 转存`、`cache 改后缀`（`缓存/迁移转存.ts`、`迁移改名.ts`） | 一次性迁移，CRF1 和 `.crf12.mkv` 都不再产生 |
| `anim verify --对基线 [--渲]`（`验收/基线.ts`） | 基线是旧项目的 1440p、24 帧，和 4K60 切片的帧对不上；要比得先把基线重做成 4K60，迁移已经结束，没人要。数据根 `基线/` 留着备查 |
| `ANIM_INLINE_TRANSCODE`、`ANIM_BG_QUEUE` / `bg_queue` | 跟着后台转存走 |

旧记录不删：调度日志的 `后台*` 事件、阶段表的 派生段签 / 转存 / 等后台 行、运行记录里的 `留CRF1` 结果原样留着；统计它们的代码 11-06 删了（见文末「删旧兼容」）。

## 风险和没做的

- 已有的认可记录全是 CRF1 时代的，切片渲出来以后 verify 每段都会报「这段没有现行认可，要重新认可」，要逐段看过再 accept。不自动转认可。
- 成片档（`ANIM_FILM_PROFILE`）换档后同一级别的切片会互相当旧的删（删旧按段、级别，不看档）；两档来回切会反复重渲。现在只有一档在用，没改。
