# 0004 多作品

- 状态：选作品、按作品分的缓存和交付已做（重组 C）；作品资产表和锁、私有作品不查「公开构建无私有资产」已做（10-22）；作品默认公开、进 Git（用户 10-22 定，替掉重组 C 时 Agent 写的「默认私有」）；作品目录搬家（B）、分层检查按作品、外部作品的 npm 解析见「还没做」。
- 依据：重组方案 b-3、d 节和末尾「批评补充」。

## 作品在哪

- 一部作品是 `作品/<名>/` 下有 `清单.ts` 的目录，外加 `anim.local.toml` 的 `[works]` 登记的外部目录（键是作品名，中文加引号，相对路径相对这个 toml）。
- 作品名统一成 NFC，查重不分大小写，不能有 `/ \ : * ? " < > |`。
- 过渡：B 搬家前「应力转动」在 `content/`，搬家期间曾回落到那里；搬完已删。

## 作品资产表

- 只有一部作品用的资产可以登记在作品那一侧：`<作品根>/资产表/<类>.toml`（人写，字段同 `assets/registry/`）和 `<作品根>/资产锁.json`（工具写，格式同 `assets/资产锁.json`）。私有作品（见「公开和私有」）的表锁跟着作品目录不进 Git。
- `anim [--作品 <名>] assets add <id> <文件>` 写进登记它那一侧的锁：共用表登记的写 `assets/资产锁.json`，作品资产表登记的写所选作品的 `资产锁.json`。登记换了一侧的，锁跟着挪。
- 打包、指纹、`check`、`extract` 都用共用的并上所选那一部作品的。同一个 id 两侧都登记、两份锁都有、锁没写在登记它的那一侧，`check` 都报错；打包和 `extract` 遇到两份锁同 id 直接失败。
- 不同作品之间同名的 id 不查：每部作品各自打包，互不影响。作品资产表登记的产物要 `extract` 时，带上 `--作品 <名>`。

## 选哪部

`--作品 <名>`（对所有 anim 命令有效，`cli/main.ts` 统一取走）> 当前目录在哪部作品里 > `anim.local.toml` 的 `work`（`ANIM_WORK`）> 只有一部就用它。都定不了就报错并列出作品名。

- 段的全名写成 `应力转动/6-斩娜迦`，选择器认全名和短名；全名的作品要是所选的那部，一次只处理一部作品。
- `anim studio` 起 Remotion 时设 `ANIM_WORK`，`remotion.config.ts` 按它取作品根。

## 公开和私有

- 作品默认公开、进 Git、开源。用户 10-22 原话：「为什么作为私有资产处理 这个我后面也是打算开源的啊」「我都没有说过这样的话 如果让我来写的话 应该是默认公开开源」。10-21 重组 C 时写的「`.gitignore` 默认挡住 `作品/*`、新建的作品默认私有、公开仓库里不出现它的名字」是 Agent 自己定的，不是用户定的，10-22 作废。
- 公开的作品就是主仓库里的普通目录，不做嵌套仓库，worktree 照常检出。`把回忆拼好给你` 原先是嵌套仓库，10-22 用 `git subtree add`（不 squash）连历史并进主仓库，原仓库的 bundle 和整个目录备份在数据根 `archive/`。
- 作品里用到的第三方字节照共用资产的规矩：资产表可见性写「私有」、字节在数据根 `私有/`、不进 Git；作品目录里 import 了私有资产的照查「公开构建无私有资产」，还没改走 cue 的在 import 上面标「待迁移（私有资产）」（先例：`作品/应力转动/配乐/Wasted.ts`）。
- 要私有的作品逐个挡，两种挡法：
  - 在 `.gitignore` 加一行 `/作品/<名>/`。作品目录可以自己做成嵌套 git 仓库，不用在 `[works]` 登记（`作品/` 下有 `清单.ts` 就认）。
    - 不登记的原因：`anim.local.toml` 在主检出，各 worktree 共用，`[works]` 指的永远是主检出里的那份；`anim check` 要求作品就在当前检出的 `作品/<名>/`，指到别处就拒绝（`pipeline/检查/命令.ts:19-22`）。
    - worktree 里被忽略的目录不会检出。外层开好 worktree 后，作品用嵌套仓库自己的 worktree 放进去：`git -C 作品/<名> worktree add <外层 worktree>/作品/<名> -b <分支>`。两边各自提交、各自合并。
  - 放在 `作品/` 以外，在 `anim.local.toml` 的 `[works]` 登记；`anim check` 暂时不查它们（见「还没做」）。
- `anim check` 的文件表带上 `作品/` 下被忽略的作品（嵌套仓库按它自己的 ls-files）。
- 私有作品不进公开构建，`anim check` 不查它自己目录里 import 私有资产（用户 10-22 定）；`engine/`、`库/` 照查。私有指作品目录被 `.gitignore` 挡住（`git check-ignore`）。
