- 状态：选作品、按作品分的缓存和交付、私有作品已做（重组 C）；作品目录搬家（B）、资产锁全面合并、分层检查按作品、外部作品的 npm 解析见「还没做」。
- 依据：重组方案 b-3、d 节和末尾「批评补充」。

## 作品在哪

- 一部作品是 `作品/<名>/` 下有 `清单.ts` 的目录，外加 `anim.local.toml` 的 `[works]` 登记的外部目录（键是作品名，中文加引号，相对路径相对这个 toml）。
- 作品名统一成 NFC，查重不分大小写，不能有 `/ \ : * ? " < > |`。
- 过渡：B 搬家前「应力转动」还在 `content/`；`作品/应力转动/` 不在时就用它（`pipeline/环境/作品.ts` 的 旧作品根，B 搬完删）。

## 选哪部

`--作品 <名>`（对所有 anim 命令有效，`cli/main.ts` 统一取走）> 当前目录在哪部作品里 > `anim.local.toml` 的 `work`（`ANIM_WORK`）> 只有一部就用它。都定不了就报错并列出作品名。

- 段的全名写成 `应力转动/6-斩娜迦`，选择器认全名和短名；全名的作品要是所选的那部，一次只处理一部作品。
- `anim studio` 起 Remotion 时设 `ANIM_WORK`，`remotion.config.ts` 按它取作品根。

## 数据根里按作品分的

| 按作品分 | 共用 |
|---|---|
| `cache/母版/<作品>/<段键>/`、`cache/叠层/<作品>/<键>/`、`交付/<作品>/`、`基线/<作品>/`（只有应力转动）、耗时标签 `render:<作品>/<键>:<级别>` | `store/`、`私有/`、`terrain/`、`cache/求解/`（按内容寻址）、`cache/剪映解密/`、`cache/核对/`（没有代码读写，不挪）、`run/` |

- 交付 manifest 记 `作品`，母版和叠层路径写相对数据根；`段` 仍记短名（`读取调整.py` 只认短名）。
- 旧布局的数据用 `node pipeline/环境/迁移多作品.ts [--执行]` 一次挪过去：先合并并删掉所有 worktree，过渲染闸，幂等，改写前的文件和日志存 `迁移/多作品-<UTC>/`。没迁移之前 `配置.ts` 的 按作品 回落到旧位置，迁移后删掉回落和脚本。

## 私有作品

- `.gitignore` 默认挡住 `作品/*`，公开的逐个放行（`!/作品/应力转动/`）。新建的作品默认私有，公开仓库里不出现它的名字，`git add -A` 也不会把嵌套仓库当 gitlink 提交。
- 私有作品可以放 `作品/<名>/`（自己可以是一个 git 仓库），也可以放任意位置；都在 `[works]` 登记，worktree 里才找得到（被忽略的目录不会检出到 worktree）。
- `anim check` 的文件表带上 `作品/` 下被忽略的作品（嵌套仓库按它自己的 ls-files）。
