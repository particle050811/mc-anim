# 0010 定制群系：按区域指定群系（草案，可行性试验已做）

- 状态：草案（10-31）。可行性试验在沙盒里做过，没做正式命令。
- 依据：用户 10-31 的话：「选种子这个功能没有那么重要，它自然生成的未必是我们想要的效果，应该自己去定制想要的地形。可以对某一块区域强制要求确认是某一个群系，比如要一大整片海就把那一片全部弄成海洋群系；或者要一片山峰，可以根据我们的要求来定制生成群系。」所以选种不搬。
- 试验记录：数据根 `run/草稿/1031-1431-工作-定制群系/`（图、量数）；试验数据包 `sourcing/datapacks/实验/定制群系/`，世界声明 `sourcing/worlds/实验-定制群系.toml`、`实验-定制群系-对照.toml`。

## 做法（试验证明行得通）

不改群系本身，也不用 FillBiome 那类「事后写群系」：游戏的群系是按 6 个气候参数（温度、湿度、大陆度、侵蚀、深度、怪异度）查多噪声群系表得到的，
所以把这几个参数在区域里拉进目标群系的取值范围，群系、地形、地表方块、地物都由游戏自己照常算，和已有的「主世界修整」同一套机制（`mcai:region` + `mcai:edit`）。
不用改 mod。

| 要的 | 参数怎么拉（区域权重 1 时） |
|---|---|
| 海（任一海洋群系） | 大陆度 toward -0.8（`etn:overworld/continents`）。深海要大陆度 ≤ -0.455；海的冷暖照原来的温度噪声，不想要冻洋再把温度压到 ≥ -0.44 |
| 雪峰（frozen_peaks） | 大陆度 toward 0.5（≥ 0.03）、侵蚀 toward -0.9（≤ -0.78）、怪异度 toward 0.67（0.5666～0.7666，`etn:overworld/m/rm`）、温度 toward -0.7（≤ -0.45）、史诗地形的山强度 `etn:overworld/m/em` toward 1.6（只管高度） |

## 试验结果（沙盒，种子 116，两片 2 km 见方，falloff 300）

- 只拉参数就够，没用 FillBiome 后备，没改 mod。
- 区域 A（35000,-1168，天然陆地：森林、针叶林、桦木林，最高 211）改海：核心 1.4 km 见方 5661 列取样 100% 是海洋群系（深海 87.5%、冷水深海 12.5%）；对照里同一块海洋群系只占 26.6%。
  过渡带：深海到 700 m（距中心），800 m 起变海洋、冷水海洋，1000 m 起回到天然（平原、森林）；高度 24 → 59 m，约 300 m 宽。
- 区域 B（41500,-1168，天然深温海）改雪峰：核心 5950 列 99.9% 是 frozen_peaks，剩 3 列 dripstone_caves（地下群系）；最高实心 236、核心均 225。
  过渡带很陡：700 m 处还是 100% 峰，800 m 已是海，高度从 204 掉到 86 再到 33，约 200 m 宽。
  峰顶是一块 208～236 的平顶，不像自然山脉：em 直接 toward 1.6 把山强度的起伏压平了。要自然的山脉用 `add`（在原来的 em 上加）而不是 toward。
- 区域外：B 区域外 1054 列实验和对照 0 列不同；A 区域外 1054 列有 46 列不同，全在东侧离边 100～200 m 的黑森林里，群系 0 列不同，地面 y 一样，差在树、蘑菇、地表小物；
  同一份对照数据包重新生成一次，同一块区域外对照和对照也差 5.3%（850 列取样），所以这是游戏生成树时的不确定性，不是定制区域漏出去。
  结论：区域外地形、群系一格没变；地物有不确定性，要逐列相同的话本来就做不到（同一配置两次生成相差 0.4%～0.9%，森林里 3%～5%）。
- 没验证：区域内整块（只生成了十字条带，核心取样是条带里的列）；mod 加的群系；其他目标群系（平原、沙漠、恶地、樱花林）；两个相邻定制区域的接缝；冻洋这类冷海的海冰。

## 参数怎么从群系查

- 原版 1.20.1 群系表（数据生成器的 `reports/biome_parameters/minecraft/overworld.json`，7593 条）里，一个群系对应若干个 6 维盒子。
  做法：取目标群系所有盒子，挑一个「别的维度取值最宽」的盒子，取各维中点（要避开盒边）。frozen_peaks 的盒子有 12 种，选 怪异度 0.5666～0.7666、侵蚀 ≤ -0.78、大陆度 ≥ 0.03、温度 ≤ -0.45，湿度五档都行。
- 这份表现在只在旧项目 clone 里（`参考模型库/工具/选种/数据/overworld-1.20.1.biome_parameters.json.gz`，旧项目退役 bundle 里有）。要做正式命令得把它登记成资产（`anim extract` 从 client jar 的数据生成器导出，或从 mcdata 下载并登记 sha）。
- 地形高低另算：史诗地形里群系参数和高度不是同一个量（高度看 `em` 山强度、大陆度、侵蚀）。群系对了、地形不对（比如山峰群系但是平地）是最常见的坑，所以每个目标要配「高度参数」。

## 世界声明的写法（建议）

```toml
[["定制群系"]]
"名" = "雪山"
"群系" = "minecraft:frozen_peaks"
"形状" = { "类型" = "polygon", "点" = [[40500,-2168],[42500,-2168],[42500,-168],[40500,-168]] }   # 或 circle、path，同 mcai:region
"渐变" = 300            # falloff：区域边内多少米权重从 1 降到 0
"高度" = { "山强度" = 1.6 }   # 可选，不写就按群系表默认
```

`anim world` 读声明，生成数据包（区域文件 + 各覆盖文件里追加 edits），再接 `anim world new` 把包放进存档。数据包依赖史诗地形原文，只自用（许可 All Rights Reserved）。

## 怎么核对

1. `anim world pregen --两角` 预生成区域中心的十字条带（东西、南北各一条，别整块生成）。
2. 导出每列的最高实心方块和群系（试验用的 `dump.ts` 是读 `存档方块源`，正式做成 `anim world 群系统计`）。
3. 量：核心命中率、过渡带宽度、最高点、区域外和「去掉定制区域的对照世界」逐列比。对照世界和实验世界只差这两片区域。
4. 同一份数据包生成两次本来就会有 0.4%～0.9% 的列不同（树、地表小物，群系 0 列），区域外对照时要拿这个当底线。
