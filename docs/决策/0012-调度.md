# 0012：资源闸守底线，主 Agent 决定调度

日期：2026-11-01。状态：采用。

## 背景与归属

用户 10-04 定“控制一下并发，不要吃满内存”；10-05 定资源允许就多开，负载太大就一个一个来，综合 CPU 和内存；10-06 的“渲染并发降到 1”指标签页。30%、负载核×0.8、60 秒是 Agent 的实现，不是用户逐项定值。

用户 11-01 定：不能只依靠写死的程序，主 Agent 要适时看整体资源、动态规划；监控成本高就适当时候看；日志应足够复盘，而不是反查会话。任务定稿要求保留 30% 下限、GPU 位容量 1、MC 客户端互斥，不改像素、不增加自动派发服务。

## 决定

1. 内存准入在拿锁前。单票人工放行可越过队序和内存；critical 压力 4 默认仍挡，需额外 `--强`。文件清理可声明不开渲染，不判内存。
2. 队列 FIFO。主 Agent 用先、后、恢复、放行、让路、取消介入，必须写原因和快照。暂缓/让路默认 30 分钟，到期回队尾；原位恢复需明确选项。没有隐式环境变量优先级。
3. 普通多段段间重领票；正规批累计持锁 120 秒且有人等才交接，或显式让路。连贯必须说明原因；旧整批只能等或取消。
4. 月度追加调度日志，任务起止、票、锁、等待原因、身份、决定和告警可关联。同步信息文件提供在途帧数与心跳。SIGKILL 的崩溃由读者原子认领，非正常退出不再从耗时表消失。
5. 可注入的闸环境，测试隔离锁和日志。告警为纯函数，看守一次通知后退出，游标和去重持久化。没有事件不输出，父死退出，有界等待单独退出码。
6. 调度快路径不加载 Remotion。渲染参数、同页路径、段序和指纹算法不动。
7. 新旧长期共存：纯 pid 锁、原票名、主机旁文件、mtime 协议保留。`上次放行` 不能加第二行 pid：旧代码 `Number(全文)` 会得到 NaN；因此用旁文件扩展，旧读者继续守原间隔。无旁文件按旧语义处理。

## 未采用

不引入 15% 红线/黄线、不自动短作业优先、不设实验路数上限、不拆母版写锁、不改迁移改名工具、不解析代理 journal、不维护板.json、不改用户 hook 或 agent-context。GPU 并发与标签页并发仍是两个不同层次，均不在本次提高。

运行中压力只告警，不保证机器不卡，也不假定系统一定替我们回收 Chrome。长让路不自动关闭原渲染会话，以免改变同页加载历史；需要释放这一路内存时由主 Agent 明确取消。旧日志缺失的机器轨迹只能标未知，回测不编造精确数字。

用法和日志协议见 `../调度.md`；旧协议退役条件见 `../待办.md`。
