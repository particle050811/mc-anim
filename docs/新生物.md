# 新加一只 GeckoLib / YSM 生物

几何、贴图、动画都用 mod 里的原文件，不手抄数值。代码在 `engine/anim/基岩动画.ts`（播放器）、`engine/anim/动画控制器.ts`（控制器）、`engine/model/基岩实体.tsx`（组件）、`库/生物/定义生物.ts`（声明）。现成的例子：`作品/把回忆拼好给你/核对/基岩动画/魔法酒狐播放器版.ts`。

1. **取材配方**（`sourcing/extract.toml`）：jar 先登记在 `sourcing/jars.toml`。几何和贴图用 `导出模型`（GeckoLib 的基岩几何 json 原样导出骨骼和方块，`--去掉` 去掉用不到的骨骼）；动画文件用 `{脚本}/拷jar文件.py <jar> <jar 里的路径> <输出>` 原样拷出。产物 id 写 `模型/<类>/<名>`、`贴图/<类>/<名>/<皮肤>`、`动画/<类>/<名>`。
2. **资产表**：在 `assets/registry/模型.toml`、`贴图.toml`、`动画.toml` 各加一条，`来源` 写 `提取:<配方名>@<jar sha 前 12 位>`，`许可` 照 mod 的资产许可，`可见性` 写 `提取`。
3. **导出入库**：`anim extract <配方名>`，产物在数据根 `run/extract/<配方名>/src/…`；新 id 用 `anim assets add <id> <文件>` 进 `store/` 和资产锁。
4. **声明**（多部作品用的放 `库/生物/<名>.ts`，只有一部用的放作品里）：

   ```ts
   export const 狐狸 = 定义生物({
     名: '狐狸', 模型, 贴图,                       // import 'asset:…'
     缩放: 1 / 16,                                 // 模组有 render scale 的再乘上
     变体: { 毛色: ['红', '雪'] },                 // 可选；贴图写成 (v) => [底图[v.毛色], 眼睛层]
     动画: { 文件: 动画, 默认层们: [{ 名: 'idle' }, { 名: 'tail', 模式: '叠加' }], 口径: '通用' },
   });
   ```

   `默认层们` 照 mod 注册控制器的顺序写（后面的盖前面的）。`口径`：TLM（GeckoLib 3 分支）写 `'TLM'`，别的 GeckoLib 3/4、Blockbench 导出写 `'通用'`（默认）。动画里用到的 `q.*`、`v.*`、模组变量（`ysm.*`）在 `环境` 里给，没给的按 0 算、名字记进 `环境.未知`；`q.life_time` 不给按 `秒` 算；不给变量表时每帧一张新表（同一帧里前面的层赋的值后面读得到，不跨帧）。组件上的 `环境` 和定义里的按命名空间合并，只盖同名项。
5. **用**：`<狐狸 pose={{ loc, yaw }} 秒={帧 / fps} 变体={{ 毛色: '雪' }} />`。镜头里手摆的动作用 `姿势` 叠在动画上面；受伤、原版光照、发光、半透明见 `engine/model/实体材质.ts`。
6. **核对**：在作品的 `核对/` 里出静帧，和游戏截图比；有手抄版的照 `核对/基岩动画/对照.test.ts` 逐骨骼比。

## 控制器：什么时候播哪段、怎么换

代码在 `engine/anim/动画控制器.ts`，出来的是一个播放器，当成一层放进 `层们`：`{ 控制器: 播放器 }`（例子：`作品/把回忆拼好给你/核对/基岩动画/控制器示例.ts`）。播放器一般在模块里建一次，渲哪帧都从同一个对象取，结果只看时间、和取帧顺序无关。

- **GeckoLib 的控制器**（mod 代码里 `setAnimation` 的那种，GeckoLib 3/4、TLM 都是）：`GeckoLib控制器({ 名, 过渡刻, 安排, 动画们 })`。`安排` 是时刻表，`{ 秒, 播 }` 表示 handler 从这一刻起返回的 RawAnimation：一个动画名，或一串 `{ 名, 循环 }`（`'once'`/`'loop'`/`'hold'`/几遍）和 `{ 等刻 }`；`null` 是 STOP。换动画时在 `过渡刻` 内从当前姿势线性插到新动画第 0 刻的姿势，再从 0 开播；只插新动画有关键帧的骨骼，别的回原位（GeckoLib 4 原样，所以坐换站时 idle 不动 Root 会离地一下）。开头第一段也从原位过渡。
- **基岩版 `animation_controllers`**：`解析控制器文件(json)` 后 `基岩控制器(控制器, { 动画们, 名表, 环境, 步长 })`。`环境` 可以是 `(秒) => 环境`，转移条件拿它求；变量表控制器自己持有，`on_entry`/`on_exit` 写进去，动画读得到。默认每 1/20 秒推一步，转移最多晚一步。状态里的动画按权重叠加；`blend_transition`（秒数或曲线）期间离开的状态接着播、交叉淡化，`blend_via_shortest_path` 转角走近路。查询补了 `q.all_animations_finished`、`q.any_animation_finished`。

动画文件里的 `start_delay`、`loop_delay` 在 `'通用'` 口径下读（开播前不给骨骼；两遍之间停在末帧，这两处是推断的）。

## 和游戏对不上的已知处

- Molang 精度跟口径走：`'TLM'` 按 float（TLM 打包的 mocha），`'通用'` 按 double（GeckoLib 4 的 mclib）；环境里写 `数值` 能改。基岩版官方说是 float，基岩版文件用 `'通用'` 时要的话自己写 `数值: 'float'`。
- 缓动名照 GeckoLib 4.8.4 源码（`engine/anim/插值.ts` 写了哪些和 easings.net 不一样）。但 `'通用'` 的 catmullrom 取点（相邻关键帧）、`lerp_mode: step`（整段停在起点）、pre/post（同一时刻跳变）按基岩版写法；GeckoLib 4 是 catmullrom 前控制点取段起点、step 按 2 级缓动、pre 挪到前 0.001 秒、长度不算时间线，真要照 GeckoLib 4 时得再分一个口径。GeckoLib 4 也不读 `start_delay`/`loop_delay`。
- 控制器的简化：基岩版淡出中又转移时只留最近的上一个状态；GeckoLib 版切换时取本控制器自己给的姿势（游戏里是骨骼的总值），不支持 overrideEasingType、triggerableAnim、声音粒子关键帧；`推进`（逐步推时间线、`anim_time_update`）不管延迟。
