# 世界和地形（`anim world`）

渲染用的地形不是实时读存档，而是先烘成区段包（`engine/voxel/区段包.ts` 的格式），段声明用哪个包、哪一版。`anim world` 管从存档到区段包这一路，和不开游戏改地形、看地形。代码在 `pipeline/世界/`。

## 数据流

```
取材服务端的存档（<ANIM_GAME>/<服务端>/<存档>/…/region/r.<rx>.<rz>.mca，只读）
   │ 读存档：一个区域文件解成一份列段（每列从上往下按方块状态、群系并段）
   ▼
列段缓存 <数据根>/cache/列段/<sha 前 2>/<sha>.列段      键 = 区域文件 sha256 + 种子 + 读法版本，换存档自动失效
   │ 编辑层：sourcing/worlds/<世界>.编辑.toml 按顺序套上（只在内存里，存档和缓存都不动）
   ▼
烘焙：2048 米一块，第 0～6 级照 Voxy Mipper 合并，群系按种子抖动（和旧项目 工具/导入 逐字节一样）
   ▼
<数据根>/run/暂存/terrain/<包>/  → 算目录指纹 → <数据根>/terrain/<包>/<版本>/（版本 = 目录指纹前 12 位，只增不改）
   │ 登记：写进 assets/地形版本.json（随代码提交）
   ▼
段的 段.ts 声明地形包 → 渲染时只把声明的包和版本传给页面 → engine/voxel/导入地形.ts 按 terrain/<包>/<版本>/ 取
```

- 读存档只认 1.18+ 的区块格式（按 1.20.1 核过；只收状态是 `minecraft:full` 的区块）。1.17 及以前的区块（包在 `Level` 里）直接报错，不会当成没生成悄悄烘出空洞。
- **登记只让声明了这个包的段过期**：`assets/地形版本.json` 不进画面代码的闭包（`anim check` 拦着），渲染时由 `pipeline/渲/地形注入.ts` 把本段 `段.地形` 的包和版本传给页面，母版、叠层传的就是指纹的地形项（批次中途登记不影响正在渲的这批）。加新包、改别的包都不影响这段；渲染时读了没声明的包，页面直接报错，不退回全表。烘出来和登记的一样时什么都不写；试验、演示用的包在声明里写 `"登记" = false`，或烘的时候加 `--不登记`。Studio 传全表，开着时登记了新版本要重开才拿到。
- 每段实际读了哪些包和区段记在 `<数据根>/run/地形用量/<作品>/<段键>.json`，见 `docs/架构.md`「指纹、过期和验收」。
- 编排用的是冻结的粗高度（`assets/冻结粗高度/<包>.json`）。包变了粗高度跟着变时，`bake` 会提醒；`anim world freeze [<包…>]` 拿登记的那版包和冻结的那份比（版本、粗高度指纹、原点），不一样只报告、退出码 1，加 `--写` 才重写（冻结文件被编排 import，写了用它的段会过期，写完静帧核对航线）。
- Node 里执行 `engine/voxel/` 的格式和规则（区段包、区段解码、合并、方块表、群系色），不另抄一份：`pipeline/世界/体素库.ts` 先注册 `pipeline/资产/node资产钩子.ts`（`asset:` 的 JSON 资产按资产锁取数据根的字节），再按路径动态 import。这几个模块的闭包不许有 react、three、remotion（`存档.test.ts` 用 esbuild 守）。vitest 不走这个钩子，烘焙的端到端测试（`烘焙/烘焙.test.ts`：小存档套编辑烘成包，包和存档逐列比、烘两次比版本）起子进程跑，数据根里没有方块表字节就跳过。

## 世界声明 `sourcing/worlds/<世界>.toml`

一个存档里的一个维度。键带引号（TOML 1.0 的裸键只能是 ASCII）。

| 键 | 意思 |
|---|---|
| `名称` | 和文件名一样 |
| `服务端`、`存档` | 存档在 `<ANIM_GAME>/<服务端>/<存档>/`；`存档` 不写 = `名称`。`--存档 <世界目录>` 临时换 |
| `维度` | `minecraft:overworld`、`twilightforest:twilight_forest`、`minecraft:the_nether`；别的维度要在 `[烘焙]` 写 `包维度` |
| `种子`、`Forge`、`模组`、`另需模组文件`、`数据包` | 从头生成同一片地要的东西：`install-server` 按 `Forge`、`模组`、`另需模组文件` 装服务端，`new` 按 `种子`、`数据包` 建存档（`bake` 只核种子） |
| `世界类型`、`生成结构` | 建新存档时写进 `server.properties` 的 `level-type`（默认 `minecraft:normal`；地形模组改的是普通世界，`large_biomes` 和 Tectonic 互斥）、`generate-structures`（默认 true；主世界取材一律 false，用户 10-04 定）。它在 `level.dat` 里管所有维度，所以主世界和暮色各建各的存档 |
| `[预生成]` | `区域文件范围`、`区块数`，和 `[[预生成.块]]`：矩形写 `两角` 或 `中心`+`半边`；走廊写 `折线`（游戏 x、z 的点）+ `半宽`，`去掉` 列前面的矩形块名（盖住过的区块不再列）；都可写 `依据`。见下面「预生成和服务端」 |
| `[烘焙]` `原点` | 场景原点 `[ox, oy, oz]`：ox、oz 是 2048 的整数倍，oy 主世界 64、暮色 0、下界 0 |
| `[烘焙]` `全高` | 有顶的维度整个高度都存（见下面「有顶的维度」）。下界默认 true，别的默认 false |
| `[[烘焙.包]]` | `名`、`区域`（`{ RX = [a, b], RZ = [c, d] }`，不写 = 全部区域文件）、`原点`（不写用 `[烘焙]` 的）、`来源`、`套编辑`（默认 true）、`登记`（默认 true） |

现在有：`测试-修整-种子116`（包 测试-修整-岛，10-30 用 `anim world bake` 重烘和当时登记的格式 1 版本逐字节一样）、`暮色放大-1752`（包 暮色放大-1752-扩展，10-30 重烘也和当时的 b29dfba0d167 一样）、`主世界-116`（包 主世界-116，10-30 重烘 702 个区域文件，和当时的 9cd3fdcf8361 一样）、`测试-修整-编辑示例`（编辑层示例，包不登记）。

## 有顶的维度（全高，11-10 起）

露天维度的区段只存地表附近：每列最高的整格方块算地表，区段从各列最低的地表再往下 4 格起存，更下面当实心。下界从上往下第一层是 y 127 的基岩顶，照这个烘法只剩一层顶。
`[烘焙]` 的 `全高`（下界默认开）换一种地表：每列**最低的非整格方块（空气、熔岩、花草）的底**，也就是从维度底往上那一摞实心的顶。熔岩海、洞腔、岩顶都在它上面，照存；它下面全是整格方块，照旧当实心不存；浮空下地表那一步不跑。
格式、合并、编码都不变，渲染那边不用知道。不开 `全高` 的包烘出来和以前逐字节一样（`烘焙.test.ts` 的「全高」一条核不给和给 false 的目录指纹相同）。

- 粗高度图存的还是每格最高方块的顶，下界处处是 128：只能用来认导入范围，不能当地面（`anim world map`、`heightmap` 看到的也只是基岩顶，看洞腔用 `slice`）。
- 渲染时 `engine/voxel/导入地形.ts` 给的 `高度` 对下界是 NaN（它的维度下界表里没有下界；改它会让应力转动用地形的段全部过期，没动），用的地方自己给 `高度={[0, 128]}`，见 `作品/亚波伦不放水/地点/真下界.tsx`。
- 粗级照 Mipper 合并，粗格里有一块实心就是实心：远处的洞腔会缩小、岩顶变厚。

## 编辑层 `sourcing/worlds/<世界>.编辑.toml`

让 Agent 不开游戏就能改世界：照 MC 1.20.1 的命令写法，烘焙和查询时按顺序套到存档读出的方块上，存档本身不动。

```toml
"说明" = "整份编辑是干什么的"

[["步"]]
"说明" = "这一步为什么"
"命令" = """
fill 39690 66 -1230 39710 66 -1210 minecraft:smooth_stone
setblock 39700 68 -1220 minecraft:lantern[hanging=false]
"""
```

`命令` 是字符串（多行，一行一条，`#` 开头的行不算）或字符串数组。支持：

| 命令 | 写法 |
|---|---|
| fill | `fill x1 y1 z1 x2 y2 z2 <状态> [replace [<过滤>] \| keep \| hollow \| outline \| destroy]` |
| setblock | `setblock x y z <状态> [replace \| keep \| destroy]` |
| clone | `clone x1 y1 z1 x2 y2 z2 x y z [replace \| masked \| filtered <过滤>] [normal \| force \| move]` |
| 摆结构 | `place template <结构> x y z [none \| clockwise_90 \| 180 \| counterclockwise_90] [none \| front_back \| left_right]` |

- 坐标写绝对整数（没有执行者，`~` `^` 报错）。命令前的 `/` 可写可不写。
- `<状态>` 写 `命名空间:名字[属性=值,…]`，省了命名空间是 minecraft。按方块表（资产 `数据/场景/关键帧/方块表`）校验：方块 id、属性、值都要在表里，写错了报出是哪一步、表里有什么。表里只导了影响外观的属性，`waterlogged`、`distance`、`power` 这类照写不查。不支持方块标签（`#minecraft:logs`）和方块实体 NBT（`{…}`）；箱子、告示牌这类方块实体本来就不在表里。
- `<结构>`：`asset:<id>`（资产锁里的 .nbt / .schem），或相对 `sourcing/worlds/` 的路径（示例在 `sourcing/worlds/structures/`）。认原版结构方块存的 `.nbt` 和 Sponge / WorldEdit 的 `.schem`（版本 2、3）。结构空位（`structure_void`、原版结构里没列出的格）不动原来的方块；摆放点是结构的最小角，旋转、镜像照 place template（先镜像再绕最小角转），方块的 `facing`、`axis`、`rotation`、四向连接属性、铁轨 `shape` 跟着转。
- 和游戏一样的地方：按顺序执行，clone 读的是执行到这一步之前的世界（源可以在别的区域、可以是前几步改出来的）；`move` 把搬走的源格清成空气；`normal` 源和目标重叠报错。
- 和游戏不同的地方：不做方块更新（沙子不掉、水不流、楼梯和栅栏不重新连）；群系不动；`destroy` 当 `replace`；楼梯的 `shape` 镜像时不换左右（铁轨 `shape` 跟着转和镜像，门的 `hinge` 镜像时对调）；方块实体（箱子里的东西）丢掉；区块没生成的格跳过（`bake` 打印警告）；出了世界高度的部分不管。
- 编辑文件和用到的结构字节一起算 sha256，记进地形登记的 `来源`。
- `anim world edit check <世界>` 只校验；`anim world edit replay <世界>` 生成游戏里重放的命令（只生成不执行）：`<世界>.重放.sh`（`anim mcai batch`，先 `forceload add` 要改的区块、等 3 秒、改、再 `forceload remove`）和 `<世界>.重放.mcfunction`。超过 32768 格的 fill、clone 拆开，hollow / outline 拆成面和内部，结构展开成 fill / setblock。游戏里会做方块更新，重放的结果可能和烘焙的不一样。

## 查询

```
anim world block <世界> <x> <y> <z> [--列]
anim world heightmap <世界> <x1> <z1> <x2> <z2> [--表 <tsv>]
anim world map <世界> <x1> <z1> <x2> <z2>
anim world slice <世界> x|z <位置> <起> <止> [--y <y1>..<y2>]
```

- 来源：默认是存档套上编辑层；`--原样` 不套；`--包 <名> [--版本 <v>]` 读烘好的地形包（不写版本用登记的），看的是渲染实际拿到的方块。包只存了地表附近，第 0 级 `k底` 以下当实心、没存（切面图里画成斜纹）。
- 群系：存档读的是那一格自己的群系；包里是烘焙时按种子抖动过的（和游戏里看到的、渲染用的一样），两边在群系交界处会差一两格。
- 出图默认写到 `<数据根>/run/草稿/<UTC 月日-时分>-工作-世界/`，`--到 <文件>` 换地方；带坐标网格和刻度，北在上。颜色是方块表里那一面贴图的平均色乘群系染色，俯视图按高差打明暗，只是示意。小范围自动放大（一格最多 16 像素），大范围隔格取（长边约 2048 像素），`--像素 <n>` 指定。
- 范围里没有列段缓存、要从存档解的区域超过 2 个就过资源闸、并行读进缓存再画；少的只解要的区块。
- 列段缓存键要算区域文件的 sha256：超过 2 个文件就在工作线程里并行算（`算键工人.ts`），同一进程里按路径、大小、修改时间、种子记着，同一存档的两个来源共用。10-30 量：主世界-116 岛那 121 个区域（1.5 GB）从约 1.6 秒降到约 0.3 秒，702 个从约 3.5 秒降到约 0.6 秒（机器负载 20 多时量的），出的图逐字节一样。

## 装服务端和建新世界

```
anim world install-server <世界> [--服务端 <目录>] [--同意EULA] [--不装加载器]
anim world new <世界> [--服务端 <目录>] [--存档 <世界目录>] [--沙盒] [--堆 <G>] [--生成线程 <n>] [-- <命令…>]
```

旧项目 `取材服务端.py --new` 和手工装 Forge 的替代（`pipeline/世界/服务端/建世界.ts`、`安装.ts`）。从零生成一片地的顺序：`install-server` → `new` → `pregen --执行` → `bake`。

- `install-server`：Forge 安装器照 `sourcing/jars.toml` 的 `forge-installer`（核 sha256；本机没有按「下载」取）装进空目录（`--installServer`，要联网取原版服务端和依赖库，约 1 分钟）；声明的 `Forge` 要和登记的安装器版本一样。再按声明放模组（`模组` 的 jar id 取 jar 拷进 `mods/`，`另需模组文件` 按文件名找）、第三方数据包（jars.toml 登记了文件名的 zip，如史诗地形，放进 `世界数据包/`），没有 `server.properties` 就写一份取材用的（`max-tick-time=-1` 免得预生成时被看门狗杀；`online-mode=false`）。装过的目录只补模组和数据包，不重装；不是空目录又不是装好的 Forge 就拒绝。
  - `mcai`（取材 mod）是自己编的，不在这里：`anim mcai build` 装。缺的模组列出来、退出码 1。
  - `eula.txt` 不替人同意：默认不写，读过 Minecraft EULA 的人自己写 `eula=true`，或在命令行加 `--同意EULA` 表态。
- `new`：存档（默认 `<ANIM_GAME>/<服务端>/<存档>`；给了 `--服务端` 没给 `--存档` 就建在那个服务端目录下）已经有 `level.dat` 就拒绝，里面有别的东西也拒绝。先把声明的 `数据包` 找齐（相对 `sourcing/datapacks/`，或服务端 `世界数据包/` 下的，或 jars.toml 里文件名对得上的），缺一个不动手；放进 `<存档>/datapacks/`（第一次启动前放，建世界时自动启用，之后每个区块都按它来）；开服前核对数据包要的模组类在不在（`核对.ts` 的 `模组要求表`：生成时修整要 `TerrainTypes`，暮色放大 4 倍要 `TwilightGrid`，古城放大 4 倍要 `BigJigsaw`）；种子、世界类型、结构开关临时写进 `server.properties`，服务端就绪后改回原文（服务端会自己再补默认值）。就绪后核对启动日志里模组认出了数据包（暮色放大要 `暮色地标网格：64 区块`，古城放大要 `大拼图结构：minecraft:ancient_city`，带 `mcai:fill_biome` 的再要 `铺满群系：…`），修整包要启用并排在它覆盖的包之上；然后发 `--` 后面的命令（`sleep:`、`wait:`、`expect:` 同 `server`，例如 `locate` 核地标）、`save-all flush`、正常停服。停完没有 `level.dat` 或半路出错，没建成的目录收拾掉。`--沙盒` 只克隆服务端，新世界建在 `<数据根>/run/沙盒/…` 里。
- 种子、世界类型、结构开关只在建世界时读一次，建错了只能删掉重建，所以前面能查的都查在开服前。
- 存档就在服务端目录下时，起服不给 `--universe`（给了 Forge 的 `Main` 报 `Invalid world directory…the same directory as your universe` 不起服）；存档在别处（沙盒、`--存档`）才给。10-31 实跑时发现的，以前非沙盒的 `pregen --执行`、`server` 会撞上。
- 10-31 实跑：`install-server 测试-修整-种子116 --服务端 <草稿目录>` 在空目录里装出的 `libraries/` 文件清单和旧服务端逐项一样、`unix_args.txt` 逐字节一样；接着 `new 测试-修整-种子116 --服务端 <同一目录> --堆 4G`（4 个数据包，主世界修整包启用并排在史诗地形之上，种子 116、结构全禁，约 2 分钟），再 `pregen --两角 39680,-1216,39808,-1088 --执行`（81 个区块，主遍 5 秒，补洞读盘跳过），烘出的高度表和正式存档同一片 128×128 列比：16384 列里 22 列差 1～3 格（最高的非空气方块，树冠一类），地面一致。

## 预生成和服务端

```
anim world pregen <世界> [--块 <名> | --两角 x1,z1,x2,z2]        只打印 Chunky 命令（走廊块的 csv 写进草稿目录）
anim world pregen <世界> … --执行 [--沙盒] [--堆 12G] [--生成线程 <n>] [--卡住分钟 10] [--老年代上限 90] [--最多无进度重启 3] [--不补洞] [--重来]
anim world server <世界> [--沙盒] [--堆 <G>] -- <命令…>             起服务端、按顺序发命令、关服（sleep:<秒>、wait:<一句话>、expect:<一句话>）
```

- 算法照 Chunky 1.3.146：矩形的中心对齐区块，半径向上取整到区块，(2r+1)² 个区块；走廊是折线两侧 `半宽` 米以内的区块（按区块中心到折线的距离），去掉 `去掉` 列的矩形盖住的，交给 Chunky 的 csv 图案，选区是外包方形。`主世界-116` 的「航线」和旧项目 `主世界范围.py csv` 逐行一样（`预生成/预生成.test.ts` 核 sha256）。
- `--执行` 起的是专用服务端（不开客户端）：`<ANIM_GAME>/<服务端>/`，Forge 照 `Forge` 键用 `libraries/…/unix_args.txt`（Windows 用 `win_args.txt`），世界用 `--universe`、`--world` 指过去，端口挑空闲的。起服前：
  - 过资源闸（放行闸，等负载、内存够）；

- `--沙盒`：把服务端目录（不带里面的世界、日志）和存档用 `cp -c` 克隆到 `<数据根>/run/沙盒/<UTC 月日-时分>-<世界>/` 再跑，原存档、原服务端一个字节不动；试命令、试新数据包用。10-30 在 `测试-修整-种子116` 的沙盒里跑过 `--两角 2048,2048,2176,2176`（81 个区块：主遍 13 秒，补洞一遍读盘跳过，两次起服都正常停服、撤掉 Chunky）。
- 停服等存盘最多 300 秒，超时才杀。Mac 上起服时顺手 `caffeinate -i -w <pid>`，跑着的时候机器不闲置睡眠。

## 预生成提速试验（10-31 量）

沙盒、种子 116。量的时候机器上还有别的重任务（负载 3～30），只能看大致比例，不是干净的速度。

## 给方块表加模组方块
体素路（`engine/voxel/`、`engine/model/方块拼搭.tsx`）画哪些方块，看方块表（`数据/场景/关键帧/方块表` + 贴图竖条 `贴图/场景/关键帧/方块表`）里有没有那个方块状态。表由 `sourcing/extract/关键帧方块.py` 从 jar 的 blockstates、模型、贴图里查出来，任意模组都能读（variants、multipart、parent 链、元素旋转、`forge:composite`）。

表只增不改：脚本带 `--基 <旧表.json> <旧表.png>` 时，旧表的贴图号、面组号、方块顺序和图集像素原样留着，只在后面追加查不到的状态；没有可加的就原样拷出。

全局表现在不动，新方块加在**按作品的附加表**里（全局表 + 追加，登记在作品侧，作品的 `换用.toml` 让这部作品把全局表的两个 id 换成它）。原因：图集多一行，着色器里 `atlasUv` 的分母（行数）跟着变，旧方块的 UV 浮点值不一样，应力转动的 4K 静帧有几百个像素不同（11-10 实测：6-飞越主世界俯冲边城 第 400 帧 343 个、第 60 帧 6 个，6-进入森林 第 48 帧 95 个，都在树叶边缘；拿旧表配新图集出的静帧和新表的逐像素相同，所以差别只来自图集行数，查表结果没变）。要不要往全局表里加等用户定，见 `docs/待办.md`。

给一部作品加方块（例子是 亚波伦不放水 的粉色教堂，配方「方块附加-亚波伦不放水」）：
1. 模组 jar 登记进 `sourcing/jars.toml`（id、文件、sha256、许可）。
2. 列出要的方块状态。结构模板：`python sourcing/extract/关键帧方块.py --列状态 <结构.nbt>` 打出用到的状态，存成 `sourcing/方块状态/<名>.txt`（一行一个，`#` 是注释）。也可以在配方里直接给 `--结构 <.nbt>` 或 `--存档 <相对游戏环境的存档目录>`。
3. 在 `sourcing/extract.toml` 写一条配方（照「方块附加-亚波伦不放水」）：`"作品"`、`"可见性"`，`"需要"` 和 `--jar {jar:…}` 点名 jar（第一个是原版客户端，按顺序查、先找到的算），`"输入"` 摆全局表两件到 `基/`，步骤带 `--基 基/方块表.json 基/方块表.png --状态表 … --出 附加 --来源 {产物来源}`，产物是 `数据/方块附加/方块表`、`贴图/方块附加/方块表`。已有附加表的作品往状态表里加行、往 jar 名单里加 jar 就行。
4. `anim extract <配方> --作品 <作品> --登记`：第一次登记进作品资产表、写作品资产锁。以后重跑 sha 变了只报告，看过追加清单后 `anim assets add <id> <暂存目录里的文件> --作品 <作品> --替换` 两件都换。脚本会打出：追加了多少状态和贴图、给的 jar 里没有 blockstates 的方块、画不出的（没有元素，方块实体画的）。
5. 作品根写 `换用.toml`（`pipeline/资产/资产锁.ts` 的 套换用）：
   ```
   "数据/场景/关键帧/方块表" = "数据/方块附加/方块表"
   "贴图/场景/关键帧/方块表" = "贴图/方块附加/方块表"
   ```
   这部作品里 `asset:` 引用、打包、指纹拿到的都是附加表，别的作品不受影响。
6. 出静帧看。亚波伦不放水 的 `核对-体素教堂` 把结构转成方块列表（配方「粉色教堂体素方块」，`sourcing/extract/结构方块.py`）用 `方块拼搭` 画出来。

要注意的：
- 可见性：附加表里有资源「保留所有权益」的模组方块（灾变、妖怪归家、Prefab）时登记成私有，不能随 Release 公开发；全是可再分发许可的才能写 提取。
- 全局表换了（或基表变了）附加表要重跑，它的输入是全局表。作品选了材质包的，换完附加表重跑 `anim assets 材质包`。
- 染色：模组方块按群系、按位置变色的要在脚本的 `TINT` 里照它的 BlockColors 注册逐个补，不补就不染。
- 方块实体画的（箱子、告示牌、旗帜、头颅、`goety:lofty_chest`）和自定义模型加载器的（lootr、精妙背包）没有元素，体素路不画，要画的场景走导网格（`anim mcai mesh`）。
- 模组的多部件方块（栅栏、墙、扶手）：来源里出现过的带属性状态都导；属性组合数超过 `--多部件上限`（默认 256）的方块不再补全部组合。
- 贴图号上限 4096（`engine/voxel/网格.ts` 把贴图号并进 16 位数），现在全局 2478、亚波伦不放水 的附加表 2502。

## 地形压缩

现行代码读取 **格式 3**：逐格预测 + 32 类状态条件概率 + 每包训练先验。状态、群系、区段范围都逐格还原，不改画面。格式 2→3 的全包实测和取舍见 `docs/决策/0011-地形压缩.md`。

- 编码 `pipeline/世界/烘焙/区段编码.ts`，WASM 源码 `wasm/区段解码.ts`，解码包装 `engine/voxel/区段解码.ts`。`包.json` 和块头都是版本 3，索引、Range 方式不变。
- **每个版本目录必须有 `模型.bin`**。表是包的数据：和块文件一起算目录指纹、清单 sha256、发布附件，缺表报错，不从全局表补。表格式在 `engine/voxel/区段模型.ts`：小端头 + 状态类映射 + 概率初值 + 条件字面值权重。
- 模型只初始化概率，仍逐区段自适应、逐区段重置，没有相邻区段依赖。同包同区段无论前面解过什么、按什么顺序取，结果相同。
- 页面取 `包.json` 时只下载一次表，再广播给每个区段 Worker；按模型 URL（含包版本）留在 Worker，Range 活只发区段索引，不再传表或重新下载表。同包的不同挖空、平整来源共用一张表。
- 只有 WASM 生成文件进 Git。训练表不进代码闭包，改表只变包版本；段指纹仍只含本段声明的地形包。登记别的包不会让本段过期。
- `engine/`、查询只认格式 3；格式 1、2 的读法只在转码工具里。读旧包明确报错并提示拉取或转码，不静默尝试别的格式。

```
anim world 转码 <包…> [--从 <版本>] [--不登记] [--线程 <n>]   格式 1/2 → 3；新目录、读盘逐格核对、通过才登记
anim world 解码器 [--检查]                                  用锁定的 AssemblyScript 重编 WASM；--检查 只比较
```

### 训练、复现和小包

`bake` 和转码都自动调用 `pipeline/世界/烘焙/模型.ts`，每包学一次，不再有修改全局代码表的 `解码器 --训练`。

- 文件名按 UTF-8 字节排序、文件内按物理偏移排序；各 L 独立计数，每 40 段取第 0 段（覆盖所有有数据的 L）。无随机数、时间或机器路径。
- 训练样本里按状态行程次数选前 31 类，次数相同按状态号排序；其余及未见状态进第 32 类。预测/跳过带状态类，整列概率共享；字面值树按上一格状态类初始化，原色板的状态/群系对原样存。
- ≤1024 区段的小包把“训练表 + 全部编码”和“16 字节中性表 + 全部编码”都真正算一遍，选总字节更小的（相等选中性表）。大包不为了择表多做整包双编码；表成本及结果必须算在实测里。
- 新世界先在暂存目录生成使用中性表的中间包，等全部区段和状态号固定，再走和转码完全相同的训练/定稿流程；成功后删的只是暂存中间件，不删旧版本。不会为了训练再读一遍游戏存档。
- 同输入的烘焙、重烘、转码、换线程重转逐字节一致，由 `烘焙.test.ts` 守。整包大小含模型、`包.json`、块头、`缺失.tsv`。
- 编码后立即用正式 WASM 解回逐格比；转码另从磁盘解两边逐格比状态与群系，成功才登记。`anim check --深` 核每个文件的 sha、模型合法性和所有块头版本；不是用“能解开”代替完整性检查。
- `anim assets pack` 自动把表装进对应的内容寻址附件；`pull` 随包解开并核整包清单。只使用 Node、WASM、TypedArray 和现有 tar/curl 链路，不新增 Windows 原生依赖。Windows 实机性能需另测。
- `anim check` 比解码源码 sha（Windows CRLF 规范成 LF），`解码器 --检查` 才真实重编。改模型数据不重编 WASM；改解码语法必须升格式版本。
- 主世界-116-远景 是高度/群系 `.bin.gz`，不是区段格式，不转、版本不变。

下面是 **格式 1→2 的历史试验**，不是格式 3 的速度或压缩率：

试验时量的方案（方案都逐格还原无差异，正式转完的数字见 0011）：

| 方案 | 主世界 | 暮色 | 解到行程（毫秒/区段，空闲机器，Node） |
|---|---|---|---|
| 现状 | 100% | 100% | 0.03（Node 的 gunzip）；浏览器走 `DecompressionStream` 明显更贵 |
| 逐格上下文算术编码，JS（优化后） | 42% | 41% | 约 0.48（主世界） |
| 同上，WASM | 41.4% | 40.3% | 0.35 / 0.27 |
| 算术 + 区间跳过 + 整列标记 + 预训练初值，WASM（**用这个**） | 42.1% | 40.5% | 0.27 / 0.19 |
| 参考列区间编辑 + 静态 rANS（JS） | 59.1% | 55.4% | 0.54 / 0.20 |
| 第 0 档（不露面的格换成上一格号，要保留盒）+ 算术（用户定不做） | 27% | 36% | 改被遮挡的方块，主世界 14 帧静帧逐字节同 |

浏览器真跑（真区段工人）的纯加载，算术反而更省：主世界 1442 区段热跑 353→202 毫秒、浏览器 CPU 1640→970 毫秒；暮色 2783 区段 756→471 毫秒、3570→2020。去掉每区段一次的 `DecompressionStream` 是最可能的原因，没单独验证。GPU 和视频硬件解码这条路不划算：熵解码是串行的，小区段的解码器调度和回读开销大，AV1/HEVC 的无损模式也没有硬件保证（未实测）。
