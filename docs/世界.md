# 世界和地形（`anim world`）

渲染用的地形不是实时读存档，而是先烘成区段包（`engine/voxel/区段包.ts` 的格式），段声明用哪个包、哪一版。`anim world` 管从存档到区段包这一路，和不开游戏改地形、看地形。代码在 `pipeline/世界/`。

## 数据流

```
取材服务端的存档（<ANIM_GAME>/<服务端>/<存档>/…/region/r.<rx>.<rz>.mca，只读）
   │ 读存档：一个区域文件解成一份列段（每列从上往下按方块状态、群系并段）
   ▼
列段缓存 <数据根>/cache/列段/<sha 前 2>/<sha>.列段      键 = 区域文件 sha256 + 种子 + 读法版本，换存档自动失效
   │ 编辑层：sourcing/worlds/<世界>.编辑.toml 按顺序套上（只在内存里，存档和缓存都不动）
   ▼
烘焙：2048 米一块，第 0～6 级照 Voxy Mipper 合并，群系按种子抖动（和旧项目 工具/导入 逐字节一样）
   ▼
<数据根>/run/暂存/terrain/<包>/  → 算目录指纹 → <数据根>/terrain/<包>/<版本>/（版本 = 目录指纹前 12 位，只增不改）
   │ 登记：写进 assets/地形版本.json（随代码提交）
   ▼
段的 段.ts 声明地形包 → 渲染时 engine/voxel/导入地形.ts 按 terrain/<包>/<版本>/ 取
```

- 读存档只认 1.18+ 的区块格式（按 1.20.1 核过；只收状态是 `minecraft:full` 的区块）。1.17 及以前的区块（包在 `Level` 里）直接报错，不会当成没生成悄悄烘出空洞。
- **登记会让所有用地形的段过期**：`assets/地形版本.json` 被 `engine/voxel/区段包位置.ts` 整个 import，指纹按字节算，改一个包的版本（甚至加一个新包），所有用到任何地形包的段都过期。烘出来和登记的一样时什么都不写；试验、演示用的包在声明里写 `"登记" = false`，或烘的时候加 `--不登记`。
- 编排用的是冻结的粗高度（`assets/冻结粗高度/<包>.json`）。包变了粗高度跟着变时，`bake` 会提醒；重新冻结的工具（旧项目 `更新冻结粗高度.ts`）还没搬。
- Node 里执行 `engine/voxel/` 的格式和规则（区段包、合并、方块表、群系色），不另抄一份：`pipeline/世界/体素库.ts` 先注册 `pipeline/资产/node资产钩子.ts`（`asset:` 的 JSON 资产按资产锁取数据根的字节），再按路径动态 import。这几个模块的闭包不许有 react、three、remotion（`存档.test.ts` 用 esbuild 守）。vitest 不走这个钩子，烘焙的端到端测试（`烘焙/烘焙.test.ts`：小存档套编辑烘成包，包和存档逐列比、烘两次比版本）起子进程跑，数据根里没有方块表字节就跳过。

## 世界声明 `sourcing/worlds/<世界>.toml`

一个存档里的一个维度。键带引号（TOML 1.0 的裸键只能是 ASCII）。

| 键 | 意思 |
|---|---|
| `名称` | 和文件名一样 |
| `服务端`、`存档` | 存档在 `<ANIM_GAME>/<服务端>/<存档>/`；`存档` 不写 = `名称`。`--存档 <世界目录>` 临时换 |
| `维度` | `minecraft:overworld`、`twilightforest:twilight_forest`；别的维度要在 `[烘焙]` 写 `包维度` |
| `种子`、`Forge`、`模组`、`另需模组文件`、`数据包` | 从头生成同一片地要的东西（记录用；`bake` 只核种子） |
| `[预生成]` | `区域文件范围`、`区块数`，和 `[[预生成.块]]`（`名`、`两角` 或 `中心`+`半边`、`依据`），`anim world pregen` 照它打印 Chunky 命令 |
| `[烘焙]` `原点` | 场景原点 `[ox, oy, oz]`：ox、oz 是 2048 的整数倍，oy 主世界 64、暮色 0 |
| `[[烘焙.包]]` | `名`、`区域`（`{ RX = [a, b], RZ = [c, d] }`，不写 = 全部区域文件）、`原点`（不写用 `[烘焙]` 的）、`来源`、`套编辑`（默认 true）、`登记`（默认 true） |

现在有：`测试-修整-种子116`（包 测试-修整-岛，10-30 用 `anim world bake` 重烘和登记的版本逐字节一样）、`暮色放大-1752`（包 暮色放大-1752-扩展，10-30 重烘也和登记的版本 b29dfba0d167 一样）、`测试-修整-编辑示例`（编辑层示例，包不登记）。

## 编辑层 `sourcing/worlds/<世界>.编辑.toml`

让 Agent 不开游戏就能改世界：照 MC 1.20.1 的命令写法，烘焙和查询时按顺序套到存档读出的方块上，存档本身不动。

```toml
"说明" = "整份编辑是干什么的"

[["步"]]
"说明" = "这一步为什么"
"命令" = """
fill 39690 66 -1230 39710 66 -1210 minecraft:smooth_stone
setblock 39700 68 -1220 minecraft:lantern[hanging=false]
"""
```

`命令` 是字符串（多行，一行一条，`#` 开头的行不算）或字符串数组。支持：

| 命令 | 写法 |
|---|---|
| fill | `fill x1 y1 z1 x2 y2 z2 <状态> [replace [<过滤>] \| keep \| hollow \| outline \| destroy]` |
| setblock | `setblock x y z <状态> [replace \| keep \| destroy]` |
| clone | `clone x1 y1 z1 x2 y2 z2 x y z [replace \| masked \| filtered <过滤>] [normal \| force \| move]` |
| 摆结构 | `place template <结构> x y z [none \| clockwise_90 \| 180 \| counterclockwise_90] [none \| front_back \| left_right]` |

- 坐标写绝对整数（没有执行者，`~` `^` 报错）。命令前的 `/` 可写可不写。
- `<状态>` 写 `命名空间:名字[属性=值,…]`，省了命名空间是 minecraft。按方块表（资产 `数据/场景/关键帧/方块表`）校验：方块 id、属性、值都要在表里，写错了报出是哪一步、表里有什么。表里只导了影响外观的属性，`waterlogged`、`distance`、`power` 这类照写不查。不支持方块标签（`#minecraft:logs`）和方块实体 NBT（`{…}`）；箱子、告示牌这类方块实体本来就不在表里。
- `<结构>`：`asset:<id>`（资产锁里的 .nbt / .schem），或相对 `sourcing/worlds/` 的路径（示例在 `sourcing/worlds/structures/`）。认原版结构方块存的 `.nbt` 和 Sponge / WorldEdit 的 `.schem`（版本 2、3）。结构空位（`structure_void`、原版结构里没列出的格）不动原来的方块；摆放点是结构的最小角，旋转、镜像照 place template（先镜像再绕最小角转），方块的 `facing`、`axis`、`rotation`、四向连接属性、铁轨 `shape` 跟着转。
- 和游戏一样的地方：按顺序执行，clone 读的是执行到这一步之前的世界（源可以在别的区域、可以是前几步改出来的）；`move` 把搬走的源格清成空气；`normal` 源和目标重叠报错。
- 和游戏不同的地方：不做方块更新（沙子不掉、水不流、楼梯和栅栏不重新连）；群系不动；`destroy` 当 `replace`；楼梯的 `shape` 镜像时不换左右（铁轨 `shape` 跟着转和镜像，门的 `hinge` 镜像时对调）；方块实体（箱子里的东西）丢掉；区块没生成的格跳过（`bake` 打印警告）；出了世界高度的部分不管。
- 编辑文件和用到的结构字节一起算 sha256，记进地形登记的 `来源`。
- `anim world edit check <世界>` 只校验；`anim world edit replay <世界>` 生成游戏里重放的命令（只生成不执行）：`<世界>.重放.sh`（`anim mcai batch`，先 `forceload add` 要改的区块、等 3 秒、改、再 `forceload remove`）和 `<世界>.重放.mcfunction`。超过 32768 格的 fill、clone 拆开，hollow / outline 拆成面和内部，结构展开成 fill / setblock。游戏里会做方块更新，重放的结果可能和烘焙的不一样。

## 查询

```
anim world block <世界> <x> <y> <z> [--列]
anim world heightmap <世界> <x1> <z1> <x2> <z2> [--表 <tsv>]
anim world map <世界> <x1> <z1> <x2> <z2>
anim world slice <世界> x|z <位置> <起> <止> [--y <y1>..<y2>]
```

- 来源：默认是存档套上编辑层；`--原样` 不套；`--包 <名> [--版本 <v>]` 读烘好的地形包（不写版本用登记的），看的是渲染实际拿到的方块。包只存了地表附近，第 0 级 `k底` 以下当实心、没存（切面图里画成斜纹）。
- 群系：存档读的是那一格自己的群系；包里是烘焙时按种子抖动过的（和游戏里看到的、渲染用的一样），两边在群系交界处会差一两格。
- 出图默认写到 `<数据根>/run/草稿/<UTC 月日-时分>-工作-世界/`，`--到 <文件>` 换地方；带坐标网格和刻度，北在上。颜色是方块表里那一面贴图的平均色乘群系染色，俯视图按高差打明暗，只是示意。小范围自动放大（一格最多 16 像素），大范围隔格取（长边约 2048 像素），`--像素 <n>` 指定。
- 范围里没有列段缓存、要从存档解的区域超过 2 个就过资源闸、并行读进缓存再画；少的只解要的区块。
