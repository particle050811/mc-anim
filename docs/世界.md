# 世界和地形（`anim world`）

渲染用的地形不是实时读存档，而是先烘成区段包（`engine/voxel/区段包.ts` 的格式），段声明用哪个包、哪一版。`anim world` 管从存档到区段包这一路，和不开游戏改地形、看地形。代码在 `pipeline/世界/`。

## 数据流

```
取材服务端的存档（<ANIM_GAME>/<服务端>/<存档>/…/region/r.<rx>.<rz>.mca，只读）
   │ 读存档：一个区域文件解成一份列段（每列从上往下按方块状态、群系并段）
   ▼
列段缓存 <数据根>/cache/列段/<sha 前 2>/<sha>.列段      键 = 区域文件 sha256 + 种子 + 读法版本，换存档自动失效
   │ 编辑层：sourcing/worlds/<世界>.编辑.toml 按顺序套上（只在内存里，存档和缓存都不动）
   ▼
烘焙：2048 米一块，第 0～6 级照 Voxy Mipper 合并，群系按种子抖动（和旧项目 工具/导入 逐字节一样）
   ▼
<数据根>/run/暂存/terrain/<包>/  → 算目录指纹 → <数据根>/terrain/<包>/<版本>/（版本 = 目录指纹前 12 位，只增不改）
   │ 登记：写进 assets/地形版本.json（随代码提交）
   ▼
段的 段.ts 声明地形包 → 渲染时只把声明的包和版本传给页面 → engine/voxel/导入地形.ts 按 terrain/<包>/<版本>/ 取
```

- 读存档只认 1.18+ 的区块格式（按 1.20.1 核过；只收状态是 `minecraft:full` 的区块）。1.17 及以前的区块（包在 `Level` 里）直接报错，不会当成没生成悄悄烘出空洞。
- **登记只让声明了这个包的段过期**：`assets/地形版本.json` 不进画面代码的闭包（`anim check` 拦着），渲染时由 `pipeline/渲/地形注入.ts` 把本段 `段.地形` 的包和版本传给页面，母版、叠层传的就是指纹的地形项（批次中途登记不影响正在渲的这批）。加新包、改别的包都不影响这段；渲染时读了没声明的包，页面直接报错，不退回全表。烘出来和登记的一样时什么都不写；试验、演示用的包在声明里写 `"登记" = false`，或烘的时候加 `--no-register`。Studio 传全表，开着时登记了新版本要重开才拿到。
- 每段实际读了哪些包和区段记在 `<数据根>/run/地形用量/<作品>/<段键>.json`，见 `docs/架构.md`「指纹、过期和验收」。
- 编排用的是冻结的粗高度（`assets/冻结粗高度/<包>.json`）。包变了粗高度跟着变时，`bake` 会提醒；`anim world freeze [<包…>]` 拿登记的那版包和冻结的那份比（版本、粗高度指纹、原点），不一样只报告、退出码 1，加 `--write` 才重写（冻结文件被编排 import，写了用它的段会过期，写完静帧核对航线）。
- Node 里执行 `engine/voxel/` 的格式和规则（区段包、区段解码、合并、方块表、群系色），不另抄一份：`pipeline/世界/体素库.ts` 先注册 `pipeline/资产/node资产钩子.ts`（`asset:` 的 JSON 资产按资产锁取数据根的字节），再按路径动态 import。这几个模块的闭包不许有 react、three、remotion（`存档.test.ts` 用 esbuild 守）。vitest 不走这个钩子，烘焙的端到端测试（`烘焙/烘焙.test.ts`：小存档套编辑烘成包，包和存档逐列比、烘两次比版本）起子进程跑，数据根里没有方块表字节就跳过。

## 世界声明 `sourcing/worlds/<世界>.toml`

一个存档里的一个维度。键带引号（TOML 1.0 的裸键只能是 ASCII）。

| 键 | 意思 |
|---|---|
| `名称` | 和文件名一样 |
| `服务端`、`存档` | 存档在 `<ANIM_GAME>/<服务端>/<存档>/`；`存档` 不写 = `名称`。`--save-dir <世界目录>` 临时换 |
| `维度` | `minecraft:overworld`、`twilightforest:twilight_forest`、`minecraft:the_nether`；别的维度要在 `[烘焙]` 写 `包维度` |
| `种子`、`Forge`、`模组`、`另需模组文件`、`数据包` | 从头生成同一片地要的东西：`install-server` 按 `Forge`、`模组`、`另需模组文件` 装服务端，`new` 按 `种子`、`数据包` 建存档（`bake` 只核种子） |
| `世界类型`、`生成结构` | 建新存档时写进 `server.properties` 的 `level-type`（默认 `minecraft:normal`；地形模组改的是普通世界，`large_biomes` 和 Tectonic 互斥）、`generate-structures`（默认 true；主世界取材一律 false，用户 10-04 定）。它在 `level.dat` 里管所有维度，所以主世界和暮色各建各的存档 |
| `[预生成]` | `区域文件范围`、`区块数`，和 `[[预生成.块]]`：矩形写 `两角` 或 `中心`+`半边`；走廊写 `折线`（游戏 x、z 的点）+ `半宽`，`去掉` 列前面的矩形块名（盖住过的区块不再列）；都可写 `依据`。见下面「预生成和服务端」 |
| `[烘焙]` `原点` | 场景原点 `[ox, oy, oz]`：ox、oz 是 2048 的整数倍，oy 主世界 64、暮色 0、下界 0 |
| `[烘焙]` `全高` | 有顶的维度整个高度都存（见下面「有顶的维度」）。下界默认 true，别的默认 false |
| `[烘焙]` `填充` | 可见变换把埋住的整格、封死的腔换成的方块（默认 `minecraft:stone`；下界没有石头，写 `minecraft:netherrack`）。要是这个包状态表里有的整格方块 |
| `[[烘焙.保真]]` | 可见变换原样保留的范围：`名`、`盒`（游戏坐标 `[x0, z0, x1, z1]`，两端都含）、`出处`。作品渲染时挖开、整平导入地形的地方都要在盒里（`anim check` 核，见下面「可见变换」） |
| `[[烘焙.包]]` | `名`、`区域`（`{ RX = [a, b], RZ = [c, d] }`，不写 = 全部区域文件）、`原点`（不写用 `[烘焙]` 的）、`来源`、`套编辑`（默认 true）、`登记`（默认 true） |

声明在 `sourcing/worlds/`（`anim world list` 列出），如 `主世界-116`、`暮色放大-1752`、`测试-修整-种子116`、`测试-修整-编辑示例`（编辑层示例，包不登记）。

## 有顶的维度（全高，11-10 起）

露天维度的区段只存地表附近：每列最高的整格方块算地表，区段从各列最低的地表再往下 4 格起存，更下面当实心。下界从上往下第一层是 y 127 的基岩顶，照这个烘法只剩一层顶。
`[烘焙]` 的 `全高`（下界默认开）换一种地表：每列**最低的非整格方块（空气、熔岩、花草）的底**，也就是从维度底往上那一摞实心的顶。熔岩海、洞腔、岩顶都在它上面，照存；它下面全是整格方块，照旧当实心不存；浮空下地表那一步不跑。
格式、合并、编码都不变，渲染那边不用知道。不开 `全高` 的包烘出来和以前逐字节一样（`烘焙.test.ts` 的「全高」一条核不给和给 false 的目录指纹相同）。

- 粗高度图存的还是每格最高方块的顶，下界处处是 128：只能用来认导入范围，不能当地面（`anim world map`、`heightmap` 看到的也只是基岩顶，看洞腔用 `slice`）。
- 渲染时 `engine/voxel/导入地形.ts` 给的 `高度` 对下界是 NaN（它的维度下界表里没有下界；改它会让应力转动用地形的段全部过期，没动），用的地方自己给 `高度={[0, 128]}`，见 `作品/亚波伦不放水/地点/真下界.tsx`。
- 粗级照 Mipper 合并，粗格里有一块实心就是实心：远处的洞腔会缩小、岩顶变厚。

## 立方区块存档（Better Cubic Chunks，11-17 起）

别人给的 1.21.1 存档，方块在 `cubes/r.<X>.<Y>.<Z>.mcr3d`（世界没有固定高度）。声明写 `"saveFormat" = "mcr3d"` 和 `"yRange" = [y0, y1]`（烘哪一段高度，游戏 y，两端都含，减 oy 对齐 64），`anim world bake` 照常烘。读取器 `pipeline/世界/立方存档.ts`；存档格式抽成了接口（`存档格式.ts`），`.mca` 是另一个实现，行为不变。例子：`sourcing/worlds/珠峰-真实地球.toml`。

模组没公开源码，格式是照存档逆向的：

- 一个文件 16 × 16 × 16 个 cube（每边 256 格），一个 cube 16³ 格。文件头 8 个扇区（一扇区 4096 字节）：4096 项 u32 大端「(扇区号 << 8) | 扇区数」，再 4096 项时间戳；项号 = `(y << 8) | (z << 4) | x`。
- cube：u32 大端长度、u8 压缩方式（见到的都是 3：u32 大端解压后长度 + LZ4 原始块，不是 LZ4 帧），解开是 NBT：`block_states { palette, data }`、`biomes { palette, data }`（紧凑数组同原版区段）、`status`。
- 怎么核的：项号里 x、y、z 的先后试了四种排法，比相邻两列的高度差在「跨 cube 边界」和「cube 内部」是不是一样小，只有一种是；跨文件边界同法；最后和同一个存档里 DH 库的列顶逐列对。

立方存档只存玩家到过的 cube，一列从上到下不一定都在。取舍：

- 只收 `status` 5（生成完）的 cube，别的是生成到一半的（只有粗地形）。
- 从上往下，没存的 cube 在这一列碰到第一格非空气之前当空气，之后当石头。
- 第一格非空气的正上方得是存着的格才算知道地表，不然这一列记成没数据（只飞过高空、只存了地下一截的列不烘成实心柱）。

几千格高的世界不用改包格式：区段本来就只存地表附近（各列最低地表往下 4 格起），场景 z = y − oy。烘焙里按高度摊开的整表（候选群系格）改成了按列存段。

别人给的存档烘的包：声明的包（`[[bake.pack]]`、`[dh]`）可以写 `license`、`visibility`，许可没核实的写 `LicenseRef-Origin-Unverified`、`私有`。可见性私有的地形包不进发布附件（`pipeline/分发/发布.ts`），用它的段在段目录放 `本机地形.txt`，别的机器没有这个包就跳过那段。

## DH 的 LOD 库（11-17 起）

存档里的 `data/DistantHorizons.sqlite` 是 Distant Horizons 存的 LOD：玩家附近细、远处粗，范围比方块存档大得多。珠峰存档生成完的方块只有 13 km²，DH 里知道地表的列：1 米一列 19.7 km²，2、4、8、16、32、64 米一列分别 57、168、420、832、1598、3758 km²，128 米一列 13422 km²，256 米一列铺到 ±1048 km。`anim world bake-dh <世界>` 直接拿它烘区段包，声明写：

```toml
["dh"]
"db" = "data/DistantHorizons.sqlite"        # 相对存档目录
"pack" = "珠峰-真实地球-DH"
"extent" = [-77824, -86016, 69632, 77824]   # 游戏坐标 [x0, z0, x1, z1)，4096 的整数倍
"yRange" = [-64, 8959]                      # 游戏 y，两端都含，减 oy 对齐 64
# 可选：origin（不写用 [bake] 的，ox、oz 要是 4096 的整数倍）、source、license、visibility
```

**格式**（立方区块版的 DH，表 `FullDataCubic`；这个分支没公开源码，照库逆向，读法在 `pipeline/世界/dh/读库.ts`）：

- 一行 = `(DetailLevel, PosX, PosY, PosZ)`。第 L 级一列 2^L 米见方，一个区段 64 × 64 列；竖直方向始终 1 格一档，一行管 `min(64·2^L, 2048)` 格高。珠峰库 66.98 万行，第 0～12 级都有，都是 `DataFormatVersion` 2、`CompressionMode` 4（zstd）。
- `Mapping`：u32 大端条数，每条 Java UTF「`<群系>_DH-BSW_<方块>_STATE_{属性:值}…`」，空气是「`<群系>_DH-BSW_AIR`」。
- `Data`：内圈 62 × 62 列；四条边各 64 列在 `North/South/East/WestAdjData`。每块依次是各列点数、全部点的「(映射号 << 2) | 标志」、全部点的高度（varint；一列从上往下，加起来 = 行高，空气也是点）。
- 怎么核的：第 0 级的列顶和 `.mcr3d` 读取器读出的逐列对。

**内圈的列是有损的**：四周和上下都被挡住的格不单独记，并进它上面那个点；四条边没并。整格方块并了看不出来。雪层、细雪这类引擎逐格出面、不合并的方块并了以后是几十格高的一段（内圈雪层 93%、细雪 92% 是高段，最高 60 多格；四条边上雪层都是 1 格、细雪最高 5 格），照原样导入一个区段几十万面；这一列第一个整格方块在段底，区段的底也跟着拉下去几十到几千格。读库里的处理：

- `HIDDEN_BELOW` 表里的方块（雪层、细雪、苔藓地毯、土径、耕地）在第 0 级内圈的高段只留最上一格，下面换成对应的整格方块（雪层、细雪换雪块）；第 1 级起整段都换，四条边也换。
- 只留地表往下 64 格的细节，再往下并成石头一直到底。
- 栅栏、台阶这类没进表的照原样（并进来的都埋在地下，看不见，只多费面）。

**烘法**（`pipeline/世界/dh/烘焙.ts`）：我们的第 L 级直接取 DH 的第 L 级，不从第 0 级往上合并。

- 第 6 级铺满 `extent`，没有的地方拿 DH 第 7、8 级的列放大。
- 往下每级：一个区段只要它的父区段里有 DH 原生的更细数据就写，四个兄弟一起写；兄弟里 DH 没有这一级的列拿上一级放大。
- 各处最细到哪一级不一样，`包.json` 多一项 `splittable`（每级一张位图：这个区段能不能再细分）。引擎每帧挑区段和航线定级都认它（`engine/voxel/区段包.ts` 的 `decodeSplittable`，`区段.ts`、`航线定级.ts` 的 `canSplit`），不能分的停在那一级；没有这一项的包行为不变。
- 竖直方向按 2^L 米一格量化，最上面那段非空气至少留一格。定稿（学模型、可见变换）和 `bake` 走同一条路（`烘焙/烘焙.ts` 的 `finishPack`）。

更远处：第 8 级以上（256～4096 米一列）铺到 ±1048 km，可以照「暮色超远景」做成高度图远景，没做。方块表是按 1.20.1 导的，1.21 的方块（凝灰岩砖、铜格栅、试炼刷怪笼等）没有，记在包的 `缺失.tsv`，画不出来。

## 编辑层 `sourcing/worlds/<世界>.编辑.toml`

让 Agent 不开游戏就能改世界：照 MC 1.20.1 的命令写法，烘焙和查询时按顺序套到存档读出的方块上，存档本身不动。

```toml
"说明" = "整份编辑是干什么的"

[["步"]]
"说明" = "这一步为什么"
"命令" = """
fill 39690 66 -1230 39710 66 -1210 minecraft:smooth_stone
setblock 39700 68 -1220 minecraft:lantern[hanging=false]
"""
```

`命令` 是字符串（多行，一行一条，`#` 开头的行不算）或字符串数组。支持：

| 命令 | 写法 |
|---|---|
| fill | `fill x1 y1 z1 x2 y2 z2 <状态> [replace [<过滤>] \| keep \| hollow \| outline \| destroy]` |
| setblock | `setblock x y z <状态> [replace \| keep \| destroy]` |
| clone | `clone x1 y1 z1 x2 y2 z2 x y z [replace \| masked \| filtered <过滤>] [normal \| force \| move]` |
| 摆结构 | `place template <结构> x y z [none \| clockwise_90 \| 180 \| counterclockwise_90] [none \| front_back \| left_right]` |

- 坐标写绝对整数（没有执行者，`~` `^` 报错）。命令前的 `/` 可写可不写。
- `<状态>` 写 `命名空间:名字[属性=值,…]`，省了命名空间是 minecraft。按方块表（资产 `数据/场景/关键帧/方块表`）校验：方块 id、属性、值都要在表里，写错了报出是哪一步、表里有什么。表里只导了影响外观的属性，`waterlogged`、`distance`、`power` 这类照写不查。不支持方块标签（`#minecraft:logs`）和方块实体 NBT（`{…}`）；箱子、告示牌这类方块实体本来就不在表里。
- `<结构>`：`asset:<id>`（资产锁里的 .nbt / .schem），或相对 `sourcing/worlds/` 的路径（示例在 `sourcing/worlds/structures/`）。认原版结构方块存的 `.nbt` 和 Sponge / WorldEdit 的 `.schem`（版本 2、3）。结构空位（`structure_void`、原版结构里没列出的格）不动原来的方块；摆放点是结构的最小角，旋转、镜像照 place template（先镜像再绕最小角转），方块的 `facing`、`axis`、`rotation`、四向连接属性、铁轨 `shape` 跟着转。
- 和游戏一样的地方：按顺序执行，clone 读的是执行到这一步之前的世界（源可以在别的区域、可以是前几步改出来的）；`move` 把搬走的源格清成空气；`normal` 源和目标重叠报错。
- 和游戏不同的地方：不做方块更新（沙子不掉、水不流、楼梯和栅栏不重新连）；群系不动；`destroy` 当 `replace`；楼梯的 `shape` 镜像时不换左右（铁轨 `shape` 跟着转和镜像，门的 `hinge` 镜像时对调）；方块实体（箱子里的东西）丢掉；区块没生成的格跳过（`bake` 打印警告）；出了世界高度的部分不管。
- 编辑文件和用到的结构字节一起算 sha256，记进地形登记的 `来源`。
- `anim world edit check <世界>` 只校验；`anim world edit replay <世界>` 生成游戏里重放的命令（只生成不执行）：`<世界>.重放.sh`（`anim mcai batch`，先 `forceload add` 要改的区块、等 3 秒、解冻、改、再 `forceload remove`，等 10 秒照原样冻回去：`game start` 进存档默认冻结，冻着时水流、沙子落下不跑）和 `<世界>.重放.mcfunction`。超过 32768 格的 fill、clone 拆开，hollow / outline 拆成面和内部，结构展开成 fill / setblock。游戏里会做方块更新，重放的结果可能和烘焙的不一样。

## 查询

```
anim world block <世界> <x> <y> <z> [--column]
anim world heightmap <世界> <x1> <z1> <x2> <z2> [--table <tsv>]
anim world map <世界> <x1> <z1> <x2> <z2>
anim world slice <世界> x|z <位置> <起> <止> [--y <y1>..<y2>]
```

- 来源：默认是存档套上编辑层；`--raw` 不套；`--pack <名> [--version <v>]` 读烘好的地形包（不写版本用登记的），看的是渲染实际拿到的方块。包只存了地表附近，第 0 级 `k底` 以下当实心、没存（切面图里画成斜纹）。
- 群系：存档读的是那一格自己的群系；包里是烘焙时按种子抖动过的（和游戏里看到的、渲染用的一样），两边在群系交界处会差一两格。
- 出图默认写到 `<数据根>/run/草稿/<UTC 月日-时分>-工作-世界/`，`--to <文件>` 换地方；带坐标网格和刻度，北在上。颜色是方块表里那一面贴图的平均色乘群系染色，俯视图按高差打明暗，只是示意。小范围自动放大（一格最多 16 像素），大范围隔格取（长边约 2048 像素），`--pixels <n>` 指定。
- 范围里没有列段缓存、要从存档解的区域超过 2 个就过资源闸、并行读进缓存再画；少的只解要的区块。
- 列段缓存键要算区域文件的 sha256：超过 2 个文件就在工作线程里并行算（`算键工人.ts`），同一进程里按路径、大小、修改时间、种子记着，同一存档的两个来源共用。

## 装服务端和建新世界

```
anim world install-server <世界> [--server-dir <目录>] [--accept-eula] [--no-loader]
anim world new <世界> [--server-dir <目录>] [--save-dir <世界目录>] [--sandbox] [--heap <G>] [--gen-threads <n>] [-- <命令…>]
```

代码在 `pipeline/世界/服务端/建世界.ts`、`安装.ts`。从零生成一片地的顺序：`install-server` → `new` → `pregen --apply` → `bake`。

- `install-server`：Forge 安装器照 `sourcing/jars.toml` 的 `forge-installer`（核 sha256；本机没有按「下载」取）装进空目录（`--installServer`，要联网取原版服务端和依赖库，约 1 分钟）；声明的 `Forge` 要和登记的安装器版本一样。再按声明放模组（`模组` 的 jar id 取 jar 拷进 `mods/`，`另需模组文件` 按文件名找）、第三方数据包（jars.toml 登记了文件名的 zip，如史诗地形，放进 `世界数据包/`），没有 `server.properties` 就写一份取材用的（`max-tick-time=-1` 免得预生成时被看门狗杀；`online-mode=false`）。装过的目录只补模组和数据包，不重装；不是空目录又不是装好的 Forge 就拒绝。
  - `mcai`（取材 mod）是自己编的，不在这里：`anim mcai build` 装。缺的模组列出来、退出码 1。
  - `eula.txt` 不替人同意：默认不写，读过 Minecraft EULA 的人自己写 `eula=true`，或在命令行加 `--accept-eula` 表态。
- `new`：存档（默认 `<ANIM_GAME>/<服务端>/<存档>`；给了 `--server-dir` 没给 `--save-dir` 就建在那个服务端目录下）已经有 `level.dat` 就拒绝，里面有别的东西也拒绝。先把声明的 `数据包` 找齐（相对 `sourcing/datapacks/`，或服务端 `世界数据包/` 下的，或 jars.toml 里文件名对得上的），缺一个不动手；放进 `<存档>/datapacks/`（第一次启动前放，建世界时自动启用，之后每个区块都按它来）；开服前核对数据包要的模组类在不在（`核对.ts` 的 `模组要求表`：生成时修整要 `TerrainTypes`，暮色放大 4 倍要 `TwilightGrid`，古城放大 4 倍要 `BigJigsaw`）；种子、世界类型、结构开关临时写进 `server.properties`，服务端就绪后改回原文（服务端会自己再补默认值）。就绪后核对启动日志里模组认出了数据包（暮色放大要 `暮色地标网格：64 区块`，古城放大要 `大拼图结构：minecraft:ancient_city`，带 `mcai:fill_biome` 的再要 `铺满群系：…`），修整包要启用并排在它覆盖的包之上；然后发 `--` 后面的命令（`sleep:`、`wait:`、`expect:` 同 `server`，例如 `locate` 核地标）、`save-all flush`、正常停服。停完没有 `level.dat` 或半路出错，没建成的目录收拾掉。`--sandbox` 只克隆服务端，新世界建在 `<数据根>/run/沙盒/…` 里。
- 种子、世界类型、结构开关只在建世界时读一次，建错了只能删掉重建，所以前面能查的都查在开服前。
- 存档就在服务端目录下时，起服不给 `--universe`（给了 Forge 的 `Main` 报 `Invalid world directory…the same directory as your universe` 不起服）；存档在别处（沙盒、`--save-dir`）才给。
## 预生成和服务端

```
anim world pregen <世界> [--box <名> | --corners x1,z1,x2,z2]        只打印 Chunky 命令（走廊块的 csv 写进草稿目录）
anim world pregen <世界> … --apply [--sandbox] [--heap 12G] [--gen-threads <n>] [--stuck-minutes 10] [--old-gen-limit 90] [--max-stalled-restarts 3] [--no-fill-holes] [--from-scratch]
anim world server <世界> [--sandbox] [--heap <G>] -- <命令…>             起服务端、按顺序发命令、关服（sleep:<秒>、wait:<一句话>、expect:<一句话>）
```

- 算法照 Chunky 1.3.146：矩形的中心对齐区块，半径向上取整到区块，(2r+1)² 个区块；走廊是折线两侧 `半宽` 米以内的区块（按区块中心到折线的距离），去掉 `去掉` 列的矩形盖住的，交给 Chunky 的 csv 图案，选区是外包方形。`主世界-116` 的「航线」由 `预生成/预生成.test.ts` 核 sha256。
- `--apply` 起的是专用服务端（不开客户端）：`<ANIM_GAME>/<服务端>/`，Forge 照 `Forge` 键用 `libraries/…/unix_args.txt`（Windows 用 `win_args.txt`），世界用 `--universe`、`--world` 指过去，端口挑空闲的。起服前：
  - 过资源闸（放行闸，等负载、内存够）；
  - `eula.txt` 要已经同意（不替人同意）、没有别的 anim 起的服务端在跑（pid 文件）、存档的 `level.dat` 在；
  - Chunky 从 `sourcing/jars.toml` 的 `chunky` 取（游戏目录有就用，没有从 Modrinth 下到 `<数据根>/cache/jars/`，核 sha256），临时拷进 `mods/`，关服后撤掉（记在 `.anim-临时模组.json`，上次没撤的下次起服先撤）；
  - 世界启用的数据包要满足模组要求（例：用了 `mcai:edit/region` 的生成时修整要装着带 `TerrainTypes` 的 mcai），`主世界修整` 这类覆盖别人的包要排在被覆盖的上面。
- 看守：发选区命令、逐句核对回话，再 `chunky start`；每 60 秒看堆（jstat）和日志，堆满、卡住（`--stuck-minutes` 内没有新日志，先存 jstack）就正常停服再起、`chunky continue`。跑完同一选区再扫一遍补洞，`--no-fill-holes` 跳过。连着 3 次重启（`--max-stalled-restarts` 调）Chunky 的 Processed 都没超过这一阶段之前的最高值，就报错放弃、不再起服（用户 10-31 定，`连续无进度`，`预生成.test.ts` 用假 java 验过）；状态文件留着，排查完重跑同一条命令只再试一次，还没进度又会停。Chunky 的任务按维度存在服务端的 `config/chunky/tasks/`，有暂停着又不是这一块的任务就拒绝。进度、每次起服、停服原因记在日志目录 `<数据根>/run/预生成/<世界>/<块>.状态.json`，看守被杀了重跑同一条命令接着来；`--from-scratch` 从头。Ctrl-C 也先正常停服。
- `--sandbox`：把服务端目录（不带里面的世界、日志）和存档用 `cp -c` 克隆到 `<数据根>/run/沙盒/<UTC 月日-时分>-<世界>/` 再跑，原存档、原服务端一个字节不动；试命令、试新数据包用。
- 停服等存盘最多 300 秒，超时才杀。Mac 上起服时顺手 `caffeinate -i -w <pid>`，跑着的时候机器不闲置睡眠。

```
anim world far tasks <世界> [--parts <n>] [--to <目录>]        按声明的 [远景] 排取样任务（粗、中、细三层的块）和地标列表任务
anim world server <世界> --sandbox -- "mcai far <任务.json>" "wait:mcai 远景：完成"     服务端里取样，存档不动
anim world server <世界> --sandbox -- "mcai landmarks <地标.任务.json>" "wait:mcai 地标：完成"
anim world far landmarks <世界> <地标.json> --camera-box x0,z0,x1,z1 [--view-dist 米] [--write <区块表文件>]   远处地标 → 预生成区块表
anim world far pack <任务.json…> [--no-register]                 取样拼成远景包、发布、登记（包名照声明的 远景.包）
```

- 取样 `/mcai far`（`sourcing/mod/…/FarTerrain.java`）：服务端进程里对每个要的区块新建一份 ProtoChunk，照游戏的顺序只跑 BIOMES → NOISE → SURFACE（暮色的噪声地形、地标附近起丘压平、黑森林硬化树冠、冰川、巨魔云都在这几步里），不放结构、不长树、不雕刻、不写存档，结果和这个区块生成那一刻一样、和别的区块生没生成无关。每点记地面（最高实心地形方块）、地表方块、群系（取地面或水面那一格，暮色群系是三维的，溪流底下是 underground）、水顶、树冠上下、云顶。
- 速度约 730～950 区块/秒（Mac 8 线程），是 Chunky 预生成的 20 多倍；全范围 226 万区块分两份各约 20 分钟。
- 和存档比：地面一样的 96.9%～98.8%，群系 99.9%；不一样的都是地物步（湖、巨石把地面压低 1～6 格，结冰，湖底的沙砾黏土）。
- 范围：`[远景]` 的 `外扩` 是导入范围（预生成矩形的外包框）四边各外扩多少米，对齐到 2048；粗层 32 米铺满，中层 16 米铺交界外 `中宽` 米，细带 8 米铺交界外 `细宽` 米（整块在导入矩形里的不铺）。格式同主世界远景包（`engine/voxel/远景网格.ts`），多 `远景.地表.bin.gz`（地表方块，下标进 `远景.json` 的 `地表名`）、`远景.冠顶/冠底.bin.gz`（黑森林硬化树叶）；海平面写 0（暮色 sea_level 0，不开含水层，地面低于 −1 的地方水到 −1）。中、细层存的差照 `distantTop` 现算，抽查细层点和取样差不超过 0.05 米。
- 远景里的树：暮色树种和各群系的郁闭度、冠顶按存档量（56 个区域文件，`engine/voxel/远景群系.ts` 的 `twilightBiomeSetups` 注释里有数）。
- 地标：`/mcai landmarks` 逐个地标网格中心问暮色自己的放置（`BiomeForcedLandmarkPlacement.isTFPlacementChunk`），再调结构自己的 `generate` 看真会不会生成（结构的 biomes 过滤），输出外包框。存档范围里和存档的结构起点对过，全对上。
- 远处地标的小块不补进原存档（重烘会改正式段用的 暮色放大-1752-扩展），另建同种子、同模组、同数据包的新存档 `暮色放大-1752-远地标`，预生成块是 `形状 = "区块表"`（`anim world far landmarks` 写的 JSON），烘成补充包；渲染时导入包没有的区段先取补充包，补充包也没有的列再用远景（`engine/voxel/主世界地形.ts` 的 `补充`）。终焉城堡的外包框有一边拉到 3 km 外，按中心 ±256 米截。
- 画面：用户 11-07 定 10 公里那档（规矩 `暮色超远景雾`），只开在 6-起飞（起飞后）、6-穿塔斩首领；落点 `作品/应力转动/地点/暮色新世界/超远景.ts`。试看参数（`REMOTION_ANIM_TRIAL`，`anim still`、`bench` 转给页面；`anim film` 设了它只出试看片进 `run/草稿/`，不进切片和交付）还能盖掉它、给别的暮色镜头临时打开，要多读的包写在它的 `地形` 下。没开的镜头和主世界画面不变。

## 给方块表加模组方块
体素路（`engine/voxel/`、`engine/model/方块拼搭.tsx`）画哪些方块，看方块表（`数据/场景/关键帧/方块表` + 贴图竖条 `贴图/场景/关键帧/方块表`）里有没有那个方块状态。表由 `sourcing/extract/关键帧方块.py` 从 jar 的 blockstates、模型、贴图里查出来，任意模组都能读（variants、multipart、parent 链、元素旋转、`forge:composite`）。

表只增不改：脚本带 `--基 <旧表.json> <旧表.png>` 时，旧表的贴图号、面组号、方块顺序和图集像素原样留着，只在后面追加查不到的状态；没有可加的就原样拷出。

全局表现在不动，新方块加在**按作品的附加表**里（全局表 + 追加，登记在作品侧，作品的 `换用.toml` 让这部作品把全局表的两个 id 换成它）。原因：图集多一行，着色器里 `atlasUv` 的分母（行数）跟着变，旧方块的 UV 浮点值不一样，应力转动的 4K 静帧有几个到几百个像素不同（树叶边缘；差别只来自图集行数）。要不要往全局表里加等用户定，见 `docs/待办.md`。

给一部作品加方块（例子是 亚波伦不放水 的粉色教堂，配方「方块附加-亚波伦不放水」）：
1. 模组 jar 登记进 `sourcing/jars.toml`（id、文件、sha256、许可）。
2. 列出要的方块状态。结构模板：`python sourcing/extract/关键帧方块.py --列状态 <结构.nbt>` 打出用到的状态，存成 `sourcing/方块状态/<名>.txt`（一行一个，`#` 是注释）。也可以在配方里直接给 `--结构 <.nbt>` 或 `--存档 <相对游戏环境的存档目录>`。
3. 在 `sourcing/extract.toml` 写一条配方（照「方块附加-亚波伦不放水」）：`"作品"`、`"可见性"`，`"需要"` 和 `--jar {jar:…}` 点名 jar（第一个是原版客户端，按顺序查、先找到的算），`"输入"` 摆全局表两件到 `基/`，步骤带 `--基 基/方块表.json 基/方块表.png --状态表 … --出 附加 --source {产物来源}`，产物是 `数据/方块附加/方块表`、`贴图/方块附加/方块表`。已有附加表的作品往状态表里加行、往 jar 名单里加 jar 就行。
4. `anim extract <配方> --work <作品> --register`：第一次登记进作品资产表、写作品资产锁。以后重跑 sha 变了只报告，看过追加清单后 `anim assets add <id> <暂存目录里的文件> --work <作品> --replace` 两件都换。脚本会打出：追加了多少状态和贴图、给的 jar 里没有 blockstates 的方块、画不出的（没有元素，方块实体画的）。
5. 作品根写 `换用.toml`（`pipeline/资产/资产锁.ts` 的 套换用）：
   ```
   "数据/场景/关键帧/方块表" = "数据/方块附加/方块表"
   "贴图/场景/关键帧/方块表" = "贴图/方块附加/方块表"
   ```
   这部作品里 `asset:` 引用、打包、指纹拿到的都是附加表，别的作品不受影响。
6. 出静帧看。亚波伦不放水 的 `核对-体素教堂` 把结构转成方块列表（配方「粉色教堂体素方块」，`sourcing/extract/结构方块.py`）用 `方块拼搭` 画出来。

要注意的：

## 裁级（11-17 起）

用户 11-17 定：区段包按全片实际用到的级裁，「只留用到的」——每处留全片用到的最细级和比它粗的级，不多留余量；第 3～6 级整包全留（只多零点几 MB）。完整包（连第 0 级）一直留着当源头，不改；裁过的包从它派生，是另一个版本目录。

```
anim world cover <段…>                        量段的地形覆盖：每帧挑哪些区段（不出图不画，过放行闸、整批一张票），存 <数据根>/cache/地形覆盖/<作品>/<段键>.json
anim world trim <包…> [--no-register]         所有作品里声明这个包的段，覆盖旧了的先量，并起来裁出包、逐段核对、登记
anim world trim <包> --keep <留表.tsv>         照手给的留表裁（核对缺级报错用），不量覆盖
anim world trim --import <裁过的包目录>        登记别的机器裁好拷来的包，本机可以没有完整包
```

**覆盖怎么量**：不另写一套模拟。`cover` 照正式出片的参数（视频级、段的输入、段渲染环境）在浏览器里把整段每一帧过一遍（`renderFrames` 不截图），页面带 `ANIM_TERRAIN_COVER`：体素世界照常算每帧要的区段（航线定级、投影余量、拼段的截、往后看都是渲染那份代码），只记下来、不取不建不画，也不做猜的预取（`engine/voxel/世界.tsx`、`导入地形.ts`）；光体这类旁路读的区段照常记。每个区段记头一次用到的帧。新加的段只要声明了 `terrain`，就自动算进来。结果按覆盖指纹认（段画面指纹去掉平台），段一改就旧了。速度约 0.065 秒/帧（6-追进竖井 235 帧 15 秒），两个包 13 段一共约 X 分钟。量出来的和整段出片时记的地形用量逐个区段相同（6-追进竖井 587 个）。

**裁**（`pipeline/世界/裁级/裁剪.ts`）：留表 = 覆盖用到的区段 ∪ 它们各级的祖先 ∪ 第 3 级以上全部，只留完整包里有的。块文件照留表只拷留下的段（每段字节独立）、重写块头索引，没留的索引长 0；每个块文件都写（页面按 Range 取块头不会 404）。`包.json` 原样加 `trim: { from: 完整包版本, keepSha256: 留表的 sha256, method: 裁法 }`，`模型.bin` 原样拷，另放 `留表.tsv`（每行 `L\ti\tj`）和 `完整包登记.json`（完整包的登记项，给 `--import`）。版本是内容指纹，放在同一个包名下。裁完逐段核对：留下的每段和完整包同一段逐字节一样、没留的索引是 0、别的文件一样，不一致不登记。登记在 `assets/地形版本.json` 那个包的 `trimmed`（版本、from、keepSha256、裁法、文件数、大小、清单 sha256）；完整包那一项不动。重烘、转码出了新的完整包版本，`trimmed` 跟着掉，要重裁。

不把留表写成 `包.json` 的 `splittable`（各处最细级本来就不一样的包，挑区段停在有的那一级）：裁过的包挑区段要和完整包一模一样，画面才不变；用到了没留的区段报「缺级」，不能悄悄停在粗一级。完整包自带的 `splittable` 原样留着。

**哪条路读哪一版**（`pipeline/渲/地形注入.ts`）：

| 读裁过的（各机器出图一致） | 读完整包 |
|---|---|
| `anim film`、`still`、`bench`、`reuse`、`verify`、试看片 | `still --tele` 的细一级、真值；会挑到正式画面不用的区段的试看（`engine/core/调试开关.ts` 里标了 `fullTerrain` 的：雾曲线、暮色远景、细分门槛、分级色调、航线定级、航线定级统计、光体、加载视点，和 `{"关":["航线定级"]}`）；`anim studio`；`anim world block/map/slice --pack`；转码、可见核对、训练、烘焙 |

完整包不在本机时，读完整包的路报错并说去哪取（`anim assets pull --full`，或从生成它的机器拷）；Studio 退回读裁过的并提示。`cover` 读完整包，本机没有就读裁过的（覆盖本身不取区段，光体冷缓存时才取）。

**段签**：段指纹的地形项记完整包版本（裁过的从它派生）。重裁不让段过期；代价是重裁后段签不变、切片照旧有效，靠下面两道保证裁过的包够用：

- **缺级报错**：裁过的包没有某个区段、粗高度图又说那里有地，页面报「缺级」（带重裁命令），出片停下。只管这一帧真要的区段；猜的预取（按前几帧外推、按航线往后备）取不到不报错、不停，撤掉等哪一帧真要到时在那一路报。同一块文件里别的区段不受连累。
- **`anim check` 的 terrain 规则**：用存着的覆盖，列出裁过的包里缺的段、头一次用到的帧、区段和重裁命令；覆盖没量或段改过只提示（给 `anim world cover` 命令）；裁过的包不是从现登记的完整包裁的算违规。要算段指纹，`--fast` 跳过。

**什么时候重裁**：改了镜头、航线、视距、画质门槛、段长这类会改挑区段的东西，`anim check` 提示覆盖旧了：`anim world cover <段>` 后再 check，有缺的就 `anim world trim <包>`；或直接 `anim world trim <包>`（会先量旧了的段）。重裁出新版本，旧版本目录留着。

**笔记本生成的世界**（用户 11-17 定）：笔记本从生成一路做到烘焙、转码、`anim world trim`，完整包、裁过的包都留在笔记本；只把裁过的包目录拷回 Mac，`anim world trim --import <目录>` 登记（核留表的 sha256、本机有完整包时逐段核对；登记表里还没有这个完整包时照包里带的 `完整包登记.json` 登记，用到它的段过期）。Mac 上要往细里看时再从笔记本拷完整包。

**Release**：`anim assets pack` 发裁过的包（`terrain-<裁过的版本>.tar`），完整包也挂上当备份（发布锁里 `terrain.backup: true`）；`anim assets pull` 默认不下备份，`--full` 才下。别人 pull 只下裁过的（主世界-116 X MB、暮色放大-1752-扩展 X MB）。`anim check --deep` 核裁过的包；完整包不在本机只提示。

## 地形压缩

现行代码读取 **格式 3**：逐格预测 + 32 类状态条件概率 + 每包训练先验。编码本身逐格还原；烘焙、转码时先过一遍可见变换（下面「可见变换」），只改看不见的格。格式 2→3 和可见变换的全包实测、取舍见 `docs/决策/0011-地形压缩.md`。

- 编码 `pipeline/世界/烘焙/区段编码.ts`，WASM 源码 `wasm/区段解码.ts`，解码包装 `engine/voxel/区段解码.ts`。`包.json` 和块头都是版本 3，索引、Range 方式不变。
- **每个版本目录必须有 `模型.bin`**。表是包的数据：和块文件一起算目录指纹、清单 sha256、发布附件，缺表报错，不从全局表补。表格式在 `engine/voxel/区段模型.ts`：小端头 + 状态类映射 + 概率初值 + 条件字面值权重。
- 模型只初始化概率，仍逐区段自适应、逐区段重置，没有相邻区段依赖。同包同区段无论前面解过什么、按什么顺序取，结果相同。
- 页面取 `包.json` 时只下载一次表，再广播给每个区段 Worker；按模型 URL（含包版本）留在 Worker，Range 活只发区段索引，不再传表或重新下载表。同包的不同挖空、平整来源共用一张表。
- 只有 WASM 生成文件进 Git。训练表不进代码闭包，改表只变包版本；段指纹仍只含本段声明的地形包。登记别的包不会让本段过期。
- `engine/`、查询只认格式 3；格式 1、2 的读法只在转码工具里。读旧包明确报错并提示拉取或转码，不静默尝试别的格式。

```
anim world transcode <包…> [--from <版本>] [--no-register] [--threads <n>]   格式 1/2 → 3、没做可见变换的 3 → 3；新目录、读盘逐格、逐网格核对、通过才登记
anim world decoder [--check]                                  用锁定的 AssemblyScript 重编 WASM；--check 只比较
```

### 可见变换（11-15 起）

用户 11-14 定「看得见的部分保留，看不见的部分不管」，11-15 定做进管线。`pipeline/世界/烘焙/可见.ts`，在 `转码目录` 里对每个区段做，所以 `bake`（写完中性中间包也走 `转码目录`）和 `transcode` 出的字节一样，训练用的也是变换后的区段。格式、解码、渲染都不变。四项，按这个顺序：

1. **封腔填实**：从最上一层和窗口外两圈列往里灌，灌不到的非整格（封死的空腔、水腔）换成填充方块。只动第 2～31 列（窗口外不知道通不通，贴边的当连通）。
2. **埋格换石**：六面都是整格的整格换成填充方块。只动第 2～31 列，最上一层不动。
3. **邻圈**：窗口最外一圈（相邻区段抄来的格，只用来剔面）里被埋的整格换填充方块、不挡面的（挡面掩码 0）换空气。
4. **第 0 级核心边**：第 1、32 列被埋的整格换填充方块，只在那一侧的同级邻段在包里、而且对面邻圈格在第 1 级的父格挡得住（整格或树叶；在粗区段 kBottom 以下的要那列最下一格实心）时换；粗区段缺、父格在粗区段顶上的不换。只换裙边贴图。

保真：世界声明的 `[[烘焙.保真]]` 盒四周多留 2 格（按各级格子大小）碰到的区段，各级都原样不动。作品渲染时挖开、整平的地方挖开以后会露出原来埋着的格，所以都要在盒里：各作品 `作品/<名>/地点/地形改动.ts` 汇总这些改动（基地小岛挖框、边城整平罩、暮色地标挖框和整平、亚波伦祭坛底），`anim check` 的 加载 规则按资产锁换真的 JSON 字节执行它，逐处核在盒里。新加挖框、整平要在那里登记；出了盒就要加盒、回存档重烘（或从没变换过的版本转码）。

`包.json` 记 `可见: { 填充, 保真 }`（盒排好序，不记名字，改名不变版本）。`transcode` 按烘这个包的世界声明做；已经做过而且盖住声明的不再转，声明多了盒、换了填充的报错（埋着的格已经换掉了，要从没变换的版本 `--from <版本>` 转，或重烘）。没有世界声明的旧试验包只换格式。`anim check` 另核登记的版本记的设置盖住声明。

核对（`可见核对.ts`，`transcode` 逐区段跑，不靠变换本身的写法）：读盘解新包和「旧包重做一遍变换」逐格比；改了的区段另核每个改了的格只许是规定的几种（封死的另走一遍独立的连通复核），再拿原样和改后各走一遍渲染那条路建网格：前八组（六个朝向、不沿轴、两面沿轴）没填腔的逐字节相同、填了的只少不改（少的面都贴着被填的格），裙边四组没换核心边的逐字节相同、换了的盖住的格一格不差。

### 训练、复现和小包

`bake` 和转码都自动调用 `pipeline/世界/烘焙/模型.ts`，每包学一次，不再有修改全局代码表的 `解码器 --训练`。

- 文件名按 UTF-8 字节排序、文件内按物理偏移排序；各 L 独立计数，每 40 段取第 0 段（覆盖所有有数据的 L）。无随机数、时间或机器路径。
- 训练样本里按状态行程次数选前 31 类，次数相同按状态号排序；其余及未见状态进第 32 类。预测/跳过带状态类，整列概率共享；字面值树按上一格状态类初始化，原色板的状态/群系对原样存。
- ≤1024 区段的小包把“训练表 + 全部编码”和“16 字节中性表 + 全部编码”都真正算一遍，选总字节更小的（相等选中性表）。大包不为了择表多做整包双编码；表成本及结果必须算在实测里。
- 新世界先在暂存目录生成使用中性表的中间包，等全部区段和状态号固定，再走和转码完全相同的训练/定稿流程；成功后删的只是暂存中间件，不删旧版本。不会为了训练再读一遍游戏存档。
- 同输入的烘焙、重烘、转码、换线程重转逐字节一致，由 `烘焙.test.ts` 守。整包大小含模型、`包.json`、块头、`缺失.tsv`。
- 编码后立即用正式 WASM 解回逐格比；转码另从磁盘解两边逐格比状态与群系，成功才登记。`anim check --deep` 核每个文件的 sha、模型合法性和所有块头版本；不是用“能解开”代替完整性检查。
- `anim assets pack` 自动把表装进对应的内容寻址附件；`pull` 随包解开并核整包清单。只使用 Node、WASM、TypedArray 和现有 tar/curl 链路，不新增 Windows 原生依赖。Windows 实机性能需另测。
- `anim check` 比解码源码 sha（Windows CRLF 规范成 LF），`decoder --check` 才真实重编。改模型数据不重编 WASM；改解码语法必须升格式版本。
- 主世界-116-远景 是高度/群系 `.bin.gz`，不是区段格式，不转、版本不变。
