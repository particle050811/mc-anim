# 光线影子抗锯齿：隔离中心射线，而不是减少采样

实测日期：2026-11-06（America/Los_Angeles；日志 UTC 为 2026-11-07）。基线 `e5bc6b1f`，分支 `codex影子`。只在该 worktree 改源码；没有升级版本、添加依赖、读取凭据、合并或推送。

## 结论与适用范围

保留当前抗锯齿的采样位置、同面判边、8 点采样和前四点一致即停，**只把中心射线从场景材质移到独立全屏遍**。本机这一段实测：

- 当前 main：150 / 150 / 151 ms/帧。
- 原来的无抗锯齿路径（主材质每像素一条）：133 / 133 / 149 ms/帧。
- 新方案：100 / 100 / 101 ms/帧。
- 第 100、101、139 帧与 main 的 RGB 平均绝对差和最大差均为 0，PNG 文件字节也一致。

因此，相对题目给的原单射线路径，保留抗锯齿后不仅没有新增帧耗时，反而更快。**这不是证明抗锯齿本身免费**：另把新方案的边检测和补采样关掉，得到 100 / 88 ms；交替的 AA 版本是 100 / 100 ms。一轮持平、一轮多 12 ms，尚未证明相对“同样优化后的中心射线版本”始终低于 +10%。不能拿优化中心射线的收益掩盖这项余量。

只对本机、该段 100–139 帧给性能结论；没有声称所有场景或 GPU 都能快同一比例。

## 1. 开销拆分

### 测法

正式计时不插探针，统一用：

```sh
./anim --作品 把回忆拼好给你 bench 2-收集快乐 --帧 100-139
./anim --作品 把回忆拼好给你 耗时 2-收集快乐 --最近 1
```

取日志的「其后每帧 中位」，即去掉首帧后 39 个出帧间隔；包括截图、交给编码器等，不是纯 GPU 时间。均经过资源闸，浏览器、输出设置、共享内存路径相同。首次初始化、打包不混入中位数。

分项诊断另跑：每个被测遍前后同步读回当前目标的 1 个像素，之后记 `performance.now()`。这包含读回、驱动同步及流水被打断的成本，**不是纯 GPU 时间，不能把分项中位数相加当作正式帧耗时**。仅 `gl.finish()` 的表面时间不能可靠归因；另外试过的 timer-query 数据也没有用作以下结论。

该段不是只有一张 3840×2160 画布：诊断识别到两个渲染器，离屏尺寸分别为 **3840×3120、3840×2160**。下表按同一歌曲时刻合计两张画布的工作，再取中位；跳过启动的头两个时刻。

| 分项 | main，同步诊断 ms | 新方案，同步诊断 ms |
|---|---:|---:|
| 罩遍（main 包含中心射线；新方案只有几何） | 78.15 | 12.45 |
| 独立中心射线遍 | — | 30.60 |
| 同面 3×3 边检测 | 7.10 | 6.35 |
| 边上补 8 条（前四条一致即停） | 15.60 | 18.90 |
| 主画面 | 5.85 | 5.85 |

另一次消融在 main 中把罩里的中心求交替换为常数，仍光栅化同样的场景、写同样的三张 RGBA32F：**罩遍 18.85 ms**。和 main 的 78.15 ms 相比，中心求交及其与场景材质组合的代价约 **59.30 ms**。这是差分归因，不是隔离出来的纯 BVH 遍历时间；删掉调用也会改变编译结果。

判断：

1. 罩遍的光栅化、MRT 写入确实有成本，但不是最大头；“多画场景就是主要开销”不符合这次消融。
2. 更大的问题是把中心求交塞进场景材质。移到独立全屏遍，几何罩 + 中心遍的诊断合计明显下降。
3. 边补采样并非免费，但本次没有靠减少边上射线来换速度。
4. 原因可能同时包括更小的片元程序、更一致的执行/纹理访问，以及只对最终可见面求交，避免光栅覆盖中随后被覆盖的片元白打射线。没有 GPU 编译器寄存器/occupancy 和射线次数计数，**不能把收益的百分比进一步归给其中某一项**。

## 2. 实现

新顺序：

1. **几何罩**：同样三张 RGBA32F，仍写起点、导数、法线；原来存中心可见度的位置改存朝光标记，法线 z 的符号编码不变。没有 BVH 声明或求交函数。
2. **中心遍**：独立全屏小着色器，读取已存的同一精度起点；只对朝光像素求交一次，写一张最近邻 RGBA8 的 0/1 可见度图。
3. **边分类**：仍是原来的同面 3×3 检测，只把可见度读取改到中心图；位置、法线、容差不动。
4. **边补采样**：原来的固定 D3D 8x MSAA 点位、前四点一致即停、深度早剔除，完全不改。
5. **主画面**：仍取最终抗锯齿可见度，不引入 BVH 源码。半透明直算变体维持原来的 8 点路径。

没有抖动、帧索引种子、历史纹理或跨帧累积。每次中心图整张写完，不能残留上一帧；既有 BVH 输入键缓存不变。

额外显存不是零：中心图每像素 4 字节，一张完整 4K 图约 31.6 MiB；本段两张实际离屏图合计约 **77.3 MiB**（不含驱动额外分配）。增加了一个全屏遍，不能简单按 pass 数量判断快慢。所有新增目标、材质和全屏几何在释放时回收。

### 为什么不采用更复杂的方法

- NVIDIA ATAA 的完整方案扩展 TAA，时间部分不符合本任务；“分类后只补少量射线”的思想当前版本已经在用了，继续削条数不是这次收益来源。
- AMD FidelityFX 阴影降噪有分块分类、时间与空间过滤；这里只要确定的硬影边覆盖率，没有必要引入一整套软影降噪/多遍空间滤波，更不能用历史帧。
- 单帧 1spp 空间重建省射线，但只有二值中心样本并不知道真实亚像素交线，可能把纹理或轮廓抹糊，不能保证当前结果。
- 解析挡光边覆盖率还要处理三角形共享边、遮挡并集和 alpha 镂空边，不是“多算一次距离就行”。既然简单隔离已经赢过指定基准且抽帧逐像素不变，本次不引入这些画面风险。
